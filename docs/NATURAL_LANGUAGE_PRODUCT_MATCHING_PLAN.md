# 자연어 품목 매칭 구현 계획

## 필드와 안전 경계

`Product.CounName`은 국가, `FlowerName`은 품종군, `ProdName`은 EXE 원본 품명, `DisplayName`은 웹 표시 별칭이다. 색상/상품명은 원문과 표시명에서 추출하되 Product 원장을 자동 수정하지 않는다. 단위는 품목 토큰에서 분리해 `단/박스/스팀(대)`로 보존한다.

검색과 이벤트의 업무 범위는 `TenantKey + OrderYear + OrderWeek + CustKey`이며 품목 선택은 `ProdKey`다. 2025년 같은 차수의 거래처 최근성은 2026년 검색에 섞지 않는다.

## 부작용 매트릭스

| 동작 | Product | Order/Shipment/Stock | Estimate/매출 | 웹 학습 원장 |
|---|---|---|---|---|
| 검색/후보 노출 | 보존 | 보존 | 보존 | 노출 이벤트만 |
| 사용자 선택/수정 | 보존 | 저장 동작 전까지 보존 | 저장 동작 전까지 보존 | 확인/음성 신호 |
| alias 승격 | 보존 | 보존 | 보존 | 검토된 alias만 변경 |

공용 순수 엔진은 NFKC, 대소문자·공백·괄호·특수문자, 한영 별칭, 국가·품종·단위를 정규화한다. 후보 DTO는 DB ID, 국가, 품종, 표시/원본 품명, 단위, 점수, 근거, 충돌, 모델 버전을 포함한다. 국가/품종 충돌 후보는 정상 후보와 분리한다.

점수는 문자열/별칭 70%, exact 22%에 국가·품종·단위 일치, 전역/거래처 사용량, 최근 사용, 확인 alias를 가산하고 국가 -48%, 품종 -42%, 단위 -18%를 감점한다. 고신뢰 0.90 이상만 자동 선택 가능하지만 현재 불량차감 화면은 기존 계약대로 항상 사용자 선택을 요구한다. 중간 0.68~0.90, 그 미만과 모든 충돌은 수동 확인이다.

## 공통화 단계

1. 불량차감 lookup과 `/api/products/search`가 공용 DTO를 사용한다.
2. 붙여넣기 주문등록, 견적 추가품목, 차수피벗, 도착원가 검색을 화면별 필터만 주입하는 thin adapter로 이관한다.
3. 모든 저장 API는 선택된 ProdKey의 국가/품종/단위를 서버에서 재조회하고 tenant/연도/차수/거래처 범위를 검증한다.

응답 역전은 요청 sequence로 차단하고 120ms debounce/서버 색인·집계 캐시를 유지한다. 원문 전체 대화는 검색 경로에서 읽지 않는다.
