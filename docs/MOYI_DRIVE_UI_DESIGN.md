# MOYI Drive·계정 연결·자동 업무 UI 설계

상태: 구현 전 설계. 운영 DB·사용자 파일·ERP 원장은 변경하지 않는다.

## 1. 근거와 설계 범위

### 실제 확인된 기반

- MOYI 프로젝트 확인 결과: 대화 분석, AI 상담, 파일 업로드, Drive 저장·검색·내용 조회, Nenova 조회·등록 도구, outbox, 말머리 기록, 자동화 미리보기 API가 존재한다.
- Nenova 저장소 직접 확인: `/api/moyi/report-push`는 로그인 사용자가 연도+차수 보고서를 MOYI로 보낸다. `exchange/members/recipients/connection`은 별도 MOYI 연결 쿠키를 사용한다.
- Nenova 화면 기준: 맑은 고딕, 12px 중심의 조밀한 표, 200px 왼쪽 메뉴, 파랑 `#0066CC`, 회색 배경 `#F0F0F0`, 24px 버튼, 선택 행 `#C5D9F1`, 성공/주의/오류 배지를 사용한다.

### 아직 확인되지 않은 부분

- MOYI 사용자·회사·기기·접속 기록의 실제 저장 구조와 파일별 최종 권한 검사
- MOYI User ID와 `UserInfo.UserID`의 승인된 연결
- 자동화 미리보기가 저장·전송을 전혀 하지 않는다는 검사 결과
- Word/Excel/PDF 내용 차이 계산기의 실제 구현

따라서 아래 화면은 확인된 API를 진입점으로 쓰되, 권한·버전 비교·승인 기능은 구현 대상이다. 기존 MOYI 연결 API를 Drive 권한 판정에 그대로 사용하지 않는다.

## 2. 화면 디자인 기준

| 항목 | PC | 모바일 |
|---|---|---|
| 글자 | 맑은 고딕, 본문 12px, 제목 16px | 본문 14px, 제목 18px |
| 간격 | 4/6/8/12/16px | 8/12/16/20px |
| 모서리 | 기본 2px, 큰 안내창 6px | 카드·아래창 8px |
| 버튼 | 높이 24px, 주요 파랑 | 높이 44px 이상 |
| 상태 | 파랑=정보, 초록=완료, 주황=확인 필요, 빨강=거부/실패, 회색=중지 | 색+글자+아이콘을 함께 표시 |

키보드는 `Tab` 순서를 화면 순서와 같게 하고, 선택 행은 색만 쓰지 않고 왼쪽 표시선과 `선택됨` 문구를 제공한다. 모든 아이콘 버튼에는 한글 이름과 도움말을 둔다.

## 3. 공통 화면 구조

PC는 `회사 선택(상단) / 왼쪽 메뉴 200px / 가운데 목록 / 오른쪽 상세 360px`의 3단 구조다. 태블릿은 상세를 겹쳐 여는 창으로, 모바일은 목록→상세의 한 화면 이동으로 바꾼다.

왼쪽 메뉴: `Drive 홈`, `최근 파일`, `내가 올린 파일`, `분류 필요`, `공유받은 파일`, `다운로드 기록`, `자동 업무`, `관리`.

회사를 바꾸면 목록·검색·최근 항목을 즉시 비우고 다시 조회한다. 회사가 하나면 선택기를 숨긴다. 이전 회사의 화면 내용을 잠깐이라도 남기지 않는다.

## 4. Drive 홈과 파일 목록

상단에는 현재 회사, 현재 폴더 경로, 검색창, `파일 올리기`, 보기 방식, 정렬을 둔다. 목록 열은 이름, 종류, 업무/차수, 담당자, 수정일, 상태, 크기다.

- 한 번 클릭: 선택과 오른쪽 상세 표시
- 두 번 클릭 또는 Enter: 폴더 열기/파일 미리보기
- 메뉴 키: 다운로드, 이름 변경, 이동, 버전 보기, 공유, 삭제
- 권한이 없는 동작은 숨기지 않고 비활성화하며 `관리자에게 요청`을 제공한다.
- 100개씩 이어 불러오고, 긴 목록은 화면에 보이는 행만 그린다.

검색 필터: 파일 종류, 차수(연도 필수), 거래처, 품목, 담당자, 문서 종류, 업무 상태, 올린 날짜, 내 파일/부서 파일. 검색 조건은 회사가 바뀌면 초기화한다.

## 5. 업로드와 분류

PC는 끌어놓기·파일 선택·붙여넣기, 모바일은 사진 촬영·사진 선택·파일 선택을 제공한다. 업로드 단계는 `선택 → 전송 중 → 검사 중 → 분류 확인 → 저장 완료`다.

분류 확인 화면에는 시스템 제안과 직원 확정값을 나란히 표시한다. 연도+차수, 거래처, 품목, 담당자, 문서 종류를 수정할 수 있으며 확정 전에는 `임시함`에 둔다. 실패 행은 성공 행과 분리해 재시도한다. 같은 해시 파일은 `새 버전`, `별도 파일`, `취소`를 선택하게 한다.

## 6. 파일 미리보기

| 종류 | 표시 | 주요 동작 |
|---|---|---|
| Excel | 시트 탭과 읽기 전용 표, 행·열 머리글 | 시트 검색, 셀 주소 복사, 변경 범위 강조 |
| PDF | 페이지 썸네일과 한 페이지 보기 | 확대, 페이지 이동, 텍스트 검색 |
| 이미지 | 화면 맞춤, 실제 크기 | 확대, 회전, 해상도 표시 |
| Word | 페이지/문단/표 읽기 보기 | 제목 이동, 변경 문단 강조 |
| 미지원 | 이름·크기·검사 상태 | `미리보기는 지원하지 않습니다`와 권한이 있을 때만 다운로드 |

미리보기와 다운로드는 별도 권한이다. `권한 없음`, `접근 기간 종료`, `다운로드 차단`을 서로 다른 안내로 표시하고 모든 성공·거부·만료를 기록한다.

## 7. 버전 타임라인

오른쪽 상세의 `버전` 탭은 최신순으로 작성자, 시간, 상태, 변경 사유를 보여준다.

- 제목만 변경: **제목 변경 · 내용 동일**
- Excel: `영업 시트 B12:D18 변경`과 마스킹된 이전/현재 요약
- Word: `문단 3개 추가 · 표 1개 수정`
- PDF: `2페이지 추가 · 5페이지 글자 변경`
- 이미지: `해상도 1200×800 → 1600×900 · 이미지 변경`
- 미지원 파일: `파일 내용 비교 불가 · 파일 자체는 변경됨`

각 항목에는 `이 버전 보기`, 권한이 있으면 `복원`, 관리자에게 `확정 버전 지정`을 둔다. 복원은 과거 원본을 고치지 않고 새 버전을 만든다. 파일명·제목·폴더 이동·권한 변경은 내용 변경과 다른 줄로 표시한다.

## 8. 권한 설정

직원/부서/역할별 행과 `보기, 미리보기, 다운로드, 업로드, 수정, 삭제, 공유` 열을 제공한다. 상속값은 `폴더에서 받음`, 직접값은 `직접 허용`, 차단은 `차단`으로 표시한다. 차단이 우선이며 기간을 지정할 수 있다.

일반 직원은 본인·부서 범위만 보고, 팀장은 부서 권한을 요청하며, 회사 관리자는 승인·회수·기록을 본다. 외부 사용자는 지정 파일, 지정 기간, 지정 동작만 가진다. 저장 전 `영향받는 사람 12명`과 새로 열리거나 막히는 항목을 보여준다.

## 9. Nenova 사용자 연결

관리 화면은 `미연결 / 승인 대기 / 연결됨 / 충돌 / 사용 중지` 탭으로 구성한다. 후보 행은 Nenova ID, 이름, 부서, 상태와 MOYI 사용자 후보를 나란히 보여준다.

- 같은 ID도 첫 연결은 `승인 대기`다.
- 동명이인과 부서 불일치는 빨간 `확인 필요`로 자동 연결하지 않는다.
- 승인 창은 회사, 두 사용자, 근거, 부여될 범위를 보여준다.
- 연결 해제 시 `앱 접속·임시 저장·새 파일 주소가 곧 차단됩니다`를 알린다.
- Nenova 비밀번호와 로그인 토큰은 화면·기록에 표시하지 않는다.

## 10. 다운로드 기록과 유출 방지

표 열: 시간, 직원, 회사, 파일, 결과, 접속 기기, 사유. 결과는 `완료`, `거부`, `기간 종료`, `대량 다운로드 경고`다. 관리자는 직원·기간·파일 등급으로 찾고, 경고를 열어 관련 기록을 시간순으로 본다.

대량 다운로드는 즉시 허용/차단을 정책으로 나누며, `일시 차단`, `직원에게 확인`, `보안 담당자에게 전달`을 제공한다. 예외 허용은 사유와 만료 시간이 필수다.

## 11. 자동 업무 화면

자동 업무 목록의 쉬운 상태명은 `미리보기`, `승인 기다림`, `실행 중`, `완료`, `실패`, `다시 시도 중`, `잠시 멈춤`이다. 행에는 업무 이름, 회사, 담당자, 입력 대화/파일, 다음 실행, 마지막 결과를 표시한다.

상세 흐름:

1. 대화를 분석해 할 일을 제안한다.
2. `미리보기`에서 바뀔 내용과 대상 파일을 보여준다.
3. 사용자가 승인한다.
4. 실행 직전에 회사·계정·권한을 다시 확인한다.
5. 같은 실행 번호는 한 번만 저장·전송한다.
6. 실패하면 시도 횟수와 쉬운 원인을 남기고 안전한 항목만 다시 시도한다.

ERP 변경은 별도 빨간 테두리 영역에 `전산 자료 변경 · 추가 승인 필요`로 표시한다. 일반 자동 업무 승인과 합치지 않는다. `nenovaweb_post`와 outbox는 이 승인이 없으면 실행하지 않는다.

## 12. 반응형·상태 전이

- PC 1280px 이상: 3단 화면, 표 고정 머리글
- 태블릿 768~1279px: 왼쪽 메뉴 축소, 상세는 오른쪽에서 열림
- 모바일 767px 이하: 아래 메뉴, 카드형 파일 행, 주요 버튼 44px, 필터는 아래에서 올라오는 창
- 가로 스크롤이 필요한 표는 첫 열을 고정하고 `옆으로 밀어 더 보기`를 한 번 안내한다.
- 닫기·뒤로가기는 입력 중일 때 저장 여부를 묻는다.

## 13. 재사용 구성요소 이름

`CompanyPicker`, `DriveSidebar`, `DriveToolbar`, `FileRow`, `FileStatusBadge`, `PreviewPane`, `VersionTimeline`, `PermissionGrid`, `IdentityMatchRow`, `DownloadAuditRow`, `AutomationRunRow`, `ApprovalPanel`, `EmptyState`, `AccessBlockedBanner`.

## 14. 구현 순서

1. 읽기 전용 Drive 홈·검색·미리보기와 회사 경계
2. 업로드 임시함·수동 분류·버전 목록
3. 권한 설정·다운로드 기록·계정 연결 승인
4. 내용 변경 비교와 복원·확정 버전
5. 자동 업무 미리보기·승인·실행 기록·안전한 재시도
6. 외부 공유·고급 유출 방지

## 15. 화면 테스트 목록

- 다른 회사로 전환할 때 이전 파일이 한 건도 보이지 않는다.
- 보기만 가능할 때 다운로드 주소를 직접 열어도 거부된다.
- 권한 회수 후 과거 주소가 다시 사용되지 않는다.
- 제목만 변경하면 내용 변경으로 표시하지 않는다.
- 연도가 없는 차수 파일은 Nenova 업무에 연결할 수 없다.
- 동명이인·부서 충돌·비활성 직원이 자동 연결되지 않는다.
- 미리보기는 DB 저장, outbox 등록, ERP 변경을 하지 않는다.
- 같은 자동 업무를 다시 시도해도 파일과 전송이 중복되지 않는다.
- 키보드만으로 회사 선택, 검색, 파일 열기, 권한 저장, 승인 취소가 가능하다.
- 320px 모바일에서 버튼·문구가 잘리지 않고 가로 스크롤이 본문 전체에 생기지 않는다.

## 16. Figma 진행 상태

Figma 연결 계정과 팀은 확인했으나 좌석이 `View`이므로 파일 생성·편집을 수행하지 않았다. 기존 Figma 파일 주소도 없어 디자인 체계를 추측하지 않았다. 편집 가능한 좌석과 대상 파일 URL이 제공되면 이 문서의 구성요소 이름과 화면 순서를 그대로 사용해 디자인 변수→공통 구성요소→PC 화면→모바일 화면 순으로 옮기고, 각 화면 캡처로 잘림·스크롤·권한 상태를 검증한다.
