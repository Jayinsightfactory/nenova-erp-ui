# 하위 세션 실행 순서와 사용량 관리

373개 원본 프로그램을 탭/기능군 기준 최대 10개씩 59개 작업 묶음으로 편성했다. 실행 목록은 `data/ecount-workbench/parity-packets.json`이다. 같은 프로그램의 별칭 430개 경로를 포함한다.

1. FOUNDATION-READONLY: 조회/다운로드만 허용하는 수집 경계와 동작 로그를 검증한다.
2. FOUNDATION-ISOLATED-SQL: 명시적으로 분리한 SQL 대상, 배치 원본/변환 이력, 검증 후 공개, 배치 롤백을 검증한다. 운영 원장 쓰기는 금지한다.
3. 각 묶음 첫 화면을 상세 조사하고 공통 검색·표·팝업의 재사용 가능 범위를 확인한다. 그 후 같은 묶음의 차이를 조사한다. 공통 코드 존재만으로 남은 화면을 완료하지 않는다.
4. 화면별 원본 근거 → 명세 → 개별 구현 → 별도 SQL 합성 검증 → 원본 대조의 순서로 진행한다. 실제 API가 필요한 화면도 UI와 저장 계약까지 진행하되 연동 검증은 미완료로 남긴다.
5. 묶음 완료 또는 차단 시 수정 파일, 완료 화면, 근거, 미확인 항목, 다음 시작 위치를 checkpoint로 남긴다. 패킷 stage와 resumeFrom을 갱신한다.

하위 작업은 원본 조사, 분리 SQL, UI 구현으로 소유 파일을 분리한다. 동일 파일을 여러 세션이 수정하지 않는다. 원본 브라우저 조사는 한 명만 수행한다. 동시 하위 작업은 최대 3개이며 각 묶음은 1명만 소유한다. 실제 수집 전에 선행 기반의 검증 상태를 확인한다.

최초 기준선은 계정 주간 사용 26%였으며, 이번 계속 작업은 41% 사용 상태에서 시작한다. 계정 전체 한도이므로 이번 작업의 토큰 소모량으로 환산하지 않는다. 정확한 토큰 예산 또는 하드 차단을 보장하지 않는다. 묶음 경계에서 사용량을 확인하고 중복 조사·재시도 반복 작업자를 중단한다. 계속 전체 대화를 복제해 새 작업자를 만들지 않고 짧은 인계와 기존 작업자를 재사용한다. 변경 관련 테스트를 먼저 실행하고 릴리스 후보에서 전체 필수 검사를 한 번 실행한다. 한도 초기화·추가 크레딧 구매는 하지 않는다.

첫 실행 근거는 E010205 은행 거래 조회 화면이다. 확인되지 않은 다른 화면에는 버튼과 새창을 추정해 채우지 않았다. 전체 버튼/새창 100% 대응 여부는 화면별 증거를 쌓아 판정한다.


## 계속 작업 체크포인트 — 2026-10-20

모든 59개 묶음·373개 프로그램 범위를 유지한다. 완료 묶음과 100% 검증 화면은 모두 0이다. 기존 3개 작업자를 재사용하며 원본 브라우저는 root 한 명만 조작한다. 작업자는 원본 근거가 없는 동작을 추정하여 완료로 표시하지 않는다.

| 우선순위 | 묶음 | 먼저 진행하는 화면 | 현재 단계 | 다음 행동 |
|---|---|---|---|---|
| 1 | P002 | E010205 은행 | 개별 구현 진행 | 확인된 검색·매핑 오버레이 동작 대응, 미확인 버튼 근거 대기 |
| 2 | P003 | E040214 채권 | 개별 구현 진행 | 확인된 조회 결과 열과 검색 전환 대응 |
| 3 | P015 | E040309 채무 | 상세 근거 대기 | 부분 관찰된 조회/표 이후 버튼·팝업 조사 |
| 4 | P011 | E040207 판매 | 상세 근거 대기 | 기존 안전 적재와 별개로 각 버튼·창의 원본 근거 확보 |

각 묶음의 다른 화면은 pending-source-survey 상태다. 우선 화면 하나를 구현해도 묶음 전체를 완료로 바꾸지 않는다. 두 구현 묶음은 동일 UI 작업자가 차례로 소유하여 같은 파일의 동시 수정을 피한다. 실제 실행 순서와 체크포인트는 parity-packets.json에 유지한다.

FOUNDATION-READONLY는 ready-scoped다. 원본 조회/검색/다운로드 허용 계약과 검사, 확인된 부분 관찰을 확보했지만 모든 원본 버튼을 기술적으로 차단하는 자동 가드나 전 직원의 전체 조작 로그를 확보한 상태는 아니다. 출처 불명 동작은 계속 금지한다.

FOUNDATION-ISOLATED-SQL은 verified-scoped다. 기존 세션 기록에 따라 독립 ecount_work 스키마의 네 데이터셋(cash/ar/ap/sales), rollback-only 9개 검사, 실제 적재와 운영 읽기를 확인했다. 기타 데이터셋은 해당하지 않는다. 안전 숫자·날짜 투영이므로 거래처/품목 등 누락 항목과 원본 전체 자료의 동등성은 미확인이다. 복원은 SQL 활성 버전만 바꾸며 ECOUNT에 쓰지 않는다.

source-action-audit.jsonl은 root가 직접 확인하여 전달한 허용된 원본 동작을 메타데이터로 누적한다. 정확한 실행 시각을 알 수 없으면 날짜만 기록한다. 과거 전달 근거는 reported-observation으로 표시하며 새로 실행한 것처럼 쓰지 않는다. 개인정보·계좌번호 값·거래행·세션 URL을 남기지 않는다. 초기 과거 기록은 확인된 다섯 동작뿐이며 원본의 모든 행동을 포괄하지 않는다.

최종 산출물에 Excel 동등성 보고서를 추가했다. `report-contract.md`와 `button-matches.json`에 모든 페이지의 원본 버튼 ID/라벨과 대상 동일 ID, 양쪽 안전 캡처, 기능·새창·조회값 검사 근거를 지속 기록한다. 아직 캡처가 없으면 null/미검증이며 빈 보고서로 완료를 주장하지 않는다. Excel 실파일은 후속 스프레드시트 스킬 작업에서 제작한다.
