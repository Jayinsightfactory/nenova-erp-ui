# ECOUNT 페이지·버튼·새창 동등성 작업 계약

기준일: 2026-10-20. 사용자 요청은 모든 페이지의 버튼 기능과 새창까지 대응하는 구현이다. 메뉴를 연결하거나 공통 폼을 만든 것만으로 완료 처리하지 않는다.

## 현재 기준선

현재 로그인 계정 사이트맵 537개 경로 중 430개 화면 경로를 프로그램 코드 기준 373개로 묶었다. 나머지는 탐색용 그룹이다. 같은 프로그램의 경로는 별칭으로 보존하고 각 경로의 진입 조건·권한·초기값 차이를 별도 확인한다. 이 수치는 해당 계정에서 확인한 범위이며 미노출 권한·상품의 전체 기능을 의미하지 않는다.

`data/ecount-workbench/parity-inventory.json`에 화면별 작업 상태를 기록한다. 초기 버튼·창 개수는 `null`(미조사)이며 0으로 간주하지 않는다. 일부만 관찰했어도 전체 개수를 확정하지 않는다. 현재 완료 화면은 0개다. 이 목록은 내부 작업 관리용이며 사용자 화면에 메뉴 수·통계 카드로 표시하지 않는다.

## 100% 판정

각 원본 프로그램과 모든 진입 별칭에서 다음 항목의 원본 근거, 구현, 실행 검증을 모두 확보해야 한다: 입력 항목, 표 열, 정렬, 검색 조건, 버튼, 새창, 대화상자, 선택 결과의 부모 반영, 검증 메시지, 다운로드, 키보드, 권한, 오류 상태. 없는 기능도 실제 확인 근거와 해당 없음 검증을 남긴다. 미확인 항목을 임의로 제외하지 않는다.

각 차원의 `stage`는 unknown → observed → specified → implemented → verified 순서다. 화면 자체의 metadata는 사이트맵 정보만 있다는 뜻이다. verified에는 원본 `evidence`와 구현 `testEvidence`가 모두 필요하다. 원본에서 창을 열어본 사실만으로 네노바 구현을 verified 처리하지 않는다. 화면의 전체 버튼·창 수가 확정되고, 개별 항목 검증과 모든 별칭 문맥 검증을 마치고, blockers/exclusions가 비어야 완료한다. 외부 연동도 디자인·저장 설계는 포함하지만 실제 API 동작 미구현은 완료로 셈하지 않는다.

## 원본 보호

이카운트에서 허용하는 실행은 확인된 조회·검색·다운로드뿐이다. 이름만 보고 안전하다고 추정하지 않는다. 알 수 없는 동작은 실행하지 않는다. 입력·저장·수정·삭제·발행·전송·이체는 원본에서 절대 실행하지 않는다. 해당 동작은 공식 도움말·제공 사양으로 명세화하고 별도 SQL 작업 영역에서 합성 자료와 승인된 수집 자료로 검증한다. 원본 저장 전 상태를 확인한다는 목적으로도 저장 버튼을 누르지 않는다.

작업 근거에는 메뉴/필드/버튼 이름과 동작 설명만 남긴다. 계좌번호 값·개인정보·거래 행·자격증명·세션 URL은 이 JSON과 문서에 기록하지 않는다. 데이터 적재 자체는 별도 SQL 보안 계약 및 배치 이력·롤백 절차의 소관이다. 기존 운영 원장과 원본 ECOUNT를 롤백 대상으로 삼지 않는다.

## 실행형 검사

```text
node scripts/check-ecount-parity.cjs
node __tests__/ecountParity.test.cjs
node scripts/check-ecount-parity.cjs --require-complete
```

첫 명령은 구조·커버리지·원본 실행 제한을 검사한다. 마지막 명령은 실제 100% 완료 전에는 종료 코드 2로 실패해야 정상이다. 일반 검사 통과를 동등성 완료로 표현하지 않는다. 자동 검사는 근거 참조의 존재를 검사하며 근거 내용의 정확성과 시각적 일치는 검토자가 대조한다.
