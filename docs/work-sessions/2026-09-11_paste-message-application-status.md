## 이어받을 때 고정된 결정

- 원문은 최신순, 원문 곁에 수동 상태와 비교 이력을 함께 표시한다.
- 수동 적용함/미적용 표시/표시 해제는 실제 ERP 등록·분배·취소가 아니다.
- 기존 checklist REVIEWED는 적용됨으로 해석하지 않고 별도 저장소를 유지한다.
- 같은 변경 이력 발견만으로 현재 적용 완료 또는 카톡 요청과의 인과관계를 단정하지 않는다.
- 이력이 없으면 미적용이 아니라 적용 미확인이다. 사용자가 명시한 미적용은 별도 표시한다.
- 비교 결과는 최근 20개 저장 보고서 범위이며 기준 시각과 표시 상한을 명시한다.
- 모든 참고 상태는 등록·분배·확정을 막지 않는다. 자동 LLM 호출과 ERP 쓰기는 추가하지 않는다.

### 1. 2026-09-11 — 최신 대화 옆 적용 상태

**Q.** 최신순으로 표시하고 적용 히스토리를 옆에 붙여 적용됨/안됨을 보고, 수동 적용함 버튼도 제공해 달라.

**A.** 별도 append-only 수동 적용 원장과 scope별 일괄 조회를 추가했다. 명시적인 연도·전체 차수·원문 identity, 사용자와 시각을 기록한다. UUID 재시도와 직전 이벤트 기준 CAS를 사용하고, 영구 잠금 대신 atomic receipt/transition hardlink로 동시 저장을 판정한다. 원장 파일은 연도·차수별로 격리하고 손상·키 불일치를 거부한다.

자동 이력은 저장된 report의 sourceIdentity와 요청 ID를 정확히 연결한다. 한 원문의 일부 요청만 일치하면 전체 동일 이력으로 표시하지 않는다. 품목·업체·수량과 전후 값·시각을 펼쳐 볼 수 있다.

**결과.** `docs/distribution-board/PASTE_MESSAGE_APPLICATION_STATUS.md`와 관련 기능 계약에 상세 기준을 남겼다. 구현 terra/high, 독립 검토 sol/high, 메인 설계·통합·외부 반영. 하위 작업은 P0_LOCAL만 사용했다.
