# 신라 손익 업로드 재저장본 검증

## 질문

`2026 신라 상반기 입고 손익계산_이사님보고.xlsx`를 신라 손익계산서에 올리면 15·30·31·33차가 다시 검증 실패하고, 행 오류가 `원본 없음 vs 파싱 없음`으로 표시되는 원인은 무엇인가?

## 확인 결과

- 최초 사용자 확인본 SHA256은 `1ce46b...`, 현재 파일은 `4b46cf...`였다. Excel을 다시 저장하며 파일 package hash가 달라져 과거 확인 정책이 전부 비활성화됐다.
- 현재 파일의 확인 대상 업무 셀은 과거 합의와 동일했다.
  - 15차 염색 호접 48개: 매입단가 빈칸, 매입액 0인 무상입고.
  - 30차 장미 2행: 헤더는 80:20인데 행 배분액만 60:40으로 남아 있음.
  - 31차8월: 합계 수식이 9행 염색 호접 매입액 266,400원과 배분액을 누락.
  - 33차: 품명은 비고/칼라 칸의 `태국샘플`을 원문 이름으로 사용하기로 확인됨.
- 30차는 현재 파일에서 이익/배분 열이 H/J/K이고, 과거 보정의 I/K/L 고정 좌표와도 달랐다.
- 행 확인 경고는 비교 숫자가 없는 정보형 검증인데도 공통 숫자 비교 문구를 써 `원본 없음 vs 파싱 없음`을 만들었다.

## 반영 결정

- 전체 파일 SHA가 아니라 시트 제목·헤더·해당 업무 셀 값이 모두 일치할 때만 이전 사용자 확인을 재적용한다.
- 확인 대상 행 값이 하나라도 달라지면 보정하지 않고 일반 검증 실패로 남긴다.
- 30차 열은 고정 위치가 아니라 실제 확인된 현재/과거 레이아웃을 판별해 보정한다.
- 행 확인 경고에는 원본 품명·칼라·수량·매입단가·매입액·매출단가·매출액을 표시하고, 숫자 비교가 없는 경우 `원본 없음 vs 파싱 없음`을 출력하지 않는다.
- 업로드 원본 파일은 변경하지 않으며, 주문·출고·재고·견적 원장은 보존한다.

## 검증

- 현재 파일: 40개 시트, 37개 단일 차수.
- 일반 파싱: 검증 실패 7건.
- 확인 정책 적용 후: 37개 차수 전체 검증 실패 0건.
- `npm run test:shilla-pnl`, `npm run test:erp-contract`, dnSpy evidence, manifest/write guards, production build 통과.
