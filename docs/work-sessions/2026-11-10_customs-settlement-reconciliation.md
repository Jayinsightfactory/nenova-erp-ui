## 고정 결정

- DB를 건드리지 않고 원문/SQL/웹 표시의 차이만 조사한다.
- ZIP 차수명보다 SQL 활성 연도·차수·AWB 귀속을 우선한다.
- 원천 연결과 기존 보고서 갱신은 분리하며, 사용자 확인 없이 저장본을 갱신하지 않는다.
- 관세·대행료 공급가와 수입부가세·대행료 VAT를 구분한다.
- 실제 PDF·금액표·DB probe는 비공개 `.verify`에 보관하고 Git에 넣지 않는다.

### 1. 2026-11-10 — 100% 매칭 확인의 의미

**Q.** 통관비와 100% 매칭하는지 확인하라는 뜻이었다.

**A.** 첫 페이지 판독 성공을 전체 통관비 일치로 설명한 것은 과도했다. 뒤 증빙과 SQL 귀속·실제 웹 표시 금액을 대사하는 작업으로 전환했다.

### 2. 2026-11-10 — 미연결 2건과 35·36차 전수 대사

**Q.** DB는 건드리지 말고 미연결 2건 원인을 찾고 정산서 항목·합계까지 끝까지 대조해 차이를 정리해 달라.

**A.** 26개 정산표의 비용 합계·VAT 관계를 모두 검산하고 대행료가 있는21건의 세금계산서를 시각 대조했다. HOOD는 SQL 활성35-01/삭제36-01로 차수 차이, CLOUD는 2AWB의 결제금액과 GW가 하나의 입고에 합산된 형태와 정확히 일치한다. 35차는 일부 공급가에 VAT를 이중 제거한 계산식과 CO/미국 비용 미연결, 36차는 관세·대행료 누락 및 태국 기본 대행료 차이를 확인했다. 세부 금액은 `.verify/35-36-customs-reconciliation-20261110.md`에 정리했다.

**결과.** 35v10/36v7 저장본 불변 확인. DB·보고서·배포 변경 없음. `.verify/build-reconciliation.cjs` assertions 통과. 단, 원문에 별도 청구가 없는 백상/운송/방역 지출을 100% 인증하거나 전 신고품목의 HS 적법성을 재심사한 것은 아니다.
