## 고정된 결정

- 원본 읽기 성공, 패킹 생성, ERP 품목 매칭, 입고 저장, 원가 확정은 각각 별도 검증이다. 한 단계 성공을 전체 완료로 말하지 않는다.
- 중국 구형 6열 Invoice는 규격 `500g/10pcs/20pcs`로 native 수량을 추정하지 않는다.
- 이번 수동 해결 경로는 **원문 수량이 단이라고 명시 확인된 행**만 지원한다. 박스와 전체 송이는 직접 입력하고 환산 근거를 남긴다. 다른 단위는 자동 승격하지 않는다.
- Invoice와 CL 비교표를 합산하지 않는다. CL 충돌이 있으면 Invoice 기준 사용을 명시 확인한다.
- 날짜의 두 자리 연도·월일 순서·invoice/shipment/arrival 의미를 파일명이나 현재 차수로 추정하지 않는다.
- CN/CO 상품 외 비용 합계를 순수 항공운임으로 자동 분류하지 않는다. 입고 초안에 미분류 합계로 보존하고 원가 항목별 확인이 필요하다.
- 이전 유료 AI 승인 30/30회 소진. 이번 수정·검증은 추가 유료 AI 호출 0회다.

## 질문 → 처리

### 1. 수정 시작 요청

**Q.** 한 건 외 모두 대응됐는지 확인한 후, 해결 가능하도록 수정 요청.

**A.** 기존 감사의 미지원·미검증 항목을 구분해 다음을 구현했다.

1. 중국 구형 Invoice/Invoice 日报表 6열 원문 파서. 상품·비용·소계·총액·수식 캐시·CL 비교표 보존.
2. 행별 단위·박스·송이·통화·사유 확인 UI와 순수 검증 helper. 원문 스냅샷 누락/중복/변경을 차단하며 확인 결과를 기록.
3. 날짜·통화·총액별 직접 수정과 개별 확인. 미해결 이슈를 일반 확인 체크만으로 해제하지 않음.
4. CO 프롬프트의 상품 소계=총액 모순 제거. 상품+명시 부대비=총액으로 검증.
5. NL 무료 파서가 원문 Arrivaldate 및 EUR 통화를 전달하도록 보완.
6. 생성기·다운로드·입고 adapter의 미해결 검토 차단. 승인된 legacy 수량 스냅샷도 재검증.

### 2. 검증 범위

**A.** 중국 감사 원본 3개는 27+32+50=109 상품행과 산술을 보존했다. 이는 실제 수량 단위 확인·운영 입고 완료를 뜻하지 않는다.

- synthetic XLSX `parse → explicit review → genChina → receipt draft`에서 상품 단수/박스/송이/가격/금액과 BOX 부대비를 확인했다.
- 과거 날짜 오류 274399, EC-5353, FGD32189와 CO 106255 날짜 의미, FC01191 부대비 36.34를 독립 회귀로 고정했다.
- NL 실제 PDF 2개 원문 읽기 회귀 통과. 원본 파일은 변경하지 않았다.
- 1920×1080 CSS pixel, deviceScaleFactor 1 브라우저 검토 입력·체크·버튼, 모달 화면 경계, 가로 넘침, 키보드 접근 확인.
- 전체 ERP 계약 검사 및 빌드 1차 통과. 최종 통합 검사 및 배포 결과는 아래 추록에서 구분한다.

## 미완·주의

- CO 15차 PDF p10~14의 4개 송장(3882, 273811, 127922, 127929)은 유료 재분석을 추가 실행하지 않았다. 기존 502 미파싱 상태를 전체 성공으로 바꾸지 않는다.
- 사용자의 실제 단위·통화 확인 없이 legacy 원본 109행을 운영 입고하거나 재고를 바꾸지 않았다.
- 원가 자료 승인/운영 입고 저장/nenova.exe 실데이터 대조까지 새로 검증했다는 뜻이 아니다. 기존 writer는 변경하지 않았다.
- `outputs/`의 원본 PDF/XLSX·AI 응답·스크린샷은 private 검증 자료이며 커밋하지 않는다.
