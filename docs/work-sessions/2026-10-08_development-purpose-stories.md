## 고정된 결정

- 커밋 제목 나열은 사용자가 원하는 업무 연혁이 아니다.
- 기본 화면은 왜 만들었는지, 실제 버튼·설정·작업 흐름과 이후 보완을 쉬운 한국어로 설명한다.
- 전체 안전 기록은 목적 이야기 또는 명시적 검토 대기에 정확히 한 번 연결한다.
- 근거 부족은 추정하지 않는다. 연결 건수는 기능 수·요청 수·성과 수가 아니다.
- 원본 날짜별 기록은 별도 보기로 보존한다.
- 비공개 대화 본문·문서 경로·규칙·원장 데이터는 새 API에 공개하지 않는다.

### 1. 목적이 보이지 않는 기존 화면

**Q.** 전체 작업 흐름을 보면 목적과 만든 버튼·설정을 알 수 있는데, 개발 제목만 나오는 것은 원한 화면이 아니다.

**A.** 기존 날짜별 타임라인의 한계를 확인했다. 안전한 전체 기록과 계획·계약 문서를 읽고 사람이 작성한 목적 이야기 catalog를 별도로 구성한다. 기본 카드에는 목적·사용자 가치·실제 변화를 표시하고 원본 제목은 접힌 근거로 둔다.

**결과.** 기본 화면을 목적별 이야기로 변경했다. 38개 이야기에는 목적·사용자 가치·실제 변화와 보완을 작성했고, 기존 날짜별 보기와 원본 근거는 보존했다.

## 검증과 배포

- 개발 이력 테스트 42/42 통과. 전체 원장의 각 기록이 목적 이야기 또는 검토 대기에 정확히 한 번 포함됨을 모든 페이지 합집합으로 검사했다.
- 현재 5,184건 중 1,782건 연결, 3,402건 검토 대기다. 이는 전체 목적을 해석 완료한 상태가 아니다. 특히 MindMap 원본과 제목만 있는 작업요약의 추가 검토가 남아 있다.
- 독립 검토에서 모바일 손익 예시를 실사용 기능처럼 설명한 문구를 발견해 `일부 확인 필요`와 예시 전용 범위를 명시했다.
- 펼침·페이지 이동 초점, 전역 집계와 필터 결과 구분, 광범위 규칙 거부를 보완했다.
- dnSpy 근거·계약 manifest 92개·ERP 쓰기 방지(변경 API 1개)·화면틀·전체 ERP 검사·프로덕션 빌드 통과. 독립 검토는 정적 읽기 전용 기능으로 조건부 승인했고, 전체 목적 서술이 아닌 부분완성이라는 제한을 명시했다. PR·배포·실제 화면 확인 결과는 후속 기록한다.

## 남은 작업

목적 검토 대기의 의미를 근거 문서와 대조해 추가 작성해야 한다. 연결률을 올리기 위한 광범위 규칙이나 저장소 단위의 임의 목적은 쓰지 않는다. 현재 결과를 ‘104페이지 모든 목적 정리 완료’라고 보고하지 않는다.

## 전체 작업내용 전수 정리 보완

**Q.** 화면만 목적별로 바꾼 것이 아니라 최초 개발부터 전체 작업의 목적, 버튼·설정, 발생한 문제와 보완 과정을 정리해 달라.

**A.** 기존 상태의 부족을 검토했다. 로컬 원장 5,196건 중 연결은 1,789건이며 MindMap은 1,909건 중 45건뿐이었다. 붙여넣기 292건을 5단계로 압축한 설명과 개발 전문용어도 사용자 요구에 부족했다. 전체 정리 완료로 판정하지 않고 원본 메타데이터·실제 계획·계약·코드 근거를 대조하는 추가 작업을 시작했다.

- 하위 작업은 MindMap, ERP, Kakao의 서로 다른 입력 범위를 읽고 별도 초안만 작성한다. 운영 원장·외부 쓰기·배포 권한은 없다.
- 모델 배정: 목적 근거 해석·작성은 프로젝트 지침의 `gpt-5.6-sol` high/xhigh, 통합·외부 반영은 메인 담당이다. 모든 작업은 로컬에서 준비된 원본 저장소와 정적 기록을 읽는다.
- 화면 설명에 선택 항목 `해결하려던 문제`, `달라진 점`을 추가하고 기존 `만든 것·바꾼 것`과 함께 표시한다. 예방 목적을 실제 발생 사고처럼 단정하지 않으며 근거 없는 항목은 만들지 않는다.
- 같은 날의 목적 이야기 순서도 실제 시각을 비교한다. 날짜만 같다고 이름순으로 최초 개발보다 보완을 먼저 표시하지 않는다.
- 전수 메타데이터 스캔과 목적 확인을 구분한다. 근거 부족은 이유를 남기고 검토 대기로 보존한다.
- 개발 이력 테스트 47개와 화면틀·dnSpy·manifest·쓰기 방지·전체 ERP 검사 및 빌드가 통과했다. 이후 내용 통합에 대한 최종 재검사는 별도로 수행한다.
- 독립 검토에서 MindMap 초안의 키워드 자동분류가 무관한 커밋을 직접 근거처럼 연결한 오류를 발견했다. 이 초안은 배포하지 않으며 실제 diff를 확인한 변화별 대표 근거로 다시 작성한다. 연결률을 높이려고 부정확한 연결을 유지하지 않는다.
- ERP 추가 초안의 농장표 `농장 선택 버튼` 오기도 실제 국가·품종 버튼과 대조해 바로잡았다. 메인에서 미연결 ERP 기록 536건의 메타데이터를 모두 읽고 입고 인사이트·수입부 정산·주문등록·선출고·업무 데이터·배포 체계 등 누락 목적을 추가 검토 대상으로 지정했다.
- `reviewNotes`는 안정된 커밋 키만 허용한다. 작업 메모 목록순번은 재생성 시 변하므로 지속 연결에 쓰지 않으며, 목록순번 사유 입력 거부·중복 거부·민감값 치환·목적 연결 기록 미노출을 검사했다.
- 최신 master `9a9a22a1`의 카톡 SQL 처리 자동확인 변경을 fast-forward로 보존했다. 주문·입고·출고·재고 원장에 대한 읽기·쓰기는 이 정리 작업에서 실행하지 않는다.
- 독립 검토는 MindMap 앞 12개 이야기의 48개 변화와 ERP 초기 14개 이야기의 78개 변화를 실제 변경 내용과 대조했다. MindMap의 무관한 직접 근거와 미확인 화면 주장은 제거하고, ERP에서는 잔량의 클립보드 복사·일회성 운영 복구·신규 주문 생성 조건·웹 전용 납품 수량·권한 변경 미지원 등 15개 불일치를 수정 대상으로 확정했다. 검토 보고서는 `config/development-mindmap-review.json`, `config/development-erp-review.json`에 남긴다.
- MindMap 후반 12개 이야기는 49개 변화·110개 고유 대표 변경을 실제 diff로 대조했다. 기존 8개 이야기의 43개 직접 근거는 새 목적에 분산 통합하며 최초 화면의 검색·종류 필터·배치 선택과 3차원 조작 근거를 보존한다.
- 새 설명에 직원·거래처의 실제 이름과 원문 대화를 옮기지 않는다. 기존 인증된 원본 제목은 별도 기록으로 보존하며, 현재 정리 기능의 민감값 치환이 한국어 인명을 자동으로 지운다고 보증하지 않는다.
- 최종 통합 초안은 84개 목적 이야기·513개 세부 변화다. 5,199건 기준으로 3,119건 연결, 2,080건 별도 확인(모호한 다중 목적 2건 포함)이다. 모든 기록의 페이지 합집합·중복 없음 검사 47/47와 프로덕션 빌드가 통과했다. 내용 확인과 현재 운영 기능의 성공 여부는 별개이며 2,080건의 목적 의미까지 해석 완료했다고 주장하지 않는다.
- MindMap 전용 경로 128개는 `config/development-mindmap-path-rules.json`에 검토 이유를 남겼다. 공용 서버·수집 프로그램·통합 화면 경로는 제외하고, 같은 전용 파일의 후속 수정만 목적 분류 보조로 사용한다. 대표 변경 본문 근거를 대신하지 않는다. 중복 소유 3건은 업무 9단계·회사 분리의 담당 이야기 한 곳으로만 정리했다.
- 실제 source 초안은 배포 대상에서 제외한다. 최종 통합 카탈로그와 적용 여부를 기록한 독립 검토 보고서만 반영한다. 최초 원본 전체, 공개 가능한 요약, 목적 미확인 기록 모두 계속 조회 가능하다.
