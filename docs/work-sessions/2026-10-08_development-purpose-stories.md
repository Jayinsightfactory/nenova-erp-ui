## 고정된 결정

- 커밋 제목 나열은 사용자가 원하는 업무 연혁이 아니다.
- 기본 화면은 왜 만들었는지, 실제 버튼·설정·작업 흐름과 이후 보완을 쉬운 한국어로 설명한다.
- 전체 안전 기록은 목적 이야기 또는 명시적 검토 대기에 정확히 한 번 연결한다.
- 근거 부족은 추정하지 않는다. 연결 건수는 기능 수·요청 수·성과 수가 아니다.
- 원본 날짜별 기록은 별도 보기로 보존한다.
- 비공개 대화 본문·문서 경로·규칙·원장 데이터는 새 API에 공개하지 않는다.

### 1. 목적이 보이지 않는 기존 화면

**Q.** 전체 작업 흐름을 보면 목적과 만든 버튼·설정을 알 수 있는데, 개발 제목만 나오는 것은 원한 화면이 아니다.

**A.** 기존 날짜별 타임라인의 한계를 확인했다. 안전한 전체 기록과 계획·계약 문서를 읽고 사람이 작성한 목적 이야기 catalog를 별도로 구성한다. 기본 카드에는 목적·사용자 가치·실제 변화를 표시하고 원본 제목은 접힌 근거로 둔다.

**결과.** 기본 화면을 목적별 이야기로 변경했다. 38개 이야기에는 목적·사용자 가치·실제 변화와 보완을 작성했고, 기존 날짜별 보기와 원본 근거는 보존했다.

## 검증과 배포

- 개발 이력 테스트 42/42 통과. 전체 원장의 각 기록이 목적 이야기 또는 검토 대기에 정확히 한 번 포함됨을 모든 페이지 합집합으로 검사했다.
- 현재 5,184건 중 1,782건 연결, 3,402건 검토 대기다. 이는 전체 목적을 해석 완료한 상태가 아니다. 특히 MindMap 원본과 제목만 있는 작업요약의 추가 검토가 남아 있다.
- 독립 검토에서 모바일 손익 예시를 실사용 기능처럼 설명한 문구를 발견해 `일부 확인 필요`와 예시 전용 범위를 명시했다.
- 펼침·페이지 이동 초점, 전역 집계와 필터 결과 구분, 광범위 규칙 거부를 보완했다.
- dnSpy 근거·계약 manifest 92개·ERP 쓰기 방지(변경 API 1개)·화면틀·전체 ERP 검사·프로덕션 빌드 통과. 독립 검토는 정적 읽기 전용 기능으로 조건부 승인했고, 전체 목적 서술이 아닌 부분완성이라는 제한을 명시했다. PR·배포·실제 화면 확인 결과는 후속 기록한다.

## 남은 작업

목적 검토 대기의 의미를 근거 문서와 대조해 추가 작성해야 한다. 연결률을 올리기 위한 광범위 규칙이나 저장소 단위의 임의 목적은 쓰지 않는다. 현재 결과를 ‘104페이지 모든 목적 정리 완료’라고 보고하지 않는다.
