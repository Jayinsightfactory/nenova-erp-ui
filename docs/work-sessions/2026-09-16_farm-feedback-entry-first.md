# 피드백 상세 입력 우선 및 기본 펼침

## 요청과 구현
- 전체 활성 또는 상태 필터에서 카드 선택 시 요청 문구 제안 → 대상 이력 선택·피드백 입력/저장 → 실제 요청·코멘트 이력 → 품목별 불량·원본 근거 순서.
- 제안·품목·원본 details는 기본 open. 카드 키로 상세 DOM을 분리해 다른 카드 선택 시 접힘과 스크롤 위치를 초기화.
- 자동 제안은 참고용이며 자동 발송·자동 저장하지 않는다.
- 기존 입력 취소 확인, 이미지 첨부, 권한, 이력 선택, 동시수정, 멱등성 및 저장 핸들러 보존.

## 부작용 및 기준
| 동작 | 웹 피드백 Case/Event/Evidence/Inbox | Order/Shipment/Stock/Estimate/WebProfitReport |
|---|---|---|
| 카드 선택·상세 펼침·배치 | 읽기 전용, 기존 상태 보존 | 보존 |
| 명시적 이력 저장 | 기존 계약 그대로 | 보존 |

현재 사용자 지시가 이전 실제 요청 최상단 배치보다 우선한다. 실제 요청과 제안의 구분은 유지한다.

## 검증 계획
렌더 테스트는 가상/기존/복수 이력 × 전체/요청 전/대기/도착/재발에서 순서·기본 open·단일 입력창을 검사한다. 기존 오류·권한·대상 검사 유지. 필수 계약·manifest·dnSpy·write guard·빌드 및 1920×1080 실브라우저 검증.
