## 이어받을 때 고정된 결정
- 실제 47차 원본 두 개의 참고 미우13행 시트가 본문 경원7/태광4행보다 자동 점수가 높았음.
- 셀 연결 메타데이터는 미우 제목과07차 열을 합쳤고 저장별칭 미우456을 선택. 파일 업체·차수가 맞는 본문을 먼저 고르고 제목은 셀별 파싱.
- 남대문경원 업로드 전용 별칭은 현재 ERP의 유일한 경원원예277, 원당태광은 기존 이름 매칭491. 공용 매칭 저장소 변경0.
- 파일 업체 미확정이면 이전 업체를 이어 쓰지 않고 직접 선택. 가격열 유무·이전모드와 무관하게 업로드 기본order.
- 주문즐겨찾기/거래명세표 옆 담당업체 분배단가 수정 버튼. 분배가 있는 업체를 Customer.Manager→UserInfo 담당자별 이름·색으로 묶고 차수업체 불러오기 제공. 업로드 초안 업체/차수는 복귀 시 복원.

### 1. 업체가 미우로 처리되는 이유
**Q.** 남대문경원, 원당태광 47차 작업로그를 확인하고 미우로 처리되는 이유 조사.
**A.** 업무 드라이브의 실제 원본(11월9일15:51/16:04)과 실제 파서/DB resolver로 오매칭 재현. 수정본은 Sheet1/47차/7·4품목으로 정상. 2026년47차 세 업체 주문·분배0,2025년47차63행은 별개. 잘못 저장된 주문 원장을 확인하거나 보정한 것으로 보고하지 않음.

### 2. 등록 기본값·단가 작업 분리
**Q.** 파일업로드 기본 주문등록만, 분배단가만 수정은 별도 담당업체 탭, 담당자별 색 구분 및 분배업체 불러오기.
**A.** 기본값 강제 리셋 및 별도 화면 전환/담당자 묶음 구현. 기존 update-cost 단가 writer 재사용. 연습 실제브라우저1920/390·업로드리셋/미매칭/그룹/재조회/키보드 검사와 영상 촬영. 운영 ERP 시험 등록 없음.
