## 고정 결정

- 메뉴수·통계 카드·개발 안내를 일반 화면에서 제거하고 ECOUNT의 탭/표/조작 구조를 근거로 구현한다.
- 100% 판정은 화면별 필드·표·버튼·팝업·새창·선택 반환·검증·오류·권한·다운로드 근거가 전부 충족될 때만 한다.
- 원본 쓰기 버튼은 조사 목적으로도 실행하지 않는다. 도움말/명세 근거와 격리 SQL 검증을 사용한다.
- ECOUNT 원본을 되돌리는 기능이 아니다. 가져온 네노바 작업 버전을 과거 버전으로 활성화한다.
- 전체 직원의 ECOUNT 조작 감사 로그를 확보했다고 주장하지 않는다. 현재 수집/업로드와 별도 SQL 변경 이력을 기록한다.
- 개인정보·계좌번호·자격증명은 기록하지 않는다. 현재 자료는 안전 숫자·날짜만 투영하며 제외된 항목의 동등성을 완료로 표시하지 않는다.

## 질문과 실행

### 1. 원본과 같은 화면, 별도 SQL에 자료 업로드와 불러오기
**Q.** 불필요한 메뉴수 표시 없이 똑같이 구현하고 SQL 작업 루트와 작업 자료 저장·불러오기를 구현.
**A.** ecount_work 스키마, nenova-ecount 루트, Version/Head/Audit를 만들었다. 원본 자료 및 이력은 불변, 활성 포인터만 revision 검사 후 변경한다. 실제 DB rollback-only 9개 검증 통과. 검사 자료는 전부 되돌렸다. 기존 WebEcountSnapshot/Row는 읽기만 한다.
**결과.** 현재 확인된 은행/채권/채무/판매 4개 자료 흐름의 구현. 전체 프로그램의 적재는 아직 미완료. 실제 적재 시 날짜 형식 차이를 발견해 원본 표시 보존을 보완 중.

### 2. 페이지별 버튼·새창 100%, 하위세션·사용량 관리
**Q.** 각 페이지 버튼과 새창까지 100% 대응하며 하위 세션으로 작업 설계·시작.
**A.** SQL/UI/명세 3개 하위 작업을 파일별 분리. 373개 원본 프로그램/430개 진입경로를 59개 묶음으로 배정. 13개 동등성 기준과 unknown 개수 null을 검사. 완전 검증 화면 0개이며 초기 관측을 완료로 바꾸지 않는다.
**결과.** E010205, E040214, E040309, E040207 조회 구조를 부분 관측했다. 은행 매핑 조회 오버레이 열기/닫기 확인. 보호 정보나 거래행은 문서에 저장하지 않았다.
