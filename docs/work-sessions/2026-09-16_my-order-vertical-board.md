## 미완 및 임시 파일

### 4. 슬래시 뒤 줄바꿈

**Q.** 두 줄이면 / 뒤 단어가 다음 줄 시작이 되도록 해 달라.

**A.** 중앙·우측 품목명에 공통 ProductName 표시를 적용해 슬래시를 앞 구간에 붙이고 뒤 구간 앞에서 우선 줄바꿈한다. 짧은 이름은 한 줄 유지하고 단일 구간도 너무 길면 잘림 없이 추가 줄바꿈한다. 원본 라벨·검색·정렬·aria·payload는 보존한다. ERP 원장은 전체 보존이며 DB 테스트 쓰기는 하지 않는다. Chrome fixture로 양쪽 줄 위치, 짧은 이름 한 줄, 모바일 넘침, 기존 승인/색상 동작을 검증한다.

### 3. 기존/수량변경/신규 색상 분리

**Q.** 변경사항이나 추가품목은 다른 하이라이트 색이 필요하다.

**A.** 공통 customerOrderHighlight(customerOrderDraft)를 중앙/우측 목록에 적용한다. 기존 양수 미변경은 연두색, 기존 증감·0 변경은 주황색, 0에서 신규 양수는 파란색, 잘못된 입력은 빨간색이다. 기존과 같은 값 및 초안 취소는 기준 색으로 돌아간다. 우측 상태 문구와 중앙 범례를 제공한다. 조회/쓰기/승인/API 및 ERP 원장 부작용은 모두 보존한다. 순수 함수 fixture와 Chrome fixture에서 양수/0/증감/신규/동일값/취소/잘못된 입력, 중앙·우측 색 일치, 승인 회귀를 검증한다.

### 2. 기존 주문 하이라이트 복구

**Q.** 기존 주문품목 하이라이트가 없어졌다.

**A.** 행 배경은 추가 입력 초안만 참조하고 기존 CurrentQty 양수는 수량 요소 클래스만 존재해 전체 행 강조가 없었다. 선택 범위 CurrentQty > 0 행을 연두색 배경/테두리와 수량 배지로 표시한다. 추가/최종 초안이 있는 행은 파란색을 우선하고 수정 취소 시 기존 연두색으로 복귀한다. 조회·저장 API 및 위 원장 부작용 표는 모두 보존한다. Chrome fixture에서 기존 양수/0/최종 수정/취소 복귀 및 기존 승인 절차를 검증한다.
