# 패킹리스트 공유 매칭 · 중국 항공 입고/원가

## 요청과 합의
- 담당자와 무관하게 매칭 데이터를 공유하고, 이름이 조금 달라도 자모·오타 기반 후보를 우선 추천한다. 추천은 자동 확정이 아니다.
- `41-2 CHINA CI.xlsx`로 입고 등록 및 도착원가 연결을 테스트한다.
- 중국 항공 원가 예시로 `CHINA 중국 원가자료 (8).xlsx`를 제공받았다.
- 운영 입고/재고 쓰기나 신규 유료 AI 분석 없이 검증한다.

## 원인과 수정
- 매칭 서버 저장소는 기존에도 팀 공용 `packing.erp-matches`였다. 화면이 최초 조회 스냅샷을 계속 사용하고, 기존 별칭 화면과 ERP 수동 매칭이 나뉘어 공유되지 않는 것처럼 보였다.
- 30초/포커스 revision 조회, 새 변환 직전 최신 조회, 변경 알림·오래된 결과 차단을 추가했다. 작업 중 초안은 덮어쓰지 않는다.
- 매칭 창을 연 revision으로 CAS 저장한다. 충돌 시 자동 재저장하지 않고 최신 매칭을 다시 확인해야 한다.
- 패킹 전용 자모·초성·영문 편집거리 추천을 추가했다. 다른 메뉴 검색 기본 동작은 유지한다.
- 중국 XLSX의 `English name`, `Length`, `A.G.W.T.`를 지원한다. GW는 원본 위치와 함께 검토 힌트로 보존하며 없는 CW를 만들지 않는다.
- 항공 공식 `CN_AIR_WEIGHT_CBM_V1`은 검증된 27-2/26-2 CLOUD 기준이다. GW≈CW는 실중량, CW>GW는 부피 환산중량 kg으로 운임을 배분하고 통관비는 항상 실중량으로 배분한다. 환율/관세/비용/현재 CW는 명시 검토가 필요하다.
- 원본의 과거 고정비, 0분모, 잘못된 셀 참조 및 음수 잔여값은 복제하지 않는다. 원본 SHA256: e1bb0315998c2f3550a0edab8353147612cd6c46d7247b287656eca1c3ee4233.
- 도착원가 메뉴에 기존 실입고 재검증 함수를 재사용하는 읽기 전용 원가 조회를 추가한다. STALE은 과거 비교용이며 현재 원가가 아니다. 기존 WebArrivalCost에 자동 복사하지 않는다.

## 실제 파일 결과와 한계
- 28행 / 159박스 / 2,380단 / 30,900송이 / 상품금액 CNY 57,330 / 총액 CNY 84,844.9 / GW 1,985.94kg.
- 전산 읽기 기준 매칭 16행, 수동 확인 필요 12행. 12행 모두 유사 후보가 있으나 실제 매칭 확정은 하지 않았다.
- 실제 파일에 CW가 없다. 실제 운영 원가를 승인/완료했다고 보고하면 안 된다.
- localhost:14339 격리 SQL의 invocation-owned DB에서 실제 28행 수량·가격과 합성 품목키 7300~7327을 사용했다. CW=GW, FX=230, 관세=0, 통관비=1000, 부대비 합산 운임 분류는 TEST_ONLY 입력이다.
- native writer 저장/재조회, 단위·단가 보존, 재고/이력, 원가 28행 저장/재조회, 멱등성 및 오류 롤백·busy gate 보존 테스트 통과. 실제 ERP 매칭이나 실제 비용 분류를 확정한 테스트가 아니다.
- 원본 27-2 행24 원가 4706.5970904890255 및 26-2 CW 분기 재현 테스트 통과.
- 신규 통합 38개 테스트, 전체 ERP 계약, manifest/write guard, dnSpy 근거 검사 및 프로덕션 빌드 통과. UI/배포 결과는 아래 후속 기록으로 보완한다.

## 안전 범위
nenova.exe, native SP, 운영 DB 스키마와 원장은 변경하지 않았다. 기존 승인된 입고 writer 및 원가 저장/STALE 검증 경로를 재사용한다. 계정/토큰/비밀번호 및 원본 업무 파일은 저장소에 포함하지 않는다.

## 최종 검토 보완
- 승인 snapshot에서 허용된 원가 입력만 별도 투영해 명시 버튼으로 복원한다. 현재 문서/revision/원본/실입고가 맞는 ACTUAL 승인만 가능하고 STALE·사용자 편집·요청 경합은 차단한다. 적용 확인은 false로 초기화한다. 실제28행 SQL 저장/조회에서 복원 입력 및 raw snapshot 비노출도 통과했다.
- 원가 초안의 중량 필드는 `reviewedMetadata.gw/cw`가 유일한 정식 필드다. Warehouse SQL 열 이름과 혼동한 `grossWeight/chargeableWeight`는 읽기 fallback으로 숨기지 않는다.
- adapter → draft payload → JSON roundtrip → 항공 계산 및 실제 SQL 문서 저장/재조회 회귀 검증을 추가하고 통과했다.
- 신규 테스트 묶음 62개 통과/옵션 파일 테스트 1개 건너뜀. 실제 원가 예시 파일 비교 테스트는 실행돼 통과했다.
- Chrome 실제 컴포넌트 하네스: 1920×1080 및1280×800 /100%, 추천·키보드·충돌 후 저장 차단·조회 오류/재시도·필터 응답 경합 통과. 브라우저 오류0, 외부/ERP POST0. 인증된 Next 전체 화면 검증과는 구분한다.
