## 이어받을 때 고정된 결정
- 전체 같은 경로의 자동자료를 조사하고 웹 일반등록 혼입 방지 후 배포한다.
- 보정 목록을 먼저 제시한다. 기존 Estimate와 웹 원장 수정·삭제는 추가 승인 전 금지다.
- 자동자료라는 사실은 개별 업무상 오류 확정과 다르다. 원문·담당자 대조 후 보정 대상을 확정한다.
- 정상 수동 및 수동 이월의 수입확인 비필수 계약을 보존한다.
- 원천 표식/과거 이력으로 구분하며 담당자·계정·날짜만으로 자동자료를 판정하지 않는다.

### 1. 담당자가 입력하지 않은 품목·수량이 차감된 이유
**Q.** 41차 초원·자연 등에서 입력 내역에 없는 품목과 수량이 등록됐다. 누가 어떻게 입력했는가?

**A.** 과거 카톡 자동생성 초안을 includeCarryover가 일반 지원 목록으로 가져오고, 지원 등록이 해당 초안의 기존 품목·수량을 현재41차 Estimate로 저장한 경로를 확인했다. 생성 감사 계정과 원장의 담당자 귀속, 실제 등록 계정은 서로 다른 개념이다. EstimateDtm은 실제 등록시각이 아니다.

### 2. 전체 확인과 재발 방지, 보정 전 목록
**Q.** 같은 방식의 전체 건을 확인하고 과거 자동자료가 섞이지 않게 수정·배포하되 잘못된 건은 보정 전에 목록을 보여달라.

**A.** 전체 원장881/이력2721건을 SELECT했다. 자동원천135건(현재행134, 이력만1), 실제 Estimate가 남은91건/29업체가 후보이다. 41차78건,38~40차13건. 등록당시 수입확인 false65/true26건으로 확인여부만으로 분리할 수 없다. 로컬 HTML/CSV를 제시했고 운영 보정은 하지 않았다.

새 서버 공통 SQL 판정과 전체 역사 JSON 감사의135개 DeductionKey 집합이 실제 운영 SELECT에서 정확히 일치했다. 초원·자연의2026/41-01·02 읽기 대조는 ViewOrder18/ViewShipment18/ShipmentDate18/ShipmentFarm0행이었다. 이 건수는 재고·수량 전체 정상성 증명이 아니라 영향 원장 읽기 근거다.
