## 고정 결정
- 별칭과 CustKey/ProdKey, 수동 선택, 저장시각, 수량/단위/단가는 유지한다.
- 이름은 정확한 키의 활성 DB 행에서 읽는다. 없는 키를 이름 유사도로 다른 품목에 연결하지 않는다.
- GET은 매칭 파일에 쓰지 않는다. 업체명과 ProdName/DisplayName만 응답에서 최신화한다.
- 복원/창 복귀/늦게 도착한 분석의 이름을 갱신하며 기존 완료 지문이 정확할 때만 이름 변경 후 지문으로 옮긴다. 빈/불일치 지문을 완료로 만들지 않는다.
- 기초재고 원문·matchName·복사 결과와 감사 이력을 다시 쓰지 않는다. 품목 목록 수 변화만으로 재매칭하지 않는다.

### 1. 저장 위치와 오래된 업체명 확인
**Q.** 붙여넣기 주문등록 매칭이 DB에서 오는지, 저장은 잘 되는지 확인해 달라.

**A.** 원본 목록은 DB, 저장 별칭은 서버 공유 파일이다. 인증 읽기에서 업체36/품목501건과 최근 저장시각을 확인했다. 모든 연결키는 현재 기준정보에 존재한다. 매일538/미우456의 저장 이름이 현재 DB와 달랐다.

### 2. 기존 매칭 보존하고 이름 최신화
**Q.** 기존 매칭값을 유지하고 업체명·품목명을 최신 DB 기준으로 수정해 배포해 달라.

**A.** 매칭 GET 이름만 보충, 페이지 최초/포커스 시 캐시 없는 기준정보 조회, 기존/복원 주문 이름만 갱신하는 helper를 구현했다. 완료 지문을 단순 삭제/버전 변경하지 않고 검증된 기존 지문만 새 이름으로 재기준화한다. 실패 시 마지막 정상 표시를 유지하며 알린다.

## 검증
- 실제 dnSpy FormOrderAdd GetCustomer/GetDataProduct의 키와 표시명 분리 확인.
- helper/API: 이름변경/null DisplayName/같은이름 다른키/누락·삭제/메타데이터·저장파일 보존/DB 실패 검증.
- 실제 Chrome: 완료 작업 복원→이름갱신→제품 수 증가→기초재고 매칭 유지→실패 후 보존→재접속 완료유지. 자동 ERP/매칭 쓰기0, 분석 재실행0. 1920x1080/1366x768/390x844 가로넘침 없음.
- 메뉴 기준선 적용: 기존 화면틀·키보드·원문/매칭구분·오류·완료상태 보존. 해당 없음: 신규 메뉴/인쇄/원장 정책. 예외 없음.
- 필수 ERP/빌드 검증과 배포 결과는 후속 기록한다.
