# 카톡 요청과 작업 이력 한눈에 확인

| 항목 | 내용 |
|---|---|
| 화면 | 붙여넣기 주문등록 영업방 |
| 기준 | 1920×1080 CSS pixel, 100% |
| 원장 | ERP 전부 보존, 수동 표시는 기존 별도 저장 경로 유지 |
| 상태 | PR565 운영 반영 완료, 실대화 잔량표 구분자 보완 |

## 고정 결정

- 사용자 핵심 요구는 카톡 요청과 변경 작업의 매칭 여부를 함께 보는 것이다.
- 기본은 변경 요청 전체 최신순; 잔량만 있는 대화는 별도 탭, 분류 불명은 건수와 함께 보존.
- 같은 메시지의 복수 요청은 한 묶음이며 일부만 일치하면 일부 매칭.
- 자동 매칭과 직접 처리함 표시는 구분. 미확인은 미처리 단정이 아니다.
- 원문·재고·상세 이력은 펼치기. 기존 등록·분배는 비교 결과와 무관하게 사용 가능.

## Q&A

**Q.** 한 화면에 내용이 너무 적다. 잔량 목록이 섞인다. 카톡과 대응 작업이 매칭됐는지만 쉽게 확인하면 된다. 작업 시작.

**A.** 조회 전용 분류·요약 helper와 밀집 행 UI를 병렬 구현한다. 원장 저장 API/SQL은 변경하지 않는다.
설계 계약은 `docs/distribution-board/COMPACT_CHAT_MATCH_BOARD.md`다.

## 작업 경계

하위 작업은 로컬 파일·검사만 담당. 메인이 GitHub 인증 확인, 최종 검토·병합·배포·운영 조회를 담당한다.
기존 `outputs/`, `scripts/check-baseline-local-files.cjs`는 사용자 자료로 보존한다.
다른 작업의 localhost:3007 서버는 종료하지 않는다.

## 검증·배포

- 전체 `npm run test:erp-contract` 성공, 분배 연결 23개 검사 포함.
- manifest 57개 및 쓰기 보호 성공 (변경 API 0개), 빌드 103페이지 성공.
- localhost 생산 빌드/Chrome: 1920×1080에서 첫 화면 완전 노출 요청 9건,
  가로 잘림 없음. 1366×768에서도 대응 작업 열 유지, 가로 잘림 없음.
- 변경 요청 12건/순수 잔량 1건/분류 불명 1건 fixture, 세 자동 상태,
  혼합 취소·잔량 메시지 유지, 상세·내 표시 메뉴, 실패 시 입력 보존 통과.
- 테스트 중 실제 ERP·LLM·수동 저장 호출 0건. 읽기 전용 비교 POST만 mock 처리.
- 재현: `scripts/paste-compact-match-ui-smoke.cjs`.
- PR565 병합 `5be745fd`, 배포 작업 `34583471861`. 운영 Chrome에서 새 버전 확인.
- 2026-37-01 / 2026-09-11 영업방 63건 자동 조회. 대구희경 11:16 요청 2건과 분배 이력이 같은 행에 매칭 2/2로 표시됨.
- 운영 실대화에서 `화이트 8F - 41 box`의 구분자 하이픈을 감소로 읽는 사례 확인.
  공백을 둔 하이픈 구분자는 수량 변경 신호에서 제외하고, 붙여 쓴 -1과 명시 취소는 유지한다.
- 카카오의 `메시지가 삭제되었습니다.` 시스템 문구는 ERP 삭제 요청으로 분류하지 않는다.
  같은 메시지에 실제 추가/취소가 남아 있으면 변경 요청으로 유지한다.
- 실제 원문·자동 비교 조회만 수행했으며 ERP 및 수동 표시 저장은 실행하지 않았다.
