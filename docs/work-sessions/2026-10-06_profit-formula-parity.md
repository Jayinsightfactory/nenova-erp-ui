|항목|내용|

## 고정 기준

- 최종 Excel 숫자에 ERP 수량을 맞추는 작업이 아니다.
- 동일 ERP 입력으로 workbook 실제 수식을 평가한 결과와 웹 계산 함수 결과를 비교한다.
- 본표 산식, 입력값을 만드는 재고평가/비용배분 정책, 원천 데이터 차이를 분리한다.
- 과거 자료 주석의 지시문은 증거일 뿐 변경 승인으로 취급하지 않는다.

## Q/A

**Q.** 전산 기반 데이터를 엑셀과 같은 수식으로 계산하는지 검증해 달라.

**A. 결론:** 본표 매출·매출원가·이익 산식은 동일하지만, 비용배분 파라미터와 재고평가 원천까지 모두 같은 것은 아니다. 데이터만 다르다고 말할 수 없다.

### 1. 동일 전산 입력 본표 검산: 498개 일치

각 파일 `주차별 매출이익 보고서` 7~22행과23합계행의 실제 C/D/G/I/J/K/M/P/T/U 수식을 읽었다. 준비된 웹 payload의 E/F/H/N/L/O/Q/R/S를 동일 입력값으로 사용해 독립적으로 Excel 산식을 평가하고 `computeProfitRow/computeProfitTotals/calcRevenueRatio/calcPurchaseRatio`와 비교했다.

- 29차166개,30차166개,31차166개: 수치 차이 1e-7 초과0건.
- C=N+L+O; P=Q×R; T=S×R; G=P+T; 일반 I=E+G+H−F; J=C−I.
- 이스라엘·뉴질랜드·일본 I/J/K 예외, 국내 합계 포함/제외, U비율의 베트남 제외 등 실제 셀 범위도 대조했다.
- 베트남30차 J21의 −4,576,000과31차 +4,576,000은 웹 manual.AJ에도 반영되어 같은 결과다. 이 조정을 누락 차이라고 보고하지 않는다.
- E/F/H를 같은 값으로 넣은 **본표 산식 검사**다. 이 값의 생성 정책까지 통과했다는 뜻이 아니다.

### 2. 평균원가 기말평가: 17개 일치

Excel F 수식이 있는29차6개·30차5개·31차6개에 동일 ERP 매입수량과 기말환산수량을 대입했다.

`(전산 G + 전산 H) / 전산 매입수량 × 전산 기말수량`

17개 모두 웹 F와 1e-7원 이내 일치.31차 예: 수국3,720,830.683576원, 카네이션984,345.913060원, 장미473,860.446541원, 베트남5,030,033.154원.

다만 Excel 장미 F는 재고잔량M92(Be Sweet50cm 한 행)를 참조하고, 웹은 장미 전체 Stock 수량을 사용한다. 같은 카테고리 총수량을 공급한 **산술 구조 일치**와 원본 참조 범위 일치를 구별한다.

### 3. 실제 다른 부분

**콜롬비아 비용 배분 파라미터:** 분배 공식은 `총액×품목무게/전체무게`로 같지만 첨부 매출원가 workbook과 웹 기준표의 박스당 값이 다르다.

|항목|31차 Excel 콜롬비아1차|웹 기준|
|---|---:|---:|
|장미 무게 K37|7|8|
|수국 무게 K41|5.6|5.5|
|카네이션 CBM P38|11|9|
|수국 CBM P41|7|6.7|

출처: `lib/boxMetricTable.js` 및 `lib/customsForwardingCalc.js:computeColombiaRatios/computeColombiaAllocation`. 이는 원천 입고/매출 숫자 차이가 아닌 **계산 파라미터·정책 차이**다. CBM은 GW/CW 조건에 따라 실제 포워딩 배분 영향이 달라진다. 현행 소스는 원가자료 표를 공유하도록 작성되어 있어 매출보고용 값으로 무조건 공통표를 바꾸면 다른 원가 기능까지 영향받는다.

**기초 이월 반올림:** Excel은 전차수 기말 소수 금액을 그대로 기초에 입력한 반면 웹은 전차수 계산값을 카테고리별 원 단위 반올림한다. 준비 데이터에서29F→30E 합계 +0.642657원,30F→31E +0.536710원. 큰 금액 차이 원인은 아니나 완전 동일하지 않다.

**수기 기말평가 부분:** 호주·네덜란드·태국·중국 등의 본표 F는 첨부 workbook에서 수기 값인 경우가 있다. 웹은 품목별 FIFO·도착원가·자동평가를 사용한다. 이 셀에는 비교할 계산식이 없으므로 동일 산식으로 통과시킬 수 없다. 특히29차 호주 잔량 일부는 매입근거가 없을 때 판매단가로 자동평가된다. 수기 금액의 평가 근거와 웹 정책은 별도 확인 대상이다.

최종 교차검토: 준비된31차 보고서의 콜롬비아 적용 H는 수기값이 우선하여 Excel과 일치한다. 자동 H 계산 기준의 차이를 현재31차 적용 H 오차라고 혼동하지 않는다.29·30차에서는 실제 배분 차이가 확인됐다. REVIEWER 교차검토에서 차단 오류 없음.

## 근거와 검증 한계

- 원본: Downloads의 `매출원가 양식 - 29차_재고수정.xlsx`,30차,31차. 읽기만 수행.
- 실제 실행: `.tmp/formula-parity.mjs`, 결과 `.tmp/formula-parity-results.json`.
- 현행 본표: `lib/profitReportCalc.js`. 이월: `pages/api/sales/profit-report.js`.
- 이전 준비자료 `.tmp/profit29/30/31-web.json`,live.json,stock-prices.json 및 purchase-qty/context JSON. 이 turn에서 운영 DB를 다시 조회하거나 실브라우저를 확인하지 않았다. 준비된 snapshot에는 stale 표시가 있으며 이전 live 대조의 E/F/G/H 일치를 확인한 자료를 사용했다. 따라서 이후 운영 변경까지 재검증했다는 뜻은 아니다.
- 국가지정/비용행 분류 차이는 보고서 입력 범위 문제이며498개 본표 산술 검증에 포함되지 않는다.
- 각 수식은 실제 파일에서 읽었고 SUM/IFERROR/산술 참조만 제한하여 평가했다. Excel 앱 전체 재계산을 실행한 것은 아니다.
- 검증 모델: main 통합, gpt-5.6-sol xhigh REVIEWER P0_LOCAL. 제공 파일·의존성 준비 완료, 외부쓰기 금지.

## 대응 우선순위

1. 기본 I/J 산식은 수정할 근거 없음.
2. 사용자가 첨부 매출원가 workbook을 기준으로 확정하면 보고서 전용 비용배분 기준과 이월 반올림을 정렬하되 공유 원가표의 부작용을 먼저 검토.
3. 직접 입력된 F 금액은 재고평가 규칙이 명시돼야 동일성 검증 가능. ERP 원장 수정으로 맞추지 않음.
4. 전체 원천값이 정확하다는 판정이나 새 배포는 이번 검증의 결과가 아니다.
