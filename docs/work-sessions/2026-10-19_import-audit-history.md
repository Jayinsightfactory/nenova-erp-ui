# 품목 입력 히스토리 · 인보이스 문제 기록

## 사용자 요청 → 처리
- 기존 품목관리 연결인가? → 기존 페이지를 수입부 10번에 임베드. PR1090/9ced3744 배포 성공.
- 품목 수정 내역을 보려면? → 품목 입력 히스토리 버튼. 전체 또는 선택 품목의 입력자·시각·변경 전후 값. 개별 신규/수정과 일괄 수정 모두 기록. 과거 EXE 수정은 소급 생성하지 않음.
- 인보이스 문제가 생기면? → 업로드 문제 로그에 파일명·분석 실패/미매칭/합계 불일치 및 건수 기록. 초안 서버 검증은 실제 행별 문제를 WebInvoiceHistory에 필수 저장. 수정 전 버전도 조회, 현재 행으로 이동·수정.
- 연결 장애는? → 사용자별 sessionStorage에 미전송 로그 보관, 미저장 표시와 로그만 재전송. 같은 탭 새로고침 복원; 창 종료/저장 차단/기기 장애까지 무조건 저장된다고 보장하지 않음. ERP 등록 재시도와 분리.

## 안전 범위
기존 개별 Product 필드 산식과 SQL 대상 유지, 전후 조회/감사만 같은 트랜잭션에 추가. 감사 저장 실패 시 전체 롤백. 기존 주문/입고/출고/재고/견적/손익 변경 없음. 업로드 문제 API는 SystemActionLog만 쓰며 수입부 권한 검사. 원문 전체/자격증명/오류 원문은 전송하지 않고 분류·건수만 기록. 검증 이력은 서버가 만든 오류 내용만 저장.

## 근거와 검증
- 실제 dnSpy ExcelLoadingPackingList.InsertMaster의 uspCreateWarehouse→uspStockCalculation 확인. 새 로그 경로는 둘 다 호출하지 않음.
- 운영 SELECT: SystemActionLog.Payload, WebInvoiceHistory.AfterJson 모두 nvarchar(max), 현재 문서2026/41-02 revision3. 운영 업무값 쓰기 테스트 안 함.
- 순수/모의 API 검사: 0/빈칸/%·변경 전후, 사용자별 대기 복원, 동일 이벤트 재전송, 권한/입력 제한, 2025/2026 범위 보존, 로그 실패 시 검증 실패.
- 메뉴 기본값: 기존 shell/필터/페이지 스크롤/버튼 키보드 적용. 원장 재계산·확정·엑셀 변경 해당 없음.
- 전체 검사·최종 배포/운영 스모크 진행 중. 미완료 항목은 완료로 표시하지 않음.
