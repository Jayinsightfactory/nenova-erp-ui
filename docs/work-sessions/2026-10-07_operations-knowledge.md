## 고정된 결정

- 기존 수입부 `checklist.handoffs`는 복사하거나 변경하지 않고 읽기 전용으로 연결한다.
- 상황별 처리·과거 사례·시즌 주의·인수인계·체크리스트 5개 분류와 국가/꽃/농장/단계 검색을 제공한다.
- 확인 필요/현재 적용/적용 종료를 구분하며 영구 삭제는 제공하지 않는다.
- 작성자·댓글·첨부·변경 항목 이력은 서버에서 기록하고 오래된 버전 저장은 409로 거부한다.
- 시즌 분류는 사용자가 지정하며 현재 시즌을 자동 추정하지 않는다.
- 기존 인증을 유지하고 첨부는 공개 폴더 밖에 저장한다.

### 1. 요청과 구현 범위

**Q.** 수입부 이슈 처리 게시판과 구두 인수인계 내용을 모아 두는 메뉴를 만들고 싶다. 상황별 처리, 과거 해결 사례, 시즌 주의사항을 찾아볼 수 있어야 한다. 작업해.

**A.** 독립 메뉴와 웹 전용 저장 계약으로 구현한다. 수입부 기존 인수인계 화면을 읽기 전용으로 확인했으며 당시 저장 버전 0, 항목 없음이었다. 실제 기존 글을 이전했다는 의미가 아니다.

**결과.** `docs/plans/operations-knowledge.md`, `docs/contracts/operations-knowledge.json`에 범위와 수용 기준을 고정했다. 작업 의도 해석 스킬로 범위를 정리하고 ERP 가드에 따라 공유 원장 쓰기를 배제했다.

## 검증 결과

- 기존 importTeamStore/Handoffs 회귀 10개 통과.
- 첨부 exact route nginx 제한 12MiB(앱 파일 제한 10MiB) 테스트 통과.
- 신규 기능 테스트 17개 통과: 실제 JSON/multipart 핸들러, CAS 충돌, 형식·크기·Origin·비활성 계정, 첨부 다운로드 헤더, 실패 파일 정리, ZIP 제한 포함.
- 큰 파일 거부 시 간헐적 임시파일 잔존을 발견해 요청별 UUID 디렉터리 정리로 보완; 첨부 테스트 5회 연속 통과.
- 전체 `npm run test:erp-contract` 통과. 계약 manifest 81건, 변경 API 3건 쓰기 가드와 dnSpy 근거 검사 통과.
- 로컬 격리 브라우저 1920×1080에서 지침 작성·댓글 저장 확인, 일반 화면 shell/메뉴/상단바 각각 1개 및 가로 넘침 없음.
- 최종 첨부 보완 재빌드 통과. 팝업 화면 1920×1080 sidebar 0/popupbar 1, 가로 넘침 없음; 목록 방향키·Enter 동작 확인.
- 미저장 초안 Escape 확인창 발생 확인. Chrome 확인창에서 자동 조작이 멈춰 사용자 취소 요청 후 후속 확인 예정.
- 배포 확인은 후속 결과에 기록한다.

## 운영 및 다음 확인

- 신규 지침과 첨부는 `data/runtime/` 아래에 저장되며 Git 배포로 덮어쓰지 않는다. 운영 서버 runtime 백업 대상에 포함해야 한다.
- 운영 시험용 글/파일을 만들지 않는다. 쓰기 검증은 격리 임시 저장소에서 수행한다.
- 설계/리뷰는 고성능 모델, 구현은 사용 가능한 중간 역할 모델로 분리했다. 지정된 terra 모델이 하위 작업 도구에 없어 gpt-6-sol medium을 사용했다.
