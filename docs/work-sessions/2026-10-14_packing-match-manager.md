## Q&A와 고정 결정
**Q.** 매칭은 DB 기반인가? 매칭 데이터를 확인하고 수정할 수 있어야 한다.

**A.** 대상은 SQL Product이며 원문→DB 품목 연결은 웹 팀 공용 저장소다. 상단 조회·수정 목록에서 국가/원문/DB 품목명·코드/확인 필요 상태를 검색하고 연결 품목을 수정한다. 업로드 파일 없이 사용 가능하다.

- 기존 변환 별칭/seed 목록과 DB 품목 연결 목록을 혼동하지 않는다.
- 원문과 국가는 보존하고 연결 DB 품목만 바꾼다. 삭제나 전체 덮어쓰기는 추가하지 않는다.
- 최신 연결명을 보여주고 기존 1회 선택 저장 모달을 재사용한다. 409/실패는 유지·명시 재조회.
- 기존 입고 문서는 소급 변경하지 않는다. 진행 중 파일/검토는 유지하고 생성파일은 재생성한다.
- UI 기준1920×1080/100%, 작은화면 줄바꿈/페이지스크롤/키보드 접근.

- 메뉴 기본값 적용: 검색·확인필요·줄바꿈·키보드·실패유지. 해당없음: 신규shell/인쇄/수량·원가·ERP원장변경.

## 이어가기
계약 `docs/contracts/packing-match-manager.json`과 계획을 읽고 최종검증/배포상태를 확인한다. `outputs/`와 기존 다른세션/생성이력 변경은 커밋하지 않는다. 전체 매칭을 DB 자체에 저장한다고 설명하지 않는다.
