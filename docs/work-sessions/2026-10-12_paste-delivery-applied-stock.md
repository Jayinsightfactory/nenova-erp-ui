# 붙여넣기 전달확인 지연과 적용재고

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-12 |
| 화면 | 붙여넣기 주문등록 |
| 원장 부작용 | 없음. 수집/확인 조회와 검증된 기존 결과의 표시·복사만 수정 |
| 배포 | 필수 검사와 실화면 확인 후 기록 |

## 이어받을 결정

- 수집 프로그램은 다른 PC에서 실행 중이다. 사용자가 30분을 10분으로 변경하기로 했다.
- 10분 수집 + 웹 60초 확인 + 서버 캐시/통신 시간이므로 10분 이내 표시를 보장하지 않는다. 표시 목표가 10분이면 수집 5분 권장.
- 전달완료는 원문이 추가취소방에서 확인됐다는 뜻이며 주문·분배 적용 완료와 별개다.
- 시작재고에 저장·검증된 추가는 빼고 취소는 더한다. 실제 ERP 재고 스냅샷과 별개다.
- 실패/롤백/중복/다른 연도·차수/입력 변경/단위 불명은 적용재고 표·복사를 차단한다.

### 1. 전달확인이 늦다

**Q.** 원인을 확인하고 10분 이내 반영되게 해 달라.

**A.** 웹은 이미 60초 확인한다. 수집기 `nenovakakao` origin/main `0602a40`의
`core/workflow_settings.py` 기본 background_interval_sec는1800초이며
`core/moyi_worker.py`의 기타 방 순회에 현장 추가취소방이 포함된다.
한 번에5개 제한, 미읽음/재확인 표시가 없으면 내보내기 생략도 있다.
그러나 실제 운영 PC 설정은 직접 확인하지 못했다. 사용자에게 확인해 다른 PC임을 알았고
사용자가 주기를 바꾸기로 했다. 이 작업에서 수집기 설정·코드를 변경하지 않는다.

웹에는 수동 전달조회, 화면/온라인 복귀 즉시조회, 마지막 성공조회 시각을 추가한다.
조회 중 버튼은 잠그며 기존 확인 근거는 유지한다. 미확인 설명의 잘못된7일을 실제3일로 맞춘다.
수동 조회도 서버의30초 캐시를 존중한다. 미확인은 미전달 확정으로 해석하지 않는다.

### 2. 시작재고에서 변경된 적용재고 복사

**Q.** 변경내역과 기초재고 기반 적용재고를 보고 복사하고 싶다.

**A.** 최신 PR1015의 복사 코어를 유지하고 같은 검증 계산으로
품목별 시작재고/추가(−)/취소(+)/적용재고 표를 추가한다.
변경 품목은 녹색,0잔량도 표에는 남고 복사문에서만 제외한다.
원문 품목명과 박스·단·송이의 별도 단위를 보존한다.

## 기준과 부작용

| 기준 | 사용 위치 | 보존 |
|---|---|---|
| 전달 원문 완전일치·연도·정확시각 | 기존 delivery API / client validator | 카톡 발송, Claude 실행, ERP 전부 |
| verified committed 동일 scope | buildAppliedStockCopy 표와 복사 공통 | 주문/출고/농장/날짜/재고/견적/매출 전부 |
| ADD 차감 / CANCEL 증가 | 기존 저장 결과의 실제 분배 전후 확인 | 수량 저장 API/SQL/SP 변경 없음 |

실제 dnSpy CLI를 설치 EXE의 FormShipmentDistribution에 재실행했다.
선택 OrderYear/OrderWeek, GetCustomerList, ShipmentDate 저장 경계를 재확인했다.
운영 인증 브라우저에서41-01 최근 SQL 작업 이력(#10855~10802)과 전달 피드23건/비교가능47건 표시를 읽었다.
직접 MSSQL 접속 자격정보가 이 worktree에는 없어 별도 직접 SQL probe는 하지 못했다.
운영 ERP를 시험 증감하거나 저장하지 않았다. 견적 Amount/Vat/isFix, Estimate, WebProfitReport를 비롯해
모든 ERP 쓰기 경로는 변경하지 않는다.
