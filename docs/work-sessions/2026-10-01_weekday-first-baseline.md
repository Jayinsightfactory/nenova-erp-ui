## 이어받을 때 고정 결정

- 최초 기준은 사용자가 주광 페이지의 확정 버튼을 누른 시점의 **현재 저장된 ERP 분배**다.
- 페이지 확정은 공용 EXE 확정/SP/isFix 변경이 아니다. 업로드/파란 초안은 최초 기준에 넣지 않는다.
- 최초 기록은 연도+전체 세부차수+업체별 최초 한 번 불변 보관한다. 재확정·수량취소로 덮지 않는다.
- 표는 전/현재/후 대차수 가로 연속이며, 차수당 최초01·목금토일·01잔량·최초02·월화수·잔량의 11열이다.
- 알스트로의 출고단위가 단이면 표시만 48(3)으로 한다. 실제 ERP 수량/단위를 환산 저장하지 않는다.
- 노랑은 최초 대비 변경, 보라는 수동 확인 선출고, 파랑은 ERP 미적용 초안이다.
- 선출고 원천은 자동 추정하지 않는다. 담당자 지정 미래 차수·실제 날짜수량 이하·출고단위를 검증한다.
- 관리 상세 합계(차감 포함)와 인쇄 합계(단가별 반올림)를 따로 읽어 일치/불일치/확인 필요를 보여준다.

## Q&A

### 1. 최초분배와 잔량 / 알스트로

Q. 알스트로 48(3), 최초분배·요일·최초기준 잔량을 표시하고 해당요일 수량과 금액만 출력해달라.

A. 최초 날짜분포까지 보관해 현재 분배 및 초안과 비교한다. 01잔량=최초01-목일 배분,
대차수 잔량=최초01+02-목수 배분이다. ERP 재고 또는 배송 완료로 주장하지 않는다.

### 2. 확정 시점과 범위

Q. 기준은 언제 고정하나? → “확정버튼을 누른시점.” / 공용 ERP 확정인가? → “지금 주광페이지에서만 확정하는거야.”

A. 전산값 미리보기 후 저장 직전 지문을 다시 확인하고 private runtime에 불변 저장한다.
다른 화면의 실제 분배 수량/날짜 변경은 그대로 읽어 최초 기준과의 차이를 보여준다.

### 3. 중심차수·품목명·변경 비고

Q. 좌우 버튼으로 중심차수 이동, 품종을 빼고 품목명 전체 표시, 변경값(최초값), 합계 옆 변경량 클릭해 떠 있는 비고창.

A. 실제 PeriodDay의 전후 cycle을 사용한다. 알려진 영문 품종 접두어만 화면에서 제거하며
ProdKey/원본명/인쇄명은 보존한다. 변경량과 비고 표식을 클릭해 floating 입력창을 열고
revision 동시수정 보호로 서버 비고를 저장한다. 새 표 열을 만들지 않는다.

### 4. 선출고와 견적 관리 수량

Q. 38차에 39차 물량을 사용한 선출고는 다른 색과 원천 차수 수량으로 표시하고 실제 견적관리 총수량과 매칭해야 한다.

A. 입고 후보만으로 실제 원천을 확정할 수 없어 담당자 수동 확인 기록으로 구분한다.
현재 날짜수량이 줄어 기존 선출고 기록보다 작아지거나 단위가 바뀌면 재확인을 표시한다.
견적관리의 실제 상세 GET과 공통 인쇄 SELECT를 읽고 차감·반올림·단위 차이는 숨기지 않는다.

## 검증 / 한계

- PR #833 및 Cafe24 workflow 36803721690은 성공했다. 이어진 운영 조회 검사에서 최초 기준
  preview가 `INVALID_ERP_DATES`로 중단되어 별도 후속 보완을 진행했다. SQL 출고일 목록의
  문자열·빈 배열을 명시하고, 실제 수량/날짜 검증은 유지한다. 최종 운영 통과 여부는 후속
  배포와 `weekday-horizontal-live-smoke.mjs` 결과로 판정한다.

- 전용 baseline/API 파일시스템·동시확정·지문 stale·저장 실패·훼손 및 연도 격리 테스트.
- 비고 revision/CAS·병행 저장·잘못된 날짜/단위·초과 선출고·가짜 source39-99 검증.
- 순수 합산·취소 후 최초 행 유지·월요일 이동·원문 불변·양수 소수·범위 밖 날짜·견적 대조 fixture.
- 필수 ERP 계약·dnSpy 근거·쓰기 scope 및 build, 1920/1280 browser smoke를 수행한다.
- 최종 fixture에서 33열/품목폭260px/첫 화면32행, 가로 문서잘림 없음, 브라우저 오류0을 확인했다.
- 최종 리뷰에서 단위 변경으로 최초 양수 취소행이 숨는 문제와 미확정/달력/범위 밖 값을 일치로 보는 문제를 회귀 테스트와 함께 수정했다.
- 선출고·셀 내역 버튼은 투명 수량 입력 위의 독립 클릭 영역으로 둔다.
- 운영 원장 또는 실제 최초 기준/비고에 자동 시험 쓰기를 하지 않는다. 실브라우저는 조회만 수행한다.
- private runtime 경로는 현재 단일 서버 in-place 배포에 유지된다. 이관 시 백업/이전하고 멀티서버 전 공유 영속 저장으로 교체해야 한다.
- 기존 ERP 적용 비활성과 메모리 초안 경계는 이번 변경으로 해제하지 않았다. 실제 재고수정/분배 반영은 별도 미완 범위다.
- 하위 작업은 모델 override 없이 상속 모델 사용, P0_LOCAL의 disjoint 구현/fixture/읽기 검토; push·병합·배포는 메인만 수행.
- `output/` 실데이터 probe·스크린샷·로그는 로컬 증거이며 커밋하지 않는다. 인증정보는 문서에 기록하지 않는다.
