## 이어받을 때 고정된 결정

- 엑셀 26~31차를 우선, 1~25차를 보조로 공통식/예외를 구분한다. 이전 차수의 숫자 자체를 미래에 복사하지 않는다.
- 엑셀 품목 묶음은 편의상 작성한 것. 전산은 SQL 품목·단가·단위·수량을 따른다. 울리부쉬 그린팁/레드팁도 별도 원가 근거가 필요하다.
- 운영 DB·현재고·후속 수량·확정 revision·단가 증거를 수정하지 않는다. 코드만 배포한다.
- 기본식이 같아도 매출·수량·원가 입력이 다르면 수익률은 달라진다. 산술 일치와 원천자료 완결을 구분한다.
- 판매단가, 현재 환율 근사, 비대상 국가 평균, 이전 국가 합계단가, 원본 F 금액 복사를 취득원가 증명으로 쓰지 않는다.

### 1. 2026-10-22 — 26~31차를 중심으로 다시

**Q.** DB는 건드리지 말고 과거 엑셀의 공통식/국가·품종 예외부터 확인해 웹을 수정하고 1~41차 검증·배포. 특히 26~31차 우선.

**A.** 두 원본 ZIP의 1~31차를 확인했다. 26~31차 원본 기본·합계858셀과 직접 남은 재고수식23셀은 같은 입력의 웹 계산과 모두 일치한다. 일반/기말제외 국가/합계 이익률 분모, 6품종 평균식, 베트남 개별 이익조정을 분리했다. 호주 26~29와 30~31 통관배분 차이는 단일 고정 단가로 일반화하지 않았다.

**결과.** lib/profitReportExcelRulebook.mjs, data/profit-report-evidence/formula-rulebook-26-31.json 및 계약/회귀 검사. 원본의 금액과 SQL 원천의 차이는 별개로 로컬 보고서에 보존.

### 2. 2026-10-22 — 단가 근거와 품목 구분

**Q.** 울리부쉬는 품목별 단가를 확인해야 하며, 엑셀은 편의상 묶었으니 전산은 전산 기준으로 표시.

**A.** 판매단가 기준으로 저장된 증거를 매입원가로 오인하지 않도록 읽기 필터를 추가했다. DB의 증거는 삭제하지 않는다. 호주는 SQL 매입이 있어도 도착원가 객체가 비면 계산하지 않던 분기를 실제 품목 매입액/동일 단위 수량×매입시점 정확 AUD+동일 단위 통관비로 보완했다. 4차수 밖 실제 매입도 같은 연도·품목·단위·미래 금지·완전 매입 조건으로 조회한다. 일반 엑셀 품명을 색상별 품목으로 복제하지 않는다.

**결과.** 26~31 및 41차 호주 누락 해소. 중국3096은 19-01차 실제 매입과 정확 CNY·같은 품목/단위/행수의 운송·통관 원가가 있어 최근4차수 밖의 실제 근거를 조회하도록 보완했다. 26~31차 원가/환율 누락0. 38~41 태국 원가와 초기 일부 누락은 임의 보충하지 않는다.

### 3. 2026-10-22 — 검증 및 배포 경계

**A.** 최종 1~41차 SQL 읽기 재계산 14,022 SELECT, 독립 산술15,058항목 실패0, 비교 가능한 E/F 불연속0. 시작/끝 원천 및 정책 지문 동일(STABLE_OBSERVED, atomicSnapshot=false). probe는 쓰기 SQL/execute/batch/transaction 차단. npm run verify:erp-change 최초 전체 검사 및 build 성공, 중국 조회 추가 후 다시 전체검사 진행. 실제 dnSpy CLI FormStockView/FormProductAdd/FormWarehouseView 읽기 확인.
