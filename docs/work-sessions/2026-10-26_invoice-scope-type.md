# 인보이스 입고 연도·차수 전달 오류

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-26 |
| 화면 | 수입부 인보이스 → 품목 매칭 → 입고 준비 |
| 원장 부작용 | 운영 DB 변경 없음. ERP writer/SP/DDL 변경 없음 |
| 배포 | 필수 검사 후 PR/배포 결과 후속 기록 |
| 이어받기 | `invoice-scope-type`, `receiptScopeIssue` 검색 |

## 고정된 결정
- 사용자 오류 `orderYear and orderWeek must be strings`는 초안 API의 엄격한 문자열 검증에서 발생한다.
- 빈 연도·차수를 payload에서 null로 바꾸던 경로를 제거한다. 숫자로 받은 연도도 기존 normalize를 통해 문자열로 보낸다.
- 명시적인 orderWeekDate 세부차수를 어댑터에서 보존한다.
- 파일명에 연도가 없고 원문 날짜가 있으면 입고 연도는 비어 있을 수 있다. 원문 날짜 연도나 현재 연도를 임의로 선택하지 않는다.
- 누락 시 저장 요청 전 한국어로 해당 입력칸을 안내하고 매칭 행은 보존한다. 수정 후 동일 문서로 재진행한다.
- 해당 사용자의 실제 실패 payload는 확보하지 못했으므로 개별 파일의 누락 원인은 미확정. 코드 재현 경로와 구별한다.

## 질문 → 답변
### 1. 매칭 후 다음 입고를 누르면 영문 자료형 오류
**Q.** 인보이스 매칭 후 다음 입고에서 오류가 난다.

**A.** nullableText가 빈 문자열을 null로 변환하고 서버가 이를 거절하는 경로를 확인했다. 값 전달, 차수 보존, 저장 전 검증과 한국어 안내를 수정했다.

**검증.** focused 51건 통과. 누락·null·숫자 연도, 2025/2026 동일 차수, 수정 후 다음 단계, 매칭값 보존, 서버 엄격 검증 유지. 전체 gate/build/운영 화면은 후속 결과로 기록한다.

## 메뉴 기본값
- 적용: 기존 입력·버튼·페이지 레이아웃 유지, 한국어 오류와 수정 위치 안내, 기존 매칭/수량 보존.
- 해당 없음: 새 메뉴·권한·다운로드·원가/재고 산식 변경 없음.
- 미검증: 사용자의 실제 파일로 운영 입고 재등록(운영 DB 보호를 위해 수행하지 않음).
