# 2026-10-08 웹·PC 메뉴별 즐겨찾기

Q. 기존 메뉴 옆에 즐겨찾기 추가/해제 구분 버튼을 웹과 PC에 모두 적용해 달라. 앱 업데이트 후 변경이 보이지 않는다.
A. 최초 업데이트 버튼 위치로 잘못 해석한 변경은 철회했다. 전체 메뉴 이름과 별을 별도 버튼으로 제공하고, ☆/★로 상태를 구분한다. 미등록 메뉴도 화면을 열지 않고 추가할 수 있다. 선택 뒤 원래 메뉴는 남기고 즐겨찾기 목록과 색상을 갱신한다.

확인: 사용자 PC 설치 버전은 1.3.0. 당시 공개 최신도 1.3.0이라 새 변경이 없었다. 본 수정은 1.3.1로 배포해 기존 앱의 업데이트 버튼으로 받게 한다.

보존: 기존 계정별 웹 즐겨찾기 및 PC별 암호화 즐겨찾기 저장 방식 유지. ERP 원장 쓰기 없음. 웹↔PC 자동 동기화는 이번 범위 아님.

검증: npm run test:ui-layout, verify:erp-change, test:nenova-dnspy-evidence 통과. 변경 범위 manifest/write guard 통과. Desktop smoke·재시작 복원 통과. 웹 1920×1080/800×1080에서 독립 별 버튼, Enter 추가/Space 제거, 원래 메뉴 유지, 실패 시 상태·초점 유지 확인(API fixture, 운영 쓰기 없음).

배포 산출물: PR #974, 구현 0bc13479, master 병합 9d276db1. Desktop 1.3.1 공개. ASAR 소스 일치와 latest.yml SHA512 확인, GitHub 업로드 SHA256 d361cbb6697d6abc09004c643c97a81ffafb6d88aa240843e8db3e9ed3ceced6 확인. 격리된 실제 NsisUpdater에서 현재 1.3.0 → 공개 피드 1.3.1 인식 확인(다운로드/설치 실행 없음). 설치된 사용자 앱 및 프로필은 변경하지 않았다. 실제 설치/UAC 검증은 수행하지 않았다.

운영 검증: 최초 Cafe24 배포 37734064346 및 master 계약/Windows CI 성공. 운영 1920×1080/800×1080 추가·제거·원래 메뉴 유지 검증은 통과했으나, 실패 알림 뒤 초점 복귀가 지연된 React commit과 경합했다. 버튼 비활성 해제를 flushSync로 먼저 반영한 뒤 초점을 복구하도록 후속 수정했다.
