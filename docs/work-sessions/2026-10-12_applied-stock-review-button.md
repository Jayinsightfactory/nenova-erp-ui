## 이어받을 결정

- 사용자가 요청한 버튼명은 `적용재고 확인`이다.
- 결과 열의 긴 처리 내역 위에서 열 수 있게 한다.
- 창 제목은 `기초재고 기준 적용재고`, 기초재고 + 취소 − 추가를 표시한다.
- 실제 저장·검증된 기존 결과만 사용하며 ERP 현재 재고라고 표시하지 않는다.
- 실패·롤백·입력 변경·교차연도·단위 불명 등 기존 차단 조건을 완화하지 않는다.
- 복사 실패 시 원문을 직접 선택할 수 있게 남긴다.

### 1. 작업 후 확인 버튼

**Q.** 작업 처리 후 기초재고 기반 적용재고를 확인하는 버튼을 만들어 달라.

**A.** 기존 `buildAppliedStockCopy` 계산은 그대로 사용한다. 상시 펼쳐진 표를
확인 버튼과 별도 창으로 바꿔 기초재고, 추가, 취소, 잔량을 보고 복사하도록 한다.
안전 조건을 통과하지 못하면 이유만 보여주고 표와 복사는 차단한다.

## 기준과 부작용

| 동작 | 계산 근거 | ERP 영향 |
|---|---|---|
| 창 열기·닫기 | 현재 draft/result/scope | 모든 원장 보존 |
| 재고 표 확인 | 기존 buildAppliedStockCopy의 ready/changeRows | 주문·분배·재고·농장·날짜 변경 없음 |
| 원문 복사 | 같은 함수의 text | Estimate, Amount/Vat/isFix, WebProfitReport 보존 |

실제 설치 EXE의 FormShipmentDistribution을 dnSpy CLI로 다시 읽어
선택 연도/차수와 GetCustomerList 경계를 확인했다. 이번 변경은 API/SQL이 아닌
기존 저장 결과의 표시만 바꾸므로 운영 시험 저장이나 DB 보정은 하지 않는다.
직접 DB probe 대신 이전 같은 기능 작업의 운영 최근 전산이력 읽기 근거와
교차연도/실패/단위 회귀 fixture를 사용하며, 새 운영 원장 검증을 했다고 주장하지 않는다.
