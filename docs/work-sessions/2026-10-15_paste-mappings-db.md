# 업체·품목 매칭을 공유 DB로 이전

| 항목 | 내용 |
|---|---|
| 기간 | 2026-10-15 |
| 화면 | 붙여넣기 주문등록, 업로드 주문등록 및 공용 매칭 소비자 |
| 원장 부작용 | WebMappingStore/WebMappingMigration만 쓰기, ERP 주문·출고·재고·견적·매출 보존 |
| 배포/PR | 검증 후 기록 |

## 이어받을 때 고정된 결정

- 기존 업체·공용 품목·업체별 품목의 전체 JSON 구조와 history를 공유 MSSQL에 보존한다.
- 런타임 저장·읽기·삭제는 DB만 사용한다. 파일 및 프로세스 캐시를 최신 저장소로 사용하지 않는다.
- 사용자 수동 확정은 자동 분석이 덮어쓰지 못하며, 동시 저장은 같은 문서의 잠금 안에서 처리한다.
- 최신 업체명·품목명은 기존 키를 기준으로 응답에서 보충한다. 원본과 과거 이력은 변경하지 않는다.
- 최초 전환은 빌드 성공 후 파일 작성자 중지 확인, 바이트 백업, 원자적 이전·검증, DB 전용 앱 시작 순서다.
- 완료 표식 이후 파일 재수입과 파일 기반 구버전 재시작을 금지한다. 진행 중 요청은 짧은 전환 중 실패할 수 있다.

### 1. 공유 DB 저장 요청

**Q.** 업체·품목 매칭을 파일 대신 DB에 저장하고, 기존 값을 그대로 옮겨 다른 계정과 공유하며 배포해 달라.

**A.** 세 문서를 웹 전용 DB에 저장하도록 구현하고, 붙여넣기/업로드/재매칭/입고비용/카탈로그/재고 챗봇 등 기존 소비자를 비동기 DB 읽기로 전환했다. 레거시 파일 수정 스크립트는 잘못된 성공을 보고하지 않도록 실행을 차단했다.

**검증.** 실제 격리 MSSQL에서 lossless 이전, DDL 포함 실패 롤백, 별도 연결 읽기, 8개 동시 저장, 수동 보호, 전체 이력, 삭제 부활 방지, 2025/2026 동일 차수 원장 보존을 통과했다. 두 계정 API fixture의 저장→조회→삭제 공유와 최신 이름을 확인했다. 1920×1080 브라우저에서 완료 상태·원문 재고·수량 보존을 확인했다.

**운영 사전 읽기.** 업체 36건, 공용 품목 501건. 운영 이전은 아직 실행 전이며 최종 건수·해시는 배포 로그로 확인한다.
