# 붙여넣기 주문등록 영업방-전산 변경 나란히 보기

## 요청

영업방 카톡 요청과 최신 전산 이력을 카드 안에서 좌우로 나란히 보고, 글씨와 공간을 다듬어 한 화면에서 매칭/미매칭 및 실제 적용 상태를 분명히 구분한다. 화면이 겹치거나 영업방 목록이 주변 입력·결과 패널을 덮지 않도록 한다.

## 구현 경계

- 기존 전산 분석·저장/API 의미는 변경하지 않는다. 변경분은 표시와 읽기 전용 이력 비교뿐이다.
- 카톡의 파싱된 요청은 원문 식별자와 요청 ID의 정확 일치로만 연결한다. 텍스트 유사도·품목·수량으로 추측 연결하지 않는다.
- API가 요청 일부를 반환하지 않거나 중복 ID를 반환하면 원문 변경 행은 유지하고 `확인 필요`로 표시한다. API에만 존재하는 요청도 원문 변경과 연결되지 않았음을 표시한다.
- 대조 근거와 실제 적용은 구분한다. 실제 적용 배지는 기존의 커밋된 붙여넣기 작업 기록이 확인될 때만 보여준다.
- 화면은 1920×1080을 기준으로 하고, 카드 목록은 자신에게 할당된 영역 안에서 스크롤한다. 1100px 이하에서는 요청/이력 칸을 세로로 쌓는다.

## 검증

- `distributionVisibleChanges`, 붙여넣기 4열 레이아웃, 영업방 대조·새로고침·압축 표시·적용 상태 테스트 통과.
- `npm run test:erp-contract`, `npm run test:ui-layout`, `npm run test:nenova-dnspy-evidence` 통과.
- `npm run test:erp-manifest -- --changed-from origin/master`, `npm run guard:erp-writes -- --changed-from origin/master` 통과. 기본 `HEAD^` 비교는 이 작업 브랜치에 부모 커밋 정보가 없어 실행되지 않아 실제 기준 브랜치를 사용했다.
- `npm run build` 통과.
- 고성능 독립 코드 리뷰에서 처음 발견된 원문/API 줄 인덱스 불일치와 메시지 단위 저장 기록의 개별 요청 오표시를 수정한 뒤 재검토 통과. API로 보내는 본문을 원문 그대로 고정하고, 저장 기록은 메시지 단위임을 명시했다.
- 1920×1080 브라우저 캡처에서 다섯 열(기초재고·영업방·입력·분석·결과) 배치와 패널 분리가 유지됨. 실제 로그인 화면으로 리디렉션되어 운영 데이터/대화 카드가 보이는 UI smoke는 수행하지 못했다. 기존 Puppeteer 스크립트는 환경에 `puppeteer-core`가 설치되지 않아 시작할 수 없고, 직접 Playwright 확인은 로그인 게이트에서 차단됐다. 작은 뷰포트의 데이터 상태 검증은 미완료.
- 저장소는 `origin/master`보다 2개 커밋 뒤인 작업 브랜치다. 원격 push·PR·병합·배포는 수행하지 않았다.
