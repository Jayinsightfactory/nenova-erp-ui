## 이어받을 때 고정된 결정

- 처리상태의 `{거래처명} 견적서 열기`는 화면 선택 연도·부모차수 + 해당 행 CustKey로 견적서관리 팝업을 연다.
- 처리상태는 등록 가능/등록 불가만 구분한다. 보완필요는 수입부 열 표시이며 등록을 막지 않는다.
- 원차수가 선택 차수보다 앞이면 `N년 M차부터 이월`을 처리상태에 보여 준다.
- 출고 존재는 OrderYear + 부모차수 정수(및 OrderYearWeek)로 본다. LIKE `33-%` 접두는 쓰지 않는다.
- 처리상태 옆 **견적서 캡쳐**는 같은 연도·부모차수·업체의 기존 음수 Estimate를 견적서 목록처럼 보여 준다. 호버는 읽기 전용 iframe이다.
- 미확정 포함 견적 목록 GROUP BY에 `sm.OrderYear` 필수.
- 영업지원 불량차감 등록은 `Estimate.Descr`을 비운다. 수입부 Note는 웹 원장만. 화면·인쇄 불량차감 적요는 기본 숨김.

### 1. 2026-08-25 13:04 — 청화원예 견적서 열기

**Q.** 영업지원 전산등록 처리상태에 청화원예 견적서 열기 버튼이 있어서 해당 차수·해당 업체의 불량차감 현황을 바로 보게 해 달라.

**A.** 처리상태 칸에 `{거래처명} 견적서 열기`를 넣었다. 클릭하면 선택 연도·차수·업체의 견적서관리가 열리고 불량차감 행을 강조한다. Order/Shipment/Estimate 원장은 건드리지 않는다.

**결과.** PR #341 squash merge `f8d2ef3`. Cafe24 배포 완료.

### 2. 2026-08-25 13:23 — 이월 원차수·보완필요 표시만

**Q.** 처리상태에 ‘선택 차수에 이 업체의 출고가 없습니다’가 나오는데 출고는 있다. 몇 차부터 이월인지 보여 달라. 보완필요는 표시만 하고 등록 가능/불가 판정에는 넣지 말라.

**A.** 처리상태는 등록 가능/등록 불가만 구분하고, 원차수가 앞이면 `N년 M차부터 이월`을 같이 보여 준다. 출고 조회는 부모차수 정수·OrderYearWeek로 맞추고, 단가 조회 실패가 출고 없음을 덮어쓰지 않게 했다. 보완필요는 수입부 열 표시만 하고 선택·등록을 막지 않는다.

**결과.** 구현 후 배포.

### 3. 2026-08-25 13:40 — 수기 처리 수동처리완료

**Q.** 처리상태에서 이미 수기로 처리했는데 표시가 안 된 항목이 있다. 그 항목을 체크한 뒤 수동처리완료 버튼으로 별도 이력을 남겨 달라.

**A.** 등록 가능/불가와 무관하게 미완료 행을 체크할 수 있게 했다. `수동처리완료`는 견적서를 만들지 않고 `WebSalesDefectDeduction.Status=MANUAL_COMPLETED`, 잔량 0, History `MANUAL_COMPLETE`만 남긴다. 이미 견적키가 있는 행은 거부한다. Order/Shipment/Estimate/Stock은 보존한다.

**결과.** PR #344 squash merge `696b77a`. Cafe24 배포 완료.

### 6. 2026-08-25 15:13 — OrderYear GROUP BY · 견적 적요 차단

**Q.** `ShipmentMaster.OrderYear` GROUP BY 오류. 불량처리 등록 후 견적서에 사유·비고·적요가 같이 올라가면 안 된다.

**결과.** PR #356 squash merge. Cafe24 배포 성공. Descr=Note 일치 4건 정리 완료.

### 7. 2026-08-25 17:57 — 분배 SqlClient · 견적 적요는 직접입력만
