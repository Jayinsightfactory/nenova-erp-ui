## 고정된 결정

- 사용자 요청은 실제 PC 앱에서 메뉴를 하나씩 확인하는 것이다. 코드 검색과 fixture 검사를 실제 앱 전체 점검으로 대체하지 않는다.
- 작업 탭 한 줄, 메뉴 접근, 메뉴별 즐겨찾기는 유지한다. 중복 제목과 여백을 줄이며 글씨를 줄여 맞추지 않는다.
- 웹/인쇄와 ERP 업무 동작은 보존한다. 표·가상 그리드 크기는 공통 규칙으로 덮어쓰지 않는다.
- 기준은 1920×1080 CSS px, 100%, 보조 800px. 실제 앱 캡처 외곽 1920×1032는 기준 viewport 검사와 구분한다.

### 1. PC 앱에서 직접 메뉴별 확인

**Q.** PC 앱에서 메뉴창 하나하나 확인하여 공간 활용과 버튼 디자인을 일관되게 적용해 달라.

**A.** 실제 설치 앱 1.3.2의 시작 메뉴, MOYI 보고 연동, MOYI Drive 관리, 직원 업무 심화 리포트를 열어 확인했다. 시작 메뉴 좌우 여백과 메뉴명 잘림, 중복 본문 제목, 작은 공통 필터 컨트롤을 수정 대상으로 잡았다. 전체 등록 85개와 시작 화면의 코드 인벤토리는 `docs/plans/desktop-menu-ui-audit.md`에 기록했다. 후속 실제 방문 결과는 아래 점검 재개 기록과 인벤토리의 관찰 열을 따른다. 나머지 메뉴는 미확인이다.

**결과.** 시작 메뉴 폭·여백·줄바꿈 CSS, 순수 제목의 PC 숨김 마커, 공통 필터 30px/13px 스타일을 작업 트리에 반영했다. 아직 사용자 설치 앱에 적용되지 않았다.

### 2. 실제 앱 제어 오류

**Q.** PC 앱은 잠시 조작하지 않겠다.

**A.** 사용자 답변 후 현재 창을 다시 조회했다. 최소화 상태에서 복원이 `user input was detected in this window` 오류로 실패했다. 상태 조회도 `window is minimized`를 반환했다. 사용자 조작이 원인이라고 확정할 수 없으며, 반복 입력을 중단하고 사용자가 작업표시줄에서 앱을 복원하도록 요청했다. 답변 대기 중 독립 코드 검증을 진행했다.

### 3. 창 복원 후 메뉴 점검 재개

**Q.** 실제 PC 앱에서 계속 확인해 달라.

**A.** 사용자가 창을 직접 복원한 뒤 실제 앱 1.3.2 점검을 재개했다. 내 작업 데이터, 업무 매뉴얼, 주의·이슈 및 업무처리 지침, 업무 드라이브, 주문등록, 내 업체 주문등록, 영업부 붙여서 주문등록, 붙여넣기 주문등록, 업로드 주문등록, 카톡 변경 검증, 카톡 변경 큐를 추가로 열어 수정 전 상태를 확인했다. 화면별 여백·제목·로딩 제한은 인벤토리에 기록했다.

**결과.** 현재14개 탭은 이번 점검을 위해 연 읽기 전용 확인 탭이다. 업무 등록·확정·분배는 실행하지 않았다. 붙여넣기 주문등록은 기존 저장 원문과40-01차 복원, 최근 작업 기록·맨위로 버튼 표시를 확인했다. 주문등록과 변경 큐의 실제 내용은 로딩 상태 때문에 미검증이다. 다음 확인은 주문관리부터이며, 이번 관찰은 수정 후 최종 검증이 아니다.

### 4. 주문관리부터 도착원가까지 후속 관찰

실제 설치 앱1.3.2에서 주문관리(`/orders`), 발주관리(`/warehouse`), 수입부 통합(`/import`), 업무도구(`/import/tools`), 경영지원(`/import/finance`), AWB 운임(`/import/freight-calc`), 입고관리(`/incoming`), 입고 인사이트(`/incoming/insight`), 카톡 수량집계(`/incoming/kakao-summary`), 입고단가·송금(`/incoming-price`), 도착원가(`/arrival-cost`)를 열었다.

발주관리 pivot·업무도구9개/국가 카드·경영지원 농장/송금·AWB2026년41-02차·입고103행·입고 요약·입고단가2026년41-02차 데이터를 확인했다. 주문관리/수입통합/카톡집계는 초기 로딩만 보아 실제 내용은 미검증이다. 도착원가는 자동반영 상태와 연도 확인 경고를 보았으나 조회품목0건으로 결과표는 미확인이다. 모두 수정 전 관찰이며 최종 검증이 아니다.

입고관리 입력일자 ISO 원문이4줄로 표시되어 행 높이를 차지하는 문제는 YYYY-MM-DD 표시 helper로 수정했다. 시간대 변환 없이 원래 날짜를 유지하며 API·필터·정렬·엑셀 원문은 보존한다. 수정코드는 아직 설치 앱에 적용되지 않았다.

## 검증

- 실제 Electron 격리 fixture smoke 통과: 탭/창 이동, 즐겨찾기, 연도 분리, 키보드, 닫기·취소, 1920×1080/800×1080.
- Desktop 단위 검사 17개 통과.
- PC CSS DOM fixture: 두 viewport에서 웹 기본값, PC 컨트롤, 표/그리드 제외, 인쇄 보존, 초점 순서/표시, 가로 넘침 검사 통과.
- 전체 ERP 검사와 빌드 결과는 완료 후 추가한다.

## 미완

- 실제 앱 점검 재개 상태에서 도착원가 이후 나머지 메뉴별 시각·키보드 점검, 초기 로딩으로 미검증인 화면 후속 확인.
- 직원 리포트 iframe 내부 중복 제목·폭 제한은 발견만 했으며 미수정.
- 최종 검토, 버전 변경 및 설치 파일 준비, PR/병합/배포, 실제 PC 업데이트 후 확인.
- 임시 로그와 fixture 스크린샷은 커밋하지 않는다.
