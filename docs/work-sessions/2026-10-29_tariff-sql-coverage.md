# 국가·품종·품목 관세 규칙의 SQL 적용 가능 범위

## 결론과 범위

2026년1~41차 활성 입고의 재고 품목을 현재 ERP 관세 설정에 연결했다. **품목별 규칙 데이터는 만들 수 있으나 현재 ERP 설정을 과거 실제 적용세율로 사용할 수는 없다.** 국가를 구별하지 않는 Flower.DefaultTariff가 국가별 차이를 잃고 있으며, 미설정NULL이 계산에서0으로 바뀌는 경우도 많다.

- 조회시각:2026-10-29T08:44:29Z, 추가 과거 스냅샷 조회08:45:19Z.
- DB4 SELECT, 총약2.7초, 오류·쓰기·차단된 쓰기시도0. execute/batch/transaction 쓰기 차단, 요청별45초 취소.
- Product·Flower·Warehouse·FreightCost·FreightCostDetail 및 웹 보고서 원장은 전부 보존. 앱 코드·DB·커밋·배포 변경 없음.
- 새 SQL 집계12,429개 차수·품목 그룹에서 기존 isNonStockableItem으로 비용/중량행을 제외했다. 국가 분류는 실제 buildProfitReportCategorySql과 baseCountry, 품종 키는 실제 normalizeFlower(trim+uppercase)를 사용했다. 임의 동의어 치환은 하지 않았다.
- 대상5개국842개 고유품목, 실제 입고원행17,603개. 과거 사용 후 현재 삭제된 품목도 입고 이력이 있으므로 제외하지 않았다. 수량·외화 합계는 세율 근거가 아니므로 미납세금으로 변환하지 않았다.

‘양쪽NULL’과 ‘명시0’은 구분한다. 품목별 유효값 경로는 Product.TariffRate가 null이 아니면 우선, 없으면 Flower.DefaultTariff, 둘 다 없으면 이5개국은0 fallback이다. 네덜란드만 별도 Excel fallback이 있으며 이번 범위 밖이다.

**0.0021은 SQL 원시값이고0.21%다.** 감사 스크립트에서 나누거나 변환한 값이 아니다. computeFreightCost는 CNF원가에 이 소수값을 직접 곱한다. 현재값의 입력 경위나 ‘의도한 세율이21%였는지’는 확인되지 않았으므로 임의100배 보정하지 않는다.

## 명시0와 과거 변경 이력

- firstNonNull은0을 유효값으로 유지하므로 Product.TariffRate=0이면 양수 Flower 기본값으로 fallback하지 않는다. 이번 입고 범위에서 ‘Product0이 양수Flower를 막는’ 실제 사례는0개다. 동작 자체를 결함으로 간주하거나0을NULL로 바꾸지 않는다.
- Product.TariffRate와 Flower.DefaultTariff는 nullable decimal이고 SQL 기본값 제약은 없다. 두 테이블 temporal_type=0. 현재 테이블만으로 언제 어떤 세율이 적용되었는지 복원할 수 없다. 별도의 감사로그 전체에 기록이 전혀 없다고 단정하는 것은 아니다.
- FreightCostDetail에는 TariffRate/TariffKRW 입력·계산 스냅샷이 실제 존재한다.1~41차 조회34행 모두 콜롬비아16-01/18-01차26품목이다. 태국·호주·중국·에콰 스냅샷0행이다.
- 콜롬비아 Prod1276은16-01 스냅샷 관세율0, 현재 기본율0.0021로 충돌한다. 따라서 현재 마스터를 전차수에 복사하면 역사 변경을 놓친다.
- 현재 도착원가 경로는 기존 FreightCostDetail의 과거 Arrival값을 직접 쓰지 않고 LIVE 계산하며 Product/Flower 현재율을 쓴다. 이 동작과 역사 실세율 인증은 별개다.

## 원본 규칙 연결

원본 도착원가 양식의294개 규칙을 실제 입고842품목에 대조했다. 사용자 기준 콜롬비아0은 현재 양수133품목과 충돌한다. 예전 FREIGHT_PIPELINE 문서의 에콰25% 일괄 설정 설명은 현재 SQL과 맞지 않으므로 적용 근거로 삼지 않는다.

출처 워크북·시트·셀·수식, 적용 국가/품종/품목, 근거 적용차수, 현재 SQL율, 후보율, 충돌/미확정 사유를 각각 보존하는 데이터 초안을 만든다. 법정세율이나 실제납부 관세로 명명하지 않는다.

### 에콰 누락25차수의 규칙 커버리지

앞선 관세감사에서 확인한 누락25차수 중24차수는 현재 입고품목 모두가25% 원본 동일명 후보와 연결된다.3차는8품목 중7개 연결,Prod2927만 미연결이다. **원본 적용 연도가 확인되지 않았고 품목별 과세표준/운임배분·환율을 이번 데이터 초안에서 재계산하지 않았으므로,24차수의 실제 누락세액을 확정했다는 뜻은 아니다.** 금액은 산출하지 않았다.

### 보존한 최종 데이터

`docs/analysis-data/tariff-rules-review-2026-10-29.json`에294규칙·842품목·국가별커버리지·에콰 누락25차수의 연결상태를 저장했다. 원본 수식은 formulaDictionary, 규칙 출처는파일/시트/셀/관측차수, 품목은ProdKey와ruleIds로 연결된다. 동일품목매칭과CO업무정책을 구별하고 `approvalStatus=review_only`, `periodVerified=false`, `automaticApplicationAllowed=false`로 표시했다. JSON파싱·842키유일성·294규칙참조 무결성 검증 통과.

양식 기준 재구성은 실납부 확정과 다르다. 과거 적용률은 원본 기간·전표 범위 확인이 필요하며, 국가별 HS분류·세율구분·효력기간·원산지 요건을 검증한 법정세율 데이터가 아니다.

## 아직 산출할 수 없는 것

국가별 관세가 CNF금액×세율이라고 해도 품목별 운임배분·과세환율·과거율·정확한 상품 범위가 필요하다. 전체 국가금액에 후보율을 일괄 곱하면 품종 예외를 잃는다.1~41차 누락관세는 후보 계산 시나리오는 가능하지만 실제 누락 세액의 확정은 불가능하다. 특히 호주/중국의 품종별 예외와 태국/에콰의 원문 적용범위 확인 전에는 DB나 본표를 갱신하지 않는다.
