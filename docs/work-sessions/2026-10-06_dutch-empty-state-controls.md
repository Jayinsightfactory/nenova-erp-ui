## 이어받을 때 고정된 결정

- 선택 차수에 네덜란드 행이 0건이면 이를 임의의 다른 차수로 대체하지 않고 빈 상태로 알린다.
- 파일 업로드와 연도·차수·DB 조회 조작은 데이터 행 렌더 조건 밖에 두어 항상 노출한다.
- 행 추가와 ERP 검증 도구도 빈 상태에 보여주되, 데이터가 없을 때 검증만 비활성화한다.
- 저장 이력은 복제하지 않고 기존 우측 단일 이력 패널을 유지한다.
- 이 변경은 ERP 데이터/API 쓰기 로직을 수정하지 않는다.

### 1. 2026-10-06 — 빈 차수에서 버튼이 사라져 보임

**Q.** “버튼이 다없어짐” (첨부 화면은 2026년 35-01 네덜란드 업체별 주문 데이터가 없다는 상태를 표시하고 아래가 비어 있음.)

**A.** 빈 차수 메시지는 그 차수에 네덜란드 주문행이 없어서 나타난다. 업로드/차수조회와 행 추가/검증 조작부가 데이터 표와 분리되어 있어도 우측 보조영역에만 배치된 구조는 빈 화면처럼 인식되기 쉬웠다. 조작부를 제목 바로 아래 전체폭 영역으로 옮기고, 작업 도구도 데이터 유무와 관계없이 표시하도록 했다. 행이 없을 때 ERP 검증은 버튼을 보이되 비활성화한다. UI 회귀 검사를 추가했다.

**결과.** [PR #913](https://github.com/Jayinsightfactory/nenova-erp-ui/pull/913) 병합됨 (`d194e9f5`). `npm run test:erp-contract`, `npm run test:nenova-dnspy-evidence`, 변경분 ERP manifest/write guard, Dutch volume SQL 격리 fixture, `npm run test:pivot`, `npm run test:ui-layout`, `npm run build` 통과. Cafe24 `SSH Deploy to Cafe24` 및 `Hydration smoke (실브라우저)` 워크플로 통과. 운영 Chrome에서 `v1.0.2·d194e9f5`와 상단 조작 영역의 업로드, 연도·차수, DB 조회, 행 추가, 빈 데이터 시 비활성 검증 버튼이 노출됨을 확인했다. 화면 실제 viewport 크기는 CUA 접근성 스냅샷에서 반환되지 않아 별도 계측값으로 주장하지 않는다.
