# 26~31차 관세·운임 SQL/Excel 독립 대조

## 범위와 방식

2026년 26~31차, 중국·태국·호주·에콰도르, 1·2 반차수 총 48조합을 조회했다. 활성 입고가 있는 조합은 25개다. SQL은 실행 전 Request.query SELECT-only 검사, execute/batch/transaction 금지 wrapper를 설치하여 11 SELECT, 쓰기 0으로 읽었다. 원본 xlsx도 수정하지 않았다.

독립 예측은 **실제 관세 입력값을 계산에 사용하지 않고** SQL 상품액+AWB 배분 운임에 동일 차수 환율과 품목별 승인/공식 조건부 세율을 곱했다. 실제 웹 적용은 이 예측과 다르게 실제 관세·명시0·수기 H를 우선한다. 따라서 예측과 엑셀의 차이는 곧 웹 수정액이 아니다. 태국/호주/에콰도르의 기존 승인 정책은 이번에 공식 검증된 것으로 승격하지 않았다.

완전 예측 14개 중 엑셀 관세가 숫자인 12개는 최종 동일형태 정책에서 모두 ±1만원 이내다. 나머지 2개는 엑셀 빈칸이므로 정확도 판정을 하지 않았다. 미완전 11개는 부분 합계를 전체 관세로 표시하지 않았다. 이 결과는 6개 차수를 모두 ±1만원 정확도로 예측할 수 있다는 증거가 아니다. 정책 연결에 참고한 자료의 대조이므로 독립 표본 외 예측 정확도 인증도 아니다.

## 27차 문제를 세 가지로 분리

1. **웹 배분 오류**: 27-02 실제 운임은 SQL에 4,269.5 CNY로 존재한다. 기존 40cm 잔여 계산과 장미 bucket 계산이 서로 달라 4,580.21832884 CNY가 배분됐다. 관세 전용 행별 중량 배분에서 GW 371kg 합계를 맞추고 실제 4,269.5 CNY를 보존한다. 기존 입고 원가 출력은 변경하지 않았다.
2. **역사 원문 빈칸 오인**: 27차 그외통관비 J10은 빈칸인데 historical fallback이 Customs2=0으로 변환했다. 해당 정확 fallback 필드만 null로 복원한다. 실제 SQL 행의0은 이 복원 함수를 거치지 않는다. 파일 SHA256 `2906ec876160f7fa2f0fbaeb1c9b89e49bda6a933cad9b7cabad9fbd7dd36689`.
3. **엑셀 운임과 SQL 운임 차이**: 엑셀 포워딩 두 번째 중국행 G5는4,924.5 CNY, SQL27-02는4,269.5 CNY로655 CNY(환율226.66 적용148,462.30원) 차이다. Excel L5의93212361은 SQL AWB99993212361 끝자리와 일치한다. K4/K5가 모두27-1 중C라 차수표시는 오기 가능성이 있지만 원문 invoice 확인 전에는 확정하지 않는다. SQL금액은 원가 스냅샷이 아니라 동일 AWB의 입고 운송료행 TPrice 합계다. 배분 오류를 고쳤다고 Excel과 운임이 일치한 것은 아니다. AWB 원문 추가 대조 없이는 어느 금액이 잘못됐는지 확정하지 않는다.

27-02 조건부 관세는 10행의 CNF×세율을 합해621,939.94603245원이다. Asparagus 2품목8%, 나머지 기존/확인 품목21.4%를 사용한다. 공식표의21.4% 존재와27차 APTA 자격은 서로 다른 사실이며 자격 미확인 경고를 유지한다.

## 29-01 동일형태 세율 검토와 운임 차이

초기 예측795,338.645원에는 ProdKey3212 `ASPARAGUS CHINA Preserved Pink / 미디오 (연핑크)`의 기존 exact-name rule168 세율25%가 포함되어 있었다. 동일 보존형태의3210 Blue는 조건부 HS0604909000/A8%를 연결했는데3212 Pink를 색상만으로 제외할 근거가 없었다. 공식근거 담당의 독립 검토 후3212도 정확키·정확명·중국·2026년 범위에만 같은 조건부8%를 연결했다. 신고분류/수량 직접확정이 아니며 색상 외 형식이 달랐다면 적용할 수 없다.

3212 과세가격은 `(상품1200 + 배분운임487.61553452) CNY × 224.22 = 378,397.15515원`. 기존25%94,599.28879원에서 조건부8%30,271.77241원으로 추정액64,327.51638원이 줄어 전체731,011.12903원이 됐다. 엑셀739,050원과의 차이−8,038.87097원은 검토 결과이지 세율 선택 근거가 아니다. 실제29-01 입력관세739,050원은 우선보존되어 웹 H와 수익률에는 추가변경이 없다.

29차 포워딩 G3=5,809.5 CNY, L3=93212420은 SQL AWB99993212420과 끝자리가 일치한다. SQL 입고 운송료행 합계는4,892.5 CNY로917 CNY 차이가 별도로 남는다. 세율 추정액이 ±1만원 안에 들어와도 운임 원문 또는 실제 신고 과세가격이 검증된 것은 아니다. 서로 다른 운임·세율 가정의 오차가 상쇄됐을 가능성이 있으므로 합계 근접만으로 개별 입력의 정확성을 인증하지 않는다.
