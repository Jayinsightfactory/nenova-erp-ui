# 국가별 발주서 단위 기준·저장수량 확인

| 항목 | 내용 |
|---|---|
| 기간 | 2026-10-15 |
| 화면 | 수입부 업무도구 / 국가별 발주서 |
| 원장 부작용 | SELECT 및 화면 표시만 변경. 모든 ERP 원장 보존 |
| 배포 | 검증 후 별도 배포 결과 기록 |

## 고정 결정

- 현재 품목관리 환산기준과 과거 주문 저장수량을 구분한다.
- 네덜란드 발주서의 원천은 저장 SteamQuantity다. 단 120을 임의로 송이 120으로 바꾸지 않는다.
- 품목 기준은 표시 전용이며 기존 주문·출고·재고·견적·매출을 수정하지 않는다.

### 1. 품목 옆 단/송이 기준과 오류 설명

**Q.** 품목관리 단/송이 기준을 표시하고, Eryngium Orion Blue 70cm의 송이 수량 오류 원인을 확인해 달라.

**A.** 현재 품목 설정은 송이, 환산계수는 모두 0이지만 2026/42-01 주문은 단 120·송이 0·기본수량 0이다. 실제 EXE FormProductAdd는 출고단위 변경 시 기존 수량을 자동 변환하지 않는다고 경고한다. 현재 설정만으로 과거 수량을 추정하지 않는다. 화면에 품목관리 기준, 발주서 단위, 저장수량 및 업체별 펼침을 추가했다.

### 2. 어느 업체가 120단인지

**Q.** 어디 업체가 120단으로 주문을 입력했는지 확인해 달라.

**A.** 주광농원(YCL2, CustKey 533), OrderDetailKey 86197이다. OrderHistory 신규 기록은 2026-10-15 09:03:42.980, nenovass4(김도준). 이력의 주문수량 값은 0이며 단 120을 직접 입력했는지 업로드가 단 필드에 기록했는지까지는 입증하지 못한다. 업체 담당자 필드와 실제 변경 이력 사용자는 구분했다.

### 3. 다운로드와 0 표시

**Q.** 언제 다운로드가 생기는지, 0수량은 화면과 엑셀에서 보이지 않게 해 달라.

**A.** 유효한 국가·차수 조회 후 수량 차단이 없을 때 미리보기 생성하면 다운로드를 제공한다. 수량 0은 화면 빈칸과 엑셀 숫자서식으로 숨기되 원본 숫자·수식·품목행은 유지한다. 오류 진단의 저장 송이 0은 이유 확인을 위해 유지한다.

## 검증 결과

- 대상 소스/API 테스트 22개 통과. 추가 UI/변환기/adapter 테스트 48개 중 45개 통과, 기존 선택 샘플 3개 생략. 7국가 파일 재개봉으로 0 표시와 숫자·수식 보존 확인.
- test:erp-contract, test:nenova-dnspy-evidence, test:erp-manifest, guard:erp-writes 및 production build 통과.
- 메뉴 기본값: 기존 shell 유지(적용), 페이지 세로 스크롤·표 가로 스크롤 유지(적용), native details 키보드 조작(적용), ERP 저장 전 확인(해당 없음: 쓰기 없음). 실브라우저 검증은 배포 후 기록.

## 미완 / 주의

- 사용자로부터 120의 실제 단위는 아직 확인되지 않았다. 데이터 보정 및 예외 생성은 하지 않았다.
- 임시 `.tmp-unit-*` 진단 파일·로그와 빌드로 생성된 개발이력 JSON은 커밋하지 않는다.
