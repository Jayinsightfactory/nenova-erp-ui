## 고정 결정

- DB 수량·단가·환율·확정 revision·보고서 입력값을 고치지 않는다.
- 가격 분모는 재고 표시 단위에 맞는 저장 Box/Bunch/Steam 수량을 사용한다. 과거 EstQuantity는 단위를 입증하지 못한다.
- 기초/기말은 같은 평가 선택기와 과거 정확 환율을 사용한다. 현재 통화마스터 환율을 과거 R로 자동 적용하지 않는다.
- 원본 1~21차의 일치하는 환율만 파일 근거로 보완한다. 18차 9개 원본 충돌은 사용자 최종본 확인 전까지 보류한다.
- 환율/재고 평가 누락은 원가·이익·이익률/합계에 null로 전파한다. 화면 최신화는 GET, 자동 계산캐시 저장도 하지 않는다.
- 기존 판매단가 자동평가 정책 자체나 수기 매출/통관비/조정값을 이번 수정으로 승인·실사값이라고 인증하지 않는다.

### 1. 요청과 결과

Q. DB는 건드리지 말고 웹 박스·단·송이 오류, 기초·기말 평가, 환율 누락을 엑셀 기준으로 수정하고 1~41차 검증·배포.

A. 실제 EXE dnSpy와 SELECT로 판매 수량 단위 결함을 재확인했다. 읽기 전용 41차 전수 계산 후 독립 산술 15,058항목 불일치 0, 비교 가능한 전차수 기말/다음 기초 불연속 0. 원본 1~31차는 별도 대조했고 32~41 원본은 없어 숫자 일치 인증을 하지 않는다. 원본 숫자와 SQL의 매출/통관비/조정/재고 차이는 여전히 별개다.

결과. 원본 26파일 SHA256 일치. 1~21차 202개 환율 원천 추가(18차 충돌 제외). 12~14차 콜롬비아 장미의 품목 단가 누락과 18차 원본 환율 충돌은 계산 보류. 수량·수기·확정본 보존.

## 검증/후속

- 운영 SELECT 전후 source/policy 지문 동일. 원자적 DB snapshot이 아니라 관측 구간 불변 검증이다.
- 실수치/SQL 응답·차수별 전후 JSON은 `.verify/`에만 보관하고 공개 Git에 넣지 않는다.
- 최초 기록 시 full ERP test 및 최종 검증/PR/CI/배포 진행 중. 이후 기록에서 성공 여부 확인.
- 18차 원본 선택, 12~14차 장미 누락 원가 근거는 자동 추정하지 않는다.
- 검색어: profit-unit-valuation EstQuantity Box Bunch Steam 환율충돌 계산보류 DB불변
