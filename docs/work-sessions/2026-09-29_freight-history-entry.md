## 고정 결정

- 같은 연도·업체의 최근 8개 부모차수 GET을 재사용. 선택 부모차수보다 이전인
  최신 이력부터 표시하고 범위 내 이전 차수 선택 가능. 현재 차수는 제외한다.
- 이력이 없으면 조회 범위를 명시하고 수기 입력은 허용한다. 조회 실패는 계속 차단한다.
- 이전 박스수·단가·저장 금액(Amount+Vat)을 표시만 하며 과거 수량 자동 복사 없음.
- 수량/단가 직접 입력은 해당 행만 자동 선택. 명시 0/빈칸을 추천값으로 덮지 않는다.
- 별도 사전 확인 체크박스 대신 상단 입력 적용 → 기존 서버 미리보기 → 최종 확인.
- 미선택 행은 보존. 기존 운임은 최종값이며 중복 덧셈 없음. ERP 저장 경로 변경 없음.

## 부작용 및 기준

| 동작 | 주문·출고·날짜 | 재고 | Estimate/WebProfitReport |
|---|---|---|---|
| 이전 차수 조회/직접 입력 | 보존 | 보존 | 보존 |
| 입력 적용 미리보기/확인 취소 | 기존 읽기 전용 prepare | 보존 | 보존 |
| 최종 확인 후 저장 | 기존 원자적 최종값 계약 | 기존 순증감+재계산 | 직접 쓰기 없음 |

기준 원천은 ClassShipmentDate 실제 CLI, 운영 SELECT, 기존 freight-register 및
amountVatFromCostEst다. 저장 업무키/잠금/날짜/확정/재고/UUID/금액 검증은 유지한다.
총액은 과거 저장값 우선이며 새 입력은 EXE 정수 견적수량 반올림 공식을 사용한다.
입력 중 자동 POST 없음. 이력 로딩 및 저장 중에는 입력 필드를 잠근다.

### 1. 이전차수 비용 표시 및 박스수·금액 입력 적용

**Q.** 해당 업체 이전 차수 비용을 보면서 박스수량·금액을 입력해 적용하고 싶다.

**A.** 상단 이전 운임 표/차수 선택, 입력 행 자동 선택/합계, 입력 적용 버튼을 구현.
금액 필드는 기존 합의대로 박스당 단가(부가세 포함), 총액은 자동 계산한다.
다른 업체·교차연도·현재/미래 차수·차감·중복 날짜를 이력 합계에서 제외한다.

**검증.** 운임 23개 실행형 테스트 통과. 필수 ERP 계약, dnSpy 근거, manifest,
변경 쓰기 가드, production build 통과. 격리 localhost SQL fixture에서 기존 31→61,
기존 날짜·주문 보존, 신규 양수 주문/분배, 중간행/native 실패 전체 롤백, UUID 재시도,
다른 업체/전년도 보존, stale preview 차단 통과. 시험 DB는 script가 생성·정리했다.
운영 DB는 SELECT만 수행했다.

**UI.** 실제 컴포넌트 + 로컬 mock API로 1920×1080 및 390×844 확인:
가로 잘림/화면 이탈 없음, 상단 적용 버튼 접근, 61×3000=183000, 자동 선택,
0원 오류 및 저장 요청 0건, 업체 변경 초기화, 이전 이력 없음/조회 실패 차단 확인.
native confirm 자동화는 브라우저 제어 타임아웃으로 완료하지 못했으며 확인 승인·취소와
중복 POST 방지는 실행형 client 테스트로 별도 검증했다. 실제 운영 운임 등록 안 함.
