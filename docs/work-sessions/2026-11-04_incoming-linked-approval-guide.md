## 고정 요구사항

- 원가 연결 입고의 품목·수량 변경, 확정 손익 정정, 기존 농장배정 수량 변경까지 수정요청→영업지원 매칭→확정으로 처리한다. 기존 차단을 그대로 둔 채 완료로 보고하지 않는다.
- 요청·매칭 단계에서는 ERP 업무 원장에 확정 변경을 남기지 않는다. 최종 확정은 관련 원장·정정 버전·감사를 한 트랜잭션으로 저장한다.
- 농장만 변경할 때 수량·금액·확정 상태를 보존한다. 품목 이동과 감소만 처리하는 경우를 구분한다.
- 41차 변경은 영향 있는 후속 차수·연도 재고와 보고서까지 검증한다. 이전 연도 동일 차수는 보존한다.
- 사용 가이드 영상은 실제 완성 화면, 1920×1080/100%, 한국어 설명·자막·작업 포인터로 제작한다. 수입부와 영업지원용으로 나누고 농장·품목·수량 수정 절차를 포함한다. 교육 자료를 운영 데이터 수정으로 만들지 않는다.
- 새 메뉴·탭 개발에서 가이드 영상 제작·화면 연결을 기본 완료 조건으로 기록하고 검사한다. 기능이 없는데 자동 생성된다고 약속하지 않는다.

## 질문과 답변

### 1. 연결 원장 지원과 영상 요청

**Q.** 차단된 원가 수량 변경·확정 손익·기존 농장분배 변경도 dnSpy와 기존 로직을 확인해 구현·테스트·배포하고, 수입부/영업지원 가이드를 제작.

**A.** 신규 작업트리에서 실제 EXE 재추출과 운영 SELECT-only를 시작했다. WarehouseDetail 물리키 삭제·재생성은 원가 연결을 깨뜨리므로 키 보존/명시 매핑이 필요하다. 기존 확정본은 덮어쓰지 않고 새 정정본과 감사 연결을 검증한다. 아직 구현 완료 아님.

### 2. 모델과 역할

**Q.** 하위 세션으로 작업을 분류하고 기획·설계만 Astra 사용.

**A.** Astra 설계 에이전트를 별도로 시작했고, 근거·검증 및 영상 인프라 작업을 분리했다.

### 3. 향후 메뉴 기본값

**Q.** 새 탭·메뉴 작업 시 가이드 영상을 기본 생성·추가.

**A.** AGENTS, 메뉴 개발 기본값과 JSON, 체크리스트, 공용 플레이어·가이드 등록부·파일 검증에 연결한다. 기존 전체 메뉴의 일괄 재제작은 이번 범위가 아니다.

## 조사 근거

- 실제 dnSpy ClassWarehouseDetail.Update는 WdetailKey 기준 UPDATE를 지원한다.
- ClassShipmentFarm은 FarmKey/ShipmentQuantity/SdetailKey를 저장하며 입고번호 연결이 없다. 입고 농장으로 자동 배정하지 않는다.
- 읽기 전용 원가 연결 표본: 입고7671(2026/42-01),7662(41-02),7345(38-01); LINK_EXISTING_COST 문서 다중행 집계 연결. 확정 손익 운영 표본0이므로 격리 fixture로 검사 예정.
- 농장명 변경도 invoiceReceiptCost의 receiptHeaderMatches에 영향을 준다. 단순 상태 변경이나 과거 snapshot 덮어쓰기로 해결하지 않는다.
- `.verify/` 조사·합성 테스트 자료만 로컬 보존, 비밀정보/운영 개인자료는 커밋하지 않는다.

### 4. 2026-11-05 — 통합 구현 검증과 재개

**Q.** 이어서.

**A.** 원가·농장배정이 있는 입고를 80→70으로 바꾸는 실제 전체 승인 writer 테스트를 통과했다. 미리보기 전체 rollback, 금융 해시 불일치, 마지막 승인 감사 실패에서 입고·분배·농장·native 재고·원가·요청 상태 전체 rollback을 확인했다. 기존 WdetailKey와 과거 원가 이력 보존, 활성 원가 유일성, 확정 재시도도 검증했다. 손익 실제 loader 테스트는 41/44/2027 범위와 2025 보존, 이전 상세 불변·새 확정본/계산본·강제실패 rollback 통과.

**추가 발견.** 기존 손익 loader가 승인 인보이스 원가를 직접 소비하지 않는 경로가 있어 보완 중이다. 기존 카테고리 평균식을 바꾸거나 원가를 이중 합산하지 않고 기존 arrivalInvoiceSource 검증·우선순위와 의존 해시로 연결한다. 이 검증 전에는 배포하지 않는다.

**검증 현황.** 초기 webpack build PASS; dnSpy·manifest·write guard PASS. 최신 master 5994f975 병합, WORK_MEMORY 양쪽 보존·package 양쪽 테스트 보존. 최종 ERP suite와 UI build 재실행 중. 운영 DB 수정 없음. 가이드는 실제 UI 합성 연습자료만 녹화한다.


### 5. 2026-11-05 — 원가 원천·재배분·부족재고 기준

승인 인보이스 원가를 기존 arrivalInvoiceSource 검증과 Excel 대체 범위로 보고서에 연결했다. 요청별 memo는 종료 시 폐기하며 동일 승인 단계 안에서만 재사용한다. 실제 loader의 잔여20단에 단가2000→2200 변경 시 기말40000→44000 반영 PASS. 기존 평균평가가 우선이면 손익금액이 그대로일 수 있음을 화면에 명시했다. 일부입고 원가의 전체확장 방지, 이월, invoice-only 스키마, 빈 의존관계 기존hash보존 검증을 포함한다.

농장-only는 출고 총수량·경제원장을 보존하면서 명시 농장별 재배분을 허용한다. 개별농장수량 multiset 불변 제한은 제거했다. 전후 농장표를 최종 확인에 추가했다.

AGENTS의 명시 부족재고 조정 규칙을 승인 흐름에 연결한다. 부족발생 차수에 최소증분만 제안하며 44부족을41로 임의당겨 과거재고를 부풀리지 않는다. native rehearsal에서 실제 부족을 읽고 전체 rollback 후 표시, 영업지원의 품목·차수·수량 동의를 저장한 뒤 최종승인에서 동일근거를 재검증한다. 재고조정/재계산/원가손익/승인감사는 한 transaction이다. 현재고만 부족하고 기간근거가 없으면 임의귀속하지 않는다.

로컬 병렬빌드와 테스트가 메모리를 소진해 검증프로세스가 종료된 실행은 실패로 보존했다. 해당 작업의 PID tree만 종료했고 다른 세션 프로세스는 유지했다. 전체suite는 작업프로세스 CPU affinity2/Nodeheap1024, 빌드는 NENOVA_BUILD_WORKERS=1로 다시 실행한다. 별도의 손익SQL timeout은 fixture rollback 전에 별도 pool로 읽은 자체잠금으로 확인·수정했고 최종 실SQL PASS했다. 실패를 제품성공으로 간주하지 않았다.
