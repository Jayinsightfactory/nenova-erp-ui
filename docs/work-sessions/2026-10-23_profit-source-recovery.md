## 이어받을 때 고정된 결정

- 기존 국가별 평균 도착원가 정책을 유지한다. 새 값을 만들기 위해 DB를 보정하지 않는다.
- missing은 SQL 미존재, 부분 근거, 분류 실패, 조회 실패와 구별해야 한다.
- 일부 입고의 환율을 차수·국가 전체 환율로 확대하지 않는다. 현재 환율·미래 입고·다른 샘플을 대신 사용하지 않는다.
- 재고가 0이 된 이전 입고 비율이 새 재고를 계속 막지 않도록, 같은 연도/품목의 실제 활성 입고분을 대사한다.
- 혼합 크기 박스는 전량 잔존이 증명될 때만 실제 송이 합계를 사용한다. 부분 소진된 lot는 임의 FIFO/최신 비율로 추정하지 않는다.
- 사용자 소액 수기 오차 허용은 익명 숫자행의 GW/CW 유형을 추정하거나 근거 없는 금액을 생성하는 허용이 아니다.

### 1. SQL에 있는데 웹에서 못 읽는 비용·환율 확인

**Q.** DB를 건드리지 말고 남은 차수의 통관비·운송비·환율 연결 누락을 고치고, 실제 입고 근거로 환산 충돌을 검증·배포해 달라.

**A.** 실제 EXE dnSpy와 SQL SELECT를 확인했다. 40차 태국은 EXCEL 비용전표의 운임 483.70+157.05=640.75 USD가 있는데 분류 문자열의 시작 위치 검사 때문에 태국 연결이 누락됐다. 18차는 일부 입고의 FreightCost 환율 1550만 있으므로 전체 범위로 확대할 수 없다. 35차 네덜란드는 현재 조사한 운임 원천이 없고, 39차 태국의 무명 숫자행은 GW/CW 구분을 입증할 수 없다.

**결과.** 세부 SQL 원천 상태 및 수정 범위: [비용 계획](../plans/profit-cost-source-recovery-2026-10-23.md). 현재 구현·검증 중.

추가 확인: 4차 콜롬비아 수국 비용전표의 InvoiceNo가 같은04-01 실제 꽃 입고의 AWB와 정확히 일치한다. 기본 AWB/명시국가/자기 전표 문맥과 충돌하지 않는 경우에만 보조 연결해 운임7,938.70 USD를 복구했다. 인식된 운임 원천의 1~41차 전후 비교에서 원천 행 수·합계는 전부 동일하고 분류 변화는 이 건과40차 태국뿐이다. 40차 태국은 GW225kg/CW345.5kg 이름 있는 실제 행이 있으므로 운임 복구 후 기존 승인 통관비 **추정** 계산도 가능해진다. 이를 저장된 실비라고 표시하지 않는다.

### 2. 환산 충돌은 실제 잔존 입고분으로 확인

**A.** 네덜란드 Prod1959의 9차 불일치는 조정과 물리수량의 관계가 불명확해 보류한다. 재고0 이후 정상 입고만 남은 29차는 5단=50송이, 31차는10단=100송이로 대사된다. 에콰도르 Prod3227은 마지막 재고0 이후150송이1박스+250송이1박스가 출고 없이 남아33~35차2박스=400송이이다.

**결과.** [환산 계획](../plans/profit-source-recovery-2026-10-23.md). DB 수량 자체는 바꾸지 않고 보고서 정규화 수량에만 적용한다.

## 검증·배포 기록

- 관련 회귀와 전체 ERP gate/build(3e6846b7) PASS. 최신12abb7a0 통합 후 `npm run verify:erp-change` 재실행도 PASS(종료0). manifest160개·dnSpy·쓰기 스코프 검사·build 포함. 최초 계약의 필수 guard 명령 누락을 보완하고 전체 재실행했다.
