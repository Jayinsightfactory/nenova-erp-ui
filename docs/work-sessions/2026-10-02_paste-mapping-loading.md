## 고정 결정
- 현황의 품목/거래처 탭에서 별칭 추가 → 대상 검색 → 선택한 매칭 저장.
- 성공 확인 이전 브라우저 캐시 업데이트 금지. 등록 성공 뒤 학습도 서버 성공 확인.
- 실패 재시도는 별칭만, ERP 재등록 금지. 모달 변경은 이전 실패 재시도보다 우선.
- fresh 서버 exact manual alias만 저장 분석 교정. matchName의 헤더 국가·품종·규격까지 검사.
- 등록분배하기는 검토 진입이며 즉시 원장 저장이 아니다.
- 원문30초, 전산이력/상태60초. 새 자료/작업 직후 갱신·영구 사전분석 유지.

### 1. 매칭 추가 없음·저장 누락·페이지 지연
**Q.** 매칭현황 신규 추가가 없고 학습이 저장되지 않는 것 같음. 버튼을 등록분배하기로 변경하고 지연 원인 확인.

**A.** 추가 UI 부재, 매칭POST 실패 무시, 전체 일괄 학습 누락, 삭제된 별칭의 로컬 재유입,
저장 분석의 과거 reviewed 선택 유지, 짧은 주기 중복 읽기를 확인·보완했다.
운영 SELECT 표본69ms는 전체 부하 측정이 아니다. 실제 운영 CPU/SQL wait 수치는 미측정.

**검증.** 실제 dnSpy FormOrderAdd와 교차연도 read-only DB 확인. 1차 전체 ERP 계약/build 통과.
로컬 실제 모달 fixture에서1920×1080 품목/업체 추가, 부모 갱신, 재로드 유지,500 오류표시 확인.
820×900에서도 입력/저장 버튼 접근 확인. 운영 테스트 주문·별칭을 만들지 않았다.
