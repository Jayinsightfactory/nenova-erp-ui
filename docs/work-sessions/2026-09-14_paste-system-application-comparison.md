# 붙여넣기 전산 적용 자동 대조 범위 보완

| 항목 | 내용 |
|---|---|
| 기간 | 2026-09-14 |
| 화면 | `/orders/paste` 영업방 원문·최신 전산 이력 |
| 원장 부작용 | 없음. `OrderHistory`, `ShipmentHistory`, 현재 분배·재고를 읽기만 함 |
| 핵심 원인 | 화면은 87건을 표시했지만 자동 대조는 50건 한 페이지만 수행했고, AI 매칭 결과는 목록 대조에 되돌아가지 않았으며, 일부 품목은 입력 단위와 전산 OutUnit 사이 환산계수가 0이었음 |

## 질문과 답변

**Q.** 전산 수정 적용이 있는 원문도 `미확인 0/N 자동 대조`로 남는다.

**A.** 운영 화면에서 동일 증상을 재현했다. 해당 원문은 87건 중 50건 자동 대조 범위 밖이었으며, 이전 50건으로 옮긴 뒤에도 원문 별칭만으로 업체·품목을 확정하지 못했다. 목록과 조회 범위가 달랐고, AI가 찾은 전산명도 목록 자동 대조에 연결되지 않은 것이 원인이다.

## 고정한 동작

- 최신 원문 최대 200건을 한 요청에서 전역 대조한다. 서로 다른 메시지가 같은 전산 이력을 중복으로 차지하지 못하도록 페이지별로 나누지 않는다.
- 200건을 넘는 과거 원문은 `미확인`이 아니라 `대조 범위 밖`으로 표시하고 날짜 범위를 좁히도록 안내한다.
- 영업방의 단일 원문을 AI 분석한 뒤 업체·품목·수량 매칭이 모두 완성되면, 같은 `sourceIdentity`의 목록 자동 대조에도 그 전산명을 재사용한다.
- `라움 → 주식회사 트라움에스앤씨 (라움)`, `미우 → 아이엠（미우）`처럼 전산 업체명의 괄호 안 명칭이 유일하게 정확히 같은 경우는 업체를 자동 확정한다. 느슨한 부분 문자열은 허용하지 않는다.
- 원문 identity, 작성 시각, 연도·차수는 바꾸지 않는다. 불완전한 AI 매칭은 원문으로 되돌린다.
- 자동 대조는 읽기 전용이다. 주문·분배·재고·별칭을 생성하거나 수정하지 않는다.
- 품목 환산계수가 0인 경우에도 같은 연도·차수·업체·품목·방향·숫자의 전산 이력이 유일하면 `단위 미확정 · 이력 후보`로 전후 수량을 표시한다. 단위 환산 근거가 없으므로 자동 `매칭`이나 적용 완료로 판정하지 않는다.

## 부작용 및 근접 실패 기준

| 경우 | 결과 |
|---|---|
| 하루 원문 87건 | 87건을 한 번에 대조 |
| 원문 200건 | 허용 |
| 원문 201건 | API가 조용히 자르지 않고 거부; 화면은 최신 200건만 보내고 나머지를 범위 밖으로 표시 |
| 같은 전산 이력 후보가 여러 원문에 겹침 | 한 전역 배치에서 경쟁하며 모호성 유지 |
| AI 분석 identity가 다른 원문 | 목록 대조에 투영하지 않음 |
| 업체·품목 중 하나라도 미확정 | AI 보정값을 사용하지 않고 원문 기준 유지 |
| 전년도 동일 차수 | 기존 교차연도 차단 유지 |
| 입력 20단, 전산 변경 20송이, 환산계수 없음 | 노란색 `이력 후보`와 실제 이력 표시; 적용 확정 아님 |
| 입력 20단, 전산 변경 200송이, 환산계수 없음 | 숫자가 다르므로 후보로 표시하지 않음 |
