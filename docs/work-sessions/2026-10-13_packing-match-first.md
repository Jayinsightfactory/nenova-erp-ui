## 이어받을 때 고정된 결정
- 업로드 분석 직후 DB 매칭 미리보기를 먼저 표시한다. 미매칭·유사 매칭·원문 이슈 기본 필터와 전체 보기를 제공한다.
- 원본 PDF는 담당자가 명시적으로 열며, 검산 근거가 없는 행만 수동 확인한다.
- 기계 검산과 사람이 확인한 기록은 별개다. 형식명/AI confidence만으로 기계 검산 완료를 만들지 않는다.
- 공유 매칭 수정·재조회 후 이전 변환 결과를 계속 다운로드하지 않는다.
- 미리보기는 입고 완료가 아니다. 기존 최종 검증과 명시 저장 계약을 유지한다.
- CW 누락 시 모든 입고를 막는 새로운 서버 정책은 추가하지 않는다. 기존 입고의 명시적 원가검토 대기(`allowPendingCost`)와 원가 계산의 국가별 필수값 검증은 별도 계약이다. 이번 화면 수정으로 그 범위를 바꾸지 않는다.
- 누락 단가를 0으로 처리하지 않는다. 이번 테스트에서는 유료 AI/운영 입고·재고 저장을 하지 않는다.

### 1. 업로드하면 매칭·미매칭이 먼저 나와야 한다
**Q.** 원본 PDF 검증창이 먼저 뜨는데 매칭·미매칭이 먼저 떠야 하지 않나? → 맞아/ㅇㅇ.

**A.** 기존 변환 생성이 날짜·단가 검토와 결합되어 미확인 값이 있으면 표가 숨겨지고 PDF 창이 먼저 열렸다. 읽기 전용 매칭 미리보기를 별도 상태로 분리하고, 최종 생성·입고 연결은 검토 후로 유지한다.

**결과.** `docs/plans/packing-match-first.md`, `lib/importPackingMatchPreview.js`, PackingListTool/Results/EvidenceReview 및 원문 검증 계약 수정.

### 2. 실제 PDF 확인 범위
**Q.** 41-1 중국 해상 파일이 정상적으로 처리되어야 한다.

**A.** 실제 7쪽 PDF의 101개 행과 박스429/단5390/송이68775를 재확인했다. 엄격한 로컬 검산이 가능한99행과 단가 누락1행·박스 번호 경고1행을 구분한다. 단가 미확인을 그대로 남긴다.

**검증 중간 결과.** 1920×1080/100%,1280×800에서 표 먼저 표시·모달 자동 열기 없음·명시 PDF 검토2행·7쪽 렌더 확인. `outputs/packing-match-first/`는 비공개 검사 결과이며 커밋하지 않는다.

## 역할과 검증 상태
- 설계/최종 검토: 고성능 검토 작업 Banach. 구현: Locke 및 Mill. 외부 쓰기/배포는 메인만 수행.
- 사용 가능한 대체 모델을 재사용했으며, 구조·ERP 부작용 판정은 메인/고성능 검토자가 담당한다.
- 단위 테스트, 전체 ERP 계약, 빌드와 배포 후 운영 smoke가 모두 끝나기 전 배포 완료로 보고하지 않는다.
