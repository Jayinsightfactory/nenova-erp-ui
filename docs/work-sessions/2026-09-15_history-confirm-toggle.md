## 고정 결정

- 목록에 확인처리/확인취소 토글을 노출한다. 상세를 펼칠 필요가 없다.
- 수동 확인과 실제 등록·분배 성공은 표시 문구로 구분한다.
- 확인취소는 웹 확인 표시만 취소하며 ERP 작업을 되돌리지 않는다.
- 분석·매칭만으로는 자동 확인하지 않는다. 같은 연도·차수·원문의 완전한 committed 로그만 사용한다.
- 실패/사전검증/부분 저장/되돌리기/불완전 로그는 자동 확인하지 않는다.
- 이후 수동 취소는 유지하지만, 더 나중의 성공한 작업은 다시 자동 확인한다.

### 1. 확인처리 요청

**Q.** 미확인이 많으니 확인처리 버튼을 만들고 다시 누르면 취소되게 해달라. 분석매칭으로 작업을 끝내면 자동 확인되는가?

**A.** 기존 서버의 수동 표시 원장을 재사용해 목록 토글·강조·실패 알림을 연결했다.
작업결과 변경/작업 종료 시 기존 적용 로그를 다시 읽도록 연결했다. 자동 polling을 꺼도 재조회한다.

**검증 기준.** 교차연도·부분 저장·실패·undo·수동 취소 시간순서 fixture,
기존 API/파일 저장소 CAS 테스트, ERP 필수 검사, 1920×1080 브라우저 토글 검증.

## 남은 별도 과제

품목 별칭·복수 후보로 인한 자동 매칭 미확인과 영업방 8초 응답 지연은 별도 문제다.
pages/api/orders/parse-paste.js의 기존 사용자 변경은 이 작업에 포함하지 않는다.
