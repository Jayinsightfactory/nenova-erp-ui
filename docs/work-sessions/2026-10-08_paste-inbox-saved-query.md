## 이어받을 때 고정된 결정
- 최신 사용자 지시가 이전 자동 진입/30초 대화/60초 이력 갱신 기본값보다 우선한다.
- 인증된 사용자·연도·전체 차수별로 대화 원문, 조회 기간, pagination, SQL 근거/비교, 수동/웹 처리 표시를 IndexedDB에 저장한다.
- 메뉴 재진입/브라우저 새로고침 시 저장본을 먼저 복원하고, 저장본이 있으면 수신함의 자동 재조회를 시작하지 않는다.
- TTL이나 오래됐다는 이유로 저장본을 폐기하지 않는다. 갱신은 명시 새로고침 또는 실제 새 작업 이후 수행한다. 주기 자동 갱신은 사용자가 현재 화면에서 켠 경우만 사용하고 재진입하면 기본 끔이다.
- 저장된 조회 시각을 표시하며 현재 SQL의 실시간 검증인 것처럼 표시하지 않는다. 기존 등록/분배의 저장 전 최신 검증은 유지한다.
- 브라우저 저장 실패를 알리고 마지막 성공 저장본을 보존한다. 브라우저 저장공간을 삭제하거나 다른 브라우저/기기를 사용하면 별도 조회가 필요하다.

### 1. 메뉴를 열 때마다 재조회되는 문제
**Q.** 한 번 조회하면 저장되어 있어야 하며 메뉴에 들어갈 때마다 새 조회하면 안 된다.

**A.** 기존 수신함은 React 메모리 상태만 유지했고 mount 시 대화·전산 이력·확인 상태를 새로 조회했다. 저장 조회 결과를 복원하는 단계를 추가하고 초기/주기 조회의 시작 조건을 바꾼다. 인증된 사용자 식별자는 붙여넣기 페이지가 이미 검증한 auth/me 응답을 전달하므로 다른 사용자의 로컬 표시와 섞지 않는다.

**근거.** 같은 세션의 EXE FormShipmentDistribution dnSpy와 운영 read-only 대조(정확 일치 55개 항목, 미확인 잔여 0)를 재사용한다. SQL·공유 원장·단위 환산·증거 기준 변경은 없다. 저장본은 조회를 보존하며 주문·분배 실행 권한을 대신하지 않는다.

**검증 완료.** 사용자/교차연도/전체 차수 분리, 손상·버전·저장 실패, 초기 복원과 빠른 이탈/재진입 순서, reload 뒤 원문/전산확인 복원 및 수신함 원격 조회 0회, 명시 갱신 후 저장 교체, 조회 실패 후 기존 저장본 보존을 검사했다. 필수 verify:erp-change와 최종 빌드가 통과했다. Chrome 1920×1080/100%, 1366×768, 1100×768에서 키보드·화면 범위 검사와 실제 reload 복원을 통과했다. 기존 bulkResult 복원 뒤 단순 초안 편집도 재조회 0회이며, 명시 갱신은 정확히 1회였다. 실패 후 마지막 성공 결과 복원도 확인했다.
