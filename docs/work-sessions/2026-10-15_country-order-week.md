## 이어받을 때 고정된 결정

- 서울 오늘에 해당하는 전산 PeriodDay 차수부터 다음 5개까지 총 6개 메인 차수 버튼.
- 실제 존재하는 세부차수만 선택. OrderYear+전체 OrderWeek로 수량 분리.
- 네덜란드 전산 수량은 저장 SteamQuantity. 사용자 확인: 첨부 Excel 수량도 이미 전부 스팀.
- 품명 기반 배수 제거. KCL/HCL/MCL/BCL/YCL 및 CLE/CLR 같은 업체 코드 인식.
- ERP CustKey/ProdKey별로 집계. 같은 코드/품명이 다른 식별자를 합치지 않음.
- 기존 국가별 출력 양식과 업로드 경로 유지. 원장이 불일치하면 추측하지 않고 생성 차단.

### 1. 차수 버튼과 자동조회

**Q.** 국가별 발주서에서 차수를 선택하면 원주문이 자동으로 나타나고 생성할 수 있게 해 달라.

**A.** 인증된 읽기 전용 조회, 실제 전산 달력, 업체별 수량 행렬과 기존 양식 생성 경로를 분리해 구현한다. 당일 실제 차수는 2026/42, 표시 범위는 42~47이다.

### 2. 네덜란드 단위와 업체 코드

**Q.** 네덜란드는 무조건 스팀으로 표시하고 변형된 CL 코드도 읽어야 한다.

**A.** 기존 파서가 CL 시작 코드만 인정하고 튤립 등에 이름 기반 배수를 적용하는 원인을 확인했다. 사용자가 첨부는 이미 스팀이라고 확인해 그대로 사용한다. 실제 첨부 변환/재개봉에서 59품목·15업체·9,220스팀 일치를 확인했다.

### 3. 운영 읽기 검증

**A.** 새 조회 함수로 7개 국가 모두 200 응답 확인. 네덜란드 42-02 64품목·16업체·14,855스팀, 차단 0건. 42-01은 저장 스팀 없는 1품목을 차단한다. 별도 전산 보정은 하지 않는다.

## 검증 및 운영 반영

- API/model 테스트 15개 통과. 최종 변경 대상 54개 테스트 통과, 기존 선택적 실파일 fixture 2개 생략. 전체 `test:erp-contract`, `test:erp-manifest`, `guard:erp-writes`(신규 API 1개 포함), dnSpy gate 및 첫 production build 통과.
- 최종 검토에서 실제 목요일 달력 검사, 미등록 코드 Total 보존, CL 대소문자 동일업체 합산, 호주 중복품명 박스 환산을 보완하고 재현 검사를 통과했다. 남은 P1/P2 없음.
- 운영 조회는 로그인된 Chrome 전용 검증 탭에서 확인 예정. 기준 viewport는 1920×1080 CSS pixel, DPR1이다.
- 설계/최종 검토: gpt-5.6-sol xhigh. 구현: 지정 terra 미제공으로 gpt-6.1-sol medium 사용.
- 원본 자료, `.tmp-country/`, `.tmp-country-probe.cjs`, 인증정보는 커밋하지 않는다.
