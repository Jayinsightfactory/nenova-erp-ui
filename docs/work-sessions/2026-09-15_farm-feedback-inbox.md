## 고정 결정

- 자동감지는 별도 전환 버튼 없이 바로 피드백 필요 목록에 보인다.
- 조회 GET은 연결·상태를 저장하지 않는다. 명시적 이력 저장에서만 연결을 기록한다.
- 같은 원본이 여러 감지 조건에 겹치면 한 묶음으로 표시한다. 서로 다른 기존 이력은 삭제·병합하지 않고 선택하여 기록한다.
- 미확정·농장 미지정 원본도 피드백을 남길 수 있다. 기존 확정 불량률과 수량 단위 기준은 그대로다.
- 새 원본과 재발 의심은 확인 표시다. 자동 완료/외부 농장 발송은 하지 않는다.
- 제외·복원은 사유를 남긴다. 제외 후 새 불량에 이력을 기록하면 다시 활성 상태를 보존한다.

### 1. 자동감지 건을 모두 피드백 대상으로

Q. 자동감지에서 피드백 이슈로 넘기는 버튼 대신, 올라온 건을 모두 피드백 필요 상태로 구성하고 적용.

A. 통합 피드백을 기본 탭으로 만들고, 원본 연결과 기존 이력을 웹 전용 Inbox/InboxSource로 보호한다. 선택 연도와 구성 revision, 대상 이력 버전, 요청 중복 검사를 저장 트랜잭션에서 재확인한다.

## 검증

- 사전 운영 SELECT: 3개 기존 피드백, 누락 원본/중복 anchor 0. 원본436/활성412 그대로. Probe34942295178.
- ERP 전체 계약검사, manifest61개, dnSpy evidence, 변경 SQL guard 통과.
- 가상 브라우저: 신규 농장 미지정 COMMENT 및 최초 REQUEST, 후속 COMMENT, 제외 자료 복원, 기존 이력 유지 확인.
- 1920×1080 CSS pixel/100%, 760×900에서 가로 잘림 없음. 20개 가상 통합 목록 스크롤 확인.
- 독립 검토에서 제외 후 새 원본 저장 시 다시 숨겨지는 문제를 찾아 영속 재활성화와 COMMENT/REQUEST 회귀 검사를 추가.
- 최종 코드 빌드/운영 반영 결과는 후속 기록에 추가한다. 운영 DB에 시험 코멘트·요청·제외 기록은 넣지 않는다.
