# 주광 요일표 상·하단 스크롤 / 잔량 가독성

| 항목 | 내용 |
|---|---|
| 화면 | /estimate/weekday |
| 원장 부작용 | 화면 전용. 주문·분배·출고일·재고·최초기준·인쇄 계산 보존 |
| 검증 기준 | 1920×1080 CSS pixel / 100%, 작은 화면 추가 확인 |
| 배포/PR | 검증 후 기록 |

## 이어받을 때 고정된 결정

- 상·하단 가로 스크롤바와 표의 scrollLeft를 동기화한다.
- 잔량을 주 숫자로 두고 상태·합계·최초 대비 변경·견적 대조를 구분한다.
- 안전 상태(미확인/미확정/초안), 비고 버튼, 견적 대조, 품목 고정·행 강조는 유지한다.
- 숫자 계산 helper, SQL, 저장 payload, 인쇄 양식은 변경하지 않는다.
- 운영 고객 수량을 시험 변경하지 않는다.

### 1. 상·하단 스크롤 및 읽기 어려운 잔량 칸

**Q.** 표 위·아래 모두 좌우 이동 바가 필요하고, 잔량·합계·변경 칸은 보기 어렵다.

**A.** 기존 요일표의 화면 배치와 스크롤 동기화만 수정한다. 계산과 저장 경로를
보존하는 계약을 먼저 고정했다. 가독성과 스크롤은 격리 브라우저 fixture로 검증한다.

**결과.** 검증 및 배포 완료 후 추가 기록.

## 로컬 검증 기록

- ERP 전체 계약 및 weekday distribution 31개: 통과.
- 기능 manifest 77개, 변경 API 쓰기 가드(변경 API 0개), dnSpy 증거 가드: 통과.
- SSR/입력·인쇄 이벤트 회귀: 통과. DOM 없는 테스트 harness의 useEffect만 noop 처리하고 실제 스크롤은 브라우저에서 검증한다.
- production 빌드: 통과.
- 독립 최종 코드 검토: P1/P2 없음. 스크롤 listener/ResizeObserver/RAF 정리 및 계산·기존 핸들러 보존 확인.
- 운영 수량, 최초 기준 및 비고 쓰기: 실행하지 않음.
- 브라우저 fixture: exit 0, 28개 검증 통과. 50행, 상/하단/표 스크롤·차수 이동·검색·크기 변경 동기화, 200px 잔량 열·14px 주 숫자·12px 보조, 알스트로·긴 소수값·초안·견적 불일치·비고창·행 강조 확인.
- 1920×1080 및 1280×800 가로 페이지 이탈 없음. 스크롤바 색상 손잡이와 sticky 하단 접근 확인. Playwright의 자동 숨김 옵션을 해제해 실제 손잡이를 시각 검사했다.
- 기존 저장/응답 불명 복구/요일별 인쇄 브라우저 회귀: 통과. 전부 로컬 API 격리 자료이며 운영 원장 쓰기 없음.
- 브라우저 page error/외부 요청 0. 개발 HMR handshake 경고만 별도 분리했으며 UI 오류로 숨기지 않았다.
