## 고정 결정

- 매칭 후보의 전체 범위·기존 공통 점수·사용량 정렬은 바꾸지 않는다.
- 현황40그룹씩 보기, 검색은 모든 별칭을 대상으로 한다.
- 입력 도중 전체 부모 주문 화면을 다시 그리지 않고 검색 계산을 Worker로 분리한다.
- 이전 검색 결과는 숨기고 늦은 응답·카탈로그 교체·닫힘을 검증한다. 모듈 실패/15초 지연은 오류로 안내한다.
- 원문은 모두 유지하고 상세 이력만 펼칠 때 만든다. 분석 영구 저장과 실제 적용 증거는 보존한다.

### 1. 매칭현황도 심하게 느림

**Q.** 매칭현황과 품목 매칭에서 렉이 심하다.

**A.** 조회 주기 조정만으로 완료하지 않고 검색 CPU와 렌더링을 별도 점검했다. 3284개 합성 품목 랭킹은 수십~수백ms 동기 연산이며 이를 입력 스레드에서 분리했다. 172원문 actual-component fixture에서 DOM8297→4169로 줄었고 전체 원문과 펼친 동작은 유지됐다. 초기 빈 화면은 랭킹 미실행이므로 운영 초기 정지의 단독 원인이라고 주장하지 않는다.

**근거.** docs/plans/paste-matching-performance-2026-10-02.md. 로컬 dnSpy FormOrderAdd 재조회, 읽기전용 DB probe50ms/활성3284개. 운영 데이터 시험 저장 없음.

**검증.** ERP 계약 전체, dnSpy, manifest77개, 쓰기 가드0개 변경API, Next production build 통과. 검색 Worker 동일 결과·fallback·오류, hook 늦은 응답·해제·카탈로그 변경, 상세 lazy 렌더 fixture 포함.

## 이어서 볼 사항

배포 후 운영 확인 결과와 실제 초기 정지 재현 여부는 최종 응답/PR에 기록한다. 자동브라우저 CDP 응답 실패는 서버 원인으로 단정하지 않는다.

`.tmp/`의 benchmark/fixture/probe/로그는 커밋하지 않는다. 인증정보 없음.
