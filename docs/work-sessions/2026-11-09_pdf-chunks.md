# 2026-11-09 콜롬비아 PDF 분할 분석

## 사용자 요청과 사실
- 46-1 콜카장 CI 원본의 추가 승인된 AI 1회도 약 600초 뒤 실패했다. 기존 streaming 배포만으로 해결되지 않았다.
- 사용자: 제안한 분할·보관·검증 방식에 맞게 수정.
- 추가 유료 분석 승인은 이번 작업에서 사용하지 않는다. 운영 입고/재고/원가 DB 쓰기 없음.

## 구현
- CO 원본 PDF를 최대 3쪽·24구간으로 실제 분리한다. 송장 경계를 가로지른 결과는 정확 supplier+invoice+currency로만 합치며 불명확하면 차단한다. 텍스트 기반 농장 경계 감지가 완료됐다고 주장하지 않는다.
- 원본 페이지 매핑, strict JSON/end_turn/구간 페이지 대조, 송장 상품+부대비=인쇄총액, manifest 송장 목록 대조.
- 완료 구간을 기존 사용자 격리 job 저널에 token/OS mutex로 보존한다. 명시 실패 작업 재시도만 성공 구간을 상속하며 통신 실패 자동 재호출은 없다.
- 전체 대조가 실패한 결과는 무효화한다. 미검증 값을 무한히 재사용하지 않는다. 따라서 전체 대조 실패는 구간 통신 실패와 달리 관련 분석 재확인이 필요하다.
- 분할 호출당 기존 quota. CO는 반복 Docling 대기를 거치지 않는다. 다른 국가 경로/입고 writer는 변경하지 않는다.
- 기존 분석 상태에서 구간 진행 표시, 구간 수에 따라 polling 기간을 제한 연장한다.

## 검증
- 표적 테스트 34개 PASS: 실제 생성 PDF 분리/크기, strict 응답, 원본 페이지 복원, 이어진 송장 합계, 실패 후 성공 구간 재사용, 사용자 격리/stale token, 실제 API 핸들러의 mock provider 통합, 농장명만 있는 manifest.
- 이는 실제 46-1 원본 AI 성공을 뜻하지 않는다. 실제 유료 재분석은 미실행.
- 정식 `npm run test:erp-contract` exit0, dnSpy/manifest201/writeguard/workflow-guides PASS, `NENOVA_BUILD_WORKERS=1 npm run build` exit0. CI/배포는 진행 중. 완료 근거는 후속 기록으로 구분한다.
