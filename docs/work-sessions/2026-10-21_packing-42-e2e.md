# 42-1 날짜 차단 로그와 격리 입고 검증

## 요청 / 안전 경계
42-1 원본 업로드→매칭→날짜 확인→입고 등록을 테스트 DB에서 검증. 운영 DB 쓰기 금지.
운영 원본·기존 입고 7671 조회만 허용. 로그/팀매칭/입고 POST는 테스트에서 가로채며 운영에 전송하지 않는다.

dnSpy 저장 소스 ExcelLoadingPackingList.cs 재조회: BOX/BUNCH/STEAM 별도, 명시 등록 후 재고 계산.
현재 코드의 ERP writer/SP 변경 없음. 메뉴 기준: 기존 화면/키보드 유지, 상세 오류와 웹 로그 확장 적용.

## 검증 결과
- 실제 42-1 CHINA CI PDF: 원문 64행, 기존 입고 상품 64행/61품목 대조. 동일 송장 OrderCode와 이름·단수·단가를 확인한 연결을 테스트에서만 사용했다. Ammi는 브라우저 후보 선택으로 저장하고 자동 닫힘까지 확인.
- 최초 날짜 사유 누락: 팝업+화면 오류, SystemActionLog REVIEW_BLOCKED 상세 저장 확인. 사유 입력 후 다음 단계 진행.
- 실제 격리 SQL writer: WarehouseDetail 64행, 186박스/2280단/31450송이/57230 CNY. 원문 각 행의 박스·단·송이·단가·금액 일치. 원본 중량을 기존 ERP 송이 필드로 덮지 않음.
- Product.Stock 및 현재 ProductStock=품목별 단수, 전년도 동일차수 재고0 보존. staging/주문/분배 sentinel 보존. 동일 operation 재전송은 같은 결과, 재미리보기 ALREADY_COMMITTED. 로그 eventId 재전송도 1행 유지.
- 기존 DB Mermaid Princess는 Spray Carnation 품명이나 원문 Spray Rose이므로 분류 확인 대상으로 남김. 이번 테스트 연결은 운영 공용 매칭 수정이나 업무 승인 아님.
- 추가 발견: 입고 완료 readback은 성공했으나 요약 WarehouseKey가 undefined. 검증된 operation 키를 표시용 문서에 전달. 재빌드 후 실제 PDF 전체 흐름 재실행 통과, 등록 문서에도 91001 표시 및 undefined 부재 확인.
- 전체 ERP 계약검사·dnSpy·쓰기 가드·빌드 통과. 배포는 아직 미완료. 원가 계산은 이번 요청 범위 밖(PENDING), 운송방식/CW 등 필수 원가값을 임의 입력하지 않았다.
- 임시 원본/증거 JSON/스크린샷은 커밋 금지.
- PR #1214. 배포 후 확인 결과는 후속 기록한다.
