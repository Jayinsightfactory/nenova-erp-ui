# 견적 운임 추가 — 기존 품목추가 흐름 연결

## 사용자 합의
- 운임비 추가에서 품목별 수량과 박스 환산을 눈으로 확인한다.
- 필요한 운임 행·수량·단가를 확인하고 기존 추가 품목의 확정해제→주문/분배→재확정 흐름을 사용한다.
- 운임의 원래 세부차수를 사용한다. 1차 운임을 2차에 강제 저장하지 않는다.
- 수정 이후 필수 검증과 배포까지 진행한다.

## 확인한 근거
- 2026-09-21 로그인된 운영 견적서에서 2026 37차 (주)영남꽃소재 조회: 37-01/37-02 확정, 현지상차운임 43박스×2,000원, 수국 21·카네이션 11·장미 4·중국 3·태국 3·루스커스 1박스 운송료 각 1,500원. 읽기만 수행.
- 로컬 dnSpy decompile `C:/Users/USER/nenova-decompiled/Nenova/FormShipmentDistribution.cs` btnSave_Click 1174행 이후: ShipmentDetail의 환산필드 및 ShipmentDate 저장, 원래 선택 연도·차수·출고일, EXE 금액산식 확인.
- 기존 추가 API /api/shipment/adjust는 임의 02차 제한 없음. 프런트 확정 사이클은 02차 고정이었고 context GET도 02차만 허용했음.
- 출고일별 견적 행의 BoxQty는 상세 전체 값으로 반복된다. 운임 계산은 DateShipQty와 OutUnit별 포장수로 해당 날짜만 환산한다. 알 수 없는 포장수는 경고 및 사용자 제외로 처리한다.

## 부작용/기준
| 동작 | 주문 | 분배/출고일 | 확정·재고 | Estimate/손익 |
|---|---|---|---|---|
| 계산/대상 확인 | 조회 | 조회 | 조회 | 보존 |
| 기존 추가 흐름 등록 | 없을 때 양수 생성 | ADD, 날짜 동기화 | 기존 범위 제한 해제/재확정 및 계산 | 직접 쓰기 없음 |
| 구 운임 API | 보존 | 보존(410) | 보존 | 보존 |

- 다른 수정 초안이 있으면 운임 등록 전에 저장/취소하도록 안내한다.
- 운임 context는 명시한 01/02/03차 및 원장에 존재하는 출고일만 허용하며 일반 품목추가의 기본 02차는 유지한다.
- 확정 사이클은 모든 추가 행의 실제 week를 검증해 사용한다.
- 같은 시도에서 저장 성공한 추가 행은 복구/재시도 때 중복 전송하지 않는다. 운임 재실행은 existingSdetailKey 조회로 중복 제외한다.
- force=false 유지. 재고부족을 자동 보정하거나 서비스 품목이라고 검사 우회하지 않는다.

## 검증
- 실행형 fixture: 날짜별 상세 중복계산 방지, 단/송이 구분, 환산 누락, 전년도/다른 차수, 중국 품종 합산, 01/02 등록 차수, 중복/0단가.
- 필수 계약·빌드·배포 결과는 최종 응답에서 실제 결과로 보고한다. 운영 원장을 시험 등록하지 않는다.
