## 이어받을 때 고정된 결정

- 2026/31-01 Apollo의 입고 GW=1420, CW=3342가 정상 비교 근거다. 저장 GW=CW=3342와 혼동하지 않는다.
- 비역사 차수의 유효한 입고 GW/CW **쌍**을 보고서·통관 화면·포워딩 화면에서 공통 사용한다. 부분/역전 원천은 확정 전 오류로 드러낸다.
- GW>CW를 CW로 자동 축소하지 않는다. CW-only/기록된 입고도 누락 진단 대상이다.
- H 창고료는 GW 기준, S는 GW=CW이면 무게 비율, CW>GW이면 CBM 비율. 항공료 총액은 보존한다.
- 실제 수수료·트럭 대수·항공료 override·국가별 명시적 GW0·2026 22~27차 역사 정책·확정 snapshot은 보존한다.
- 도착원가 업로드 부재를 환율 미확정으로 간주하지 않는다. 실제 보고서 과세환율 R의 값/원천으로 판정한다.
- 선택 연도는 필수이고 NULL 연도를 선택 연도로 자동 포함하지 않는다.

### 1. 사용자 요청 — 계산 원천 확인

**Q.** 원가자료 업로드가 없어서 환율 미확정이라는 안내와 GW3342/1420 중 어느 값이 맞는지 묻는 경고가 왜 나오는가?

**A.** 실제 입고와 웹 통관 저장값의 중량 차이가 있었고, 환율 안내는 파일 업로드 유무를 별도로 판단해 실제 과세환율과 불일치할 수 있었다. 입고 GW1420/CW3342를 확인했으며 최초 저장 이력만으로 직접 입력/자동 채움 여부는 단정하지 않았다.

**결과.** 실제 비용을 유지한 31-01 회귀 fixture에서 H 1,885,320→1,001,200원, 차이884,120원. S 총액9026.56 USD는 보존하고 배분만 CBM으로 전환.

**Q.** 주차별 매출이익자료 웹 로직이 수정됐는지, 전체적으로 보완하라.

### 6. 2026-10-07 — MD 연결 정보로 SQL 직접 대조

### 5. 2026-10-07 — 이익률 이상을 기초·기말 원인으로 구분

**Q.** 매출이익 자료에서 이익률이 이상할 때 기초재고 문제인지 기말재고 문제인지 알 수 있어야 한다.

**A.** 목표는 수량 잔차 표시가 아니라 재고 원천·평가금액의 원인 진단이다. 기초는 전차수 기말과의 이월 연결뿐 아니라 전차수 입출고·실제 조정·기말 자체를 검사한다. 기말은 이번 기초+입고−출고+실제 조정과 스냅샷을 대조한다. 수량 차이와 평가단가 차이는 분리하고, 단위·평가근거가 검증된 경우에만 손익 영향금액을 산출한다. 근거가 없는 경우 '정상' 또는 특정 재고 오류로 단정하지 않는다.

**결과.** 로컬 dnSpy CLI로 FormStockView가 StockHistory와 CodeInfo의 StockType을 연결하여 실제 조정 증감을 읽는 것을 확인했다. 독립 설계 검토에서도 기존 분석의 adjustment는 실제 이력이 아닌 잔차임을 재확인했다. 32차 실제 StockHistory·선택 StockKey·품목행 존재·전차수 원천 DB probe가 아직 없어 ERP 사전검증 단계에서 구현·배포를 보류한다. 원장·웹 코드·확정 보고서 변경 없음. 상세 수용 기준은 아래 점검 문서의 마지막 절에 기록한다.

### 3. 2026-10-07 — 이전 차수 실제 조회

**Q.** 그전차수들은 수정하고 나서 다 맞는가? 확인해봐.

**A.** 읽기 전용으로 운영 통관비·포워딩 2026년 22~30차를 조회했다. 22~27 통관 합계는 원본 추출값과 1원 이내 일치. 28은 네덜란드 통관비에서 원본 대비 -92원. 29-02·30-02는 실제 운영 화면에서 입고 GW/CW 원천 확인 경고가 남아 있어 전체 정상 판정 불가다. 본표 수기값·환율·확정본·E/F 전수 대조는 안전한 읽기 경로가 없어 미완이다. 본표 자동 snapshot 저장을 피했고, 운영 저장·코드 수정·배포는 하지 않았다.

**결과.** [차수별 실제 점검 결과와 잔여 조건](../work-reports/2026-10-07_profit-prior-weeks-readonly-audit.md). 이 조사 문서는 로컬 미커밋이다. 기존 배포 결과와 이번 미완 전수 감사 범위를 혼동하지 않는다.

- 배포 후 본표의 근거 있는 수기 H/S override 우선 경로를 추가 확인했다. 자동값과 다르면 경고로 두 값/차이를 표시하되, 원래 근거 확인 없이 수기값을 삭제하지 않는다. 확정본과 역사 차수는 비교하지 않는다.

- 확정 보고서는 자동 수정하지 않는다. 기존 확정본의 변경은 별도 명시적 업무 절차가 필요하다.
- 브라우저 smoke는 1920×1080 CSS pixel/100%에서 수행한다. 운영 저장 버튼은 누르지 않는다. 보고서 조회의 기존 자동 최신화는 미확정 웹 계산 snapshot을 새 버전으로 저장할 수 있으나 ERP 원장과 확정본은 보존한다.
- verify-*.log는 로컬 검증 로그로 커밋하지 않는다. 비밀값과 DB 접속 정보는 기록하지 않는다.
