## 고정된 결정

- 기존 전체 이력의 모든 페이지에 해당하는 기록을 원천으로 쓴다. 첫 페이지나 주요 기록만 가져오지 않는다.
- 기업 연혁 같은 월·날짜 연결 구조, 안내 SVG 캐릭터와 작업 종류별 색상을 제공한다.
- 원본 기록 제목과 근거를 보존한다. 작업 시간·요청 횟수·성과를 추정하지 않는다.
- 기존 전체/메뉴/레거시 화면과 API를 유지한다. 새 탭의 URL만 추가한다.
- KST 날짜별 합계와 상세 결과는 공용 selector를 사용한다. 상세는 50건씩 조회한다.

### 1. 전체 기록 기반 시각화

**Q.** 104페이지 전체 내용을 하나씩 타임라인처럼 정리하고 캐릭터·컴포넌트를 넣어 달라는 요청.

**A.** 월별 개요와 날짜별 기록 목록을 연결하는 읽기 전용 개발 여정을 구현한다. 기존 안전 snapshot, 인증 GET과 필터를 재사용하고, 전체 union 및 KST 경계·하루 105건 fixture를 검증한다. 현재 구조는 사용자 비공개 대화 전체가 아니라 검증된 Git 기록과 안전한 문서 제목 범위다.

**결과.** 설계 승인, helper/API/화면/회귀 테스트 작업. 최종 검증·PR·배포 및 실브라우저 결과는 아래에 추가한다.

## 검증 결과

- 기존 전체 개발 이력 17건: 공용 selector 추출 후 통과.
- 신규 여정 테스트: 별도 테스트 작업에서 9건 통과. 통합 후 다시 실행한다.
- dnSpy evidence guard와 manifest guard: 통과. 웹 전용 metadata 기능으로 SQL probe 해당 없음.
- 초기 ERP 통합 검사 중 신규 테스트 작성 시점이 겹쳐 미완성 UI 검사 실패. 완성 후 전체 재실행 필요.
- Chrome 화면은 실제 80% 확대 상태로 확인되어 사용자에게 100% 변경을 요청했다. 기준 1920×1080 CSS 검증은 아직 미완료다.

## 통합 검토

- 집중 검사 28/28 통과. 실제 생성 원장 5,179건(104쪽 상당)의 모든 날짜를 기존 selector와 대조했고 월/일 합계가 일치한다. 이 숫자는 이후 빌드에 따라 증가한다.
- 하루 최대 131건: 3쪽으로 모두 접근 가능. KST 연말 경계, 중복 출처, 미분류 보존을 검사했다.
- 독립 리뷰에서 동일 월/날짜/초기화 재선택 시 상세를 비워 버리는 문제를 발견·수정했고 회귀 검사를 추가했다.
- 페이지 이동 전에 persistent 상세 영역으로 초점을 이동하도록 수정했다.
- 독립 리뷰 `gpt-5.6-sol` high 승인, 차단 이슈 없음. 구현/테스트 하위 작업은 로컬 범위만 수행했다.
- ERP 계약 전체, UI layout, dnSpy evidence, manifest 92개, 변경 API 1개 쓰기 guard 통과. 최종 초점 수정 후 `npm run build`도 성공했다.
