# 기초재고와 영업방 변경 대조

## 질문

영업방 카카오 변경내역이 저장해 둔 기초재고 기준으로 누락 없이 반영되는지 확인하고, 품목 후보가 복수일 때 선택할 수 있게 한다.

## 확인한 결과

- 라이브 붙여넣기 주문등록은 기본 최근 7일(2026-09-23~2026-09-29)을 조회 중이었다. 최신 3건만 조회하는 설정은 아니었다.
- 2026-09-18 저장된 38-1 시작 잔량 기록은 20줄이었다. 기초재고 품목매칭 패널은 11/13으로 표시했고, `인디 1`은 미매칭, `염색연그린 5`는 복수 후보였다.
- 기존 줄 파서는 행 끝에 수량/단위가 있기를 요구해 괄호 메모가 붙은 `오션송 10단 (티바)`, `나디야 1 (37-2 잔량)`, `벨라스타 1 (37-2 잔량)`을 수량행으로 만들지 못했다.
- `블루 1+15스팀`, `화이트 57+17스팀`의 세부수량이 품목 매칭·잔량 계산 단계에서 빠질 수 있었다.
- 2026-09-29 09:26의 `연핑크 1박스 취소`에는 같은 차수·업체·품목·방향·수량의 전산 분배이력 `1→0박스`가 있었지만 원문은 미확인으로 남아 있었다. 사용자 기준(동일 변경·수량이면 처리)과 자동확인 판정이 불일치한다.
- 같은 원문의 `피치 2박스 추가`는 연결되는 정확한 전산 이력을 찾지 못해 미확인이 타당하나, 조회된 이력 부재는 미처리의 확증은 아니다. 기준 저장본의 피치 42만으로 현재 잔량을 단정할 수도 없다.
- 이 표본은 실제 저장본 한 건 및 최신 카카오 변경 한 건을 연 것으로, 전체 최근 7일의 모든 변경을 행 단위로 검증한 결과가 아니다.

## 변경

- 괄호 주석을 떼고 수량행을 파싱하도록 공통 순수 파서를 추가했다.
- 박스와 스팀/송이/단 등 명시 세부단위를 별도 수량축으로 계산하고, 입력한 단위 표기는 결과에 보존한다.
- 관리품목 후보가 둘 이상이면 점수 차이가 크더라도 자동 연결하지 않는다. 알림과 첫 후보 선택창을 띄우며, 사람의 선택 전에는 계산값을 확정 잔량으로 표시하지 않는다.
- 기초재고 행 누락, 품목 미매칭, 단위 불일치가 있으면 숫자를 만들어 보여주지 않고 선택/확인 필요로 표시한다.
- UI 투영·기초재고 텍스트 읽기·선택은 주문·출고·재고·견적 원장을 바꾸지 않는 범위로 유지했다. 라이브 화면에서 실제 저장/처리/AI 분석은 실행하지 않았다.
