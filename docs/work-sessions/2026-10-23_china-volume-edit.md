- 품목별 주문 대비 인보이스 초과/부족과 미매칭 표시. 원문 보존, 분할 합계 검증.

Q. 차수 조회, 인보이스와 주문의 차이, 품목/업체/지역 편집, 혼합박스 품목 수량 분할과 등록분배.
A. 사용자가 확인한 기능대로 연결. 공란은 명시 0, 이전 품목은 분배 0, 새 품목에는 입력 수량. DB에 기존 주문이 있으면 보존, 신규 양수 조합만 주문 생성.

### 2. 실제 근거와 검증
Q. 기존 주문을 절대 건드리지 않고 테스트·배포까지.
A. 실제 dnSpy FormShipmentDistribution 실행 및 SELECT-only 같은 업무키/전년도/견적/확정매출 대조 후 구현. 계획 문서에 기준선 보관.
- 격리 MSSQL: 기존 주문77 전체 컬럼 불변, 분배60→20→0→12, 신규5단/50송이 환산, 신규 주문도 이후0 취소 시 보존.
- 전년도·입력 밖 같은 품종·다른 셀·Estimate/WebProfitReport/입고/재고 불변. 확정/stale 차단, 두번째 행 실패 전체 롤백. 트리거가 기존 주문을 변조해도 저장 실패·전체 롤백.
- 네덜란드 실제 SQL 회귀 통과(가격/단위/날짜/농장/교차연도/누락교체/실패 rollback).
- 실제 Chrome 1920×1080 및800px: 명시 조회, 업체/품목 검색 추가, 지역, 공란0, 등록분배 payload, 차수변경 차단, XLSX 업로드·5+3 분할·품목교체0/8, 확인창/Escape, 페이지 가로 넘침 없음. API는 합성 응답이며 ERP 쓰기 검증은 위 격리 SQL에서 수행.
- 전체 test:erp-contract, test:pivot, dnSpy, manifest157개, 변경 API5개 write guard, webpack build 통과. 마지막 문구/초점 수정 후 CI 빌드 재검증.
