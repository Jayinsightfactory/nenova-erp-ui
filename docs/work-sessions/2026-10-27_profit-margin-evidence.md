## 실제 원인과 보완

1. **동일 품목 복수 입고 연결**: 기존 연결이 `ProdKey` 첫 행을 반복 선택했다. 신규 분석에서만 `strictReceiptLines=true`를 전달하여 `WdetailKey + ProdKey` 유일성을 확인한다. 누락/중복은 보류하며 첫 행으로 대체하지 않는다. 기존 보고서 기본 동작은 그대로 유지한다.
   - 대표 ProdKey228의 39-02 실제 입고: W42761 100송이 + W42793 400송이. 기존 연결은 W42761 두 번/200송이였으나 정확 연결은 500송이다.
   - 39차 복구 21품목: 네덜란드14, 중국5, 콜롬비아 카네이션1, 장미1.
2. **과거 입고 조회한도**: 전역 12세부차수 제한을 없애고 품목의 실제 0재고 앵커 이후 필요한 정확 매입기간만 조회한다. 미래 매입이나 전년도 같은 주차를 섞지 않는다. 동시성2/기존 짧은 메모를 유지한다.
3. **전산 수량 반올림**: 실제 native SP의 세부차수별 입고·출고·조정 합계 ROUND2와 잔량 ROUND2를 재현한다. raw 입고/출고/조정 각각이 native 원시합계와 같아야 한다. raw입고100 vs native200, 입출고가 함께100 증가해 잔량만 같은 반례는 모두 차단한다. 수량을 수정하거나 원가 없는 조정을 금액으로 채우지 않는다.
4. **환산·환율 출처**: 비어 있는 단수량은 독립된 양수 박스·송이 근거가 OutQuantity 환산과 모두 맞을 때만 읽기 단계에서 복원한다. 양수 상충값은 보존/보류한다. 실제 저장환율·해당 매입기간 근거만 인정하고 현재 CurrencyMaster/미래·단순 이월 환율을 원가로 승격하지 않는다.
5. **대사 설명 누락**: 기존 경고에 숨겨져 있던 차수·국가/품종별 N/L/O의 SQL/저장값/차액, 저장시각, 실제 조회범위와 분류 적용 효과를 표시한다. `view=reconciliation`은 전체 원가 재계산 없이 같은 인증·연도/업무달력 검증을 거친다.
   - 본표 합계 제외분류(국내/미분류/공제 등)와 전체 원장 합계를 구분한다. 38차 미분류 O 41,818원은 본표 규칙상 합계 제외이며 오류로 꾸미지 않는다.
   - 분류 지문만으로 과거 원인을 추측하지 않는다. 현재 수동 분류 적용 전후 SQL 값과 저장값이 실제 일치할 때만 해당 차액을 설명한다.

## 남아 있는 근거 부족

- 39차 98품목: 취득금액이 없는 양수 재고조정 97품목 + SALAL 환율 미확정 1품목. 단위/기초 앵커/과거 환율 문제는 일부 품목에 겹치므로 사유별 수를 더하지 않는다.
- 38차 45품목: 양수조정 원가 부족42품목이 주요 원인. 일부 원천 단위 충돌, 역사 원가/환율, 음수재고가 겹친다. ProdKey1065/2406은 실제 입고단수량과 마스터 단/박스 환산이 다르므로 native 잔량이 맞아도 원가를 보류한다.
- WebStockPriceEvidence의 VERIFIED25행도 출처를 읽었다. 판매단가 재고평가 또는 운송·통관비가 없는 구매단가 근거여서 평균 도착원가 앵커 채택0건.
- 반대 수량 조정만으로 취소/반품이라고 추정하거나 0원/판매단가로 보충하지 않는다.
