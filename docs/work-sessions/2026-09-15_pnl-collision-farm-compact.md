## 이어받을 때 고정된 결정

- 중복 충돌을 임의 병합·삭제하거나 매칭 허용 기준을 낮추지 않는다.
- 어디서 충돌했는지 호텔·연도·차수·품목·업로드 원본 위치를 표시한다. 없는 위치는 추정하지 않는다.
- 농장 피드백은 최신 3건 미리보기, 전체 건수와 상태를 압축 표시하고 상세에서 전체 기록을 본다.
- 기존 저장·삭제·이미지·권한·연도·동시수정 보호는 그대로 둔다.
- 기준 viewport 1920×1080, 확대 100%. 작은 화면도 가로 잘림 없이 접근 가능해야 한다.

### 1. 중복 위치가 보이지 않음

**Q.** 동일 품목 단가가 어느 차수에 있는지 알림이 없었다.

**A.** 서버의 구조화된 오류 details가 HTTP helper와 일반 저장 API 경로에서 소실되는 문제를 확인했다. 호텔·연도·차수·품목·업로드 원본 위치·판매단가·확인 내용을 오류표로 전달한다. 0원과 서로 다른 연도는 구별한다.

**결과.** HTTP/뷰모델/React 렌더 회귀검사. 실제 사용자 파일 재업로드 및 운영 결산 쓰기는 하지 않았다.

### 2. 피드백이 많아질 때를 위한 공간 축소

**Q.** 농장불량피드백 탭의 공간 여백을 최대한 줄여 달라.

**A.** 기존 큰 다열 카드를 약 118px의 밀집 행으로 바꿨다. 최신 기록 3개를 가로로 표시하고 우측 전체 이력/입력칸을 유지했다. 상태는 색상과 글자로 함께 표시한다.

**결과.** 24건 로컬 fixture, 1920×1080/760×900에서 화면 확인. 상세 전체 8개 이력과 상태 필터를 검증했다. 전체 ERP 계약·빌드·쓰기 가드·dnSpy 근거 검사 통과.

## 한계·미완 기록

- 실제 중복 오류 파일과 차수는 제공되지 않아 해당 파일의 저장 성공 여부는 미검증이다.
- 운영 기록을 수정하는 브라우저 시험은 하지 않는다.
- outputs/의 로컬 서버·fixture·검증 로그·빌드는 커밋하지 않는다.
