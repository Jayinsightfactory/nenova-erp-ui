# 메뉴 새창 뒤로가기 동작 수정

## 사용자 요청

- 메뉴별 `뒤로가기`는 새창을 닫는 기능이 아니라, 새창 안에서 직전에 보던 메뉴 화면으로 돌아가는 기능이어야 한다.

## 원인

- 공통 뒤로가기 컴포넌트는 브라우저 이력이 없고 `window.opener`가 있으면 `window.close()`를 실행했다.
- 팝업/자식창에서 다른 팝업형 메뉴를 누르면 현재 창에서 이동하지 않고 새 팝업을 다시 열어, 돌아갈 동일 창 이력이 생기지 않았다.

## 반영

- 팝업/자식창의 메뉴 이동은 같은 창에서 수행한다.
- 같은 창의 메뉴 경로를 `sessionStorage` 스택에 최대 30개 기록한다.
- 뒤로가기는 기록된 직전 메뉴로 이동하며, 기록이 없는 자식창은 닫지 않고 대시보드로 이동한다.
- 일반 창에서는 기존 브라우저 뒤로가기를 유지한다.
- 별도 `닫기` 버튼의 창 닫기 기능은 유지한다.

## 보존 범위

- 페이지별 업무 데이터, MSSQL, 주문·출고·재고·견적·매출 원장은 변경하지 않는다.
- 팝업 크기와 일반 창에서 메뉴를 처음 여는 방식은 유지한다.
