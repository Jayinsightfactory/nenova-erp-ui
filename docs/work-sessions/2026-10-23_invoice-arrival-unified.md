# 인보이스 자동 원가 → 도착원가 본표

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 화면 | 도착원가 / 수입부 인보이스 |
| 원장 부작용 | 없음. 기존 승인 원가와 입고를 SELECT로 읽음 |
| 배포 | 검사 후 PR·배포 진행, 후속 검증 아래 기록 |

## 이어받을 결정
- 직원이 별도 원가 엑셀을 만들고 드라이브에 다시 올리는 과정 없이, 승인 저장된 인보이스 원가를 본표에 자동 표시한다.
- 기존 입고/주문/출고/재고와 저장 원가를 수정하거나 복제하지 않는다.
- 같은 연도·세부차수·국가·품목·농장·단위의 기존 엑셀 값은 상세 비교로 남긴다.
- 현재 승인된 ACTUAL만 포함하며 문서/입고가 변경된 원가는 제외하고 안내한다.
- 호텔/피벗/손익 downstream 계산은 이번 변경 대상이 아니다.

### 1. 자동 적용 방식
**Q.** 직원들이 원가를 따로 만들지 않고 자동 생성된 자료로 도착원가 페이지가 적용되어야 한다.

**A.** WebInvoiceCostRevision/Line의 현재 승인값을 본표 조회 원천에 연결했다. 검색/품종/페이징/누락 판단도 같은 원천을 사용한다. 엑셀 재업로드는 필요 없다. 기존 엑셀 원가는 삭제하지 않고 비교한다.

**검증.** 태국 2026/38-01 입고7345: 승인19행, 총3,184,993.955819원. 실제 본표 API 코어에서 자동19행 및 기존 비교19행 확인. 교차연도/문서변경/중복 문서 후보/단위/실패 차단 테스트 통과. ERP 전체 계약·dnSpy·manifest·write guard 통과. 빌드 및 배포 후 브라우저 확인 진행 중.

## 작업 파일
- `lib/arrivalInvoiceSource.js`와 기존 arrivalCost 본표 연결.
- `.tmp-arrival-probe.mjs`는 로컬 SELECT 검증용이며 커밋 제외.
- 자동 생성 개발이력 JSON은 빌드 산출물 변경이며 이번 커밋 제외.

## 후속 검증
- PR/배포 상태와 실제 본표 화면 결과를 아래 추가한다. 확인 전 배포 완료로 간주하지 않는다.
- PR1265: 전체 계약/dnSpy/manifest/write guard 및 `npm run build` 성공. 통합 검증에 잘못 붙인 CLI 인수로 한 번 빌드 경로 오류가 있었고 정상 빌드 재실행으로 통과했다.
- 실제 읽기 검색 ARAN Azima 자동1행, 전년도2025/38-1 자동0행. Warehouse7345 master/detail SHA-256이 작업 전과 동일하다.
- 최신 master의 주광 메뉴 작업은 병합 보존했으며 이력 문서 충돌은 양쪽 내용을 모두 유지했다.
