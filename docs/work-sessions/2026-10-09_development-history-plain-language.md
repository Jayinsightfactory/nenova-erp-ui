# 개발 이력을 코딩을 몰라도 읽을 수 있게 정리

| 항목 | 내용 |
| --- | --- |
| 날짜 | 2026-10-09 (한국 시간) |
| 화면 | 개발 히스토리 → 개발 여정 → 업무 목적별 여정 |
| 원장 영향 | 없음. 기존 설명·화면 문구만 변경하며 주문·입고·출고·재고를 조회하거나 수정하지 않음 |
| 작업 상태 | 설명 수정·검증 진행 중. 배포 결과는 확인 후 기록 |

## 이어받을 때 고정된 결정

- 전문 용어를 단순 번역하지 않고 왜 필요했는지와 실제 사용 장면을 설명한다.
- 실제 버튼·설정·처리 조건은 보존하고, 확인되지 않은 목적이나 결과는 만들지 않는다.
- 기존 84개 목적 이야기·513개 세부 변화가 대상이다. 연결 규칙과 원본 기록은 바꾸지 않는다.
- 기본 화면은 쉬운 설명, 원래 개발 제목·확인번호는 사용자가 펼친 원본 기록에서 제공한다.
- 앞선 배포 이후 추가된 다른 작업은 보존한다. 기존 미추적 초안 3개는 배포에 포함하지 않는다.

### 1. 쉬운 설명으로 다시 작성

**Q.** 전문적인 내용이 많아 이해하기 어렵다. 코딩을 몰라도 이해할 수 있게 작업해 달라.

**A.** 기존 이야기 설명과 화면 안내를 확인했다. 개발 구조 이름 대신 왜 필요했는지, 어떤 버튼·설정을 만들었는지, 어떤 반복이나 불편을 줄였는지를 중심으로 수정한다. 설명의 정확성과 원본 연결은 함께 검증한다.

**검증 예정.** 개발 이력 전체 검사, 화면틀, ERP 안전 검사, 빌드 및 실제 화면 조회·검색·원본 펼치기. 기준 viewport 1920×1080 CSS px/100%와 좁은 화면.

### 2. 수정 중 확인한 내용

- 화면 안내·검색·프로그램 이름·확인 상태를 쉬운 말로 수정했다. 원래 개발 제목은 원본 목록에서 개별 기록을 펼쳐 확인한다.
- 기존 전문 용어와 잘못된 조사를 문장별로 고치며, 미완성 계획과 실제 구현을 구분한다.
- 수정 중간 단계에서 기존 5,199건의 분류 비교가 같았다: 3,119건 연결, 2,080건 별도 확인. 마지막 내용 통합 뒤 다시 검사한다.
- 화면틀·dnSpy·manifest 92개·쓰기 범위(변경 API 0개)·전체 ERP 검사가 통과했다. 문구 통합 후 개발 이력 최종 검사와 빌드가 남아 있다.
- 지정된 중간 비용 모델을 사용할 수 없어 문구·화면 구현을 사용 가능한 `gpt-5.6-sol`로 대체했다. 하위 작업은 로컬 파일만 다루며 외부 반영은 메인에서 수행한다.

## 다음 작업

### 3. 최종 내용 통합과 검증

- 84개 이야기·513개 변화를 검토하고 사람용 설명 459곳과 전체 흐름 설명 3곳을 수정했다. 수정 문장 수는 새 기능 수가 아니다.
- 독립 검토에서 발견한 문법, 서로 다른 작업 설명의 중복, 종료와 재시작의 구분, 메모리 의미, 실제 버튼명 변경, 초기 근거 범위 누락을 배포 전에 바로잡았다.
- 분류 근거·ID·확인 수준·정확한 요약 참조·규칙을 고정한 보존 검사와 변경 설명 중복 검사를 추가했다. 통합 뒤 개발 이력 검사는 49/49 통과했다.
- 최신 기준 코드의 5,210건에서도 수정 전후 분류가 동일했다: 3,126건 연결, 2,084건 별도 확인. 최근 코드 기록 추가로 이전 5,199건과 전체 수가 다르며 설명 수정으로 기록을 삭제하거나 재배정하지 않았다.
- 처음 문법 검사의 `기록인` 조건이 정상 문장 `어느 기록인지`까지 잡은 오탐을 확인해 잘못 바뀐 로그인 표현만 검사하도록 좁혔다. 이후 49개 검사가 모두 통과했다.
- 최종 `npm run build` 성공: 115개 정적 페이지 준비 완료. 배포와 실제 수정본 화면 검증은 아직 진행 전이다.
