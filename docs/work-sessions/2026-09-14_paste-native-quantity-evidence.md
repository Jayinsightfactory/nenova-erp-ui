# 붙여넣기 분석 높이와 전산 처리 이력

| 항목 | 내용 |
|---|---|
| 기간 | 2026-09-14 |
| 화면 | /orders/paste |
| 원장 부작용 | 없음. 기존 읽기 전용 distribution-live-history API 재사용 |
| 배포 | 첫 변경 PR #589 배포 완료. 매칭명 연계 후속 변경은 해당 파일 커밋의 PR 참조 |
| 다음 확인 | 1920×1080에서 분석 높이와 현재 분석 기준 전산 이력 확인 |

## 고정된 결정
- 분석 영역을 오른쪽 2개 행에 배치하고 내부 330px 높이 제한 제거. 운영 첫 검증에서 높이 약 505px.
- 붙여넣기 작업 기록과 ERP 주문·분배 수량 이력은 별도로 표시한다.
- 같은 연도·차수·업체·품목과 원문 이후의 정확한 수량 변동만 근거로 사용한다.
- 원문 시각이 없거나 근거가 모호하면 미처리로 단정하지 않는다.
- AI 매칭이 완성된 단일 원문은 현재 매칭한 전산명·수량 기준으로 조회하며 그 기준을 화면에 알린다. 원문과 별칭 저장은 변경하지 않는다.

### 1. 분석 영역과 최신 이력
**Q.** 상하 공간을 넓히고 전산 수량변동을 확인해 기존 처리 여부를 보여 달라.

**A.** 분석 높이를 늘리고 `PasteErpHistoryEvidence`를 추가했다. 조회 버튼, 자동 읽기 갱신, 개별 주문·분배 변경 전후 수량을 제공한다. 동일 처리/일부 처리/확인 필요를 구분하며 요청 재등록은 실행하지 않는다.

### 2. 운영 예시 매칭 차이
**Q.** 미니아틱처럼 분석에서 매칭된 항목의 전산 처리 확인.

**A.** 첫 운영 검증에서 원문 별칭만으로 품목을 찾지 못한 것을 확인했다. 현재 분석의 완전 매칭 전산명을 읽기 조회에 연결했다. 양수 추가 1박스가 분배 1→2 이력에 대응하는 fixture 및 다른 차수/불완전 매칭 보존 fixture를 검증했다.

## 검증
- ERP 계약 전체, manifest, 쓰기 가드, 빌드 통과.
- `pasteEvidenceSource.test.js`: 원문 연도/시각/identity 보존, 미매칭 보존, 실제 이력 파서로 1→2 매칭, 차수 불일치 거부.
- 실브라우저는 LLM 응답만 fixture로 대체하여 유료 분석과 주문/분배 저장 없이 확인한다.
- 임시 smoke와 화면 PNG는 Temp에 있으며 커밋하지 않는다.
