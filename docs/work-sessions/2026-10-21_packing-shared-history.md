## 고정 결정
- 공용 DB 품목 매칭은 전 직원 공통. 원본 파일/분석 작업의 개인 IndexedDB 보관과 혼동하지 않는다.
- 팀 이력은 원본·분석·검토 데이터를 보관하고 최신 팀 매칭을 다시 읽어 복구한다.
- 저장 이력은 입고 완료가 아니다. 생성 파일/승인 토큰/입고 가능 플래그를 복구하지 않는다.
- 자동 AI 재분석·입고·재고 쓰기 없이 사용자가 복구/진행/입고 승인한다.
- 과거 업로드 원본이 보관되지 않았으면 과거 파일을 복구할 수 있다고 말하지 않는다.

### 1. 업로드 후 작업이 멈추는 이유
**Q.** 매칭은 직원 공용인지, 업로드 이력 보관/불러오기를 만들고 직원 로그로 중단 원인을 찾아 달라.

**A.** 공용 매칭 API는 팀 단위다. 기존 원본 복구는 PC·계정별 최신1건이어서 공유 이력에는 없었다. 10/20 16:41KST 다음·입고준비 이후 원문 박스/단수 확인창을 열고16:42 취소한 클릭을 확인했다. 과거 실패2건은 오류 상세를 저장하지 않아 숫자/필드 원인 확정 불가. 일부 인보이스 문서는 COMMITTED/APPROVED라 전체 중단으로 단정하지 않는다.

**결과.** 팀 공용 원본·분석 이력 API/불러오기/자동보관/실패 재시도 구현. 격리 A/B 브라우저와 전체 ERP 회귀 검사 통과. 원본만 보관된 복구를 검증했고 실물 인보이스 입고·원가 E2E는 이번 범위에서 미실행.

**추가 당일 근거.** 10/21 09:49~09:51 다음·입고준비 반복/날짜·통화·총액 안내 및 metadata 확인창 클릭. 당일 입고 drafts API 요청은0건. 서버 저장 실패가 아니라 초안 저장 이전 중단을 관측했으나 정확한 필드값은 로그가 없어 미확정. 최신200개 클릭을 조회했고 전체 클릭 페이지를 전수 확인한 것은 아니다.
