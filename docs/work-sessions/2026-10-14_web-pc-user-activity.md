# 2026-10-14 웹·PC 웹앱 사용자 작업 기록

## 사용자 요청
네노바웹, 네노바웹앱(PC), NENOVA.EXE를 구분하며 웹과 PC 웹앱의 버튼 클릭 및 작업 기록을 남긴다.

## 확인된 기존 한계
apiLogger는 재시작 시 소실되는 메모리 집계다. 기존 화면 재생은 일부 계정과 화면을 제외하고 API 결과를 연결하지 않는다. /admin/activity의 ERP 이력은 버튼 조작 기록과 다르다. 기존 Replay 원문 수집 정책과 새 감사의 원문 비수집 정책은 별도로 검토해야 한다.

## 합의한 설계
서버 인증 사용자 기준의 공통 이벤트·서버 API 결과·PC 셸 명령을 구분한다. 클릭은 시도이고 응답 성공을 ERP 저장 완료로 단정하지 않는다. 입력값·비밀번호·요청/응답 본문은 새 감사에 저장하지 않는다. 웹과 PC 표시는 UA 분류이며 인증 근거로 사용하지 않는다. EXE 조작 수집은 이 작업 범위에 없다.

## 조회 화면
기존 작업내역 화면 위에 웹·PC 사용자 로그 영역을 추가한다. 기존 열람 권한 사용자에게만 표시한다. 서버는 별도로 권한을 검사한다. 기간·사용자·환경·동작·결과·경로와 다음 페이지를 제공한다. 긴 내용은 줄바꿈하고 표만 가로 스크롤한다. 조회 날짜·시간과 표시 시각은 한국시간으로 통일한다.

## 기준선
- 적용: 공통 화면틀 유지, 페이지 주 스크롤, 키보드 표준 조작, 긴 이름 표시, 오류 표시, 1920×1080 및 작은 화면 검증.
- 해당 없음: ERP 쓰기·분배·매칭·원장 수량 변경·파일 가져오기.
- 예외: 넓은 로그 표는 가로 스크롤 허용.

## 검증 및 배포 상태
UI smoke 스크립트 scripts/user-activity-ui-smoke.cjs를 포함한 통합 검증을 완료했다. 운영 배포와 PC 릴리스 결과는 아래에 별도로 기록한다.

## 통합 중간 검토
- 서버 결과와 기기에서 전달한 조작을 recordedBy로 구분 표시한다.
- 서버 저장은 actor+event ID 중복 제거와 Linux fsync를 사용하며 배포 외부 경로를 구성한다. 자동 보존기간 삭제는 없다. 파일·inode 증가 모니터링이 필요하다.
- 브라우저 localStorage에 계정별·이벤트별 미전송 큐를 보존해 재진입 시 복구한다. 저장소 삭제·저장 실패 시 복구가 제한된다. PC 셸 큐는 암호화 파일에 보관한다. 무손실을 보장하지 않는다.
- 클릭 연결은 동기 이벤트 요청 범위이다. await·지연 실행 뒤 요청에 무조건 클릭을 연결하지 않는다.
- 서버 재시도 큐 1000건과 pending/dropped 건강상태 경고, 디스크/inode 감시를 추가했다. 서버 프로세스 종료 중 메모리 재시도 큐 소실 가능성은 남는다.
- 운영 ERP 쓰기·native EXE 변경이 전혀 없어 추가 dnSpy 수정 근거 수집은 해당 없음이다. 기존 ERP 계약을 변경하지 않는다.

## 통합 검증 진행 갱신
- 메인/클라이언트 담당 실제 Chrome 검증: 웹 1920×1080, PC UA 800×1080 통과 보고를 확인했다. 로그 조회 전용 smoke는 별도 실행 결과 확인 필요.
- 서버 저장 로컬 Windows 실측: 50건 129ms, 1000건 1966ms. 운영 Linux 저장장치 성능 수치로 간주하지 않는다.
- manifest 공통 schema에 따라 보존 대상 ERP 업무키와 auditIdentity를 분리했다. dnspyEvidence는 웹 전용·원장 무변경 범위를 기존 근거 README에 연결하며 새 native 분석을 수행했다고 주장하지 않는다.

## 최종 통합 검토
- 코드 검토상 배포를 차단할 새로운 결함을 발견하지 않았다. 인증 actor·계정 불일치·서버/기기 출처·원문 비수집·중복 ACK·서버 재시도·암호화 PC 큐·외부 보관 경로와 PM2 환경 갱신을 확인했다.
- 메인 실제 고립 HTTP 검증 보고: 운영 JWT 없이 fixture JWT, DB 127.0.0.1:1 조건에서 identity, metadata 비반사, 조회 미허용 404, 계정 불일치 409, 없는 API 404 전역 서버 기록 통과.
- 메인 실제 조회 UI 1920×1080/800×1080 검증 및 이미지 검토 통과 보고 확인.
- 지속 저장 장애·스토리지 삭제·프로세스 종료 시 미전송 기록 손실 가능성을 숨기지 않는다. 배포 완료 여부는 메인이 실제 배포 결과로 추가한다.

## 메인 검증 결과
- `npm run test:user-activity`: 서버·클라이언트 8개·PC 큐 3개 검사 통과. KST 실제 2025/2026 경계 및 중복 재전송 검증 포함.
- 실제 Chrome: 1920×1080/100%, 800×1080/100%에서 기록·조회, Enter/Space, 줄바꿈, 네트워크 실패 재시도, 권한, hydration 오류 없음 확인.
- 실제 Electron: smoke, 별도 프로세스 재실행 후 암호화 미전송 큐 복구, 마지막 창 종료, 다운로드 무결성 검사 통과. 운영 ERP 호출은 fixture로 차단했다.
- `npm run build` 및 Windows NSIS 1.3.10 빌드 통과. ASAR의 main.cjs/activity.cjs가 검토한 소스와 동일하고 latest.yml의 SHA512가 설치파일과 일치한다.
- 설치파일 SHA256: `ca3baecc1e9ea08f619c0a1cbd6e8c2338d1371a81a208b4aec34f23b7e9e075`.
- 기존 withAuth를 추출하는 weekday 테스트 두 곳에 새 감사 의존성 mock을 추가했다. 미인증·만료 토큰은 기록과 업무 실행 전에 거부되는 것을 검증했다.
- 로그는 `/admin/activity`의 웹·PC 웹앱 사용자 작업 로그에서 기존 조회 권한으로 열람한다. NENOVA.EXE 및 수집 적용 이전 작업은 포함하지 않는다.
- `desktop/menu.json`은 기존 Layout 메뉴로 재생성한 결과이며 이미 웹에 있던 물량표 항목을 포함한다. 신규 ERP 메뉴·원장 동작은 추가하지 않았다.
- 프로젝트가 요구한 `docs/CODEX_SUBTASK_ORCHESTRATION.md`는 현재 checkout에 없다. 사용자 제공 역할 분리 규칙대로 하위 구현/검토를 나누고 운영 쓰기·배포는 메인이 담당했다.
