# 네덜란드 패킹 매칭·검산 수정

Q. AI 분석 후 발견한 미매칭 원인을 수정하고 도착원가까지 검증해 달라.

A. CL로만 시작하는 주문코드 제한이 Y2의 상품행을 누락시켜 로컬 검산을 실패시켰다. 고객코드는 보존하면서 기존 행 금액·주문 소계·CBS 송이수·송장 총액 검산을 유지한다. 성공한 로컬 파서만 일회용 증명을 받아 원문 행별 체크를 생략한다. AI 결과에 검산 완료 표시를 부여하지 않는다.

반복 품명은 원본 인보이스/행번호로 표시하며, 병합 행의 후보가 모두 같은 경우만 이름 폴백을 허용한다. Aisha3+와 Casablanca12st는 실제 Product에 존재한다. NL 후보는 품종/등급을 비교하고 미리보기와 파일 생성에 동일 함수를 사용하며, 유사 후보의 수동 매칭 확인은 유지한다.

## 기준과 부작용
- 파싱·미리보기·후보·검토: Order/Shipment/Warehouse/Stock/Estimate/WebProfitReport 모두 보존.
- 기존 팀 공용 매칭 CAS, 입고 트랜잭션, 도착원가 계산 공식은 보존.
- 메뉴기준: 기존 모달/키보드/초점 유지(적용), 새 메뉴/shell 변경 없음(해당 없음).
- dnSpy 실제 ExcelLoadingPackingList.MakeTempTable/CheckData/InsertMaster에서 이름+SIZE, 별도수량/가격, SP 및 재고계산 순서를 재확인.

## 실제 파일과 DB 대조
- PDF146행·16,251송이·EUR31,141.91, GW2298.3/CW2555 자동 검산 통과.
- 송장1214205는2026/41-02 WarehouseKey7662로 이미 등록됨. Casablanca60송이와 Aisha3+1510송이 확인.
- 기존 입고 중량행은 GW2296.5/CW2553으로 PDF와 다름. 운영 보정 없음.
- 해당 WarehouseKey의 WebInvoiceCostRevision 0건. 이 사실은 모든 다른 원가 업로드 원장 부재를 뜻하지 않음.
- 운영 중복 입고나 원가 저장은 실행하지 않았고 실제 원가 저장 성공은 미검증.
