# 중국 인보이스 Excel와 요일 업무 편집

## 사용자 요청
`41-1 중국 해상 ci1.xlsx`를 중국 패킹리스트 생성기에 업로드하여 품목·장미 길이·단수·단가를 반영한다. 요일 업무 추가/수정/삭제와 체크 계정 표시를 구현한다.

## 판단과 변경
- 기존 업로드는 PDF만 허용했고, 중국 출력은 박스/단당 송이수를 1로 고정했다. XLSX 경로만 원본 수량을 보존하도록 분리했다.
- Excel 50MiB, PDF 20MiB. Excel은 로컬 코드 분석, AI 호출 없음. 원본은 커밋하지 않는다.
- Total of Flower Material=단수, Stems=송이수, Unit Price=단당 CNY. 장미 길이는 매칭키 및 출력에 보존한다. 동일 길이 범위는 일치 가능하지만 길이 없는 품목을 임의의 길이로 추정하지 않는다.
- 품목 합계와 비용 합계를 독립 검산하고 꽃 금액 반복행을 이중 합산하지 않는다. 0원 품목도 유지한다.
- 요일 반복 업무는 `checklist.templates.<요일>`로 공동 저장. 기본 113개 원본과 기존 `국가::순번` 체크 키를 유지한다. 신규 업무는 UUID.
- 템플릿 편집은 과거 날짜 표시에도 적용됨을 UI에서 알린다. 날짜별 체크 데이터는 삭제하지 않는다.
- 일일/월별/미결/항공 체크 담당자는 인증 계정으로 서버에서 생성하여 체크와 원자 저장한다. 기존 담당자 없는 체크는 미확인, 다른 업무 저장으로 덮어쓰지 않는다.
- CAS 충돌 시 초안 보존 및 비교 후 재확인. 요일 템플릿의 반복 범위와 날짜별 체크 범위를 구분한다.

## ERP 안전성
운영 SQL, nenova.exe, 주문/분배/재고/견적은 읽거나 쓰지 않는다. 로컬 변환 및 기존 웹 공동 저장소만 사용한다. 계약 `docs/contracts/import-team-tools.json` 갱신.

## 검증 결과
- 실제 34,304,924바이트 파일: 101행 / 429박스 / 5,390단 / 68,775송이.
- 품목 CNY126,325 + 부대비용45,825.50 = 전체172,150.50. 112행 0원·2,100송이 보존.
- 원본 파일 테스트16개 통과. 두 로컬 카탈로그 모두 51/101행 자동 매칭, 나머지50행(중복 제거47개 확인항목)은 수동 확인 필요. 모두 자동매칭됐다고 안내하지 않는다.
- 수입부 통합 테스트148개:145통과/3선택검사생략. 실제 파일·Chrome 명시 실행은37개 전부 통과.
- 전체 ERP 계약, manifest, ERP write guard, dnSpy evidence 통과.
- 실제 앱 브라우저:1920×1080/100%,900/480px; 실제Excel,요일업무CRUD,체크담당자,새로고침 유지,가로넘침0/pageerror0. 공동자료는 브라우저 fixture로 격리하여 운영쓰기0/AI0/ERP0.
- 코드/수량 안전성은 Nenova guard, 입력 파일 분석은 spreadsheets 스킬 적용. 서버형 SQL 확장 불필요.

- 일반 장미/스프레이 장미의 동일 이름·길이 충돌: 매칭/alias/cache 키를 family+length로 통일하고 교차 재사용 회귀 테스트 추가.
- 미결/항공 업무: 기존 원본 필드만 허용, 숫자/문자열 ID 충돌 및 중복 ID·담당자 필드 주입 거부. 기존 소수 timestamp ID는 보존.
- production build 통과. production 앱의 실제 Excel 및 CRUD/체크 담당자 smoke 재통과.
- 기존 AWB1379.60 / NL7589송이 / 중국발주1850단 smoke 재통과, AI0/운영쓰기0.
- gpt-5.6-sol/high 독립 재검토 승인: 두 지적 해결, 새 차단 이슈 없음. 구현은 gpt-6.1-sol/high 분리 작업, 메인이 계약·통합·운영 배포 담당.
