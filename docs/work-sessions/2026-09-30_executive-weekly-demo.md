# 주차별 보고서 예시 기능 활성화

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-09-30 |
| 화면 | /m/executive?preview=1 |
| 원장 부작용 | 모든 ERP 테이블·인증 설정·실제 보고서 보존. 신규 SQL/API 없음 |
| 범위 | 주차별 보고서만 가상 데이터로 상세/차수 변경/Excel/인쇄 활성화 |

## 고정 결정
- 일반 접속과 기존 인증된 미리보기 유지. 공용 비밀번호, 실제 금액, 자동 게시 연결 없음. `?demo=weekly`는 로그인 없이 가상 데이터만 직접 체험하는 별도 공개 예시 URL이다. 인증 세션이나 실제 데이터 접근 권한을 만들지 않는다.
- 주차별 예시 2026-38/39만 지원. 전년도 동일 차수는 빈 상태/다운로드 거절.
- 라움·신라 파일은 미연결 상태 유지.
- 순수 `weeklyDemo` 한 함수가 목록/상세/Excel 값을 제공. 가상 입력 3개 구분을 합산; 38차/39차 값이 다름.
- 엑셀은 앱의 기존 ExcelJS 런타임으로 생성. 합계·이익·이익률 수식, 숫자 형식, 예시 제목/파일명/바닥글 포함.
- 중복 다운로드 잠금, 생성 실패 알림, 브라우저 다운로드 요청과 실제 저장 완료를 구분.

### Q. 주차별 매출이익보고서를 예시로 모든 기능 활성화
A. 상세 보고서, 차수 선택, 전차수 대비, 구분별 실적 펼침, 예시 Excel 받기, 브라우저 인쇄/PDF 저장 버튼을 연결했다. 실제 재무자료와 인증 설정은 변경하지 않았다.

## 검증
- npm run test:executive-mobile-ui: 데이터 합계/교차연도/파일 내 수식과 numeric type/Excel roundtrip/SSR 통과.
- ui-layout, erp-contract, dnSpy evidence, manifest(origin/master), write guard, production build 통과.
- 브라우저 390×844, 320×760, 1920×1080: 상세, 차수 변경, 펼침, 가로 잘림 없음.
- 실제 다운로드된 `예시_주차별매출이익_2026-38.xlsx`, `2026-39.xlsx`를 Downloads에서 읽어 합계와 수식 확인. 38차 매출116,000,000/이익21,000,000; 39차 매출124,800,000/이익23,800,000.
- IAB download event는 timeout이었으나 실제 파일 저장 확인. 인쇄 버튼 호출은 CDP 응답 timeout; 실제 PDF 파일 저장은 검증하지 않았음. PDF는 사용자가 브라우저 인쇄 창에서 선택하는 방식.
- .tmp 로컬 harness, 로그, 화면 캡처는 커밋하지 않음.
