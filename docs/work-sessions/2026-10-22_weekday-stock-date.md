| 화면 | 주광 견적서 → 견적서관리 |

## 고정 결정
- 실제 재고를 임의 증액하거나 자동 재고조정하지 않는다.
- 기존 확정 취소→수량 변경→재확정 계약 유지. 확정 날짜만 이동하면 재고 보존.
- 미확정 날짜 이동은 native 차수 잔량 검사 후 확정→날짜 이동.
- 실패는 전체 rollback, 초안 보존. 선출고 내부 legacy 호출 변경 없음.
- 판매요청/검역은 기존 견적서관리 등록 경로 사용. 연결은 업체·연도·차수를 유지하는 새 탭.

### 1. 장미 실패 원인
**Q.** 카네이션 성공·장미 실패, 플라야블랑카 출고일이 안 바뀌었다. 재고가 왜 다른지 확인하고 보정 없이 고쳐라.

**A.** 네 건의 weekday-apply HTTP409 실패를 조회했으나 당시 요청본문/품목은 로그에 없어 특정 실패행을 확정할 수 없다. 실제 운영 usp_ShipmentFix와 주광 코드의 판정 원천이 달랐다. native는 전차수 잔량+해당차수 입고−확정출고+StockType조정인데 주광은 누적 Product.Stock으로 선차단했다. 43-01 미확정 당시 Mondial White60은220 대430, Ocean Song50은60 대70, Shimmer60은0 대10. 두 원장은 갱신 방식과 시점이 다르며 이전부터 차이가 있었다. 10월 대상5품목 StockHistory 연결 단절0; 최초 역사적 차이 발생 행은 미확정. 근거 없이 누적값을 스냅샷으로 덮어쓰지 않았다.

**결과.** normal lifecycle을 native 차수 검산으로 변경, 앞 차수 배치 효과를 뒤 차수에 반영. native cascade/readback 및 실제 부족 rollback 유지. Product.Stock은 기존 native 확정/취소 증감만 기록하고 결과를 검증한다. 실패 로그에 stockValidation 추가.

### 2. 현재 업무값 보존
**Q.** 이미 NENOVA.EXE로 수정했다. 다음부터 웹에서 해결되게 해달라.

**A.** 현재 출고일·수량을 수정하지 않는다. 격리 MSSQL에서 변경·인쇄를 검증한다. 실제 DB 50cm10단/60cm70단을 사용자 설명70단으로 임의 변경하지 않는다.

### 3. 견적서관리 접근
**Q.** 출고일 변경 후 바로 인쇄하고 판매요청·검역차감도 입력해야 한다.

**A.** 주광 상단에 견적서관리 링크를 추가했다. 현재 중심 차수·업체, 미확정 포함, 즉시 조회로 기존 입력 화면을 연다. 원래 주광 입력은 별도 탭에 보존된다. 실제 분배 인쇄 SQL/HTML fixture에서 확정/미확정 날짜 이동 후 새 날짜150송이, 이전 날짜0건을 검증했다.

## 검증
- 설치 EXE dnSpy CLI exit0, 운영 SP 정의 및 주문/출고/재고/날짜 SELECT.
- native stock 단위11건 및 격리 MSSQL lifecycle 전체 성공(타업체/2025 보존, 후속연도 부족 rollback, 각 저장단계 주입실패 rollback, UUID 재실행, actual ALLOCATION print SQL/HTML).
- ERP 계약 전체·dnSpy evidence·manifest·write guard 성공. UI layout 검사 성공.
- 최초 기록 시 빌드/PR/배포/실브라우저 최종 확인 진행 중. 결과 후속 기록.
- 메뉴 기준: 화면틀·스크롤·키보드 링크·업체/차수 맥락·저장 전후 검증 적용. 새 메뉴/매칭 변경 해당 없음.

## 후속 및 제외
output/의 DB probe/테스트 로그·dnSpy 원문은 ignored, 비밀값은 문서에 넣지 않음. 오래된 누적 현재고의 최초 오차 발생 지점은 별도 장기 대사 대상이며 이번 코드 수정으로 과거 재고를 임의 수정하지 않는다.
