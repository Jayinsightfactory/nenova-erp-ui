## 고정 결정

- 단일 원문 안에서 연속된 같은 업체의 표시만 묶는다. 개별 수량을 합산하거나 항목을 삭제하지 않는다.
- 유효 CustKey가 있으면 그 키로, 없으면 정확한 표시 업체명으로 묶는다. 이는 적용 판정 근거가 아니다.
- 원문 행과 연결되지 않은 API 분석 항목은 추가 확인 건수를 항상 표시하고 기본 접는다.
- 전체 카톡 원문·품목별 적용/미확인·정확한 원문/요청 ID·연도/차수 판정은 보존한다.

### 1. 적용 항목이 원문보다 길어짐

**Q.** 같은 업체/품목의 묶음 표시가 안 돼 적용 항목이 너무 많은 공간을 차지한다.

**A.** 반복 업체명을 한 그룹 헤더로 옮기고 각 품목은 간결한 수량/상태 행으로 표시했다. 원문 행과 연결되지 않은 분석 결과는 건수가 있는 추가 확인 영역에서 볼 수 있다. 연결 실패를 중복이라고 단정하거나 삭제하지 않는다.

**검증.** 순수 그룹 함수 테스트: 순서, 동일 이름/다른 업체 키 분리, 미연결 항목 보존, 입력 불변. 기존 교차연도 적용 판정 유지. 전체 ERP 계약, dnSpy 근거, 변경 manifest 69개, 쓰기 guard(변경 API 0개), production build 통과. 최초 빌드에서 발견한 JSX 오타를 수정한 뒤 재빌드 통과.

**UI.** 실제 컴포넌트 + 외부 요청을 차단한 로컬 fixture, CUA Chrome 1920×1080 및 390×844. 4개 원문 항목/1개 업체 헤더, 적용 1/4, 미연결 4건 접기·펼치기(총 8행), 전체 원문 및 상태 유지, 가로 overflow 없음. 실제 ERP 등록 버튼은 실행하지 않음.
