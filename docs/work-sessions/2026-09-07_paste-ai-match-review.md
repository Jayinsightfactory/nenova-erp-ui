## 고정 결정

- 사용자가 API 비용을 허용하고 업체·품목 매칭 개선을 요청했다.
- 기존 Claude API의 문장 파싱 뒤 최종 후보 검증을 추가한다. 실제 활성 후보 키만 선택.
- 업체명 완전일치는 지역명/과거 별칭보다 우선. 정확 저장 별칭은 유지하고 부분 별칭·AI 제안 키는 비교 후보다.
- 품목 후보는 기존 검색 결과/현재 선택을 사용하고 국가·화종·명시 길이 불일치를 제거한다.
- AI 누락/중복/목록 밖 키/확신0.9미만/실패는 확인 필요, 원문 수량·단위·연도·차수·취소/추가 보존.
- 서버 검증 결과는 미매칭이어도 브라우저 저장값이 덮어쓰지 못한다.
- 품목 학습 저장은 Git 추적 seed와 분리된 runtime JSON. 배포는 기존 값 보존 및 이전 실행 빌드의 구파일 쓰기도 runtime 링크로 연결한다.

## Q&A

### 1. 업체와 품목 매칭이 바뀌었나
Q. 양재동이 다른 업체, 서부꽃집이 서부청과로 나온다.
A. 운영 read-only 조회상 양재동686/서부꽃집671 별칭은 정상. 브라우저 캐시가 서버 결과를 덮는 경로와 Git 추적 품목 저장파일의 배포 초기화 위험 확인. 특정 과거 요청의 오선택 원인을 로그만으로 확정한 것은 아니다.

### 2. API로 정확도 보완 시작
Q. 품목도 API 분석을 추가해서 보완하라.
A. 기존 Anthropic API로 후보별 재검증을 구현했다. 고객/품목 키만 검증 선택하고 주문등록 실행은 분리했다. 근거를 미리보기에 표시하며 사용자 수정은 기존 검색/저장 API 유지.
