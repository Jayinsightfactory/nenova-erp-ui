## 고정 결정

- 원본 품명·물량·가격을 유지하며 selectedProdKey만 선택한다. 활성·유일성은 서버 재검증.
- 동명 중복은 native SP 이름 조인이 모호하므로 강제 저장하지 않는다.
- EXE의 채번→입고 SP→재고 SP 순서 유지. 웹 재매칭 UI 자체가 EXE와 동일하다는 뜻은 아니다.
- 현재 확정/이전 미확정/다음 확정은 native DetailFix 기준. 연도 포함 StockMaster 차수 순서.
- 미처리 EXE staging 보존, 동일 파일 중복 등록 차단, 실패 시 파일 전체 롤백.

### 1. 품목 인식 실패 후 다시 매칭하여 업로드

**Q.** 입고 업로드에서 SQL 품목과 다른 이름이면 오류 후 품목을 다시 선택해 저장할 수 있게 해 달라. dnSpy로 EXE 동일 기능을 확인하고 안전하게 추가.

**A.** 실제 ExcelLoadingPackingList/CommonLogic CLI와 SP 정의를 대조했다. 행별 원본/ERP 품목/단위별 수량, 검색 선택, 오류 필터, 재검증 및 명시 저장을 구현했다. 기존 non-identity 키 누락, 공용 임시자료 무조건 삭제, master 확정 기준 문제도 보완했다.

**검증.** parser/매칭 단위 테스트, 운영 SELECT로 정상/수동/미등록/동명, native staging 완료 잔여 대조. 격리 #table/#proc 8개 fixture(정상·미처리·부분·중복수·생성 실패·후속 실패 롤백) 통과. 운영 원장 테스트 쓰기는 하지 않았다. 실제 StockCalculation과 2세션 경쟁은 수행하지 않은 범위다.

**화면.** 로컬 실제 페이지 + mock API에서 30행 엑셀 파싱→미등록 1행→검색 수동 선택→전체 검증 0오류/저장 활성화 확인. 브라우저 팝업 대신 화면 내 차수/농장/행 수 확인 후 별도 저장 버튼을 사용한다. 409 저장 실패를 재현하여 오류 표시·수동 매칭/원본 수량 보존·재검증 전 저장 차단을 확인했다. Chrome 1920×1080 및 800×720에서 모달과 고정 하단 버튼 접근을 확인했다. 표는 작은 화면에서 내부 스크롤한다. 운영 쓰기 테스트는 하지 않았다.

**추가 검토.** 독립 안전성 검토의 배포 차단 결함 없음. UTC 음수 시간대 1월 1일의 연도 판정도 문자열 연도 추출 및 회귀 fixture로 보완했다. 실제 운영 저장/동시 EXE 경쟁은 테스트 범위에 포함되지 않는다.
