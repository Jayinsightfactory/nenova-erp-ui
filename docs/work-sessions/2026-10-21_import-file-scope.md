# 새 업로드 파일 기준 범위

사용자 정정: 수국만을 추가 선택하는 방식이 아니라 수국 파일을 올리면 그 파일 내용만 자동 처리. 이전 중단 요청이 새 파일에 섞이지 않아야 함.

기준/부작용: 파싱·검증은 현재 표시 시트의 실제 행/품종으로 결정. 숨김/삭제시트 키맵은 범위에 추가하지 않음. 알려진 품종과 다른 DB 품종은 유사 이름/명시키/수동매칭으로도 통과하지 않음. 실제 여러 품종이면 실제 포함된 품종만 처리. 일반 최종분배 교체의 같은 품종내 누락/0 취소 계약과 기존 주문 보존 writer는 변경하지 않음. 주광 별도 요일 모드는 보존.

실제 설치 EXE FormShipmentDistribution CLI 재실행: ShipmentDetail/ShipmentDate 저장 순서 기존 증거와 동일. 이번 변경은 웹 파일 입력·preview 범위이며 저장 원장은 변경하지 않음. 운영 SELECT 감사122 STARTED/AppliedCount0, 기존 auditRow0. 모든 ERP 쓰기와 audit 적용 상태는 한 transaction이므로 이 상태는 committed 성공이 아님. 이전 프로세스는 배포로 교체되어 실행 지속 없음. 새 검증은 현재 DB를 읽음.

회귀 계획: 카네이션 파일→수국 파일 상태초기화, 늦은 이전 preview 응답 무시, 수국 제목/행을 카네이션 key/같은이름으로 오매칭 차단, 복수 표시시트 현재내용, 삭제시트 keymap 제외, 전년도 및 기존 주문 보존.
