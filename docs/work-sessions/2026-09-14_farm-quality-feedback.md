## 수입부 확인 묶음 보기 보완

- 요청: `수입부 확인`은 기본적으로 같은 거래처끼리 나열하고, 버튼형 `품종`을 누르면 같은 품종끼리 나열한다. 두 기준 중 하나만 활성화한다.
- 구현: 기본 `거래처`/선택 `품종` 버튼과 활성 상태를 추가하고, 선택 기준이 바뀌는 지점에 구분선을 표시한다.
- 안전 기준: 조회된 원본 행 배열은 재배열하지 않는다. 화면 정렬 후에도 원본 행 인덱스와 `DeductionKey`를 유지하여 농장 입력·확정·확정취소 대상이 바뀌지 않는다.
- ERP 영향: 표시 전용 정렬이며 불량차감·견적·주문·출고분배·재고 원장은 변경하지 않는다.
- 검증: 순수 정렬 fixture와 1920×1080 브라우저 smoke에서 기본 거래처 묶음, 품종 전환, 활성 버튼, 원본 행 인덱스 보존, 가로 잘림 없음을 확인했다.
- 후속 보완: 품종 보기의 묶음 키를 품종 단독에서 전산 `Product.CounName → Product.FlowerName → 거래처`로 변경했다. 중국·콜롬비아의 동일 품종은 별도 국가 제목 아래 나뉘며, 국가 미확인 행은 확인 가능한 국가 뒤에 표시한다.
- 진입 위치 보완: `농장 불량 피드백` 바로가기는 조회·저장 작업 도구줄이 아니라 영업수입불량차감의 `미처리·다음 차수 재시도` 바로 다음 업무 탭에 배치하고, 같은 창에서 피드백 페이지로 이동한다.
- 기존 분석 노출 보완: 운영 2026년 원장에서 농장·품목 분석 그룹 145개가 조회되지만 수동 생성 피드백 건은 0개라 기본 피드백 화면이 빈 화면으로 보였다. 진입 기본 화면을 불량 그래프로 바꾸고, 기존 불량 중 분석에 반영된 농장·품목 그룹 수를 상단에 표시한다. 수입부 미확정·농장/품목 미지정 행은 기존 계약대로 제외 건수로 안내한다.

## 농장별 불량률·차수별 이슈 후보 보완

- 요청: 특정 농장을 선택해 차수별 불량률 변화를 보고, 특정 차수에 불량이 많았던 품목을 찾아 피드백 이슈로 처리한다.
- 분모: 같은 연도 `ViewWarehouse.OutQuantity`를 원대차수·농장·단위로 합산한다. 농장 추이는 해당 농장의 모든 입고 품목을 분모로, 품목 후보는 동일 `ProdKey` 입고만 분모로 쓴다.
- 단위: `Product.OutUnit`과 불량 원단위가 정확히 같은 경우만 비율을 계산한다. 박스·단·송이 변환은 하지 않는다.
- 누락 표시: 운영 API 대조에서 기존 피벗 기준 농장·품목 직접 연결은 101개 그룹 중 69개였고 32개는 연결되지 않았다. 분모가 없거나 0이면 0%로 오인시키지 않고 `입고 분모 없음`으로 표시한다.
- 이슈 생성: 차수별 후보는 불량률 우선, 동률은 불량수량 순으로 보인다. 사용자가 `이슈로 처리`를 눌러야만 기존 WebFarmQualityCase/Event 경로로 초안을 열며, 자동 저장하지 않는다. 같은 원본 불량로 이미 만든 건은 `기존 이슈 열기`로 연결한다.
- ERP 영향: Warehouse/Product는 읽기 전용이며 주문·분배·재고·견적·결산 원장을 변경하지 않는다.

## 동일 차수·지속 불량 자동 감지 보완

- 요청: 같은 차수의 같은 농장·품목이 서로 다른 주문에서 반복되거나, 같은 농장의 여러 품목이 동시에 불량이면 이슈로 감지한다. 품목 또는 농장이 연속 차수에 반복되는 상황도 구분한다.
- 표시: `다중 거래처` 문구와 거래처 수를 쓰지 않고 `불량 N건`으로 표시한다. N은 중복 제거한 `DeductionKey` 원본 건수다. 차수·품목·수량·세부차수 근거는 사용자가 항목을 펼쳤을 때만 보인다.
- 감지 기준: 동일 품목 반복은 같은 연도·대차수·농장·품목·단위에서 서로 다른 `CustKey`가 2개 이상인 경우다. 농장 품목 집중은 같은 연도·대차수·농장·단위에서 품목이 2개 이상인 경우다. 품목 지속/농장 반복은 인접 대차수 또는 4개 대차수 안의 3개 발생으로 판정한다.
- 개인정보 경계: `CustKey`는 서버 내부의 서로 다른 주문 판정에만 사용하며 API 응답과 펼친 상세에는 거래처 키·이름을 포함하지 않는다.
- 저장 경계: 자동 감지와 상세 펼치기는 읽기 전용이다. 사용자가 `피드백 이슈로 처리` 또는 이력 저장을 명시적으로 누른 경우에만 기존 `WebFarmQualityCase/Event` 저장 경로를 사용한다.
- ERP 영향: `WebSalesDefectDeduction`, `ViewWarehouse`, Product는 조회만 한다. Order/Shipment/Warehouse/Stock/Estimate/WebProfitReport 원장은 모두 보존한다.

## 피드백 증거 이미지 보완

- 요청: 코멘트·답변·개선 기록에 증거 이미지를 파일로 선택하거나 화면 캡처 후 `Ctrl+V`로 붙여넣고, 저장된 이력에서 바로 확인한다.
- 구현: JPG/PNG/WEBP를 한 기록당 최대 5장 첨부한다. 브라우저에서 긴 변을 1920px로 축소한 뒤 업로드하며, 업로드 중·실패·첨부 예정 썸네일·제거 상태를 표시한다. 내용 입력칸에 초점을 둔 상태의 이미지 붙여넣기도 인식한다.
- 저장·보안: 공개 이미지 URL을 사용하지 않는다. 인증된 전용 API와 `WebFarmQualityEvidence`만 사용하고, 파일 시그니처·10MB 제한을 서버에서 재검사한다. 임시 이미지는 작성자·연도·24시간 만료로 제한하며, 이력 저장 트랜잭션 안에서 생성된 불변 `EventKey`에 연결한다. 저장된 증거는 기존 이력과 함께 표시되고 삭제·덮어쓰기하지 않는다.
- 실패 복구: 이미지 업로드 중에는 이력 저장을 막고, 이력 저장 실패 시 본문과 첨부 이미지를 유지한다. 동일 requestId 재시도는 이벤트와 이미지 연결을 중복 생성하지 않는다.
- ERP 영향: 전용 웹 테이블 외에는 쓰지 않는다. EXE 공유 주문·출고분배·입고·재고·견적·결산 원장은 모두 보존한다.
- 검증: 이미지 시그니처/연도/작성자/멱등 트랜잭션 테스트, 전체 ERP 변경 검증, 프로덕션 빌드, 1920×1080·760×1080·390×1080 브라우저 smoke를 통과했다. 운영 migration·실제 업로드 smoke 결과는 배포 후 아래에 갱신한다.
