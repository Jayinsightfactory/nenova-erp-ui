## 사용자 요청과 확인 결과

**Q.** 41-1 콜 카네이션 변경사항 / 상희 / 돈셀 2박스 추가 / 오늘 출고건입니다는 전달했는데 미확인이다. 최신 메시지는 완료이니 원인을 찾아 해결해 달라.

**A.** 운영 브라우저와 Railway PostgreSQL을 읽기 전용으로 대조했다.

| 원천 | 원문 첫 줄 | 작성시각(KST) | 수집 저장시각(KST) |
|---|---|---|---|
| 영업방 | 41-1 콜 카네이션 변경사항 | 10월12일 11:50 | 11:51:06 |
| 현장 추가취소방 | 41-2 콜 카네이션 변경사항 | 10월12일 12:02 | 14:57:52 |

업체·품목·수량·나머지 본문은 같지만 첫 줄의 세부차수가 다르다. 기존 완전일치 정책상 정상 DELIVERED가 아니다. 수집 지연도 있었지만 14:57 이후에도 완전일치는 성립하지 않는다. 수집기 설정은 다른 PC에서 사용자가 관리하며 이 작업에서 변경하지 않는다.

## 고정한 판단과 부작용

- 정확한 동일 원문은 기존 DELIVERED와 영구 근거 저장을 유지한다.
- 정확 일치가 없고 유효한 선두 차수만 다른 유일 후보이면 UNCONFIRMED/week_mismatch로 안내한다.
- 화면은 주황색으로 `전달 내용 발견 · 차수 다름 (41-01 → 41-02)`를 표시한다. 완료 버튼처럼 작동하지 않는다.
- 수량·업체·품목·동작·본문이 다르거나 이전 시각/다른 연도/추정 시각/잘림/다른 방이면 후보로 연결하지 않는다. 후보 중복은 AMBIGUOUS로 보류한다.
- 후보 원문은 응답에 내보내지 않는다. 후보 식별·시각·차수만 표시하며 후보 근거는 영구 DELIVERED 저장에 넣지 않는다.
- 카톡 발송, 실제 주문·분배 적용, 차수 변경, 재고/확정/견적/매출 원장 보정은 하지 않는다.

| 동작 | Kakao 원문 | 전달완료 저장 근거 | Order/Shipment/Stock/Estimate/WebProfitReport |
|---|---|---|---|
| 차수 다른 후보 조회·표시 | SELECT만 | 보존, 후보 저장 금지 | 전부 보존 |

dnSpy CLI로 설치 EXE FormShipmentDistribution의 선택 연도·차수 및 ShipmentDate 경계를 재확인했다. SQL 저장/API 변경이 없으므로 이번 판단의 실제 운영 probe는 Kakao 원천 PostgreSQL의 BEGIN READ ONLY/SELECT/ROLLBACK이다. MSSQL 원장을 시험 변경하지 않았다.

## 후속 Q&A — 차수 수정 전달도 자동 완료

**Q.** 차수는 잘못 작성해 수정하여 전달한 것이다. 업체·품목·수량이 같으면 확인처리만 문제없이 되면 된다. 수정해 달라.

**결정.** 유효한 맨 앞 차수 토큰만 다르고 나머지 정규화 전체 본문이 같은 유일한 전달은 DELIVERED/week_corrected로 자동 확인한다. 별도 수동 승인 버튼은 요구하지 않는다. 확인된 sourceWeek/targetWeek, 전달 식별자·시각을 웹 전용 증거에 보관하여 재진입·재시작에도 유지한다. 이전 완전일치 저장본은 그대로 읽는다.

### 기준과 소비 경로

| 기준 | 근거 | 적용 경로 |
|---|---|---|
| 차수만 다른 전달 허용 | 최신 명시 사용자 결정과 위 실제 PG 원문 대조 | 공통 matchDeliveryStatus → API → 증거 저장 재검증 |
| 나머지 전체 본문 일치 | 업체·품목·수량·단위·추가/취소 보존 | NFC/공백 정규화, 맨 앞 유효 차수만 제외 |
| 기존 식별·연도·정확 시각·방·원문 완전성 유지 | 기존 인증/전달 계약 | matcher, client, evidence read |
| 중복/경쟁 후보 제외 | 다른 요청을 중복 완료시키지 않음 | 같은 batch 및 분할 요청 경계 |
| 표시·저장 | 전달완료와 전산 적용은 별개 | 녹색 완료 + 차수 수정 이력, 기존 주문/분배 버튼 보존 |

| 동작 | 원문/카톡방 | 웹 전달 증거 JSON | Order/Shipment/ShipmentDate/Farm/Stock/Estimate/WebProfitReport |
|---|---|---|---|
| 차수 수정 전달 자동확인 | 읽기·보존 | 검증된 완료 근거만 원자적 저장 | 전부 보존, 실제 차수 이동·등록·분배 없음 |

실제 설치 EXE FormShipmentDistribution을 다시 CLI로 읽어 선택 OrderYear/OrderWeek 및 GetCustomerList 경계를 확인했다. 이 기능은 해당 SQL/SP를 호출하지 않는다. 원천 데이터 근거는 이번 세션 앞선 읽기 전용 PG 대조이며 운영 원장 테스트 쓰기는 하지 않는다.

메뉴 기준: 완료/실패 구분·재진입 이력 유지·1920×1080/100% 표시 검증 적용. 새 shell/메뉴/검색/ERP 저장 전 확인은 해당 없음. 배포 전 관련 회귀·전체 계약·dnSpy·manifest·write guard·빌드, 배포 후 실제 상희 돈셀 건 재조회로 검증한다.
