# 주광 웹 전체 작업 발주 양식 다운로드

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-07 KST |
| 화면 | 주광 요일 견적서 |
| 원장 부작용 | 없음. 브라우저 XLSX 생성만 변경; Order/Shipment/Stock/Estimate/WebProfitReport/확정 보존 |
| 기준 화면 | 1920×1080 CSS / 100% |

## 고정된 결정

- 사용자는 원본 파일 재다운로드가 아니라 **원본 디자인·셀 서식에 웹 전체 품목명과 현재 작업 수량을 채운 결과**를 요구했다.
- 명시 원본셀 연결만 덮어쓰던 기존 정책은 다운로드 경로에서 폐기했다. 저장 원본은 디자인 자료로 사용한다.
- 화면과 동일한 buildHorizontalWeekdayMatrix → applyWeekdayCarryoverToMatrix 결과에서 모든 품목을 사용한다. 검색/접기/미분배 숨김으로 다운로드 품목을 자르지 않는다.
- 품종 순서는 카네이션→장미→수국→알스트로→그 외. 품목/단위와 날짜 수량, 세부차수 최초·합계·잔량, 대차수 합계·잔량·변경을 채운다.
- 최신 지시로 엑셀의 선택 요일은 기존 수량 / 윌슨 수량 / 요일 합계 3셀로 구분한다. 세부차수·대차수 합계는 이미 합산된 canonical 날짜 총량을 한 번 사용한다. 절대 입력 초안이 저장값보다 우선한다. 미확인은 공란, 0과 음수 잔량은 숫자로 보존한다.
- 단위가 다른 차수는 별도 품목/단위 행으로 보존하고 품종 소계도 단위별이다. 원본의 다른 거래처·과거 값/시트/공유 문자열은 결과에 포함하지 않는다.
- 다운로드 도중 파일·범위·입력·전산 조회·달력·기준·이월 변경을 확인하고 오래된 결과를 다운로드하지 않는다.

### 1. 요청과 수정

Q. “웹작업 전체 품목수량이 디자인 셀양식 품목 이름까지 변경되어서 적용되게 해달라는거지.”

A. 저장 원본의 셀 스타일·너비·품종 병합 구조를 사용해 현재 웹 전체 결과의 새 시트를 생성한다. 두 다운로드 버튼은 동일한 경로를 사용한다. 수동 업로드 내용도 저장한 주광 디자인에 웹 결과를 채운다. 웹 입력/분배/확정은 다운로드에서 실행하지 않는다.

### 2. 윌슨 표시 추가 지시

Q. “윌슨 수량은 웹처럼 해당요일기존수량과 윌슨수량이 셀로 나누어져서 표시되게하는거고.”

A. 이전 합산만 표시하는 엑셀 정책보다 이 지시가 우선한다. 웹에서 선택한 요일을 Matrix→Workspace callback으로 공유해 기존/윌슨/합계 열을 생성한다. 최신 분류 초안을 우선하고 단위·현재 합계·상태가 맞지 않는 이전 분류는 다운로드를 차단한다. 분류 또는 요일을 파일 생성 중 바꾸면 오래된 파일을 내리지 않는다. 실제 견적서는 기존 ERP 총량으로 유지한다.

## 검증

- 실제 Workspace callback: 전체 모델 전달, 중복 클릭/실패 복구, 비동기 파일/범위/수량/달력/기준/이월 변경 차단.
- 실제 공유 matrix 계산: 최초5/일요일3 → 세부합계3/잔량2, 초안4 → 합계4/잔량1; 전년도 같은 차수 미혼입.
- 생성 XLSX 재읽기: 웹 품목명, 숫자0/음수/미확인, 동적 품목·품종, 단위별 소계, 원본 스타일 보존 및 과거 개인정보 제외.
- 원본과 생성 XLSX는 bundled artifact-tool로 렌더링해 확인한다.
- 필수 ERP 계약/dnSpy/manifest/쓰기 가드/빌드 후 PR/master/Cafe24 배포. CUA는 kernel assets 경로 오류로 실제 버튼 클릭 검증 불가; 서버/Actions smoke 결과와 구분해 보고한다.
