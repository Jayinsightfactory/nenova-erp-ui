# 2026-09-16 업로드 주문등록 원본·매칭 동시검토

## 질문 → 답변

- 질문: 출고 내역서 Excel을 업로드했을 때 원본 시트와 매칭 결과, 합산수량을 동시에 보고 사용자가 등록을 시작한 뒤 진행 로그와 결과까지 확인하고 싶다.
- 답변: 선택된 원본 시트를 읽기 전용으로 왼쪽에 표시하고, 오른쪽에 매칭 품목 합산표와 상세 수정표를 배치했다. 등록은 `주문등록 시작`을 눌러야만 기존 `/api/orders` 경로로 수행되며, 요청·저장·DB 재조회 단계와 최종 결과를 화면에 남긴다.

## 함께 보완한 파싱 규칙

- `컬러`와 `칼라` 헤더를 모두 인식한다.
- `합계(박스)`·`합계(단)` 단위를 앞선 품목행에 적용한다.
- 국가·화종·길이 문맥을 품목 매칭어에 유지해 중국/콜롬비아 동명 품목 충돌을 막는다.
- 특별 주문·주말 도착 그룹의 빈 품명 후속행도 누락하지 않는다.
- 본문 제목에서 업체·차수를 못 찾으면 파일명(`37차 업체명 출고 내역서.xlsx`)으로 보완한다.
- 같은 ERP 품목에 서로 다른 단위가 남아 있으면 등록 버튼을 차단해 단위 혼합 저장을 방지한다.

## ERP 안전 범위

- 업로드·원본 시트 미리보기·매칭·합산은 읽기 전용이다.
- 명시적 등록 버튼을 누르기 전 `OrderDetail`을 쓰지 않는다.
- 주문 저장 API와 `delta:true` 의미는 변경하지 않았다.
- `ShipmentDetail`, `ShipmentDate`, 재고, 견적, 손익 원장은 변경하지 않는다.
- 저장 후 `OrderYear + OrderWeek + CustName`으로 주문을 다시 읽어 결과를 표시한다.

## 추가 합의 — 업로드 파일은 추가분이 아니라 전체 최종본

- 질문: 주문등록 프로세스가 기존 수량에 더하는 방식인지, 업로드 파일의 수량이 해당 업체·해당 차수의 최종수량인지 확인 요청.
- 답변/결정: 업로드 파일은 `OrderYear + OrderWeek + CustKey` 전체 주문 최종본이다. 파일 내부에서 같은 ERP 품목으로 매칭된 여러 행만 합산하고, 그 합계가 해당 `ProdKey`의 절대 최종수량이 된다.
- 기존 `delta:true / source=import` 가산 호출은 요구와 달라 즉시 사용 중지를 안내하고 `source=order-import-final / orderMode=FINAL_SNAPSHOT` 전용 정책으로 교체했다.

### 최종본 적용 계약

- 파일에 있는 품목: 현재 주문에 더하지 않고 최종수량으로 교체한다.
- 파일에 없는 현재연도·현재차수·현재업체 활성 주문 품목: 같은 트랜잭션에서 0/삭제 처리한다.
- 누락 품목에 이미 `ShipmentDetail`이 있으면 주문과 분배가 어긋나므로 품목을 표시하고 전체 롤백한다.
- 동일 파일 재실행: 수량을 다시 더하지 않으며, 동일 품목은 `UNCHANGED`로 반환해 `OrderDetail`과 `OrderHistory`를 다시 쓰지 않는다.
- 2025 같은 차수는 변경하지 않는다. 업무키는 `OrderYear + OrderWeek + CustKey + ProdKey`다.
- 직접 변경 범위는 `OrderMaster`, `OrderDetail`, `OrderHistory`뿐이다. `Shipment*`, `Stock*`, `Estimate`, `WebProfitReport`는 보존한다.

## 후속 보완 — 원본 Excel 행 옆에 ERP 매칭 셀 표시

- 질문: 좌우로 분리된 원본 시트와 매칭 상세표를 번갈아 보지 않고, 업로드한 Excel 행 바로 옆 셀에서 매칭값을 확인하고 싶다.
- 답변/구현: 원본 시트의 열과 행번호를 유지한 채 오른쪽에 `ERP 매칭 품목`, `최종수량`, `단위`, `상태·수정` 열을 붙였다. 파란 구분선과 연두색 원본 행으로 원본/전산 영역을 구분한다.
- 같은 ERP 품목으로 합산되는 원본 행은 첫 행에서 합산 최종수량을 편집하고, 후속 행에는 `이 행 수량 → 합산수량`을 표시해 중복 등록으로 오해하지 않게 했다.
- 품목 변경·수량·단위·제외는 인접 셀에서 바로 수정한다. 입력 품목명과 추천 후보까지 필요한 경우에는 접힌 `전체 상세 편집표`를 펼친다.
- 합산 품목 요약과 명시적 `주문등록 시작`은 유지했다. 인접 셀 편집은 클라이언트 초안만 바꾸며 주문·분배·재고 원장 저장 방식은 변경하지 않았다.

### 열 위치 정정

- 사용자 확인 결과, 매칭 열을 원본 전체 열의 끝에 붙이면 가로 이동이 필요했다.
- 원본 헤더에서 `발주수량`을 우선 찾고, 없으면 `주문수량`, `수량` 순으로 찾아 바로 뒤에 ERP 매칭 품목·최종수량·단위·상태를 삽입한다.
- 출고수량·단가·단수량·비고 등 나머지 원본 열은 ERP 매칭 열 뒤에 계속 표시한다. 수량 헤더를 찾을 수 없는 예외 양식만 원본 열 끝에 붙인다.
