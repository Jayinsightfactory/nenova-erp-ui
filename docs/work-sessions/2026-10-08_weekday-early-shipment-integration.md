## 이어받을 때 고정된 결정

- 선출고는40차→41차 같은 큰 차수에서만 처리한다. 세부차수는 내부 실제 업무키다.
- 기존 추가 분배를 선출고로 분류할 때 물량을 다시 더하지 않는다. 초안은 날짜 최종 절대수량이다.
- 원천 재고+q/대상 재고-q와 날짜 분배 및 연결 원장은 하나의 트랜잭션이다.
- 업로드 원문10/처리선출고3/기존분배2이면 최종7, 증감+5다. 기존2를 다시 차감하지 않는다.
- 이미 제외된 원문과 포함된 원문을 명시적으로 구분하고, 대상첫실제업무차수에서만 자동 차감한다.
- 윌슨·전체 웹 품목명/수량을 원본 디자인으로 출력하는 기능은 이전 PR952 배포가 기반이다.
- 분류 취소는 기존 날짜 분배를 보존한다. 날짜 수량 수정은 기존 분배 작업으로 수행한다.

### 1. 대차수 선출고와 업로드를 같이 관리

**Q.** 주광에서 선출고 처리한 품목·수량은 다음 큰 차수 업로드에서 제외하고, 검증 시 이미 분배된 부분을 표시해야 한다. 작업기획 후 시작.

**A.** 설계·계약·실제 EXE와 DB 읽기 근거를 준비한 뒤 연결 원장/API, 페이지 밖 처리 패널, 업로드 비교값과 최신 원장 재검증을 구현했다. 재시도는 같은 UUID를 보존한다. 일반 분배 수정이나 EXE 변경으로 원천 물량이 사라지면 잘못된 대상 차감을 차단한다.

**결과.** `docs/plans/weekday-early-shipment-integration-2026-10-08.md`, `docs/contracts/weekday-early-shipment-integration.json`, `docs/exe-golden/WeekdayEarlyShipmentIntegration.md`. 원시 dnSpy/운영 조회·로그는 ignored output에 보관하며 커밋하지 않는다. 운영 업무 데이터의 선출고 적용은 테스트 목적으로 수행하지 않았다.

## 검증·배포 진행

- 직접 브라우저 UI 자동화는 Windows 현재 URL 확인 실패로 도구가 중단했다. 기준1920×1080/100%의 직접 조작 검증은 완료로 주장하지 않는다.
- 로컬 필수 계약검사·dnSpy 근거·manifest·쓰기 검사·빌드 모두 통과했다. 격리 실제 MSSQL에서 고정/미고정 절대수량, 재시도/취소, source upload 무결성, target anchor 생성, 미래/현재 음수와 단계 실패 원자성 검증을 통과했다.
- PR/배포 결과는 확정 후 갱신한다.
