## 고정 결정
- 직원 작업 진행을 로그로 재구성하되 클릭/응답/실제 저장을 혼동하지 않는다.
- 기존 공통 수집기를 확장하며 원장/EXE/SP 변경 없음.
- workflowId는 동일 로그인 창의 흐름, requestId는 요청↔응답, actionId는 동기 조작만 연결한다.
- 계정 변경/새 로드 시 흐름 분리. 비동기 호출에 직전 클릭을 임의 귀속하지 않는다.
- 입력값/원문/SQL/비밀정보 수집 금지. 서버 응답의 제한된 집계·감사키만 기록한다.
- EXE 방법 조사 요청이며 운영 EXE 패치/배포 권한으로 확장하지 않는다.

### 1. 로그만으로 업무 진행 확인
**Q.** 기존 모든 웹 로그를 확인하고 작업 파이프라인을 볼 수 있게 보완.
**A.** 기존 공통 활동 로그 존재 확인. 요청 시도와 서버 응답 연결, 흐름·요청 검색, 페이지 내 시간순 표시, 연결단절 저장여부 미확인, 서버 집계/감사 참조를 추가. 클라이언트 위조 증거는 저장하지 않음.
**한계.** 전 화면 변경 전후 값과 원자적 저장 증거를 모두 신규 구축한 것은 아니다. 기존 업무별 감사가 실제 반영 판정 근거이며, 이번 전역 기록은 경로·순서·요청·응답 추적을 보강한다. 과거/EXE/ECOUNT 제외/저장소 장애의 완전성 보장 없음.

### 2. 실행 파일만 있는 EXE도 가능 여부
**Q.** dnSpy 기준 기존 기능과 충돌 없이 EXE 작업 흐름 로깅 방법 조사.
**A.** 실제 EXE 로그인/분배/DBMSSQL 호출 확인. 별도 계측 복사본+로컬 저널 권장, 원본/격리 비교 후 카나리. 상세 `../plans/exe-workflow-audit-2026-11-04.md`. 운영 EXE 교체·DB 변경 없음. 계측본 실행 호환성은 미검증.

## 검증
- 사용자 활동 서버/클라이언트/PC 앱 테스트 PASS. async 연결/계정 전환/서버 증거 위조 배제/0건 보존/교차연도 테스트 포함.
- manifest 191, ERP 쓰기 가드, dnSpy 근거 가드 PASS.
- 전체 ERP/빌드/브라우저/PR/배포 진행 중.
