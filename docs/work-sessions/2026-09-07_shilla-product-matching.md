# 신라 품목 연결·차수별 매입단가 통합

## 사용자 요청

“신라도 품목 매칭 가능하게 해주고, 차수별 매입단가관리에 같이 매칭 되었으면해.”

## 적용할 답변/설계

- 신라 저장행에서 전산 품목 검색·선택·연결 해제를 제공한다.
- 같은 전산 품목과 같은 단위는 차수별 매입단가 관리의 한 품목 행에서 함께 비교한다.
- 라움·초이문 공통 단가와 신라 별도 단가는 독립 저장한다. 세 업체 공통 가격으로 확대하지 않는다.
- 원본명·색상·단위·수량·금액·이익배분율을 연결 때문에 변경하지 않는다.
- 전역 매칭 학습과 ERP 주문·분배·재고·견적 원장은 변경하지 않는다.

## 실제 확인

사용자가 저장한 신라 2026년 35차 6개 품목을 로그인 화면에서 읽었다. 매입 합계 10,250,892원, 매출 합계 13,145,120원이다. 단위가 다른 품목은 임의 환산하지 않는다. 실제 사용자 자료를 시험 목적으로 변경하지 않았다.

## 역할/자료

- 설계·최종 검토: 고성능 작업자. 범위 확정 구현: 중간 비용 작업자, API/순수 함수와 화면을 분리.
- 외부 쓰기·운영 반영은 메인만 수행한다.
- 설계: `docs/work-reports/2026-09-07_shilla-product-matching-design.md`
- 사전 근거: `docs/work-reports/2026-09-07_shilla-product-matching-preflight.md`
- 상태: 구현 및 검증 진행 중. 실제 배포·검증 결과는 완료 시 추가한다.

## 구현·로컬 검사

- 신라 행 전용 품목 연결 저장, 활성 품목 재확인, 행/차수 충돌 차단과 재업로드 연결 보존을 구현했다.
- 같은 전산 품목·단위의 공통 단가와 신라 단가는 한 행의 별도 입력칸에 표시한다. 무상입고 0원·다른 단위·미매칭 품목은 보존한다.
- 연결 성공/해제/no-op, 2025·2026 교차연도, 모든 원본값 변경, 부모 저장 실패 시 되돌림, 가격만 바뀐 경우의 독립성, 신라 전용 셀 격리와 중복 결산 차단을 실행형 검사했다.
- 실제 React 렌더링에서 공통/신라 입력 2개, 0원, 입력 중 매입액 계산, 음수 안내, 저장 중 비활성 상태를 검사했다.
- `verify:erp-change` 전체 성공(103페이지 빌드 포함). 최종 안내 보완 후 `test:raum-pnl`, 재빌드, 신규 API 1개 포함 쓰기 보호, 계약 42개 범위 검사와 dnSpy 근거 검사도 성공했다. 고성능 최종 검토에서 미해결 P1/P2 없음. 운영 반영은 이어서 메인이 수행한다.
