# 카톡 원문과 최신 전산 변경 이력 나란히 연결

## 목표

저장된 AI 보고서가 없어도 명시적인 카톡 변경 요청을 현재 전산 이력과 읽기 전용으로 대조한다. 카톡 원문과 해당 품목별 이력을 같은 가로 행에 붙여 표시한다. 자동 비교는 작업을 차단하거나 전산을 변경하지 않는다.

## 기준 원천과 부작용

- `FormOrderHistory.GetData`, `FormOrderAdd`의 이력 저장: OrderHistory는 주문 변경이다. `ColumName=주문수량`의 before/after는 OutQuantity이며 미발주수량과 구별한다.
- `FormShipmentHistory.GetData`: ShipmentHistory→ShipmentDetail→ShipmentMaster로 연도·차수·업체·품목을 연결한다. 확정 때만 기록되거나 삭제된 상세로 연결이 끊길 수 있어 부재는 미적용의 증거가 아니다.
- 최신 사용자 정정: 수동 체크만 원문에 붙이는 것으로는 부족하다. 실제 이력 연결과 물리적 인접 표시가 필요하다.

| 동작 | Order/Shipment/Stock/Estimate/WebProfitReport | 수동 표시 | AI 보고서 |
|---|---|---|---|
| 최신 카톡·이력 대조 | SELECT only / 전부 보존 | 보존 | 보존 |
| 기존 명시 AI 비교 | 기존 조회 계약 | 보존 | 기존 저장 계약 |
| 수동 적용함/해제 | 전부 보존 | 기존 명시 저장 | 보존 |

## 고정 판정

1. 선택 year/full week, 최대 7일 기간을 명시한다. 02 합산은 명시 설정에서만 한다.
2. 카톡 파싱은 저장된 별칭/전산 정확명으로 업체와 품목이 유일한 경우만 연결한다. 문장 속 수량·단위·추가/취소를 보존하며 줄별 업체 문맥은 같은 원문 내부에서만 적용한다.
3. 차수가 원문과 다르거나 복합 수량, 출고일 변경만, 삭제 메시지, 불명확한 별칭은 확인 필요로 남긴다. 같은 이름 후보를 최근 사용량만으로 확정하지 않는다.
4. 원문 시각 이후의 같은 연도·전체 차수·업체·품목 이력만 후보로 삼는다. 단위는 Product의 명시 환산계수만 사용한다. 누락 계수와 근사 시각은 판정 제한을 표시한다.
5. 주문수량 이력과 분배 이력을 별도 표시한다. 0→0 및 미발주수량을 분배 적용 근거로 쓰지 않는다. 단일 동일 변화량은 동일 변동 이력, 부분/복수/경쟁 원문은 확인 필요다. 동일 이벤트를 여러 요청의 완료로 중복 사용하지 않는다.
6. 이력이 없으면 '대응 이력 미확인'. 원천의 누락 가능성/조회 상한과 조회 시각을 표시한다. 자동 적용됨 판정이나 ERP 쓰기 금지.
7. 자동 대조는 코드만 사용한다. AI 비교는 기존 명시 버튼만 호출한다. raw chat은 명령이 아니라 데이터다.

## 화면과 수용 기준

- 1920×1080, 100%. 왼쪽 두 열 폭을 카톡/해당 이력 쌍으로 사용하고 입력·분석·실행결과는 옆의 남은 폭에 유지한다. 좁은 화면은 원문 바로 아래 이력으로 전환한다.
- 최신순 원문 한 묶음마다 관련 업체·품목·주문/분배·전후수량·시각·연결 사유가 붙는다. 수동 적용 버튼은 보존한다.
- 주기 조회는 중복 실행 없이 bounded, scope 변경/응답 역전/실패 때 초안 보존. LLM 자동 호출/ERP POST 없음.
- 실제 실행은 기존 버튼만 담당한다. 오른쪽 주문 전체 이력은 접힌 참고 목록으로 남기되 주된 연결 결과로 오인하지 않게 한다.
- 실행 fixture: 한국어 별칭, 복수 업체/품목, 1박스 환산, 취소 후 타 업체 추가, no-op, 이전 시각/전년도/다른 차수, ambiguous alias, 복합수량, 동일 이벤트 경쟁, 조회 실패/기간 변경, 가로 잘림.

## API 계약

- `POST /api/orders/distribution-live-history`: 로그인된 같은 출처의 읽기 전용 일괄 대조.
- 명시 year/week/from/to와 최대 50개 원문을 받으며 `advisoryOnly:true`,
  `erpAction:NONE` 및 원문 `sourceIdentity`별 요청·주문 이력·분배 이력을 돌려준다.
- 원문이나 대조를 서버에 저장하지 않으며 LLM을 호출하지 않는다. 기존 수동 확인
  저장 및 사용자가 누르는 AI 비교 버튼은 별도 경로로 유지한다.
- 15초 자동 조회는 활성 화면에서만 한다. 실패 때 마지막 정상 결과와 입력 초안을
  보존하며, 다른 연도·차수·기간의 응답을 새 화면에 섞지 않는다.
- 전산 이력은 동일 범위 진행 중 요청을 공유하고 성공 결과를 30초 보관한다.
  SQL 요청 제한은 8초이며 실패 결과는 캐시하지 않는다. 화면 기준 시각은 실제
  자료를 읽은 시각이다. 카톡 수신의 15초 확인 주기와 구별한다.
