# 영업방 원문 옆 적용 표시

## 사용자 결과

최신순 원문마다 수동 적용 표시와 저장된 전산 비교 이력을 함께 보여준다.
기존 등록·분배·확정은 체크리스트 상태와 무관하게 계속할 수 있다.

## 기준과 상태

- 원문 키는 source/chat_id/external_message_id의 기존 identity를 그대로 사용한다.
- 선택 연도와 전체 세부차수로 분리한다. 다른 연도 또는 차수 기록은 가져오지 않는다.
- `REVIEWED`는 확인완료일 뿐 적용됨으로 변환하지 않는다.
- 기존 checklist의 `REVIEWED`는 독립적인 검토 상태로 보존한다. 적용 여부와 서로 변환하지 않는다.
- `MANUALLY_APPLIED`: 적용됨 · 수동 확인. 사용자가 직접 누른 경우만 별도 수동 적용 원장에 저장한다.
- `MANUALLY_NOT_APPLIED`: 미적용 · 수동 확인. 이력 부재로 자동 지정하지 않는다.
- `CLEAR`: 표시 해제. 기본 적용 미확인으로 보이게 하되, 기존 이벤트를 지우지 않고 별도 수동 적용 원장에 새 이벤트로 남긴다.
- 수동 적용 이벤트에는 선택 연도·전체 세부차수, 원문 `sourceIdentity`, 요청 UUID, 직전 이벤트 ID의 낙관적 CAS 기준, 서버 actor/time을 함께 보관한다. year/week별 private 원장의 결정적 transition claim이 receipt를 exclusive hard-link해 CAS winner를 정하며, 단순 read-then-append·TTL 기반 잠금 탈취는 사용하지 않는다.
- 자동 비교의 MATCHING_HISTORY는 동일 변경 이력이지 요청의 인과관계나 현재 완료를 증명하지 않는다.
- 자동 비교와 수동 상태는 각각 표시하고 서로 덮어쓰지 않는다.
- 저장한 비교 결과의 기준시각을 표시한다. 자동 LLM 분석은 실행하지 않는다.
- 원문 전체의 여러 품목 중 일부 결과만 있는 경우 전체 적용으로 표시하지 않는다.

## 부작용 표

| 동작 | 수동 확인 파일 | 비교 파일 | 모든 ERP 원장 |
|---|---|---|---|
| 목록/이력 표시 | 읽기 | 읽기 | 보존 |
| 수동 적용/미적용/표시 해제 | 별도 이벤트 추가 | 보존 | 보존 |
| 기존 명시 비교 | 보존 | 기존 보고서 저장 | 기존 읽기 계약, 쓰기 없음 |

Order/Shipment/ShipmentDate/ShipmentFarm/Stock/Estimate/WebProfitReport와 기존 저장 API는 수정하지 않는다.
dnSpy golden의 native 이력은 매 수정의 완전한 기록이 아니므로 이력 없음=미적용 판정은 금지한다.

## UI와 요청

1920×1080, 100%에서 원문과 적용 상태/이력을 같은 카드에 배치하고 주요 버튼을 인접하게 둔다.
좁은 열에서는 카드 내부 줄바꿈을 허용하되 페이지 가로 넘침은 만들지 않는다.
수신함 단위 일괄 조회를 사용하며 메시지 수만큼 GET/LLM 요청을 만들지 않는다.
늦은 응답은 차수 변경이나 새 저장을 덮어쓰지 않는다. 저장 실패는 미완료 표시하며 재시도 UUID를 유지한다.
운영 검증에서 실제 고객 메시지를 시험 목적으로 적용됨 표시하거나 ERP 분배를 수정하지 않는다.

## 수용 검사

신규/기존 상태, 재조회 지속, 표시 해제, 중복 요청, 교차연도/차수, 오래된 응답,
부분/불명확/이력없음, identity 불일치, 전체 원문 내 여러 요청, 최신순,
자동 GET 이외 쓰기 없음, ERP 계약/빌드, 1920×1080 화면을 검증한다.
