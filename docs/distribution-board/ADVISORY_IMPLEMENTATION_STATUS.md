# 참고용 카톡 체크리스트 구현 상태 — 2026-09-10

## 사용자 결정

카톡 변경 요청과 실제 분배를 비교하는 기능은 참고용이다. 미반영 의심, 일부 반영,
대조 불가, 조회/저장 실패를 이유로 기존 주문등록·분배·수정·확정을 막지 않는다.
기존 ERP 자체의 유효성 검사는 변경하지 않는다.

## 원문 수동 확인 구현

- 영업방 수신함의 원문별 수동 확인 상태: 미확인/확인완료/처리불필요/나중에확인.
- 메모와 인증된 작성자·서버 시각을 웹 전용 파일에 추가 기록. 과거 이벤트 보존.
- 연도와 세부차수, 원문 식별값으로 조회. UUID 재전송 중복 방지.
- 수동 확인을 전산 반영 완료로 표현하지 않음. 자동 대조는 아직 실행 전으로 표시.
- 기존 작업 handler, 전산 쓰기 API, 확정·재고 계산은 변경하지 않음.
- 목록이 200건을 넘으면 다음 검토 목록으로 이동 가능. 앞 200건만 숨겨진 한도로 두지 않음.

## 검증

- distributionChecklistStore, distributionChecklistUi, distributionSalesInbox 테스트 통과.
- 앞선 ERP 전체 검사 및 빌드 통과. 최종 UI 추가 후 별도 빌드 재검사.
- 1920×1080 CSS px, 100% 로컬 운영 빌드 시험 화면: 가로 1920, 문서 폭 1920, pageerror 0.
- API를 시험 응답으로 대체해 503 오류 객체 → 메모 유지 → 기존 작업 시험 버튼 활성 → 같은 요청 재시도 성공 확인.
- 브라우저 시험의 POST는 모의 checklist API 두 번뿐. 운영 ERP 쓰기 없음.
- 임시 화면 pages/dev/checklist-local-review.js는 검사 후 제거.

## 후속 자동 대조 구현 — 2026-09-10

- 카톡 원문을 선택한 뒤 별도 버튼으로 변경 요청을 추출한다. 수량·단위·차수를 임의로 채우지 않는다.
- 원문 식별값과 인용문을 검증하고, 빠진 메시지는 확인 필요로 남긴다.
- 전산 업체·품목, 명시 연도와 세부차수, 단위, 변경 시각 및 출고일을 대조한다.
- 현재 합계만 같다는 이유로 완료로 판단하지 않는다. 같은 변경 이력, 일부 이력, 확인 필요를 구분한다.
- 실제 37-01·37-02 SELECT 검증: 변경 이력 347건, 현재 출고일별 자료 809건. 원장 쓰기 없음.
- native nenova.exe의 이력은 확정 시 생성될 수 있고 삭제된 출고행은 연결이 끊길 수 있으므로 이력 완전성은 false다.
- 조회 전용 인증키 설정은 사용자가 승인했고 source와 web secret에 설정했다. 원문 서버 PR8 병합 및 Railway 배포 성공, health 200·비인증 조회 401 확인.

## 아직 별도로 검증할 범위 — 완료로 오해하지 말 것

- 카톡 변경 요청 대조와 별개로, 기준 엑셀의 출고일·단위 연결 및 전산 현재값을 같은 표에 합치는 기능은 별도 범위다.
- 자동 대조의 실제 화면, 영구 저장 재조회 및 웹 운영 배포 결과는 최종 검증 보고서에 기록한다.
- 이 문서의 구현 설명만으로 운영 반영 완료를 주장하지 않는다.

## 다음 작업

카톡 해석 결과를 원문 묶음·개별 변경 요청과 연결하고, 전산의 정확한 연도/차수/업체/품목/
출고일/단위 및 변경 이력으로 비교한다. 현재 합계만 같으면 반영 완료라고 단정하지 않는다.
자동 대조 결과는 수동 확인 이벤트와 별도로 보존하고 어떤 결과도 기존 작업의 차단 조건으로 연결하지 않는다.
