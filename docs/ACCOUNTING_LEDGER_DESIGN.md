# 네노바웹 회계 원장 설계 (이카운트 해지 → 바로빌 API 원천)

작성 2026-10-20 · 상태: **설계만(코드·DB 변경 없음)** · 결정자: 사장님(2026-10-20 "이카운트 해지, 바로빌 API를 원천으로 네노바웹이 전표·거래처원장·결산·세무사 전달까지")

## 0. 읽는 법

- **근거 표기**: `[관찰 MM-DD HH:MM]` = 강명훈 관찰 기록(`nenova-work-features/observed/강명훈.json`, `_kmh-ecount-detail.md`, `_kmh-ecount-spec.md`, 9/18~10/14)에서 직접 확인. `[코드]` = 저장소 코드/PR에서 확인. **`[가정]` = 관찰 없음, 설계자 가정 — 사람 확인 후 확정**.
- **관찰이 말해 주는 핵심**: 강명훈의 이카운트 사용은 *입력*이 아니라 *대사(검증)* 가 압도적이다. 직접 저장(생성)하는 화면은 지출결의서·지급결의서·급여 지출결의서·구매수정·견적서입력 **5종뿐** [관찰 spec §11]. 따라서 네노바웹의 1순위는 "이카운트를 대체해 전표를 *손으로* 쓰게 하는 것"이 아니라 **원천(은행·카드·세금계산서·ERP)에서 전표를 자동으로 만들고, 사람은 보류함만 푸는 것**이다.
- **제약 준수**: ECOUNT 조회 전용(해지 전 이관 데이터는 스냅샷 읽기만), ERP 원장 테이블(Order/Shipment/Stock 계열) 쓰기 금지, 웹 전용 테이블(`Web*`)만 신설, 새 API는 `docs/contracts` 등록 필수(§4.4).
- **미수행→보완(2026-10-20 후속)**: ① 스냅샷 조회 완료(§2-1에 결과). 단 스냅샷 4종(판매·채권·채무·입출금)에는 **계정과목 필드가 없어** 계정 목록 자체의 검증은 불가 — 거래처 구성만 검증. ② 바로빌 요금은 사장 제공 견적값으로 §6-3 D3 에 반영(PDF 직접 추출은 실패, 값은 요청 세션 전달분). ③ 바로빌 API 필드명은 바로빌 개발자센터 문서 확인 전의 `[가정]`.

## 3. 자동분개 규칙

공통: 모든 자동분개 전표는 `Status=작성`(초안)으로 생성, 확정은 사람(강명훈) 또는 규칙별 "자동확정 허용" 플래그가 켜진 규칙만. 거래처는 **Customer.CustKey(국내 매출처) 또는 해외농장 마스터**로 매칭하고, 매칭 실패는 전표를 만들지 않고 **보류함**(§4.1 `WebLedgerHold`)에 원천 레코드를 그대로 쌓는다. 중복 방지 키 = (원천종류, 원천 고유ID) UNIQUE.
