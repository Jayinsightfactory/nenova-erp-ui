# 화면 기준 한 벌 (버튼·카드·표·탭·알림·빈 화면)

기준일 2026-11-14 · 담당 파일(한 곳). 솔루션으로 내놓는 화면(`/work/manuals`, `/pm`, `/pm/radar`, `/ops`, 메뉴 제안 카드, 아침 브리핑)은 이 기준을 따른다.
근거 사례는 [`UI_REFERENCES_2026-11-14.md`](UI_REFERENCES_2026-11-14.md), 고치기 전 진단은 [`UI_AUDIT_2026-11-14.md`](UI_AUDIT_2026-11-14.md).

## 0. 원칙 세 줄

1. **한 화면에 주 버튼은 하나.** 나머지는 보조·약한 버튼으로 낮춘다.
2. **글은 제목만 먼저.** 긴 설명·원문·근거는 접어 두고 누르면 펼친다. 사람이 해야 할 일만 위에 둔다.
3. **새로 만들지 않는다.** 버튼·칩·탭·카드·알림·빈 화면은 `components/pm/ui.js` 키트에서만 꺼내 쓴다. 색은 `lib/pmThemes.js` 토큰(`var(--pm-*)`)만 쓴다.

## 1. 공용 부품 (`components/pm/ui.js`)

| 쓰임 | 부품 | 규칙 |
|---|---|---|
| 주 버튼 | `<Button variant="primary">` | 화면(또는 창·카드 묶음)당 1개. 묶음의 오른쪽 끝. |
| 보조 버튼 | `<Button variant="secondary">` | 기본값. 줄 안 버튼은 `size="sm"`. |
| 약한 버튼 | `<Button variant="ghost">` · `<LinkButton>` | 돌아가기·더 보기·접기처럼 흐름을 바꾸지 않는 것. |
| 위험 버튼 | `<Button variant="danger">` | 지우기·되돌릴 수 없는 일에만. 글귀에 대상을 적는다("이 단계 지우기"). 색만으로 알리지 않는다. |
| 진행 중 | `<Button loading>` | 누른 버튼 안에 돌림 표시. 글귀는 그대로 둔다(폭이 흔들리지 않게). 1초 안에 끝나는 일에는 쓰지 않는다. |
| 필터·상태 고르기 | `<ToggleChip on>` | 즉시 반영. 걸린 조건이 있으면 "조건 지우기"를 같은 줄 끝에 둔다. |
| 탭 | `<Tabs>` | 같은 화면 안의 다른 묶음. 글귀 1~2단어. 순서가 있는 작업은 탭이 아니라 단계 표시. |
| 누르는 카드 | `<SelectCard>` | 카드 전체가 눌린다. 펼치는 카드는 `expanded`, 고르는 카드는 `pressed`. 카드 안에 다른 버튼을 넣지 않는다. |
| 닫기 | `<IconButton label="닫기">` | 아이콘만 있는 버튼은 `label` 필수. |
| 상태 꼬리표 | `<Badge>` | 색 + 글을 함께. 색만으로 상태를 말하지 않는다. |
| 화면 안 알림 | `<Notice tone="info\|ok\|warn\|error">` | 자동으로 사라지지 않는다. 오류는 "무슨 일인지 + 다음 행동 버튼 1개". 사용자 탓으로 쓰지 않는다. |
| 빈 화면 | `<EmptyState title action>` | "왜 비었는지 + 다음 한 걸음(버튼 1개)". 불러오는 중에는 쓰지 않는다. |
| 불러오는 중 | `<Skeleton rows card>` | 표·카드·목록 자리에만. "불러오는 중…" 글자만 두지 않는다. |
| 상단바 뒤로가기 | `components/MenuBackButton.js` | 모든 메뉴 공통. 옆 버튼과 같은 모양(흰 바탕·얇은 테두리). |

`/pm` 계열 화면은 키트 밖의 `<button>`을 쓰지 않는다(`__tests__/pmUiKit.test.js`가 검사).

## 2. 버튼 배치

- 창·서랍·양식의 아래 줄: 왼쪽 **취소**(보조), 오른쪽 끝 **실행**(주). 주 버튼은 하나.
- 승인·거절: 오른쪽 끝 **승인**(주), 그 왼쪽 **돌려보내기**(보조). 거절이 되돌릴 수 없으면 위험 버튼 + 확인 한 번.
- 저장: 양식은 **저장 버튼으로 한 번에**, 켜고 끄는 것만 즉시 반영. 한 양식에서 둘을 섞지 않는다. 저장이 실패해도 입력한 값은 남긴다.
- 되돌리기: 가벼운 일(순서 바꾸기·숨기기)은 확인 창 대신 바로 하고 "되돌리기"를 준다. 확인 창은 드물고 무거운 일에만.
- 표 안의 줄 버튼: 2개까지 `size="sm"`로 줄 끝에. 3개부터는 "더 보기"에 넣는다.
- 내려받기·올리기: 글귀에 무엇을 받는지 적는다("엑셀로 받기"). 올리기는 받는 형식·크기 제한을 버튼 옆에 미리 적는다.

## 3. 버튼 말투

- **동사로 끝낸다**: "매뉴얼 열기", "다시 불러오기", "조건 지우기", "엑셀로 받기".
- **쉬운 말**: 내부 이름·영어·개발 용어를 쓰지 않는다. (금지 예: "pm-office 데이터", "토큰 미설정", "fetch 실패")
- **모호한 말 금지**: "확인", "예/아니오", "완료"만 단독으로 쓰지 않는다 → "확인 완료로 바꾸기", "지우기 / 그대로 두기".
- 실제 일어나는 일과 같게: 저장하지 않으면 "저장"이라고 쓰지 않는다.
- 12자 안쪽. 문장부호 없음. 이모지는 버튼 글귀에 넣지 않는다(상태 꼬리표에는 허용).
- 직원이 보는 문구에 감시·추적을 떠올리는 낱말을 쓰지 않는다 → "업무 기록", "내 작업 내역".

## 4. 크기·간격·글자

| 항목 | 값 |
|---|---|
| 버튼 높이 | 기본 32px · 작은 것 28px · 좁은 화면(640px 이하) 44px / 36px |
| 누르는 것의 최소 크기 | 24×24px 아래로 내려가지 않는다(상단바 포함). 좁은 화면은 36px 이상. |
| 모서리 | `var(--pm-radius)` (버튼·칩·카드 공통). 카드 바깥은 `+4px`까지. |
| 간격 눈금 | 4 · 8 · 12 · 16 · 24 · 32px 만. 부품 안 4~12, 부품 사이 16~24, 큰 구획 32. |
| 글자 크기 | 11(꼬리표·보조) · 12(작은 버튼·칩) · 13(본문) · 14(탭·카드 제목) · 16~17(구획 제목) · 22~24(화면 제목). 10px 이하는 쓰지 않는다. |
| 굵기 | 본문 400, 강조·선택됨 700. 그 사이 값은 쓰지 않는다. |
| 한 줄 길이 | 설명 글은 60자 안팎에서 줄바꿈되게(`max-width: 46~60ch`). |

## 5. 색

- 테마 색은 `lib/pmThemes.js` 한 곳. 화면 CSS에는 hex 를 쓰지 않는다.
- 뜻이 있는 색: 됨 `--pm-ok-*` · 기다림/주의 `--pm-idle-*` · 문제 `--pm-err-*` · 꺼짐 `--pm-off-*`. 각각 `-bg`(바탕)와 `-ink`(글자)를 짝으로 쓴다.
- 강조색(`--pm-accent`)은 주 버튼·선택된 칩·선택된 탭 밑줄에만.
- **함정**: 이름에 숫자가 있는 토큰은 `--pm-surface-2`와 `--pm-surface2` 두 이름이 모두 나온다. 새 토큰을 넣으면 운영 화면에서 `getComputedStyle(document.querySelector('.pm')).getPropertyValue('--pm-이름')`이 빈 값이 아닌지 본다.

## 6. 카드·표

- 카드: 제목(14px 굵게) → 한 줄 요약 → 꼬리표 → 맨 아래 줄 오른쪽 끝에 버튼 1개. 긴 설명은 "자세히 보기"로 접는다.
- 하위 부품으로 뺀 카드에는 페이지의 scoped 스타일이 닿지 않는다 → `<style jsx global>` + 페이지 최상위 클래스(`.radar …`) 아래에 둔다.
- 표: 줄 높이 32~40px, 숫자는 오른쪽 정렬, 글자 열은 폭 상한 + 말줄임. 전역 `.tbl` 줄무늬와 이름이 겹치지 않게 화면 전용 클래스 이름을 쓴다. 세부는 `UI_LAYOUT_AND_MENU_CONTRACT.md`.

## 7. 세 가지 상태를 반드시 그린다

| 상태 | 보이는 것 |
|---|---|
| 불러오는 중 | `<Skeleton>` (자리 모양 그대로). 1초 안에 끝나면 아무것도 안 보여도 된다. |
| 정말 없음 | `<EmptyState>` — 왜 없는지 + 다음 한 걸음. |
| 오류 | `<Notice tone="error">` + "다시 불러오기" 버튼. 기술 원문은 접어서. |

불러오기 전에 "없음"을 먼저 보여 주지 않는다.

## 8. 눌렀을 때 반응

- 누르는 순간: 버튼은 1px 내려앉고, 칩·카드는 살짝 줄어든다(키트에 들어 있음).
- 기다리는 동안: 누른 버튼에 `loading`. 다른 버튼은 막지 않는다.
- 끝난 뒤: 바뀐 자리에서 바로 보이게(상태 꼬리표가 바뀜). 화면 밖 일은 `<Notice tone="ok">`.
- 움직임 줄이기 설정(`prefers-reduced-motion`)을 켠 사람에게는 움직임을 끈다.

## 9. 좁은 화면

- 390px 폭에서 가로로 밀리지 않아야 한다. 탭이 넘치면 줄바꿈 대신 옆으로 밀어 본다.
- 한 줄 버튼 묶음이 넘치면 주 버튼을 맨 위로 올리고 폭을 채운다.

## 10. 고친 뒤 확인표

1. 주 버튼이 화면에 하나인가.
2. 키트 밖 `<button>`이 없는가(`node __tests__/pmUiKit.test.js`).
3. 불러오는 중·없음·오류 세 상태가 모두 그려지는가.
4. 테마 색이 빈 값이 아닌가(5절 함정).
5. 1440px·390px 두 폭에서 겹침·잘림·가로 밀림이 없는가.
6. 검색·추가·수정·저장이 예전과 똑같이 되는가(모양만 바꾼다. 숫자·저장 동작은 건드리지 않는다).
7. 그 화면이 가이드 영상 지문 검사 대상(`config/workflow-guides.json`의 `sourceFiles`)이면 영상도 다시 찍는다.

## 약점(알고 쓰는 것)

- 이 기준은 `/pm` 테마 키트를 쓰는 화면에만 바로 적용된다. 주문·견적 같은 기존 전산 화면은 전역 `.btn`(styles/globals.css)을 쓰고 있어 모양이 다르다. 전역 버튼까지 맞추는 일은 범위가 커서 이번에 하지 않았다.
- `/ops`는 어두운 바탕, `/pm`·매뉴얼은 밝은 바탕이다. 분위기를 하나로 맞출지는 사장님이 시안에서 고른 뒤 정한다.
