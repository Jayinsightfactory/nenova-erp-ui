# 업무 드라이브 목록의 읽기 격리

일반 `GET /api/work/drive`의 파일 색인 해석과 관리자 디스크 전체 순회를
웹 프로세스에서 분리했다. 내려받기·내려받기 로그·교정·업로드 quota·송금 SQL은
변경하지 않는다. 화면, 정상 응답 필드, 정렬, 별칭 보정과 권한 의미도 유지한다.
메뉴/키보드/작업 순서 변경이 없어 사용 가이드 영상 갱신은 해당 없음이다.

## 읽기 경계

- 목록과 관리자 디스크 집계는 각자 낮은 우선순위로 실행하는 읽기 전용 자식을 사용한다. 쿠키, 토큰, DB 접속 정보는 전송하지 않는다.
- 첫 화면 호출에 한해 인증된 요청의 사용자 ID와 표시 이름 두 필드를 자식으로 전달한다. 같은 색인에서 기존 접근 정책과 정렬을 적용하고 해당 사용자에게 허용된 전체 개수 및 최근 100개만 회신한다. 요청별 결과를 다른 사용자에게 재사용하지 않는다.
- 변경 이후 도착한 요청은 새 배치에서 색인의 dev/ino/size/mtimeNs/ctimeNs를 확인한다. 전체 목록과 미리보기는 한 자식을 공유한다. 미리보기를 받은 뒤 전체 목록을 요청하면 디스크 내용이 그대로인 경우 자식이 이미 해석한 색인을 재사용한다.
- 목록 자식은 대기 호출 최대 64개, 큐 포함 10초 제한 및 유휴 60초 종료로 운영한다. 관리자 사용량 집계는 독립 자식에서 수행하며 큐는 최대 8개, 제한 시간은 30초다.
- 색인은 최대 64 MiB다. 혼잡·크기 초과·읽기/실행/IPC 오류·기한 초과는
  `503 + Retry-After: 2`로 반환한다. 동기 실행/IPC 예외도 이벤트 루프 밖으로
  빠져나가지 않는다. 읽기 자식은 `data/drive`에 잠금·작업·임시 파일을 만들지 않는다.

배포에는 새 `lib/workDriveListAsync.cjs`, `lib/workDriveListWorker.cjs`와 기존
`workDriveChild.cjs`, ESM loader 및 같은 버전의 `workDrive.js`가 필요하다.
별도 상시 서비스나 수동 관리자 작업은 추가하지 않는다.

## 합성 볼륨 검증

`scripts/benchmark-drive-list-read.cjs`는 임시 저장소에서 실제 파일 12,000개,
9,243,550바이트 색인, 9,471,738바이트 HTTP 응답을 만들었다. 독립 프로세스가
동시에 HTTP heartbeat를 보내며, 비교 경로 모두 실제 ACL·정렬·JSON 응답 생성과
응답 전체 전송까지 수행했다. 원본/사용자 데이터·SQL·운영 서비스는 사용하지 않았다.

| 경로 | 콜드 목록 응답 | heartbeat p95 | heartbeat 최대 |
|---|---:|---:|---:|
| 기존 동기 읽기 | 536.86 ms | 450.46 ms | 450.46 ms |
| 별도 읽기 자식 | 599.84 ms | 20.43 ms | 88.80 ms |

파일 배열은 완전히 같았다. 큰 IPC, 메인의 권한 필터 및 JSON 변환을 포함해
heartbeat 정지는 줄었지만, 콜드 시작에는 약 63 ms가 추가되었다. 웹 지연이 0이
되거나 목록 자체가 빨라졌다는 결과는 아니다. 한 로컬 합성 볼륨의 관측이며,
운영에서 보고된 2초 요청의 원인을 확정하거나 운영 수치를 보장하지 않는다.

## 회귀 범위

- 새 7개 검사: 같은 스냅샷/정렬/요청별 ACL·관리자 용량, 배치 coalesce,
  외부 교정/append·동일 크기 교체·삭제, 읽기 오류 시 stale 거부,
  동시성 한도·timeout·종료·원본 불변, 실행 중 새 호출의 freshness,
  인증정보 없는 IPC, 동기 실행/전송 예외의 503 정리, 큐 만료 전송 방지·자식 종료 지연 중 대기 기한 유지.
- 기존 `workDrive.test.js`(권한·다운로드·교정·용량), `workDrivePairs.test.js`,
  `workDriveIngestIndex.test.cjs` 통과. 계약 manifest와 ERP 쓰기 범위 검사 통과.
- 전체 필수 CI·빌드·운영 재확인은 별도 단계이며 이 로컬 검증만으로 완료로 보지 않는다.
