# Import Team PedidosHome source analysis

Scope: static analysis of `output/import-tool-sources/pedidoshome.py` as untrusted source data; the Python file was not executed. The sample workbook was opened read-only with the repository's existing `xlsx` package. This is source analysis only: no application code, ERP data, credentials, network service, or external system was changed.

## Source and operational entry points

- The source describes a desktop flow: choose country, enter week, select/drop an Excel workbook, then generate outputs. Destination folder is selected on first run, remembered, and editable later. `pedidoshome.bat` is supplied as a launcher; it was not executed. Evidence: `pedidoshome.py` lines 1–18, 53–78, 1255–1299, 1306–1344, 1358–1395.
- Country is a manually selected card, not inferred from workbook contents. Week is user-entered and sanitized by deleting characters outside `\w` and `-`; no week is extracted from the source workbook. The source accepts `.xlsx` and `.xls` in the picker/drop handler (lines 1306–1310, 1333–1344), but parses through `openpyxl.load_workbook`; legacy `.xls` is therefore a declared/accepted extension with no demonstrated parser/conversion path.
- Parser behavior is positional: every country reads only the workbook's active sheet with `data_only=True`; most locate a total column by searching the first eight rows for exact `Grand Total`, then fall back to a cell ending in `Total`. Numeric conversion accepts only Python `int`/`float`, otherwise returns zero. Formula cells without cached results can therefore appear as missing/zero. Evidence: lines 130–132, 352–367, and each parser cited below.
- Required Python dependency: `openpyxl` (read/write workbook, styles, column helpers); standard library imports include `os`, `re`, `sys`, `json`, `shutil`, `subprocess`, `tkinter`, `collections`, and `pathlib`. `tkinterdnd2` is optional for drag/drop. LibreOffice/`soffice` is optional for recalculating generated formula caches and failures are swallowed; Excel is expected to recalculate when opened. Evidence: lines 14–46, 144–160. The sample inspection used existing Node `xlsx` only; it is not a runtime dependency of the Python tool.

### China CL indexing defect and narrow web-port correction

- **Original defect (static evidence, Python not executed):** `parse_china` builds `cl_cols` as **CL name → zero-based column index**, assigning `cl_cols[cl] = i` for an aggregate header and `cl_cols[v] = i` for the first raw header. However, its product comprehension is `by_cl = {cl_cols[i]: r[i] for i in cl_cols if isinstance(r[i], (int, float)) and r[i] != 0}`. Iterating `cl_cols` yields string keys such as `"CL1"`, not numeric positions. Consequently, the condition evaluates `r["CL1"]` against a row tuple and would raise `TypeError: tuple indices must be integers or slices, not str` when a product row is processed with a nonempty CL mapping; additionally, `cl_cols[i]` would be a column index rather than the intended output CL name. Evidence: `output/import-tool-sources/pedidoshome.py`, `parse_china` header registration and `by_cl` comprehension (lines 905–924 and 950–952). The China row above describes the intended mapping, not demonstrated successful Python execution.
- **Web correction:** `lib/importPedidos.js`, `clColumns(rows, true)` / `parseCL(ctx, true)`, retains **CL name → [zero-based column index]** and explicitly iterates `[cl, positions]`, reads the numeric cell at each position, and writes `byCL.set(cl, qty)` for nonzero quantities. The equivalent intended Python mapping would be `{cl: r[col] for cl, col in cl_cols.items() if isinstance(r[col], (int, float)) and r[col] != 0}`. For China each positions list contains one column: `CLx Total` still takes precedence, otherwise the first raw `CLx` wins. Duplicate product overwrite and absence of Netherlands multipliers are preserved. This fixes the indexing defect without introducing a new country conversion rule.
- **Regression fixture:** the inline synthetic, non-live fixture in `__tests__/importPedidos.test.js`, test **`China intended CL name-to-column mapping, first raw, total precedence, duplicate overwrite; no multiplier`**, has raw `CL1` at indexes 6/7 and raw/aggregate `CL2` at indexes 8/9. Expected mapping is `CL1 → 6`, `CL2 → 9`; the later duplicate `MEL Tulip A` row yields CL1=4, CL2=5, one output product and total=9 in `W_Melody.xlsx`. Sentinel values 99 in the ignored columns expose an incorrect column choice. This establishes the intended web behavior only; no real China workbook or Python-generated golden output was supplied.

## Supplied example workbook: parity fixture candidate

Read-only inspection of `output/import-tool-sources/발주 목록_2026-09-07.xlsx` found one worksheet, `Sheet`, range `A1:I86`; no formula cells. Its first rows establish headers (`A1:I1`), a `변경수량` marker at A3, country at A4, category at C4, product at G4, and quantity heading `변경수량 Total` at I5. `콜롬비아` begins A6; `카네이션` is present at C6 and structurally continues down the block; product names are in G and numeric quantities in I. Rows 6–85 contain 80 product entries totaling 1,010; first is `CARNATION Altair` = 1 at I6. This matches Colombia's marker-layout candidate columns (category C, product G, detected total I) and supports an initial parity fixture asserting one generated Clavel workbook, 80 rows, quantity sum 1,010, blank Changes, and formula-derived Cajas Total. The account, unit, C.N., and input-date fields have no corresponding use in this parser. Evidence in the input file: `Sheet!A1:I6`, `Sheet!C86`, `Sheet!I86`; parsing conditions in `pedidoshome.py` lines 388–463 and output contract lines 118–123, 257–309, 466–481.

Because the week is supplied manually, the sample does not establish a canonical week value or a final filename. For an entered week `W`, expected output is `W_Clavel.xlsx`, sheet `Clavel W차`.
