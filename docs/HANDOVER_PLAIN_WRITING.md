# 인수인계 매뉴얼 「쉬운 글」 쓰는 법

부서 인수인계 자료의 원고(`data/import-handover.json`, `data/handover-<부서>.json`)는 근거(날짜 · 건수 · 출처 · 추정)가 본문에 섞여 있어 새 직원이 읽기 어렵다. 그래서 따라 하는 사람이 읽는 **쉬운 글**을 `data/handover-plain-<부서id>.json` 에 따로 쓴다. 화면은 쉬운 글을 먼저 보여 주고 원고 글은 「자세히 · 근거」로 접어 둔다. 원고는 고치지 않는다.

## 읽는 사람
입사 첫 주의 직원. 화면 캡처와 이 글만 보고 따라 한다. 누가 언제 알아냈는지는 궁금하지 않다.

## 쓰는 규칙
1. **할 일만 쓴다.** 날짜, 건수, 「○곳 중 ○곳」, 출처, 「추정」「확인 필요」「기록에는」 같은 말을 쓰지 않는다.
2. **지어내지 않는다.** 원고에 있는 내용만 쓴다. 원고가 「추정」「확인 필요」라고 한 것을 사실처럼 쓰지 않는다 — 그 부분은 뺀다. 한 칸 전체가 불확실하면, 원고에 나온 물어볼 상대(예: 영업지원, 수입방)에게 묻는다고 쓴다.
3. **짧게 쓴다.** 한 칸에 한두 문장. 길이 제한은 `scripts/validate-handover-plain.cjs` 의 `LIMIT`.
4. **「합니다」체**로 쓴다.
5. 화면 · 단추 · 칸 · 대화방 이름은 원고에 적힌 그대로 「」 안에 쓴다. 시각(8~10시), 기준(85%), 마감(오후 4시)처럼 **따라 하는 데 필요한 숫자는 남긴다.**
6. 칸마다 쓰는 것
   - `oneLine`: 이 일이 무엇인지 한 문장.
   - `why`: 안 하면 무엇이 막히는지 한두 문장.
   - `when`: 언제(요일 · 시각 · 시작 신호) 하는지만.
   - `prepare`: 시작 전에 손에 있어야 하는 것(항목마다 짧게).
   - `steps["번호"]`: `look`(어디에서 무엇을 본다) · `input`(무엇을 누르고 넣는다 — 동작으로) · `why`(한 문장). 단계 번호와 개수는 원고와 같아야 한다. 단계 제목은 원고 것을 그대로 쓰므로 쓰지 않는다.
   - `doneCheck`: 끝났는지 확인하는 것.
   - `pitfalls`: `{ "mistake": 실수, "fix": 처리 }` — 원고의 실수를 같은 순서로, 짧게.
   - `next`: 다음에 이어지는 일.
   - `schedule["업무표 줄 id"].detail`: 그 시간에 무엇을 하는지 한두 문장(원고에 설명이 있는 줄만).
7. 사람 이름, 전화번호, 메일 주소, 금액을 쓰지 않는다. 직원을 평가하는 말을 쓰지 않는다.

## 파일 모양
```json
{ "version": 1, "dept": "import",
  "manuals": { "<매뉴얼 id>": { "oneLine": "", "why": "", "when": "", "prepare": [""],
      "steps": { "1": { "look": "", "input": "", "why": "" } },
      "doneCheck": [""], "pitfalls": [{ "mistake": "", "fix": "" }], "next": "" } },
  "schedule": { "<업무표 줄 id>": { "detail": "" } } }
```

## 검사
`node scripts/validate-handover-plain.cjs <부서id>` 가 ✓ 가 될 때까지 고친다. 검사는 빠짐 · 길이 · 쓰지 않는 표현을 본다. 글이 정말 쉬운지는 사람이 읽어 봐야 한다.
