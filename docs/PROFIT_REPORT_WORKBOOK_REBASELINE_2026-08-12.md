## 2. 본표 수식 (27차 기준, 22~26차 동일)

|---|---|---|
| C 매출액 | `=N+L+O` | 계산 |
| D 매출비율 | `=IFERROR(C/$C$23,"")` | 계산 |
| E 기초상품재고액 | (직접입력) | 원천 |
| F 기말상품재고액 | (직접입력) | 원천 |
| G 매입액 | `=P+T` | 계산 |

| I 매출원가 | `=E+G+H-F` | 계산 |
| J 매출이익 | `=C-I` | 계산 |
| K 이익률 | `=IFERROR(J/C,"")` | 계산 |
| L 불량금액 | `=SUMIF(불량차감!$J:$J, B{n}, 불량차감!$F:$F)` | 참조 |
| M 불량율 | `=IFERROR(-(L/C),"")` | 계산 |

| O 그 외 매출액 | `=SUMIF('그 외 매출액'!J:J, B{n}, '그 외 매출액'!F:F)` | 참조 |
| P 상품 금액(구매) | `=Q*R` | 계산 |
| Q 구매금액(외화) | `=SUMIF(구매현황!N:N, B{n}, 구매현황!G:G)` | 참조 |
| R 환율 | (직접입력 — 과세환율) | 원천 |
| S 포워딩(USD) | `=SUMIF(포워딩!$N:$N, B{n}, 포워딩!$G:$G)` 또는 콜롬비아 시트 참조 | 참조 |

### 예외 — 이스라엘·뉴질랜드·일본(18~20행)

```
I = E+G+H        (F 미차감)
J = C-I+F
K = IFERROR(J/(C+F),"")
```

### 합계행(23행) SUM 범위 — 열마다 다르다

```
C,D,E,F,J : SUM(7:22)   ← 공제(22행) 포함
G,H,I,L,N,O,P,Q,S,T : SUM(7:21)   ← 공제 제외
K = J23/(C23+F23)
M = -(L23/C23)
U = SUM(U7:U20)         ← 베트남(21행)까지 제외. 원본 그대로 유지.
```

## 3. `그외통관비` 시트 — 국가별 H 구성요소

블록별 행 오프셋(모든 차수 동일):

| 블록 | 라벨행 | 1차 | 2차 | 금액 | 공급가액 |
|---|---|---|---|---|---|
| 백상 창고료 | 4 | `C5:C15` (GW kg) | `D5:D15` | `E=(C+D)*$C$3` | `F=E` (÷1.1 **안 함**) |
| 관세 | 4 | `I5:I15` (원) | `J5:J15` | `K=I+J` | `L=K` (÷1.1 **안 함**) |
| 선율 | 19 | `C20:C30` (원) | `D20:D30` | `E=C+D` | `F=E/1.1` |
| 월드운송료 | 19 | `I20:I30` (원) | `J20:J30` | `K=I+J` | `L=K/1.1` |
| 한국방역 | 34 | `C35:C45` (원) | `D35:D45` | `E=C+D` | `F=E/1.1` |
| **합계 H** | 34 | — | — | — | `I{n} = F백상 + L관세 + F선율 + L월드 + F방역` |

- **베트남 예외**: 선율 30행만 `F30=E30`으로 ÷1.1 하지 않는다(모든 차수 동일).
  방역 45행도 `E45=(C45+D45)*$C$3`, `F45=E45`라는 복사 흔적이 있으나 `C45/D45`가 전 차수 공란이라
  결과는 0으로 무해하다.
- 트럭 단가표 `N20:O22` = 1t 99,000 / 2.5t 187,000 / 5t 275,000 (22~27차 전부 동일).
- 백상 창고료 요율 `C3` = **22~27차 전부 460원/kg**.

## 4. `콜롬비아 1차`/`2차` 시트 — 반차수 H 구성요소

```
C10 창고비(백상)      = E10(Gross W) × 요율        ← 22차만 370, 23~27차 460
C11 통관수수료(선율)   = 33,000 (고정)
C12 검역대행수수료     = E12(품목수 4) × 10,000
C13 운송비(월드종합운수) = Σ(I5×H5 + I6×H6 + I7×H7)  ← 대수 × 1t/2.5t/5t 단가
C14 관세료 / C15 소독비용 / C16 검역비용 = Σ(차감stems × 검역차감액)
C17 TOTAL = SUBTOTAL(9, C10:C16)
```

배분비율(`K37:M40` / `P37:R40`):
`IF(L29=L30, 박스당무게×박스수량 비율, 박스당CBM×박스수량 비율)` — GW=CW면 무게, 아니면 CBM.
그외통관비 H는 **항상 무게비율**, 항공료(포워딩 S)만 GW≠CW일 때 CBM비율로 전환한다.

## 6. `재고잔량` 시트 — E/F 원천

```
품목 행 : 기초 G = E(송이/단) × F(가격),  기말 O = M × N
그룹 합계: G24 = SUM(G7:G23),  G25 = G24/1.1   (기말도 동일: O24, O25)
전체 총합: G2/O2 = 그룹 합계들의 합,  G3/O3 = G2/1.1, O2/1.1
```

즉 **F = Σ(품목별 수량 × 평가단가) ÷ 1.1**이다. 이전 웹 구현의
`(구매금액×환율 + 포워딩×환율 + 그외통관비) ÷ 매입총수량 × 기말수량`은 **원본 어느 시트에도 없다.**

### ⚠️ 시트 총합을 본표 E/F로 복사하면 안 된다

27차 `재고잔량` 시트 30행: 기초 카네이션 단가 `F30=11000`, 기말 `N30=110000` — 10배 오입력이다.
본표 F는 카테고리별로 따로 입력된 값이라 시트 총합과 일치하지 않는다. 자동 검증
(`__tests__/profitReportEndingStockValuation.test.js`)이 이 불일치를 근거로 "시트 합계 복사 금지"를
고정한다.

## 8. 남는 한계 (운영 DB 없이는 확인 불가)

이 작업은 **원본 워크북 대조와 계산 공식 교정**까지다. 아래는 운영 DB 접속이 필요해 이번에 검증하지
못했고, 배포 후 실데이터로 재측정해야 한다.

- **N/L/O/Q/S 집계값 자체**: 원본은 `판매현황`/`불량차감`/`그 외 매출액`/`구매현황`/`포워딩` 시트를
  `SUMIF` 하고, 웹은 `ShipmentMaster/Detail`·`Estimate`·`WarehouseMaster/Detail`을 집계한다.
  두 원천이 같은 거래를 담고 있는지는 운영 DB에서만 대조 가능하다. 27차 기준 기존 측정치는
  C 5.6%, N 5.1%, O 117.6%, P 14.6%였다 — O(그 외 매출액)와 P(=Q×R, R 교정 후 재측정 필요)가 특히 크다.
- **E/F 실측**: 공식은 원본과 같아졌지만, `ProductStock` 마지막 확정 스냅샷 수량과 `WebStockPrice`
  평가단가가 원본 `재고잔량` 시트 수량·단가와 실제로 같은지는 DB에서 확인해야 한다.
