사용자가 별도 SQL 작업 영역 생성·적재를 명시 허용했다. 이 문서는 초기 합성 설계 엔진 `lib/ecountWorkbench.cjs`의 계약/과거 기록이다. 현재 화면·저장·롤백은 `ECOUNT_WORKSPACE_CONTRACT.md` 및 `contracts/ecount-workspace.json`이 담당한다. ECOUNT 원본과 기존 운영 원장은 계속 조회 전용/보존이다.

# ECOUNT 전체 메뉴 개발 작업실 계약

2026-10-20 사용자 지시: 실제 DB 입력·수정 금지. 모든 탭 구현 시작. 외부 API 기능도 화면과 저장 로직을 설계하고 실제 연동만 보류.

## 기준선

- 8개 탭, 537개 메뉴 경로, 423개 말단 메뉴를 실제 로그인된 사이트맵에서 수집했다. 사용자 거래 행·세션 URL은 저장하지 않았다.
- 원본 상세 동작은 아직 전체 검증되지 않았다. 화면은 기능군별 개발 초안이며 ECOUNT와 100% 동등하다고 표시하지 않는다.
- 모든 선택·필터·입력·수정·검토는 브라우저 메모리에서만 동작한다. DB·API·로컬 스토리지·IndexedDB·쿠키 쓰기 없음.
- 외부 기능도 동일하게 입력·검토·저장 계획 제공. 외부 발행/수집/이체 완료 상태는 만들지 않는다.
- 작업실은 공통 인증·사용기록·화면 녹화 API 호출을 막기 위해 _app에서 전용 shell을 제공한다. 운영 화면과 별개 경로다.

| 저장 계획 | 대상 테이블·키·검증·payload 미리보기 | 실행 없음 | 실행 없음 |
| 합성 예시 | 고정 합성 값 추가 | preserve | 호출 없음 |
| 파일 내보내기 | 사용자가 선택한 초안·목록을 다운로드 | preserve | 업로드 없음 |

OrderMaster/Detail, ShipmentMaster/Detail, Warehouse, StockMaster, ProductStock, ShipmentDate, ShipmentFarm, Estimate, WebProfitReport 모두 preserve.
이번 변경은 DB 조회·쓰기 helper를 import하지 않는다. 실제 dnSpy/DB probe를 실행하지 않으며, 이 초안을 운영 원장에 연결할 때 기존 필수 절차를 다시 적용한다.

## 입력 및 저장 기준

| 기준 | 정책 |
|---|---|
| 초기 데이터 | 빈 목록. 예시는 명시적 버튼으로만 추가 |
| 저장 | 검증·계산→계획 미리보기→메모리 초안 적용. 서버 전송 수단 없음 |
| 숫자 | 공란과 0 구분, 유한값·정밀도·범위 검사 |
| 계산 | 합성 데이터용 명시적 산식. 원본 회계/급여 규정으로 인증하지 않음 |
| 연도 | 날짜 연도와 차수 업무키 분리. 서로 다른 연도/법인의 초안 격리 |
| 외부 상태 | 설계/연동대기만 사용. 발행·전송·송금 성공을 모의하지 않음 |
| 수정 | revision 일치, 검토 이후 수정하면 초안으로 복귀 |
| 취소 | 메모리 기록 보존, 취소 사유 필수 |
| 보관 | 새로고침 시 소멸 안내. 미적용 편집 이동 시 확인 |
| 민감정보 | 합성 코드·불투명 참조 ID만 입력. 계좌번호·자격증명·개인정보 입력 금지 |

## 검증 범위

모든 메뉴의 부모·경로·안정 ID·화면 계약과 외부 저장 계획 존재를 검사한다.
전표 차대 불일치, 재고 음수 결과, 부분 수금 초과, 반올림, 날짜/연도, revision 충돌, 외부 실행 차단, 교차연도 독립성을 실행형 테스트로 확인한다.
브라우저에서 전체 탭 탐색·초안 추가/수정·오류·저장 계획·네트워크 무호출·키보드·좁은 화면을 확인한다.

## 메뉴 기본값 판정

페이지 스크롤·반응형·키보드·상태 표시 적용. 원장 확인 해당 없음(실제 쓰기 없음).
공통 Layout은 예외: 사용기록/인증 부수 호출까지 차단하는 전용 shell을 _app이 소유한다.
이 화면의 CRUD는 개발 초안 동작이며 실회계·재고 확정 및 권한 시스템 구현 완료를 의미하지 않는다.
