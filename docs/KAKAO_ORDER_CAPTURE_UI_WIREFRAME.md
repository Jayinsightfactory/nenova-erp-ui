# 카카오 주문 수집·등록 UI 와이어프레임

상태: 기획 초안

목표: 원본 근거와 정규화/매칭 결과를 같은 화면에서 검토하고, 주문등록과 출고분배의 경계를 항상 보이게 한다.

## 1. 데스크톱 기본 화면

```text
┌ 카카오 주문 수집  [새 작업] [원본 추가▼] [임시저장] [복제] [다시 열기] ┐
│ 연도 [2026] 차수 [29-02 후보▼] 기본 거래처 [라움 / CustKey 680]     │
│ 상태: 초안  입력자: 홍길동  승인자: 미지정  원본 3  행 48  오류 6   │
├──────────────────────────────┬────────────────────────────────────┤
│ 원본 (좌측 40%)              │ 정규화 주문 행 (우측 60%)           │
│ [카톡텍스트1][발주.xlsx][IMG]│ 필터 [전체][미매칭6][검증4][중복2] │
```

## 2. 상단 입력 영역

- `원본 추가` 메뉴: 파일, Excel/CSV, 표/텍스트 붙여넣기, 클립보드 이미지, 빈 수기행.
- 화면 전체 drop zone은 파일/이미지를 받되 편집 중 행 위 drop은 막는다.
- 붙여넣기는 `text/html` 표→`text/tab-separated-values`→`text/plain`→이미지 순으로 사용 가능한 형식을 보여주고 사용자가 선택하게 한다.
- 연도·차수·거래처 기본값은 후보일 뿐이며 원본별 값과 충돌하면 행에 경고한다.
- 차수 입력은 `2026 / 29-02`처럼 연도를 별도 컨트롤로 유지한다.

## 3. 좌측 원본 pane

- source tab에 형식, 파일명/라벨, 수신시간, parse 상태, 행수, hash 일부를 표시한다.
- Excel은 sheet 선택과 원본 행/열 좌표, 텍스트는 줄번호, 이미지는 페이지/좌표를 표시한다.
- 우측 행 선택 시 원본 근거를 scroll/highlight하고 반대 방향도 동작한다.
- OCR은 `원본 이미지`, `OCR 텍스트`, `정규화`, `수정 이력`을 탭으로 분리한다.
- 원본 자체는 편집하지 않고 재처리는 새 version을 만든다.

## 4. 우측 정규화/매칭 grid

고정 열: 상태, 원본 위치, 거래처, 품종, 원본 품명, 색상, 전산 품명, 수량, 단위, 출고일, 연도/차수, 중복, 작업자.

매칭 셀 상태 색상:

- 초록 `자동`: threshold/격차 통과.
- 파랑 `수동`: 사용자가 선택.
- 노랑 `추천`: 확인 필요.
- 빨강 `미매칭/오류`: 등록 차단.
- 회색 `제외`: 원본은 보존하되 등록 대상 아님.

후보 dropdown은 선택 행에 붙여 열리고 방향키로 이동, Enter 확정, Esc 닫기, Tab 다음 오류 셀로 이동한다. 후보마다 국가·품종·품명·단위·ID·점수·근거를 한 줄에 표시하고 현재 강조 항목에는 굵은 외곽선과 `선택 예정` 텍스트를 함께 둔다.

## 5. 대량 편집

- checkbox/Shift 범위 선택 후 거래처, 단위, 출고일, 연도/차수, 제외/포함을 일괄 변경한다.
- `같은 원본 품명 모두 적용`과 `이 batch에만`/`추천 사전에 저장`을 분리한다.
- 중복 그룹은 `원본별 유지`, `source 내 합산`, `batch 전체 합산` preview를 나란히 비교한다.
- 음수/취소는 별도 아이콘과 confirmation reason을 요구하며 정책 미확정 상태에서는 등록 차단한다.
- 오류 행을 고쳐도 정상 행의 선택·매칭·수정 이력은 유지한다.

## 6. 검증/승인 drawer

`등록 결과 미리보기`는 다음을 표시한다.

| 항목 | 표시 |
|---|---|
| 업무키 | OrderYear, OrderWeek, CustKey, ProdKey |
| 대상 원장 | OrderMaster/OrderDetail만 |
| 수량 | 현재 주문, 입력 delta/목표정책, 예상 후 수량, 단위별 ERP 컬럼 |
| 충돌 | 동일 batch/idempotency, 기존 원장, 연도/차수 모호, 승인 이후 변경 |
| 비대상 | Shipment*, Warehouse*, Stock*, Estimate, WebProfitReport 모두 `변경 없음` |
| 승인 | 입력자/승인자, revision/hash, 부분등록 정책 |

승인 이후 행이 바뀌면 승인을 무효화하고 재검증을 요구한다. `주문등록` 버튼은 승인된 동일 revision에만 활성화한다.

## 7. 실행 결과

- 상단 summary: 성공/실패/건너뜀/중복방지/재시도 가능.
- 행별 결과: OrderMasterKey, OrderDetailKey, 업무키, before/delta/after, source locator, 오류코드.
- 명시적 무영향 배지: `출고분배 0건`, `재고 0건`, `견적 0건`, `매출 0건`.
- 실패행 재시도는 새 execution을 만들되 같은 성공행을 다시 등록하지 않는다.
- `작업 다시 열기`, `실패행 복제`, `감사내역 보기`를 제공한다.

## 8. 모바일/좁은 화면

좌우 pane을 `원본`/`정규화` 탭으로 전환하고 하단 summary/action bar를 고정한다. 매칭 후보는 bottom sheet로 열며 키보드 대량 작업은 데스크톱 권장 안내를 표시한다. `/m`은 네이티브 앱이 아닌 Nenovaweb 모바일 웹이므로 Android/Expo 별도 요구를 이 기획에 섞지 않는다.

## 9. 접근성/오류 문구

- 색상 외에 상태 텍스트/아이콘을 함께 사용하고 focus ring을 유지한다.
- grid의 원본-정규화 연결은 `aria-describedby`와 행 번호 텍스트로 제공한다.
- 오류는 행동을 안내한다: “2025와 2026에 29-02가 있습니다. 등록 연도를 선택하세요.”
- OCR 신뢰도 숫자만 제시하지 않고 “수량을 확인해야 등록 가능”처럼 차단 이유를 말한다.
- 자동 클립보드 읽기에 실패하면 권한 오류 대신 “이 영역에서 Ctrl+V로 붙여넣으세요” fallback을 제공한다.
