### 1. 기존 33개 화면부터 닫기
일보·재고/BOM·견적/주문/발주현황·미청구현황의 남은 버튼/팝업을 먼저 끝낸다. 그 뒤 이미 일부 구현된 거래조회·채권채무·세금조회로 진행한다. 화면마다 미관측 버튼/미구현/실패/검증대기/API설계전용을 분리한다. 임의의100% 표기는 금지한다.

### 2. 미관측340개 프로그램 조사와 구현
순서: 재고I 기초/거래잔여(P008–P019) → 재고II/AS/원가(P020–P027) → 회계I(P028–P039) → 회계II(P040–P051) → 관리/그룹웨어(P052–P059) → 사용자설정(P005–P007). 기존P001–P004는1단계와 함께 닫는다. 이 순서는 의존성에 따라 조정 가능하되 누락하지 않는다.
한 번에 관련 화면1–3개를 처리한다. 첫 화면으로 공통 검색/표/창 명세를 확보하고, 같은 컴포넌트군은 차이만 기록한다. 이름이 비슷하다는 이유로 미관측 화면을 복제 완료 처리하지 않는다. 입력/저장 동작은 원본에서 실행하지 않고, 읽을 수 있는 양식/공식 명세와 별도SQL 합성자료·트랜잭션 테스트로 검증한다. 원본과 동일함을 증명할 수 없는 부작용은 미검증으로 남긴다.

### 3. 외부API 전용 처리
은행·카드·PG·홈택스/전자세금계산서·현금영수증·이체·사업자/예금주조회·메시지/팩스·전자계약·신고/통관·환율·쇼핑몰/배송은 공급자 연동과 자체업무를 나눈다. 사용자 요청대로 UI+저장계약+합성 응답 검증을 완료 기준으로 삼고 실제 외부 연결은 별도 표시한다. 현재문서가 있다고 모든페이지 UI/저장로직 구현완료로 보지 않는다. 토큰/민감 원문 없이 불투명참조·중복키·정정버전·감사·복원 정책을 적용한다.

### 4. 릴리스와 보고서
한 화면마다 배포하지 않고 관련1–3화면이 준비된 릴리스 후보를 고정한다. 개발중 변경 관련 검사, 고정후 필수5검사(계약/dnSpy/manifest/쓰기guard/build), CI, 병합, Cafe24, 변경된화면 실제스모크 순서를 지킨다. 검사면제는 없다. 새결함/코드변경/원인불명실패일 때만 필요한 재검사를 수행한다. 일보같이 대량행은 숫자/nullable/순서/합계를 코드로 일괄대조하고 브라우저에는 요약만 반환한다. Excel은 릴리스 검증 종료시1회생성, 메타·이미지·해시 자동연결. 보안정책/PII로 사진이 없으면 사유를 표기하고 대체사진을 위조하지 않는다.

## 사용량 운영 규칙

- 기본은 root1명. 독립적 코드 변경이나 보고서 작업이 실제로 있을 때만 하위1명 추가(동시총2명). 원본브라우저는 root만. 기다리는 작업자를 계속 깨우지 않는다.
- 작업지시는 목적/근거파일/수정허용파일/완료검사/중단조건/최대결과길이를 명시한 짧은 명세로 전달. 신규worker는 전체대화 fork 금지; 기존worker도 문맥이 비대하면 짧은 인계로 교체한다.
- 패킷 시작/끝에 계정사용량을 기록하고 증가분을 **계정전체 증가분**으로만 표시한다. 세션별 토큰이 제공되지 않으면 작업단독비용으로 추정하지 않는다.
- 초기3개 소배치에서 완료화면/미완료사유/계정증가폭을 측정해 이후 범위를 정한다. 계정사용량이 한 소배치에서2%p 이상 증가하면 다음착수 전 범위·중복을 검토한다(과금예산이나 정확한task토큰 보장이 아님).
- 계정85%부터 새묶음 규모축소,90%부터 새묶음 착수금지·검증/배포/인계만,95%에는 증거와잔여목록을 저장하고 추가모델작업 중단. ordinaryUsageAllowed=false면 즉시 신규작업중단. 사용자기존설정/계정전체사용은 자동통제불가.
- 동일브라우저/캡처실패2회이면 원인과막힘을 기록하고 독립작업으로 이동. 의미없는 재시도·full DOM·무변화poll 금지. API 보안차단 우회 금지.
- 한도리셋·추가구매·추가사용설정은 자동변경하지 않는다. **현재 정보로 남은340개를 다음한도1회 안에 모두 끝낸다고 보장할 수 없다.** 완료율을 꾸미는 대신 작은단위의완료를 누적한다.
