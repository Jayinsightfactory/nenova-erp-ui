# 메뉴별 개발 히스토리

## 목적과 집계 정의

개발 히스토리(`/dev/history`)에서 메뉴별 기능 추가·수정 내역과 반복 개선량을 보여준다. 수치는 대화 횟수나 작업시간이 아닌 저장소 first-parent 변경 커밋의 고유 건수다. 같은 커밋이 여러 메뉴를 변경하면 메뉴별로 각각 포함하지만 전체 변경 건수는 한 번만 센다.

- 메뉴는 `components/Layout.js`의 MENU_ITEMS를 근거로 한다.
- 기본 화면과 명시적으로 연결한 기능 코드 경로를 분류한다. 임의 의미 추론 없이 경로 기반 자동 분류임을 표시한다.
- 최초 추가는 기능 기준 파일의 실제 `A` 이력만 증거로 인정한다. 확인할 수 없으면 알 수 없음으로 표시한다.
- 추가 후 수정은 최초 추가 이후 관련 코드를 변경한 고유 커밋 수다. 삭제나 재추가는 과거 최초 이력을 초기화하지 않는다.
- merge 커밋도 first-parent 대비 실제 변경 파일을 사용한다. PR 제목은 merge 본문에서 표시하며 변경 파일·해시·날짜를 펼쳐 확인할 수 있다.

## 구현과 보존

전체 Git 이력은 빌드 시 한 번 정적 snapshot으로 생성한다. 화면 진입이나 메뉴 선택 때 Git 명령을 실행하지 않는다. Git이 없는 환경은 저장된 snapshot을 사용하며 자료 시점과 범위의 한계를 표시한다. 조회 API는 로그인 사용자에게 GET만 허용한다. 기존 커밋, diff, 미커밋 변경, 작업 플랜, 작업이력 탭은 보존한다.

1920×1080 CSS px/100% 기준, 작은 화면에서는 한 열로 배치하고 새로운 목록은 자연스러운 페이지 스크롤을 사용한다. 메뉴·기능 선택은 버튼, 이력 확장은 aria-expanded 버튼을 사용한다. 오류·빈 결과·재시도·페이지 이동을 제공한다.

## 원장 부작용

Git 메타데이터와 서버에 동봉된 snapshot만 조회한다. ERP/MSSQL, 주문·분배·입고·재고·견적·매출과 `nenova.exe` 저장 로직은 조회하거나 변경하지 않는다. 따라서 차수 업무키와 교차연도 ERP probe 및 실제 EXE 저장 순서 재검증은 이 웹 전용 기능에 해당하지 않는다. 빌드·계약·쓰기 가드와 UI 회귀는 실행한다.
