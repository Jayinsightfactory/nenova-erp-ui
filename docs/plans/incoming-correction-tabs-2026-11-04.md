# 입고 정정 업무 탭·진입점 기획과 이번 적용 범위

## 공통 진입점

- 입고관리 `/incoming`: 기존 농장·품목 수정/파일 교체 버튼 유지. `입고 정정 업무` 버튼을 추가하여 `/import/tools?tab=incoming`으로 이동한다. 선택 WarehouseKey, 업로드일 조회기간, 농장/차수/검색과 팝업 여부를 전달한다.
- 수입부 업무도구 `/import/tools`: 상단 `입고 정정 업무` 바로가기와 패킹리스트 다음 `입고 조회·수정` 탭 추가. 기존 Incoming 컴포넌트를 지연 로드하여 동일 조회/수정/이력을 사용한다.
- 업무도구의 다른 탭으로 갔다 돌아와도 조회·선택을 보존한다. 임베드 화면의 닫기는 창을 닫지 않고 패킹리스트 탭으로 돌아간다. 공통 shell은 부모만 소유한다.
- 이번 작업은 기존 수정 기능의 진입점 통합이다. 새 승인 엔진은 미구현이므로 요청 접수/영업지원 확정이 되는 것처럼 표시하지 않고 현재 제공 범위를 화면에 명시한다.

## 승인 기능 완성 시 내부 탭 3개

| 탭 | 주 사용자 | 구성 | 핵심 버튼 |
|---|---|---|---|
| 수정 요청 | 수입부 | 내 요청 목록(초안/검토대기/반려), 입고 검색·선택, 농장만/품목·수량 구분, 파일 최종값·사유·변경 전후, 요청 상태 | 새 요청, 초안 저장, 영업지원에 요청, 요청 취소 |
| 매칭·확정 | 영업지원 | 대기/검토중 목록, 요청 상세, 차수·업체·출고일별 기존 분배와 최종 배정, 품목 이동·감소만·추가, 단위·단가·견적·매출·후속재고 영향 | 검토 저장, 반려, 영향 재계산, 검토 내용 최종 확정 |
| 처리 이력 | 수입부·영업지원 | 완료/반려/취소/실패, 원요청·검토안·최종 반영 전후, 요청자·확정자·시각·사유, 적용 여부와 재조회 결과 | 상세 보기, 원입고 열기, 재검토 요청 |

세 탭은 동일 요청번호와 원장키를 공유한다. 메뉴마다 별도 요청 사본을 만들지 않는다. 역할에 따라 첫 탭을 수입부는 수정 요청, 영업지원은 매칭·확정으로 제안하되 조회 권한과 확정 권한은 서버에서 검증한다. 처리 이력에서 과거 완료 건을 직접 덮어쓰지 않고 새 정정 요청으로 연결한다.

## 화면 흐름과 행 동작

수입부는 입고 선택→수정 파일/농장·사유→차이 확인→요청 순서다. 요청 시 입고/분배/재고는 그대로다. 영업지원은 해당 요청을 열어 업체·출고일별 유지/이동/감소/추가를 결정하고, 견적·매출과 재고 영향을 확인한 뒤 최종 확정한다.

농장만 변경되고 품목별 수량·단가가 같으면 매칭 표 대신 농장 연결 확인을 보여준다. 전체 분배/확정을 다시 만들지 않는다. 품목 변경은 새 품목으로 수량을 옮길 수 있고, 감소만 선택하면 대상품목 입력을 요구하지 않는다. 모든 차수·품목을 자동으로 바꾸지 않으며 승인한 행만 대상으로 삼는다.

영업지원 최종 확정은 입고·분배·날짜별 견적/매출·재고·감사까지 한 번에 성공해야 완료로 표시한다. 기존 데이터가 달라지면 다시 검토한다. 상세 기준과 실제 dnSpy/DB 근거는 [승인 흐름 설계](incoming-correction-approval-2026-11-04.md)를 따른다.

## 이번 변경의 부작용·기본값

| 항목 | 적용/범위 |
|---|---|
| ERP 테이블 | 새 쓰기 없음. 기존 correction API/권한/확정·연결 차단을 그대로 사용 |
| 재고·분배·견적·매출 | 새 정책/산식/저장 변경 없음 |
| 단일 shell | 적용: 페이지 자체 Layout 추가 없음, 일반/팝업 검증 |
| 조회 맥락 | 적용: 선택 입고/기간/필터/팝업 전달, 탭 방문 상태 보존 |
| 스크롤 | 적용: 부모 페이지 자연 높이, 가로표/명시 수정 모달만 내부 스크롤 |
| 키보드 | 적용: 기본 버튼·링크, 기존 행 선택/모달 Escape·초점 복귀 |
| 초안·이력 | 기존 수정창 기능을 재사용. 새 승인 상태/감사 이력을 생성하지 않음 |
| 새 API/schema | 해당 없음 |
