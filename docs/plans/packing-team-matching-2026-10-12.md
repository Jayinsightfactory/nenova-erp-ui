# 공용 패킹 매칭·중국 인보이스 검증

## 요구와 확인된 원인

담당자에 관계없이 같은 매칭을 재사용하고, 이름이 조금 다르면 가장 가까운 전산 품목을 우선 추천한다. 추천은 저장/확정과 분리한다. 실제 41-2 중국 인보이스를 입고/원가 경로로 검증한다.

서버 `packing.erp-matches`는 이미 계정별이 아닌 공용 파일/CAS 저장이다. 사용자 ID는 감사 작성자다. UI가 최초 조회 snapshot을 유지하고 매칭 선택창은 원문 추천 없이 빈 검색으로 열려 공유 미반영처럼 보였다. 기존 별칭과 저장된 ERP 연결 표시도 구분한다.

## 중국 항공 원가 예시

사용자 추가 파일 `CHINA 중국 원가자료 (8).xlsx` SHA256 `e1bb0315998c2f3550a0edab8353147612cd6c46d7247b287656eca1c3ee4233`.

- 대표 `27-2 CLOUD`: 항공료 K7=IF(GW=CW,C11*AD8,C11*AI8), AD=kg/단×단수/GW, AI=CBM계수×단수/CW. 통관비 T7=P10*AD8, U7=T7/L7.
- 상세 J24=(FOB단가+단당운임)×환율; K24=J24×관세율; L24=단당통관비; M24=J24+K24+L24; O24=M24×N24.
- 통관 총액 P10=SUM(P6:P9)+R6+R7. P6=GW×460, P8=품목수×10000 등은 과거 파일 값이며 현재 차수 기본값으로 복사하지 않는다.
- `26-2 CLOUD` GW201/CW316은 활성 CBM 분기 검증 대상으로 사용한다.
- 비활성 CBM 영역의 음수 잔여값, 과거 0분모와 불일치 참조는 원문 오류/한계로 기록하며 자동 정상값으로 복제하지 않는다.
- 환율·CW·부대비 분류·통관 실제비용·관세율은 해당 차수 담당자 확인이 필요하다. 해상식을 항공에 적용하지 않는다.

### 승인한 항공 원가 계약

후기 `27-2 CLOUD / 26-2 CLOUD`의 CW 분모 방식만 `CN_AIR_WEIGHT_CBM_V1`로 등록한다. 각 행 실중량합계는 GW, 부피 적용 시 용적환산중량합계는 CW와 일치해야 한다. 용적환산중량은 kg 기준이며 원문 m³에 임의 환산계수를 적용하지 않는다. 항공료는 GW=CW일 때 실중량, CW>GW일 때 용적환산중량으로 배분한다. 통관비는 항상 실중량 기준이다. 행 총원가=(상품금액+배정운임)×FX×(1+확인 관세율)+배정통관비+기타비. 실제 ERP 입고단위 수량으로 나누어 단위원가를 표시한다.

기존 도착원가 관리에 별도의 인보이스 입고 원가 조회 구역을 둔다. 기존 `readInvoiceCosts`가 실제 Warehouse 원장과 다시 대조한 ACTUAL 승인/STALE 상태를 표시한다. 과거 엑셀 업로드 원장 `WebArrivalCost`에 자동 복제하거나 기존 원가를 덮지 않는다. 없는 테이블·조회 실패를 정상 0건으로 표시하지 않는다.

## 부작용

공유 매칭은 웹 runtime 매칭/actor 이력만 변경한다. 추천/변환/미리보기는 Product 읽기 외 Order/Shipment/Estimate/Warehouse/Stock/WebProfitReport를 보존한다. 시험은 별도 localhost14339 격리 DB에서만 수행하며 운영 입고 등록으로 시험하지 않는다. 원가 승인 저장은 기존 WebInvoiceCostRevision/Line의 별도 승인 경로만 사용한다. 공용 SP/nenova.exe/운영 스키마 변경 없음.

## 메뉴 기본값

1920×1080/100%, 키보드·초점, 오류·충돌 안내 적용. 기존 페이지 세로 스크롤 유지, 매칭/검토 모달은 독립 스크롤 예외. 관련 없는 페이지 일괄 수정 없음. 원문/수정/확정 상태 분리와 원가 실패 시 입고 재등록 방지 유지.
