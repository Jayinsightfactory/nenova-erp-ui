# 44-01 누락 출고 헤더 보정 계획 — 2026-10-21

사용자 승인: 기존 주문수량을 건드리지 않고 확인된 10개 업체의 EXE 분배 연결정보만 보정·검증.
대상: OrderYear=2026, OrderWeek=44-01, CustKey=31,277,490,491,500,503,515,592,664,674.

| 대상 | 동작 |
|---|---|
| ShipmentMaster | 해당 업체/연도/세부차수 헤더가 전혀 없을 때만 빈 미확정 헤더 생성 |
| KeyNumbering ShipmentMasterKey | native 다음 키 충돌 방지를 위한 최대값 동기화 |
| 주문 Master/Detail/History | 수량을 포함한 모든 기존 필드 보존 |
| ShipmentDetail/Date/Farm, Estimate | 생성·변경 없음 |
| Product/StockMaster/ProductStock/StockHistory/WebProfitReport | 보존, CALC/FIX 미실행 |

근거: 실제 dnSpy FormOrderAdd.btnSave_Click의 빈 ShipmentMaster 생성 및 FormShipmentDistribution.GetShipmentMaster의 연도+세부차수+업체 조회. GetShipmentMaster 원본에는 isDeleted 필터가 없으므로 삭제 헤더 포함 이미 존재하면 자동 추가하지 않고 중단/보존한다. raw OrderYearWeek=202644, EstimateName=44차 종합견적서, isFix=0/isDeleted=0. 배포된 orders API와 동일 필드 및 safeNextKey/KeyNumbering 방식 사용.

사전확인: 10업체 모두 활성 주문Master 각1, 삭제 포함 출고헤더0, ShipmentMaster/KeyNumbering 트리거0, 재고게이트IDLE. 보정 직전 잠금 안에서 재확인. 동일 transaction에서 보호테이블 row hash를 전후 비교하며 차이/실패 시 전부 rollback. 먼저 rollback 리허설, 이후 승인된 commit, 별도 연결 재조회. 원문·개인정보는 저장하지 않고 집계/hash만 증거로 남김.

상태: 실행 전. 실제 EXE GUI 클릭은 별도 미검증이며 native SQL lookup 성공과 구분한다.
