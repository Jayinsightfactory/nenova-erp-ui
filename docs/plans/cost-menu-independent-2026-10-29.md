# 도착원가 독립 작업 흐름

## 요청
- 입고용 업로드와 도착원가 작업을 독립적으로 유지한다.
- 도착원가 메뉴에서 기존 입고/저장 문서를 조회하고 생성 및 다운로드한다.
- 기존 매칭을 다시 요구하거나 업로드 화면으로 강제 이동하지 않는다.
- 44-01 호주 자료로 웹앱 직접 검증, 운영 DB 변경 금지.

## 확인한 현재 원인
- pages/import/tools.js의 cost 진입 버튼이 setPackingWorkMode('upload')를 호출한다.
- 입고와 원가가 하나의 receiptSource와 InvoiceReceiptWorkbench 인스턴스를 공유한다.
- InvoiceWarehouseCostBrowse 및 NativeReceiptCost에 기존 입고 기반 독립 계산/다운로드 경로는 이미 존재한다.

## 구현 방향
- 도착원가 전용 작업대를 독립 마운트하고 기존 입고 조회를 기본 경로로 노출한다.
- 원가 메뉴 내 저장문서 선택과 원가 계산을 유지하며 입고 작업의 편집 상태와 분리한다.
- 새 인보이스가 필요한 경우에만 원가 메뉴 내부에서 입력하고 이전 업로드 화면으로 이동하지 않는다.
- 조회/계산/다운로드는 기존 읽기 및 미승인 계산 API를 사용한다. 입고 commit과 원가 승인 API 호출 금지.

## 보존 대상
OrderMaster/Detail, ShipmentMaster/Detail/Date/Farm, Warehouse, Stock, Estimate, WebProfitReport, 기존 승인 원가 전부 보존.

## 검증 상태
- 독립 작업대 구현: 기존 입고 기본 진입, 새 인보이스도 원가 메뉴 내부 진행, 마운트 유지.
- 입고/원가 IndexedDB 복구키 분리. 동일 계정 초안 보존 및 오래된 매칭 콜백 차단 테스트 통과.
- 실제 네노바 데스크톱에서 2026/44-01 Premium Greens 41002, 입고7863, 11품목 조회 확인.
- 실제 앱에서 기존 입고 경로의 관세율 기본값 누락 발견. 검증된 호주 품목키+품목명+연도/차수+항공 조건을 재사용해 보완. 미확인 품목은 추정하지 않는다.
- 원장 GW/CW null. 시험 계산에만 사용자 확인 AWB805kg 사용. Red Tip 저장 총액5100 보존.
- SQL은 WarehouseMaster 후보 SELECT와 native read-only source SELECT만 실행. 운영 쓰기0.
- native 원가 회귀:60개 중51통과/9개 private-original 선택검사 skip. 2025/2026·해상·미등록품목 관세율 누출 방지 포함.
- 웹앱 최종 다운로드 및 배포 검증은 진행 중. 아직 완료 아님.

## 부작용 계약
| 작업 | ERP 입고/재고/매입/손익 | 승인원가 | 로컬 상태 |
|---|---|---|---|
| 기존 입고 조회·원가 계산·다운로드 | SELECT-only, 보존 | 보존 | 입력값만 |
| 원가/입고 메뉴 전환 | 호출 없음 | 보존 | 독립 초안 유지 |
| 검증된 호주 관세율 기본값 | 쓰기 없음 | 보존 | 직접 수정 가능, 근거 표시 |
