# 입고 원장 목록과 상세

입고 수량을 빠르게 읽되 저장한 박스 수량과 환산값을 구분한다. 인보이스와 AWB는 원가·통관에 쓰이는 원본 식별값이다.

| 동작 | 업무키와 근거 | 변경 범위 |
|---|---|---|
| 박스수량 표시 | `WarehouseKey + WdetailKey`. 현재 저장값이 NULL이고 원장행의 송이 수/박스당 송이가 양의 정수로 정확하게 나뉠 때만 검토한다. 무게, 여러 상품의 공유 포장, 불일치하는 단수량과 비어 있는 근거는 제외한다. 명시적으로 저장한 0은 그대로 읽는다. | 화면 참고값만 표시. 원장 합계·엑셀·원장 수량에는 저장값만 사용. |
| 원장·상세 레이아웃 | 기존 입고관리와 수입부 업무도구 진입점을 사용한다. 폭·행간·작업 버튼을 조정하되 원장 선택·행 키보드와 엑셀 값은 유지한다. | 화면만. |
| 인보이스·AWB | 저장 후 인보이스 문서의 인보이스번호는 변경을 금지한다. AWB도 공식 복수 입고 및 통관·도착원가 묶음과 관련된다. 연결 여부가 확인되지 않았으면 원장 번호 변경을 허용하지 않는다. | `WarehouseMaster` 식별값과 연동 문서·운임·통관 자료를 따로 바꾸지 않는다. |

설치 EXE SHA256 `FEDEA619A6E54D6CDD58802E0707DD51D06F5D46E883F53F00134E801AC62F79`에서 dnSpy로 확인했다. `FormWarehouseView.GetData`는 `WarehouseMaster.InvoiceNo/OrderNo`를 읽고 `WarehouseDetail.BoxQuantity`를 더한다. `GetDetail`은 행의 `SteamOf1Box/SteamOf1Bunch`를 읽는다. `FormWarehouseAdd`는 입력한 수량을 품목의 출고·견적 단위로 다시 산정하므로 화면 참고값이 원장행 저장으로 흘러가면 안 된다. `ClassWarehouseMaster.Update`는 이 두 번호를 수정하지 않는다.

운영 SELECT로 확인한 2026/47-02 입고 8247의 상세 140행 중 박스 NULL 62행, 저장한 0행 0, 행 기록만 사용한 정확한 박스 환산 후보 0이었다. 해당 입고의 웹 문서 작업 이력 3건, 인보이스 원가 개정과 운임·운임 상세·같은 연도/차수/농장/품목 분배 연결 각각 0건을 확인했다.

같은 연도·차수·품목의 `ViewOrder` 130행, `ViewShipment` 130행(모두 `DetailFix=1`), 같은 대차수의 활성 확정 손익 0건을 읽었다. 변경된 조회 SQL에서도 입고 140행·박스 NULL 62행이 유지됐다.

입고 표시와 번호 조회에서 주문, 출고, 재고, 출고 농장·날짜, 견적, 매출, 손익을 변경하지 않는다. `Estimate`, `ShipmentDetail.Amount/Vat/isFix`, `WebProfitReport`에 추정값을 넣지 않는다.
