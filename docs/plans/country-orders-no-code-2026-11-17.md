# CL 없는 업체 발주 포함

사용자 기준: CL 번호는 선택 표시이며 주문 품목은 누락하지 않는다. 네덜란드는 저장된 환산 송이수를 출력한다.

## 기준 및 부작용
| 항목 | 원천/적용 | 보존 |
|---|---|---|
| 업체 식별 | CustKey, 코드 없는 경우 이름 표시; 동명/코드와 이름 충돌은 표시용 키로 분리 | Customer.OrderCode 변경 없음 |
| 수량 | 기존 ViewOrder의 국가별 저장 단위, NL SteamQuantity | Order/Shipment/Warehouse/Stock/Estimate/WebProfitReport 전체 |
| 미확정 수량 | 양수 주문에 필요한 수량이 없으면 전체 다운로드 보류, 기존 직접 입력 허용 | 임의 배수/원주문 보정 없음 |
| 출력 | 전체 품목·업체 수량, 기존 국가/품종/공급사 파일 분리 | 기존 양식·수식/정렬 유지 |

## 선검증
- 실제 dnSpy.Console.exe -t FormOrderView: GetData에서 ViewOrder, OrderYear/OrderWeek, BunchQuantity/SteamQuantity와 ExportToXlsx 확인. 저장/삭제 메서드 호출 안함.
- 운영 SELECT: 5개 업체의 CL 공란은 최근 콜롬비아 주문에 존재. 47-02는 원천162행→61품목/29업체(공란4), 47-01은633행→141품목/54업체(공란4). 파일4/5개에 품목 개수·각 국가단위 총량 보존 및 XLSX 재개봉 확인. 품종별 다른 단위를 합친 숫자는 업무 총수량으로 표시하지 않음.
- NL47-02: 원천25행→17품목/6업체/2020송이, 파일1개 보존. NL46-02는3품목 일부 업체 송이수 미확정으로 전체차단을 유지. 제품별 총합에 송이수가 있어도 다른 업체의0을 합계로 숨기지 않음.
- 교차연도와 5공란업체×7국가 fixture, 동일명/실코드 충돌, 단주문 저장송이 보존, 누락 수량 전체차단을 회귀로 유지.

## 메뉴 기준
- 적용: 기존 표·키보드·전체주문 보존·출처 분리. 해당없음: 새 메뉴/새 탭/작업순서/ERP writer/스키마 변경. 기존 흐름과 영상 연결은 유지, 표시 라벨/정상 공란 경고만 수정.
- 전체 ERP 계약·dnSpy·manifest·쓰기 가드·webpack 빌드 통과. 기존 workflow 가이드22개/검증 영상23개 검사 통과. 운영 브라우저에서 수정 전47-02 경고 반복 재현. 남은 검증: CI/배포 및 수정 후 브라우저 스모크.
