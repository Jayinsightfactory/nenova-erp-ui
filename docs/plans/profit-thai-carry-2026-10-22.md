# 태국 과거 매입 원가 연결 — 2026-10-22

## 요청과 범위
- DB는 변경하지 않는다. 태국 두 품목의 34차 매입·운송·통관 근거를 조회하고 38~41차에도 품목별 원가 재현을 이어 사용한다.
- 설치 EXE FormWarehouseView.GetData/상세 조회를 실제 dnSpy CLI로 재확인: WarehouseMaster/Detail + Product, UPrice/TPrice. 가격·수량 원장 수정이나 EXE 배포는 없다.
- 읽기 probe는 query 변경문·execute·batch·transaction을 차단한다. 운영 수치/품목 식별자는 private .verify에만 보관한다.

## 판정 기준
| 기준 | 근거·소비자 |
|---|---|
| 연도/세부차수/품목 | 같은 연도, 평가 시점 이하 최신 매입. selectOlderAcquisitionPurchases / SQL 후보 조회 |
| 최근 4차수 | FIFO 유지, 그 밖만 과거 매입 재현. 더 최신 불완전 매입을 건너뛰지 않음 |
| 환율 | 매입 차수 정확한 과세환율. 태국 FIFO와 오래된 이월 모두 같은 조회; 현재 통화마스터 금지 |
| 수량/단위 | 완전한 양수 매입, 동일 단위, 재현 입고 행 수 일치. 박스/단/송이 임의 혼합 금지 |
| 비용 | 기존 AWB 운임·통관 배분 공식 보존. 실제 운임 행과 매입 TPrice 사용. FreightCost 없는 통관 기본값은 실제 청구 확정값이라고 주장하지 않음 |
| 판매단가 | 기존 판매 근사값은 계속 제외. 품목 간 가격 복제 및 DB 근거 저장 없음 |
| E/F | 각 기간 SQL 재고×그 기간의 품목별 근거. 전차수 F/다음차수 E 일치 검사 |

## 확인된 결함과 한계
- 태국은 오래된 매입 허용 목록에서 빠져, 34차 매입이 최근4차수 범위를 벗어나는 38차부터 원가 누락.
- FIFO 도착원가의 가격 하한 검사만으로는 현재 환율로 높게 계산된 값을 잡지 못함. 태국은 정확한 매입차수 환율로 재현 후 사용한다.
- 입고에 낮은 외화 매입액이 실제 존재한다. 임의 정상가로 바꾸지 않는다. 물리적 인보이스/실제 청구서와 일치하는지는 별도 미검증.
- 해당 입고 FreightCost 스냅샷은 없다. 도착원가 엔진의 통관 기본값과 손익 H의 GW 기반 산출값은 별도 기준이며, 이 작업에서 실제 청구액으로 합치거나 DB 저장하지 않는다. 조회의 과거 원가 재현은 실지 비용 인증이 아니다.
