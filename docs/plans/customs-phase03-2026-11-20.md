## 구현 전 실제 근거

- 2026-11-20 실제 `dnSpy.Console.exe --no-color -t FormWarehouseView Nenova.exe` 실행: GetData의 WarehouseMaster OrderYear/OrderWeek/OrderNo, GetDetail의 WarehouseDetail/Product/TPrice 확인. 삭제 ClassWarehouseDetail/StockHistory/uspStockCalculation은 호출하지 않는다.
- 같은 날 선택 연도·차수 SQL SELECT baseline을 비공개 `.verify/baseline.json`에 보존. 운영 쓰기 0. 연도·AWB·기존 비용 확인에만 사용한다.
- 35차 베트남 원본 PDF의 수수료 공급가와 VAT, 엑셀 수식, SQL split 입력을 대조했다. PDF/SQL은 net, 엑셀은 gross 그대로 합산하는 차이가 확인됐다. 36차에는 베트남 문서·입고·저장행이 없어 정책 변경 경계로 단정하지 않는다. 기존 역사값을 일괄 재분류하지 않는다.
- 기존 코드의 일반 국가 target 및 ledger/합계는 01·02까지만 지원한다. 콜롬비아 공유 풀은 이미 실제 세부차수 키를 사용하므로 기존 경로를 보존한다.

## 완료 조건 및 현재 상태

### 후속 사용자 승인 — 베트남 gross 비용

2026-11-20 사용자가 26·28·29·31·35차 엑셀의 F30=E30(수수료 VAT 미분리) 기준으로 웹을 맞추도록 승인했다. ZIP 문서 canonical net/VAT/total과 기존 ledger values는 변경하지 않는다. 읽기 투영만 증빙 gross로 바꾸며, 기존 수기가 증빙 net 또는 gross와 정확히 일치할 때만 허용한다. 미확인 legacy 금액에 1.1을 곱하지 않는다. 검증된 35/37 PDF fallback은 exact 연도/차수/베트남/AWB의 유일한 실제 입고와 금액 일치를 모두 요구한다. 명시 0 및 불일치는 보존한다. 03차 베트남도 수수료 VAT만 비용 포함하며 수입 VAT·다른 국가 정책은 보존한다. 이 승인은 운영 DB 또는 과거 보고서 저장 권한이 아니다.

- 신규 13개 회귀: 실제 후보·표시·저장 공통 identity, 교차연도/다른 차수/AWB, 공급가·VAT 쌍, 명시 0, ZIP/수기 중복, stale digest, 원자 저장 후 재조회, ZIP 등록 후 수기 보존, 기존 phase01 중복 금액 불일치 차단, 베트남 문서 gross 및 정확 PDF fallback, 중국 실제 03 관세 중복 방지, 태국 03 GW/default 이중합산 방지를 검증했다.
