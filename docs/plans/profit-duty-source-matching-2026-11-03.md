# 중국·태국 관세 원본-전산 연결 조사

상태: 읽기 조사, 정책/금융 코드/DB 수정 없음. 평균 대체안보다 직접 원본 근거 연결을 먼저 검토한다. 공식·엑셀 원문 재검증은 독립 에이전트 담당이며 아래는 기존 전산 지문·정책과의 연결 결과다.

## 용어 정정

이번 사용자 표현 **CO는 Certificate of Origin(원산지증명서)**이며 콜롬비아 국가 코드가 아니다. ‘중국 CO 별도 적용 시3.2%’를 콜롬비아 전체3.2%로 해석하지 않는다. 과거 전산의 국가=콜롬비아 오분류 문제는 별개다.

## 확인한 현재 동작

- `profit-official-duty-2026.json`162품목을 `resolveTemplateDutyRule`이 기존 엑셀 기반 정책보다 먼저 선택한다. 국가·품명·연도 지문을 검사하지만 **원본 셀의 직접25%와 신고 품명그룹 추론8%가 충돌해도 추론이 우선**할 수 있다.
- base의3193 Preserved White는25%(rule149),3212 Preserved Pink는25%(rule168). official에3212가8%로 존재하여 현재 resolver는8%를 반환한다. 이는 원본25%를 확인한 뒤 정책 우선순위 정정이 필요한 핵심 후보다.
- official의 보존 아스파라거스8%는8키:3086·3087·3088·3089·3210·3211·3212·3384. 앞4개는[MEL]역사품목이다. 현25%원본과 동일입고의 실제 신고서8%가 있다면 차수·입고별 적용을 분리해야 하며, 어느 한쪽을 전체기간에 일괄 덮지 않는다.
- 실제 관세 SQL/명시0/수기 H 우선은 유지한다. 본 조사에서 법정율이나 실제 납부액을 새로 확정하지 않는다.

## 원산지증명서3.2% 적용 조건

현재 원본 기반 정책에3.2% 연결은 없다. 중국 소재8%와 CO 적용3.2%는 서로 다른 적용조건일 수 있으므로 exact 품목/HS만으로 원산지증명서 유무를 자동 인정하지 않는다. 필요한 키는 OrderYear+실제세부차수+AWB+품목/신고행이며, 당시 증명서/협정코드/원산지요건 근거가 있어야 우선 적용할 수 있다. 단순 이름 ‘CHINA’는 원산지 증빙이 아니다. 사용자 운영규칙으로 적용하려면 실제 납부 확정과 구분한 승인조건을 계약에 명시해야 한다.

## 전산 국가·품종 오류와 분리 처리

기존 연간입고에 사용된 상품 중124키는 이름에CHINA가 있지만 원Product.CounName='콜롬비아',FlowerName='아나나스'로 저장되어 있다. 웹 보고서는 이름 근거로 중국으로 재분류하나 기존 운임 통화 추정은Product국가를 읽어USD가 될 수 있다. 이 문제를 원산지증명서CO와 섞지 않는다. 정확품명/원본농장·AWB·통화로 읽기 분류를 검증하되 DB Product를 수정하지 않는다. FlowerKey86 자체는 본 재사용자료에없어 별도SQL없이 숫자키를 확인했다고 하지 않는다.

## 수정 필요 / 확인 필요

1. 수정 후보: 원본 exact 세율과 official 분류추론의 충돌을 무조건 official우선으로 덮는 동작. 직접 원본·해당입고실제조건·사용자승인과 일반형태추론을 구분하는 provenance 우선순위가 필요하다.
2. 원본 확인:25%Preserved와8%신고서의 동일상품/동일기간 여부,CO3.2의 적용HS·증명서 조건,태국 직접품명 매칭.
3. 별도 검증:중국124키의 국가/통화 오분류. 정확품명만으로 외화금액의 통화를 확정하지 않는다.
4. 구현 전: 실제0/수기/실납부 보존, 같은연도/차수/입고 범위, 예외기간, 원본행오참조 반례, E/F/H/I/J/K전후 영향표 필수.
