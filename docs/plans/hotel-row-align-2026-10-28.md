# 호텔 비교 행 정렬 및 차별 수량표

요청: 반복 원문/출처 열 제거, 원본 줄과 매칭 줄을 맞춤. 저장 직후 우측1차·2차·3차·4차·총수량과 직접 수정. 원본 hover 비교.

여기서1~4차는 같은 주문 연도/차수 안의 저장자료 번호(기존 요청수량1~4)다. ERP 세부차수를 합치거나 옮기지 않는다. 5번째 이후도 열 추가. 요청/발주 각각 적용.

| 동작 | 기준 | 부작용 |
|---|---|---|
| 비교 | 원문은 이미지/텍스트에 한번, 매칭품목·수량·단위만 우측 | 표시만; 자동선택/매칭 저장 없음 |
| 줄 정렬 | 이미지 가로 경계선 탐지, 품목 개수와 연속 간격 일치 시만 정렬. 불명확하면 수동 위치 조정 | 원본 파일/파서/수량 불변 |
| 저장 | 기존 pending→번호별 server CAS 완료 후 우측 표 | 웹 초안만 |
| 셀 수정 | 기존 Product.OutUnit/hotelConvert로 동일 품목 통일, 같은자료 중복행은 기존 수량 비율로 분배, 마지막 행에 소수6자리 잔차 반영 | request/purchase 초안 행만, allocations 초기화; 원본qty/unit 보존 |
| 원본 보기 | hover/focus/click으로 이미지와 편집 매칭표 비교 | 명시 품목 적용만 기존 overlay 저장 |
| 등록 | 기존 합산→사전확인→my-customer ADD, 업무키 unchanged | 기존 검증 그대로. 신규 SQL 없음 |

Order/Shipment/Stock/Estimate/WebProfitReport/금액/확정은 표시·수정 단계 모두 보존. 등록은 기존 정책을 재사용. 이전 FormOrderAdd 실제 dnSpy/read-only probe 근거 재사용(동일 세션의 UI 후속 수정). 키·단위·환산·권한·등록정책 변경 없음. frozen과 저장실패는 수정 금지.

검증: 다중자료/중복품목/혼합단위/0/빈값/2025·2026동일차수·원본 수량 보존, 실제 화면 나란한 줄/경고 높이/4열합계/셀 수정·서버 복원/hover·키보드·좁은화면. 필수 ERP guard/build 및 운영 배포.
