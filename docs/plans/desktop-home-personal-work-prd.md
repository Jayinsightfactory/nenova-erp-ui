# 네노바 PC 홈 — 개인 업무와 최신 소식 PRD

작성: 2026-10-09 · 상태: PC 홈 구현·fixture 검증·웹 API 배포·PC 1.3.5 릴리스 완료. 사용자 설치 적용은 미확인. 아래 초기 기획의 제안 표현은 작성 당시 상태이며 최종 계약은 `docs/contracts/desktop-home-workspace.json`을 따른다.

## 2026-10-09 구현 확정

사용자의 “기존색상이 좋은데 새로만들어준 지침이랑 이런건 적용” 지시에 따라 기존 남색·연한 파란색·즐겨찾기 색상을 유지했다. PC 네이티브 홈에 개인 업무와 두 소식 줄을 추가했으며, 웹 홈 전체 개편은 이번 범위가 아니다. 업데이트 영역 240px, 검색 260px, 작은 창에서는 쌓이는 배치다.

개인 업무는 인증 사용자별 서버 파일에 저장한다. 생성·수정·완료·해제·보관·복구·반복 종료, 날짜별 조회와 미완료 이월을 제공한다. 반복 변경/종료는 선택일과 현재 한국 날짜 중 늦은 날짜 다음 날부터 적용하며, 과거 완료 기록을 보존한다. 409 충돌과 저장 실패에서 초안을 유지하고 재시도하며, 계정 전환 후 이전 계정의 지연 응답을 폐기한다.

지침/피드백은 최근 7일 수정본(중요 지침은 기간 예외), 각 최대 20건이다. 홈 표시 중 30초마다 재조회하며 피드백 원천에는 25초 서버 캐시가 있으므로 새 변경의 표시까지 최대 약 55초와 통신 시간이 걸릴 수 있다. 초 단위 push가 아니다. 개인 업무 날짜를 과거로 옮겨도 소식은 현재 최신 소식을 보여준다. 차수 근거가 없으면 추정하지 않고 “차수 미확인”으로 표시한다.

실제 Electron fixture의 IPC·계정 전환·키보드·1920/1024/800px 검사와 원문 페이지의 1920/800px 읽기 전용 이동을 통과했다. 설치된 사용자 앱의 새 버전 적용 여부와 배포 결과는 구현 세션 기록에서 별도 확인한다. 이전 모든 메뉴 UI 점검을 완료했다는 의미는 아니다.

## 목적과 범위

홈에서 오늘 할 일을 입력·수정·완료하고, 새 업무 지침과 수입부 피드백을 놓치지 않게 한다. 사용자가 표시한 가로 영역에 **개인 업무 체크리스트**를 추가한다. 기존 즐겨찾기는 그 아래 유지한다. PC 앱 홈이 우선 대상이며 웹 홈 적용은 동일 계약을 재사용할 수 있도록 설계한다. 이번 산출물은 PRD와 조작 가능한 예시 시안이다. 운영 데이터나 설치된 홈 화면을 변경하지 않는다.

사용자 요청: 개인 업무 입력/수정, 수입부 요일 업무와 유사한 반복 체크, 제목 아래 뉴스 전광판, 수입부 피드백 자동 갱신, 업데이트·검색 영역 폭 축소. 기존 합의인 한 줄 작업 탭, 현재 탭 강조, 메뉴별 즐겨찾기, 메뉴 열림 시작, 작업 공간 최대 활용은 보존한다.

## 화면 구성

1. 맨 위: 기존 작업 탭 한 줄. 탭·닫기·메뉴 동작 변경 없음.
2. 헤더: 왼쪽 인사말, 오른쪽 작은 업데이트/검색. 1920px에서 업데이트 약 240px, 검색 약 260px을 시작값으로 잡고 실제 문구로 검증한다. 긴 변경 내용은 ‘변경 내용’ 펼치기로 읽는다. 버튼 상태와 실패 문구는 숨기지 않는다.
3. ‘오늘의 업무를 시작하세요’ 아래: **주의·업무 지침 / 수입부 피드백** 두 소식 줄. 제목, 새 소식 표지, 수정 시각, 이전·다음·일시정지, 원문 보기. 본문이 길면 줄바꿈하며 행 높이가 늘어난다.
4. 표시한 영역: **오늘의 내 업무**. 날짜, 요일 반복 보기, 완료 개수, 업무 입력과 추가. 각 행은 넓은 체크 영역, 전체 업무명, 반복 요일, 수정 버튼. 초기 6건까지 표시하고 ‘전체 보기’로 페이지 안에서 확장한다. 작은 내부 세로 스크롤을 만들지 않는다.
5. 기존 즐겨찾기, 전체 업무 메뉴. 즐겨찾기 개수/순서/메뉴별 별 버튼을 보존한다.

기본 검증은 1920×1080 CSSpx/100%. 1024/800px에서는 헤더와 체크리스트가 쌓이고 글자 크기는 유지한다. 길이가 다른 품목·농장·지침 제목을 생략점으로만 감추지 않는다. 페이지 주 스크롤로 마지막 항목까지 접근한다.

## 개인 업무 동작

| 동작 | 결과 |
|---|---|
| 입력 + Enter/추가 | 로그인 사용자 소유의 업무 생성. 저장 성공 후 입력 초기화 |
| 수정 | 행 안에서 제목·날짜·반복 요일 수정, 저장/취소. 취소하면 원문 복원 |
| 완료/해제 | 해당 날짜의 실행 건만 완료/복구. 전체 행의 레이블 영역 클릭 가능 |
| 요일 반복 | 매주 선택 요일에 실행 건 생성. 같은 규칙·날짜는 중복 생성 금지 |
| 날짜 변경 | 지난 기록 조회 가능. 완료 기록과 미완료 업무를 삭제하지 않음 |
| 다음 날 | 미완료는 ‘이월’로 표시. 반복 규칙의 다음 실행 건과 식별자로 구분 |
| 삭제 | 업무 삭제와 반복 종료를 구분하고 범위 확인. 복구 가능한 보관 처리 |
| 재접속/재시작 | 서버 저장본 복원. 계정 변경 시 다른 사용자 자료를 즉시 지움 |

공용 수입부 업무는 개인 업무와 독립한다. ‘공용 업무에서 가져오기’를 향후 제공하면 원본 출처가 붙은 개인 사본을 만든다. 개인 완료로 부서 공용 완료 상태를 변경하지 않는다. 관리자 임의 대리 수정 기능은 1차 범위에 넣지 않는다.

추가/수정 중 실패하면 입력과 수정 초안을 유지하고 ‘저장 실패·다시 시도’를 표시한다. 자동 재시도는 요청 식별자로 중복 생성을 막는다. 여러 창에서 같은 업무를 바꾸면 버전 충돌을 알려 다시 불러오기/내 수정 비교를 제공한다. 시안은 예시 메모리 조작이며 서버 저장으로 표시하지 않는다.

## 순환 소식 규칙

두 줄은 서로 독립하며 기본 8초마다 한 항목을 교체한다. 글자가 좌우로 흘러가는 방식보다 문장 전체를 멈춰 보여주는 뉴스 교체 방식을 권장한다. 마우스 올림·키보드 초점·원문 열기 동안 자동 교체를 멈춘다. 일시정지와 이전/다음을 제공하고, 동작 감소 설정에서는 자동 교체 없이 수동 이동한다. 전체 소식 목록은 항상 열 수 있다.

업무 지침: 읽기 권한이 있는 유효한 게시물의 최근 수정본을 사용한다. 긴급/고정 항목 우선, 이후 최신 수정 순서. 초안·보관·권한 밖 항목은 제외한다. ‘최신’은 기본 최근 7일 변경으로 시작하며 고정 긴급 건은 기간 밖에서도 유지한다. 수정본마다 읽음 상태를 구분한다. 단순 노출만으로 읽음 처리하지 않고 사용자가 원문을 열었을 때 읽음 처리한다.

수입부 피드백: 기존 불량피드백 원문의 읽기 권한을 적용한다. 연도와 차수를 함께 표시한다(예: 2026년 40차). 새 등록·내용 수정·처리 상태 변경만 소식으로 만들고 조회 횟수는 변경으로 취급하지 않는다. 같은 사건·같은 수정본은 한 번만 포함한다. 처리 완료는 상태 변경 소식으로 보여주되 오래된 완료 건을 계속 순환시키지 않는다. 댓글·첨부 공개 범위는 기존 원문의 권한을 따른다. 연락처 등 불필요한 민감 정보는 홈 요약에 노출하지 않는다.

초기 ‘실시간’ 목표: 홈을 보는 동안 30초 이내 재조회, 홈 복귀 시 즉시 갱신. 현재 구조에서 push 지원이 확인되지 않았으므로 1차는 폴링으로 명확히 표현한다. ‘마지막 갱신 HH:mm’ 표시. 실패 시 기존 내용과 ‘갱신 지연’을 유지하고 지수 백오프, 수동 재시도. 항목 없음과 조회 실패를 구분한다. 순환 일시정지는 화면 교체만 멈추고 수신은 계속한다. 홈이 숨겨지면 조회를 줄이거나 중단한다. 초 단위 즉시 수신은 후속 SSE/이벤트 전달 검증 후 제공한다.

## 저장·연동 계약 제안

PC 홈은 `desktop/shell/index.html`, `desktop/shell/shell.js`가 제공하는 네이티브 홈이다. 웹 페이지에만 위젯을 붙이면 PC 홈에 적용되지 않는다. `desktop/main.cjs`의 인증된 `webSession.fetch` 경계와 제한된 preload IPC를 통해 읽기/명시적 개인 업무 변경을 전달한다. 현재 shell의 `connect-src 'none'`을 무제한으로 풀지 않는다.

제안 API(아직 없음): `GET /api/desktop/home-workspace`는 인증 사용자 개인 실행 건과 권한 필터된 두 피드, 수정 버전/동기화 시각을 반환한다. 개인 업무 생성·수정·완료·보관은 별도 명시 명령으로 처리한다. 프론트가 보낸 ownerId를 신뢰하지 않고 서버 인증 사용자로 소유자를 결정한다. 읽기와 쓰기를 모두 소유자 기준으로 제한한다.

개인 업무 규칙: id, ownerId, title, startDate, weekdayMask, archivedAt, revision, createdAt/updatedAt. 날짜별 실행 건: id, taskId, ownerId, localDate, completedAt, revision. 사용자·업무규칙·실행일 unique, 날짜는 Asia/Seoul 업무일 기준. 반복 변경은 미래 건에만 적용하고 과거 완료 기록은 보존한다. 미완료 이월은 원래 실행일을 보존해 복제하지 않는다.

피드: sourceType, sourceId, sourceRevision, title, safeSummary, updatedAt, priority, sourceRoute, orderYear/orderWeek(관련 건만). 읽음 키는 사용자+원천+수정본. 원문 이동은 승인된 메뉴 경로와 검증된 식별자만 허용한다. 임의 URL/명령 전달 금지. 피드 원문 저장소와 개인 체크리스트 저장소를 분리하고 견적·주문·재고 등 ERP 업무 원장에는 쓰지 않는다.

## 디자인 레퍼런스와 적용

- [Microsoft To Do — My Day](https://support.microsoft.com/en-us/todo/my-day-and-suggestions): 당일 업무 입력과 체크 중심의 단순한 목록을 참고한다. 네노바는 다음 날에도 미완료를 바로 보여주도록 정한다.
- [Linear — Inbox](https://linear.app/docs/inbox): 중요한 변경과 일반 변경 구분, 원문 중심의 짧은 소식 표시, 읽음 상태와 키보드 이동을 참고한다. 거대한 알림 카드 대신 두 줄 뉴스 영역으로 압축한다.
- [Atlassian Home — navigation](https://support.atlassian.com/platform-experiences/docs/what-is-the-new-navigation-in-atlassian-home/): 개인 작업과 자주 쓰는 곳을 홈에 모으는 구조를 참고한다. 네노바에서는 기존 즐겨찾기와 전체 메뉴의 접근성을 유지한다.

색은 기존 네노바 남색/파랑을 유지하고 지침은 호박색 표지, 피드백은 파랑 표지로 구분한다. 색 외에 분류 문구를 항상 붙인다. 긴 문장은 줄바꿈하고 기본 업무 글씨는 14–16px을 유지한다. 체크 클릭 영역 최소 32px(터치 44px), 명확한 초점 표시. 체크리스트는 차분한 흰색 작업면, 얕은 구분선, 버튼 수 최소화로 구성한다.

## 완료 기준과 구현 순서

1. 원천 API의 권한·최신 변경 시각·저장 계약을 확정하고 개인 업무 계약/fixture를 추가한다.
2. 개인 업무 서버 저장, 재접속·계정 전환·동시 수정·실패 복구를 구현한다.
3. 두 읽기 피드와 메인 프로세스 IPC를 연결하고 순환/멈춤/원문 이동을 구현한다.
4. 작은 헤더/기존 즐겨찾기 보존, 실제 PC 앱 홈에서 검증한다.
5. 계약·단위·UI·빌드 통과, 웹 배포와 PC 앱 릴리스 각각 검증한다. 네이티브 shell 변경이므로 웹 배포만으로 완료 처리하지 않는다.

필수 시나리오: 서로 다른 계정의 업무 격리, 재시작 복원, 요일/자정/이월 중복 없음, 2025/2026 같은 차수 구분, 권한 없는 소식 미노출, 실패 시 초안 유지, 긴 제목 줄바꿈, 1920/1024/800에서 겹침·가로 잘림·마지막 버튼 접근, Tab/Shift+Tab/Enter/Space/Escape와 원문 복귀 초점, 피드 방향키 이동, 자동 갱신과 읽음 상태 충돌 없음. 실제 원문 조회만으로 완료/차감 등 업무 상태가 바뀌지 않음을 확인한다.

## 메뉴 기준선 판정

| 기준 | 판정 | 근거 |
|---|---|---|
| 범위/화면/키보드/스크롤 | 적용 | PC 홈 기획에 반영, 운영 화면 검증은 구현 단계 |
| 입력 보존/이력/실패 | 적용 | 소유자 저장·버전 충돌·재시도·반복 실행 계약 |
| 매칭/파일업로드/ERP 반영 확인 | 해당 없음 | 개인 업무와 읽기 소식만 대상 |
| ERP 안전 | 적용 | 원천 읽기 권한, 연도차수 구분, ERP 원장 쓰기 없음 |

`docs/CODEX_SUBTASK_ORCHESTRATION.md`는 현재 체크아웃에 없어 사용자 제공 역할 지침을 적용했다. 원천 코드 조사 결과와 시안 검증 결과는 후속 섹션에 기록한다.

## 확인한 기존 코드와 구현 전 주의점

- `components/import-tools/ChecklistTool.js`, `lib/importTeamChecklist.js`, `lib/importTeamClient.js`, `pages/api/import/tools/state.js`: 기존 업무는 사용자별이 아닌 날짜별 공동 기록이다. 키는 `checklist.day.YYYY-MM-DD`, `checklist.templates.{weekday}`, `checklist.month.YYYY-MM`. `data/runtime/import-team` 저장과 expectedRevision 충돌 검사, taskActors 이력이 있다. 개인 업무는 이 키를 재사용하지 않는다. 공용 체크리스트 원화면은 그대로 유지한다.
- `pages/api/operations-knowledge/index.js`, `lib/operationsKnowledgeStore.js`: 활성 계정 공용 지침, updatedAt/updatedBy와 revision/audit 제공. CURRENT/CHECK/RETIRED를 구분한다. 홈 기본은 CURRENT, CHECK는 ‘확인 중’으로 따로 표시하거나 제외한다. RETIRED는 제외. 레거시 인수인계는 상태 미분류이므로 현재 유효 지침으로 추정하지 않는다. 댓글/첨부도 수정시각을 바꿀 수 있어 ‘본문 변경’과 ‘새 댓글/첨부’를 구분해야 한다. 최근 500개 audit를 전체 기록/개인 미확인 건수로 쓰지 않는다.
- `pages/api/sales/farm-quality.js`, `lib/farmQualityStore.js`, `lib/farmQuality.js`: 영업/수입/영업지원 또는 관리자 읽기 범위. canManage/canDelete를 유지하고 홈에는 읽기만 제공한다. year 조회의 cases는 **그 연도 전체**이며 from/to는 분석 범위다. 홈에서 차수 선택을 붙이면 사례 자체의 실제 연도·차수로 별도 필터해야 한다. 세부차수 40-01과 대차수40을 구분한다. UpdatedAt 최신순과 사례별 최근 이벤트3개는 확인되었으나 이것만으로 모든 중간 변경을 전달했다고 주장할 수 없다. 새 소식은 사례+수정 버전 단위 요약으로 정의한다.
- 기존 피드백의 ‘미답변/기한 초과’는 개인 읽음이 아니다. 사용자별 읽음 저장을 새로 만들기 전에는 미확인 개수를 표시하지 않는다. 기존 import/tools/state 및 지침 API는 활성 로그인 범위이며 수입부 전용 권한으로 단정하지 않는다. 새 홈 API는 원천별 권한을 각각 적용한다.

이 조사는 코드 읽기만 수행했다. DB 접근·서버 실행·운영 쓰기는 하지 않았다. 신규 개인 저장소/피드 API/IPC는 위 제안이며 아직 구현되지 않았다.
