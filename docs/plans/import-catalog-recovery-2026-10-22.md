# 전체 품목 자동매칭 복구 기준

사용자 요청: 루스커스 외 누락/오연결 모두 수정, 전체 검증 후 즉시 배포. 진행 중 업로드 유지.

## 근거
- 실제 DB 활성3359품목/102품종/6175원문 이름으로 10/19 및 PR1213 직전 parser/preview와 비교: 신규 미매칭269명칭(184품목), 정상키→잘못된키61명칭. 수동 연결 없는 실제 XLSX 최소 재현에서도 확인.
- 유일한 정확 원문을 row품종 추론 때문에 거부하고 generic ROSE로 fuzzy fallback하는 것이 문제. 품종은 식별 단서이며 정확 ProdKey의 대체물이 아니다.
- FormShipmentDistribution dnSpy 저장·연도 업무키와 기존 세션 SELECT downstream 증거 유지. 이번 후속에서도 dnSpy 재실행 및 대상 품목 SELECT 검사.

## 판단 기준
1. 수동 선택/무효 선택/건너뛰기와 이전 키 복구를 보존한다.
2. DB에 유일한 원문 이름은 row/heading 품종 추론보다 우선한다. 원문 괄호·규격·공급자 구분을 정리한 축약명보다 우선한다.
3. 정확 원문이 중복이면 명시된 시트/블록의 DB국가품종→품종으로 범위를 좁히고, 하나이거나 같은 연도·차수·업체의 양수 주문이 하나일 때만 선택한다. 모호한 여러 품목은 임의 점수 순위로 고르지 않는다.
4. 존재하는 정확 후보를 버리고 일반 품종명으로 fuzzy fallback하지 않는다. 알려지지 않은 세부 이름을 일반 ROSE/수국 등으로 연결하지 않는다.
5. 명시된 잘못된 workbook ProdKey와 수동 선택은 자동 정확매칭과 구별한다. 잘못된 키 우회 금지.
6. 수량/단위/확정/서명/연도/건너뛰기 제외 범위는 기존 계약 유지. 미매칭0뿐 아니라 각 원문→기대 ProdKey를 대조한다.
7. 과거부터 있던 동명 후보는 자동으로 강제 연결하지 않는다. 실제 원문이 모호한 경우 명확히 표시한다.
8. 선택 키는 정리 전 원문 이름을 사용해 MIX BOX 괄호 규격을 구분한다. 열린 화면의 이전 정리 이름 키는 유일한 원문에만 복원하고, 여러 원문에 겹치면 재선택을 요청한다. 현재 정확한 키는 우선한다.
9. 수정 전 잘못된 매칭 결과가 담긴 유효 서명도 그대로 적용할 수 없도록 matchPolicy를 서명에 포함한다. 배포 후 열린 파일·선택은 유지한 채 검증하기 한 번 필요. 저장 전409로 안내하며 운영 쓰기 시작 전에 차단한다.

## 검증
- 실제 전체 카탈로그 원문 비교, 한글/영문/혼합 제목, 미니카네이션/중국장미/색상 Rose/혼합박스 규격, 모호한 동명/일반품목 fallback 차단, 기존 수동/skip, 2025/2026 및 수량 일치.
- 전체 ERP 계약·dnSpy·manifest·쓰기 가드·build·CI·Cafe24·운영 실브라우저 확인. 운영 시험분배 및 DB보정은 하지 않는다.
