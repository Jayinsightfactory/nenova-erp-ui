# 주광 분배 적용 결과 확인

- 저장 성공 응답과 제출 초안을 저장 결과로 합성하지 않는다. 성공 후 같은 작업 UUID와 거래처로 영속 작업을 다시 읽고, 각 연도·대차수의 감사 before/after를 교차 확인한다.
- 작업의 연도·세부차수·품목 집합이 제출 범위와 정확히 같아야 한다. 감사 조회의 거래처/연도/대차수 응답 범위를 검사한다. 조회 범위가 바뀐 비동기 응답은 화면에 적용하지 않는다.
- 저장 시점의 총량·날짜별 수량·확정 상태와 최신 재조회 결과를 구분한다. 불일치와 최신 조회 실패는 저장 실패로 오인시키거나 재전송하지 않고 별도 안내한다.
- 결과 영역은 페이지에 짧은 요약과 native details로 제공한다. 자동 모달, 중첩 세로 스크롤, 강제 초점 이동을 추가하지 않는다. UUID, 사유, 담당자, 날짜별 전후 수량, 확정 전후와 실제 제공된 서버 검증 근거를 표시한다.
- 과거 저장 감사도 동일한 날짜별 전후 수량을 펼쳐 볼 수 있게 하고 상단에서 이력 위치로 이동할 수 있게 한다.
- 검증: 잘못된 UUID/거래처/교차연도/중복·누락 감사, 최신 자료 변화/미조회, 오래된 요청의 응답, 동일 작업 재조회, GET 실패를 pure fixture로 확인한다. ERP 쓰기는 추가하지 않는다.

메뉴 기준선: 화면틀·페이지 세로 스크롤·키보드 native controls·초안/저장 근거 분리 적용. 새 메뉴/매칭/외부 저장 해당 없음. 실브라우저 1920×1080/100% 검증은 메인 담당.

배포 후 브라우저에서 과거 이력 바로가기가 닫힌 업체·엑셀 연결 패널 내부에 가려지는 문제를 확인했다. 바로가기 실행은 바깥 도구 패널과 안쪽 이력을 모두 연 후, 모든 details 조상이 열린 것을 보장하고 스크롤·summary 초점 이동을 수행한다. 회귀 테스트는 실제 exported handler를 실행해 조상 펼치기 이후에만 스크롤과 초점 이동이 발생함을 검증한다.

웹 요일 저장 감사를 이력 영역 첫 부분에 표시한다. 기존 초안·EXE 공용 이력은 바로 아래 별도 details에 보존하고 기본 접기로 제공한다. 따라서 과거 EXE 내역 수천 행이 저장 감사 접근을 밀어내지 않으며, 펼치면 기존 페이지 주 스크롤로 전체 기록을 확인한다.
