# 원천 복원·표시 정책 독립 검토 초안

상태: 구현 전 검토안. 앱 코드·SQL 수정 없음. 사용자 최신 의도는 공란 대신 업무에 필요한 결과를 보여주고 반복되는 “추정 포함” 문구를 제거하는 것이다. 이는 근거 없는 숫자 생성 또는 실제 납부 확정으로의 승격을 허용하지 않는다.

## 1. 재사용한 증거

- 기준 commit939d5ec1. 이전 `.verify/profit-all-weeks-after-audit.json`의01~43 저장본·파생값을 읽었다. 추가 SQL 조회0.
- 관세 overlay로 숫자였던 값이 null이 된 개수: H69, E46, F48, I/J/K각64행. 원래부터 없었던 E18/F17/H17도 별도 존재한다.
- **숫자 존재와 유효 근거를 구분한다.** H69 중 여러 행은 원 source=missing, H=0, customsComponents없음이다. 이런0을 실제 통관비로 복원하면 안 된다.
- 중국16~21 및34 이후 일부의 gw_auto H는 백상·운송 계산만 있고 Customs1/2는 자동0이다. 관세가 포함된 완전한 H라고 인증할 수 없다.

- 정책 미연결217품목은 웹 관세 정책에 exact 연결이 없다는 뜻이며 관세 SQL 행 또는 실제 납부가 없다는 뜻이 아니다.

## 2. 최소 구현 제안

1. **기존 유효 근거 보존**: 새 관세 보완이 미완전하면 원래 근거가 완전한 기존 H/E/F를 유지한다. 원래0 또는 양수라는 이유만으로 통과시키지 않는다. 원래 H가 실제입력/수기/기존 승인규칙인지 provenance와 구성 완전성을 검사한다.
2. **계산 묶음의 일관성**: H만 이전값으로 돌리고 E/F는 새관세값을 쓰는 혼합은 금지한다. 행의 E/F/G/H/I/J/K와 평균식 메타가 동일 비용 정책을 사용해야 한다. 기초는 그 기초재고 평가 차수의 동일 정책을 사용한다.
3. **실제 누락 구분**: source missing의0, 불완전 환율·운임·단위, 판매단가만 존재하는 재고는 숫자로 복원하지 않는다. UI는 빈칸 대신 “원가 근거 없음”, “환율 확인 필요”처럼 짧은 이유를 표시할 수 있다. API null을0으로 바꾸지 않는다.
4. **표시 정리**: 제목/버튼의 반복 “추정 포함”은 제거 가능하다. 상세 근거에는 적용 규칙·자료 차수·원문 연결·실제 납부 대사 여부를 남긴다. `approved_estimate` 같은 내부 상태값을 `verified`로 바꾸지 않는다.
5. **원천 재사용**: exact 실비/실제0/수기 근거 우선. 같은 연도·같은 품목·평가 기준 이전 실제 매입, 그 매입차수 환율, 완전한 단위·운임·통관 재현만 재사용한다. 미래 매입·현재 환율·판매단가는 금지한다.

## 8. 추가 공식 분류 문언 검토 — 장미 cultivar 제한 해제 후보

관세청 [한중협정 품목 문언](https://www2.customs.go.kr/download/ftaportalkor/_down/trty/han_ch_07_kor.pdf)과 [CLIP 품목분류](https://unipass.customs.go.kr/clip/hsinfosrch/openULS0201008Q.do)에서0603의 신선 절화 하위0603.11은 장미이며 cultivar별 하위분류가 아니다. 이 자료는 상품형태 분류 근거이며 한중FTA 세율 적용 또는 APTA 자격 인증 근거로 쓰지 않는다. 2026 세율은 앞서 검증한 공식 연간표를 유지한다.

따라서 기존과 동일 cultivar여야 한다는 제한을 넘어, 명시 ROSE CHINA/SPRAY ROSE CHINA 신선절화 형태의 정확 품목39개를 추가 제안한다. 이는 신고필증 직접 확인이 아닌 공식 문언과 상품명에 따른 분류 추론이다. exact 목록은 `.verify/source-completion-rose-form-candidates.json`:2474,2614,2663,2470,2504,2472,2861,2891,2899,2889,2890,2887,2841,2922,2473,2935,2852,2962,2947,3026,3018,2996,3034,2740,3050,2156,2282,3352,3287,2508,3397,2409,3292,3380,3279,3488,3505,3388,3386.

3351은 ROSE 접두어와 Plum anemone 상품명이 충돌하여 제외한다. Petal Use/Preserved/seed/sample도 제외한다. 실제 입고에 다른 형태 증거가 있으면 후보에서 제거한다. E1 특혜 적용요건 미확인 및 실제 납부액 우선 정책을 유지하고 신규 품목의 직접 신고 AWB를 생성하지 않는다.

1차32개 적용 메모리 재검산 결과: 누락705→540입고행, 고유217→185품목. 최종 E/F/G/H/I/J/K 숫자 복구0행. 정책 연결 개선을 공란 전체 해결로 보고하지 않는다. 추가39개 적용 여부 및 숫자 복구 결과는 후속 기록한다.

## 9. 18차 missing R 복원과 재고평가의 독립성 재검토

18차 R 누락9행의 기말은 product_cost7행/태국no_stock/콜롬비아장미missing이다. 그러나 **product_cost 또는 VERIFIED_FIFO 라벨만으로 실제 원가가 독립 검증되었다고 판정하지 않는다.** 구저장본 원천에는 구체 FX출처 없는 `:live:`만 있는 항목이 있고, 당시 계산 경로가 currencyMasterRate를 허용했는지 배제할 수 없다. 구현담당의 profitReport.js513~528 및 pivotFreightArrival.js366~383 검토와 교차했다.

- 콜롬비아 수국·알스트로: 당주18-01 live원가 참조는 있으나 구체 적용 환율·출처 부족.
- 콜롬비아 카네이션: 위 문제 외 음수1.05단 포함.
- 네덜란드: unitMismatch=true로 평균식 실패.
- 호주: goods-cost-missing 및 off1단가 fallback 원문 존재. 수치가 있다는 이유로 실제매입원가 인증 금지.
- 중국: 당주 live원가와11차 매입환율 carry 혼합. 국가R 하나로 재고전체의원가를 인증하지 않는다.
- 루스커스: prod3085 전량26.4단이17-01입고라18R와시간적으로독립이나, 구체FX출처없는legacy경로문제는남는다. 또한17기말평균116565.84원→18기말FIFO129161.73원으로 동일수량 평가방식차이12595.89원이 있다. 원천원가인증과시간적독립은다르다.
- 태국: 재고0이지만 H관세정책미연결은 별도 남는다. 장미missingF는 R만으로 복원 금지.

이번 저장JSON만으로 최종 I/J/K의 안전한 신규 복구를 독립 승인하는 행은0이다. 원천R 복구가능성과 재고평가 완전성을 분리하며, 통관주간환율 적용만으로 구저장본 FIFO를 실제원가로 승격하지 않는다. 추가 SQL은 이 독립검토에서 실행하지 않았다.
