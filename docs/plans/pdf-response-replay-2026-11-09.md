# 저장 응답 무료 재검증 기준

원천: 실제46-1 3/15구간 완료 뒤4번째 strict JSON.parse 실패. 기존 job은 검증 후에만 구간 결과를 저장해 raw 응답은 유실됨. 유실 응답을 복구했다고 주장하지 않는다.

| 동작 | 분석 파일 | ERP 주문/입고/재고/견적/손익 |
|---|---|---|
| provider 응답 수신 | 파싱 전에 사용자 격리 sidecar·해시 저장 | 모두 보존 |
| 무료 재검증 POST | 같은 사용자·PDF cacheKey·실패 job만 mutex 아래 재검증, 완료 구간 보존 | 모두 보존; SQL/AI/quota 호출0 |

- 원본 PDF/키/인증정보는 응답 보관에 넣지 않는다. 본문 text/stop_reason만 저장, 파일0600/사용자해시 폴더/30일·240응답·응답당2MiB. raw는 일반 조회/로그에 노출하지 않는다.
- 재검증은 완결 JSON의 설명·코드펜스 포장만 제거한다. 잘린 JSON 닫기·수량/금액/페이지 보간·부분 송장 복구 금지. 다중 JSON 객체도 차단한다.
- 원본에 없는4번째 응답은 MISSING_SAVED_RESPONSE로 명시. 기존 완료3개를 삭제하거나 provider를 호출하지 않는다.
- 실패/전체대조 오류는 원래 오류와 raw를 보존. 전체 구간+금액/manifest 대조가 끝나야 SUCCEEDED. 누락 구간은 자동 분석하지 않는다.
- 기존 정상 업로드·매칭·입고 순서는 불변. 오류 상태의 선택적 무료 재검증 버튼만 추가, 새 메뉴/탭/일반 작업 순서 변경 없음. 가이드 신규 촬영 해당 없음.
