# 자동수집 일괄등록 전수 확인 및 재발 방지

사용자 기준: 자동수집도 전산 매칭·업체 출고·단가·중복 검사를 통과하면 일반 입력과 같이 영업지원에서 일괄등록한다. 10/13의 자동 원천 전면 차단 계약은 이 기준으로 대체한다.

## 기준과 부작용

| 동작 | 원천 조건 | 업체/품목/수량·출고·단가 | Estimate | 웹 원장/History | 주문/출고/재고/손익 |
|---|---|---|---|---|---|
| 목록/사전검증/미리보기 | 원천으로 제외 금지 | 기존 공통 검증 | 조회 | 조회 | 보존 |
| 공통 등록 계획 | 현재/과거 자동 표식도 허용 | 업무키·잔량·출고·단가 검증 | 변경 없음(순수 함수) | 변경 없음 | 보존 |
| 기존 실제 등록 | 출처와 무관 | 중복 잠금·수량·단가 재검증 | 기존 계약의 INSERT/UPDATE | 기존 감사 | 보존 |

별도 수동처리완료/연결 견적 직접 편집/수동단가 정책은 이번 일괄등록 변경 범위에 포함하지 않는다. 기존 자동 견적에 대한 중복 방어는 유지한다.

## 근거

- 로컬 dnSpy ClassEstimate Insert/Update/Delete: Estimate 필드만 저장, ShipmentKey 연결. 자동수집 표식은 EXE 정책이 아닌 웹 감사 정보.
- PR1339 배포 abca005f 이후 주광/태림 2026년43차14행의 운영 preflight/preview 오류0, 업체별 ShipmentKey6852/6877 및 양수 단가 확인.
- 추가 감사는 2026년43차 support 목록 전체에서 현재 또는 이력의 자동수집 자료를 대상으로 한다. 이전 연도/차수의 미처리 이월을 포함하며, 목록에서 제외된 삭제·완료 역사 전체를 신규 등록 대상으로 간주하지 않는다.
- scripts/audit-defect-registration-api.mjs는 조회/preflight/preview만 호출한다. 토큰·원문·담당자 개인정보를 저장하지 않는다. 등록 가능 행은 preflight와 preview의 ShipmentKey/Cost/오류를 비교하고, 불가 행은 원천차단 재발 여부와 정상 차단 사유를 집계한다.

## 자동 검증

- 96개 업체/연도/수입확인/현재·과거원천 조합에서 일반 입력과 같은 등록 계획, 목록·상태 판정을 검증한다.
- 업체/품목 미매칭, 출고 없음, 단가0, 동일 견적, 자동 원천 연결 견적 중복, 미래 연도는 기존 차단을 검증한다.
- salesDefectAutoSource.test.js가 위 검증을 import하고 GitHub CI도 독립 단계로 실행한다. 자동수집을 무조건 막는 구현은 양성 fixture에서 실패한다.
- 원천 표식이 등록 직전 재조회에서 추가돼도 정상 업무키·출고·단가가 유효하면 혼합 일괄등록에 성공하는 서비스 테스트를 유지한다.

## 메뉴 기준선

적용: 기존 체크 선택·사전 확인·견적 검토·서버 재검증 흐름 유지. 해당 없음: 새 메뉴, 화면 레이아웃, 환산/세율 수식 변경. 운영 실제 Estimate 등록은 전수 확인 작업에서 수행하지 않는다.
