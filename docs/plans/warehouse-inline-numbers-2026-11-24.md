# 입고 원장 번호와 차수·일자 표시

| 동작 | 기준 | 데이터 영향 |
|---|---|---|
| 인보이스/AWB 인라인 수정 | 권한 있는 계정, 활성 입고 1건의 WarehouseKey+OrderYear+OrderWeek. 원래 두 값의 정확한 비교, 새 값의 중복 및 양쪽 식별값의 연결을 같은 트랜잭션에서 다시 검사. | WarehouseMaster 한 행의 한 번호와 기존 변경자·변경 시각만 갱신. |
| 문서·통관·운임·손익 연결 | 인보이스 문서/작업과 비용 기록, 같은 공급자 중복, 공유 AWB, 운영 원가·통관·정산, 처리 중 정정이 있으면 기존 소유 경로에서 검토. | 읽기만 수행. |
| 차수·날짜 | 저장된 A/B 접미 차수만 점을 넣어 표시. 저장된 원본 차수로 조회·정렬·업무키를 유지하고 두 형태 검색. 입력일은 원본 날짜로 정렬하고 표에서는 YY-MM-DD. | 표시만. |

실제 설치 EXE SHA256 `FEDEA619A6E54D6CDD58802E0707DD51D06F5D46E883F53F00134E801AC62F79`. `FormWarehouseView.GetData`는 원장 `InvoiceNo`, `OrderNo`, `OrderWeek`를 읽는다. `ClassWarehouseMaster.Update`는 번호를 변경하지 않는다. 웹의 문서 연동 입고에는 당초 작성기의 영수증 스냅샷 해시와 문서 개정이 있으므로 원장 한 칼럼만 변경할 수 없다. 기존 문서 작성기에서 확정 문서의 인보이스 변경은 금지한다.

운영 2026/47-02에는 활성 입고 26건, 재고 헤더 1건, 활성 출고 헤더 46건이 있다. 세 원장 모두 A/B 접미 차수 0건으로 구분을 생성하지 않는다. AWB 공란 8249/8250은 각각 웹 인보이스 작업 1건, 8247은 3건이 연결되어 있다. 세 예시에서 출처별 운임·도착원가·통관/포워딩·활성 확정 손익은 0건이었다.

공식 작성기와 동일한 읽기 검사에서 8249와 8250 모두 현재 차수의 출고 확정으로 차단됐다. 8249는 기등록 영수증 해시 불일치, 8250은 일치였다. 새 가드의 운영 읽기에서 26건 중 인보이스 편집 전 확인은 17건, AWB는 0건이 통과했다. 두 공란의 셀은 저장 문서로 이동할 수 있도록 안내하며 운영 데이터는 건드리지 않았다.

숫자 보존 범위는 WarehouseDetail, StockHistory/Product/StockMaster, OrderDetail, ShipmentDate·ShipmentFarm, ShipmentDetail.Amount/Vat/isFix, Estimate, 확정 손익 및 기존 인보이스 문서다. 운영 시험 편집을 수행하지 않는다.

데스크톱의 기존 입고관리 `/incoming` 및 수입 업무 `/import/tools` 메뉴가 같은 컴포넌트를 사용한다. 기존 경로에서 새 기능을 제공하고 클라이언트 버전을 갱신한다. CLOUD 차수 원가 검토 초안은 저장 입력을 유지하며 원장 해시 변경을 감지하여 다시 대조한 뒤 적용한다.
