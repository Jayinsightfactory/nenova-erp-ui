# PC 메뉴 UI 코드 인벤토리

작성: 2026-10-08. 기준: `components/Layout.js`의 MENU_ITEMS + 시작 `/dashboard`. **이 문서는 코드 정적 확인이며 실제 PC 앱 확인 결과가 아니다.** 앱 검증 열은 메인 작업의 실제 앱 확인 전달분만 반영한다. 나머지는 미확인이다. 권한별 메뉴 노출이 달라지므로 등록 전체 수와 계정별 메뉴 수가 같지 않다.

## 판독 기준

- 표의 위치는 각 페이지 직접 소스에서 발견한 첫 근거다. 자식 컴포넌트와 조건부 화면은 별도 앱 확인이 필요하다.
- 자체틀: `_app.js` NO_LAYOUT 또는 모바일 `/m/*`. 공통틀은 Layout의 PC 마커로 사이드바·상단바를 숨긴다.
- 제목마커: `data-desktop-chrome` 존재. 마커가 없다고 중복 제목이 확정되는 것은 아니다.
- 폭 제한/큰 여백/화면높이 패턴은 **후보**이며 모달·입력·가상표 등 정상 예외일 수 있다. 자동 일괄 삭제 금지.
- 버튼: 공통 `.btn`, Ant Design, 자체 native button 여부. 파일 직접 소스에 없으면 위임으로 표기한다.
- 실검증 기준: 1920×1080 CSS px, 100%; 작은 화면 800px; 제목 중복·잘림·겹침·주스크롤·Tab/Shift+Tab·Enter/Space·Escape·방향키·focus 복귀·실패 알림.

## 집계 및 공통 수정 후보

등록 항목 85개 + 시작 1개 = 86행. 정적 후보 집계(동일 페이지 query 항목 중복 포함): 자체틀 12, 제목마커 9, maxWidth 51, padding≥20 56, vh 40, Ant Design 5, native button 75.

1. 공통 PC stylesheet에는 현재 중복 chrome 숨김과 min-width만 있다. 페이지 콘텐츠 외곽 여백·폭을 명시적 마커로 통일하는 것이 우선이다. 모든 maxWidth를 지우면 인쇄/모달/입력형 화면까지 깨지므로 루트만 대상으로 한다.
2. 자체틀 페이지는 제목만 숨겨도 상위 header 높이·padding이 남는다. 필터/언어/뒤로가기/상태가 섞인 toolbar 전체를 숨기지 말고 제목 영역을 분리해 검증한다.
3. `.btn` 공통 토큰과 native/custom 버튼이 혼재한다. 최소 클릭영역, focus-visible, disabled, radius를 맞추되 삭제/확정 등 의미색과 표 안 작은 버튼을 보존한다. Ant Design은 theme token으로 맞추는 편이 안전하다.
4. 큰 외곽 padding과 maxWidth는 MOYI 연결처럼 짧은 양식에도 쓰인다. 작업형 목록·표 root부터 확장하고 짧은 양식은 가독성을 고려해 실제 앱에서 판단한다.
5. vh/내부 scroll은 차수피벗 가상표·모달 등 예외가 섞인다. 전역 height:auto/overflow:visible 강제보다 페이지별 주스크롤 및 sticky 영향을 확인한다.
6. `/m/executive?preview=1`는 모바일 보고서 미리보기이므로 데스크톱 전체폭 일괄 확장 대상에서 제외한다.
7. `/dashboard`와 PC 시작 shell은 별개다. 시작 카드 옆 ☆/★, 메뉴 Drawer의 ☆/★, 저장 후 즉시 반영과 탭 비열림을 각각 실제 PC 앱에서 확인한다.

## 제목 마커 보완 (2026-10-08)

메인 작업이 실제 PC 앱 1.3.2에서 확인한 MOYI 화면을 기준으로, 원본 메뉴 85개 페이지 소스의 제목 후보를 검색하고 정적 단일 제목인 35페이지에만 `data-desktop-chrome`을 추가했다. 변경은 각 파일 1개 속성 추가이며 필터·버튼·상태·데이터 문자열과 인쇄 HTML은 그대로다. 기존 마커가 있는 페이지와 모바일은 수정하지 않았다. 위 표의 정적 집계는 수정 전이다.

- 실제 앱 증거 전달 기준: 사용자 설치 LocalAppData/Programs 앱 1.3.2, 캡처 외곽 1920×1032, 100%. 기준 1920×1080 CSS viewport 완전 일치 검증으로 주장하지 않는다.
- 보류: `/sales/profit-report` 제목에 연도·차수와 월별/주별 모드가 포함된다. 해당 업무 상태까지 숨기지 않는다.
- 보류: `/work/manuals`는 부서 선택에 따라 제목 대신 breadcrumb와 돌아가기 버튼이 표시된다. 조건부 내비게이션 검토 필요.
- 보류: `/dev/action-log` h2에 설명이 합쳐져 있다. 순수 제목을 별도 span으로 분리하는 후속 설계 없이 전체를 숨기지 않는다.
- 보류: `/import` 및 `/import/finance`는 공용 컴포넌트와 역할/보기 상태를 사용한다. 상태 제목과 메뉴 제목을 실제 앱에서 구분해야 한다.
- 유지: `card-title` 표·패널 제목, 모달/상세/오류 제목, 문서 렌더링 및 인쇄 템플릿 h1, MOYI Drive의 동적 activeTab.label.
- `/orders/sales-paste`는 메뉴명이 영업부 붙여서 주문등록이나 실제 정적 h1은 내 업체 주문등록이다. 모두 해당 페이지 제목이므로 마커만 추가하고 이름은 바꾸지 않았다.

### 개발 히스토리 위임 컴포넌트 추가 확인

`HistoryPage` 실제 기본값은 `full`이며 `FullDevelopmentHistory`를 렌더링한다. `view=journey`는 `DevelopmentJourney`, `view=menu`는 `MenuDevelopmentHistory`다. 기존 작업은 legacy 제목만 포함했으므로 세 컴포넌트의 정적 h1에 마커를 추가했다. 상단 보기선택 버튼·필터·통계·자료시각·결과 h2는 그대로다. 각 h1 문구는 바로 위 현재 보기선택 버튼으로도 확인할 수 있다.

직원 업무 심화 리포트의 iframe 내부 제목 및 max1000 제한은 실제 앱에서 메인이 확인했지만 이번 마커 수정에는 포함하지 않았다. 외부 임베드 자체 CSS와 iframe 내부의 별도 조정이 필요하다. 나머지 미확인 메뉴는 실제 앱 검증 대기 상태다.

### 내 작업 데이터 pipeline 주스크롤 보완

`pages/my-work.js` PC 전용 `[data-my-work]` 범위에만 표 lane 높이제한과 우측 상세 높이제한·sticky를 해제했다. 업무 탭과 기존 주 `.stage` 스크롤은 유지하며 표의 가로스크롤도 유지한다. 800px에서는 `.plm`의 min-width를 0으로 설정해 표 최소너비1150px이 화면 전체를 밀어내지 않게 한다. 브라우저 웹과 iframe은 변경하지 않았다.

검증: 실제 Chrome headless에 현 페이지 CSS와 긴 표/상세 fixture를 렌더링했다(실제 사용자 앱 데이터 검증 아님). 1920×1080 및800×1080에서 표·상세 scrollHeight=clientHeight로 내부 세로스크롤 없음, stage만 세로스크롤. 800px 표 clientWidth770/scrollWidth1150으로 가로스크롤 유지, stage clientWidth=scrollWidth800. PC 마커 제거시 원래 lane max-height850px, 상세sticky 유지 확인. 스크립트: `%TEMP%/nenova-my-work-scroll-smoke.cjs`.

### 주문관리~도착원가 후속 관찰

위 추가11개 화면 관찰은 설치 앱1.3.2의 배포 전 상태다. 실제 데이터가 표시된 화면과 초기 로딩만 본 화면을 구분했으며 최종 수정 검증으로 취급하지 않는다. 발주관리는 `/warehouse`, 입고관리는 `/incoming`으로 MENU_ITEMS에서 확인했다. 조회·선택만 진행했고 업무 쓰기는 수행하지 않았다.
