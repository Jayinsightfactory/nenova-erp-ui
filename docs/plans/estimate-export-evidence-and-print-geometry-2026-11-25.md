# 업체 견적 출력 치수와 EXE 내보내기 이후 변경 근거

## 사용자 기준
- 판매등록은 직원이 nenova.exe에서 이카운트 업로드용 Excel을 실제로 성공 내보낸 시점이다. REG_CONFIRM, 웹 다운로드, 이카운트 실제 입력으로 대신하지 않는다.
- 독립 변경안 작성 메뉴는 보존한다. 견적서관리의 품목별 변경 이력 링크는 현재 그 메뉴로 연결되며 실제 전산 수정 감사가 아니다.

## 실제 확인
- origin/master 1b0cbf3c4 기반 격리본. 설치 EXE dnSpy FormEstimateView 재실행: btnExcel_Click가 선택 업체마다 GetExcelDetail을 합친 뒤 ExportToXlsx(fileName)를 호출하고 성공 대화상자를 표시한다. 성공 후 DB·서버 이력 기록 호출은 없다. 파일 기본 이름의 날짜는 날짜만이며 성공 시각·차수·업체범위 증명이 아니다.
- SELECT 운영 metadata에 export/download 전용 테이블 없음. AppLog의 Excel/export 후보0건. SystemActionLog 후보12건은 웹 revenue-import-excel(2026-06-04~06-29). EcountSyncLog1730건(2026-04-02~04-05)은 거래처/판매입력 동기화다. EXE 성공 export 근거로 사용할 수 없다.
- WebSalesSnapshot REG_CONFIRM4건(2026-08-20~08-28)은 별도 웹 확인 스냅샷이다. TUE_FINAL·CHANGE 등도 EXE export 성공 기준이 아니다.
- Orbit erp-change-link는 엑셀 저장을 not_covered로 분류한다. 기존 drive-egress는 파일 복사/인쇄/업로드 등 관측으로 EXE callback·선택 업체·당시 품목 baseline을 포함하지 않는다. Orbit의 실제 과거 work.action DB는 이 환경에 접속 설정이 없어 미조회다.
- 공식 원본 소스와 공급사 업데이트 배포 채널은 미확인이다. decompile 프로젝트를 공식 소스로 취급하거나 EXE를 무단 패치하지 않는다.

## 정확한 향후 수집 선행조건
1. 공식 EXE 수정·배포 경로와 카나리1대 지정. 기존 직원 PC 광역명령 금지.
2. ExportToXlsx 성공 직후 고유 eventId, source=nenova.exe, 실제 성공 시각/오프셋, 선택 연도·차수·업체 범위, 선택 필터, 당시 GetExcelDetail 불변 행과 파일SHA를 함께 확보. 취소·실패는 성공으로 기록하지 않는다. 비밀·계좌·로컬 전체 경로 수집 금지.
3. 인증된 전용 수신과 eventId 멱등 append. 기존 웹 전용 파일 저장 패턴을 우선하고 ERP/ECOUNT 쓰기 없음. 실제 생산자가 준비되지 않은 웹 클릭로그로 성공을 가장하지 않는다.
4. 재다운로드는 이전 baseline과 이후 변경을 보존하고 새 비교 구간을 만든다. 묶음 차수전체 상태와 업체·품목별 상세는 해당 event 범위에서만 집계한다.
5. ShipmentHistory의 실제 시각·전후값과 snapshot 관측기간을 구분한다. Estimate/단가 등 자동감사 미기록은 완전감사로 보장하지 않는다. 날짜만 있는 수기확인은 같은 날짜 순서 불명, 미연결·미기록·재등록 경계는 변경 없음이 아닌 미확인이다.

## 출력 독립 수정과 실측
- CSS 개별변 테두리·색과 header 외곽 프레임을 보존하고 병합 뒤 테두리 외곽을 적용한다. 원래 공통 변환은 모든 테두리를 회색4변으로 강제해 외곽이 빠졌다.
- 한국어 Excel Normal테마 글꼴의 숫자폭과 OOXML 열폭 패딩 이중환산을 수정한다. 절대 경계를 정수 pixel로 먼저 맞춰 미세 조각의 행높이 누적 손실을 줄인다. 실제 셀 서체·수치·SQL 산식은 보존.
- 합성 중국 TOTAL·출고대행수수료 종합견적, 실제 Excel100% COM·편집화면·인쇄미리보기 확인. 수정 전 제목폭519pt 대 HTML510.234pt. 수정 후510pt. 참조/TEL·FAX/결제조건/유효기간은 원 HTML의 빈 값도 그대로 보존하며 임의 데이터를 채우지 않는다.
- 기존 긴2업체55행씩 문서는 페이지수4가 같아도 첫페이지38/42행으로 달랐다. 사용자 보정 지시에 따라 같은 전체행 페이지구획을 HTML 인쇄와 Excel에 적용하고, Excel은 인쇄페이지별 시트로 나눈다. 인쇄 머리글은 각 페이지, 문서 머리글은 첫 페이지, 최종합계는 마지막 페이지에 한 번 보존한다.
- 실제 Chrome PDF와 Microsoft Excel PDF8종(종합 중국TOTAL/수수료, 일반, 긴2업체, 박스OFF, 긴명세서, 음수명세서, 부가세미분류음수, 전년동일차수) PASS. 페이지별 품목ID·행순서·모든 금액의 중복횟수·완전한 장문을 비교. 긴2업체는 양쪽35/20/35/20행, 긴명세서는29/26행 일치. 캡처파일은 합성자료만 .verify/estimate-print-parity에 보존.
- 일반편집의 격자와 실제 프린터 인쇄의 글꼴·DPI 메트릭은 플랫폼에 따라 다르므로 픽셀 단위의 모든 프린터 동등성을 보장하지 않는다. 검증은 현재PC의 실제Excel100%와 실제PDF 및 명시적 페이지/품목 범위 기준이다.

## 부작용과 기준
| 동작 | ERP 전 테이블 | ECOUNT | 웹 저장 |
|---|---|---|---|
| 출력 치수·테두리 생성 | 보존 | 보존 | 없음 |
| 운영 근거 probe | SELECT만 | 접근 없음 | 로컬 집계 증거만 |
| EXE 성공 연동 | 아직 미구현, 공식 경로 선행 | 쓰기 금지 | 향후 인증된 불변 이벤트만 |

견적서관리 상단에는 차수전체 판매등록 이후 변경, 품목행에는 업체·품목 범위의 변경이력 상태를 연결했다. 공식 성공원천이 없어 기준미기록/변경여부미확인을 표시하며 기존 독립 변경안·과거수기 메뉴로 이동할 수 있다. 새 자동감사나 성공이벤트 수집이 구현됐다고 주장하지 않는다.

메뉴 기준선: 인쇄 기존 URL/데스크톱 검색·즐겨찾기 경로 유지 및1.3.97업데이트 적용, 키보드·작은 화면·가이드 적용. 새 DB·Rust·원장 writer 해당 없음. 정확한 EXE 관측기가 새 상주 실행파일로 필요해지면 Rust 원칙 및 별도 공식 카나리 배포 조건을 적용한다.
