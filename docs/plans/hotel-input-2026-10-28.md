# 호텔 차수·카톡 입력 복구

기준: 사용자 요청 기본차수 ±5, 기존 hotelMiuMajorWeekOptions의 영업 기본(달력 대차수+1), 52차수 연도 이월 및 숫자 세부차수 01~04. 기존 업체별 탭의 +9 정책은 보존한다.

| 동작 | 기준과 소비자 | ERP 원장/견적/매출/재고 |
|---|---|---|
| 신규 작업 | 기본 대차수-01 미리 선택, 앞뒤5 대차수와 01~04 선택; 선택 연도와 차수 함께 전달 | 보존 |
| 원문 입력 | 자동저장 중/저장실패에도 편집 가능; 실제 분석/불러오기/등록 중 및 frozen은 잠금 | 보존 |
| 서버 초안 | 내용 없는 신규 작업은 자동저장하지 않음. 저장 중 입력은 최신 화면 상태로 후속 저장. 기존 revision/CAS/등록 전 intent 보호 유지 | 웹 runtime 파일만 |
| 등록 | 기존 source=my-customer ADD/expectedCurrentQty/사후검증 그대로 | 기존 계약, 이번 수정 없음 |

이 변경은 웹 입력 컨트롤과 선택 기본값만 수정한다. SQL/API/ERP 저장 순서는 변경하지 않는다. FormOrderAdd golden의 2026-10-27 실제 dnSpy 및 동일키 읽기 probe 근거를 재검토했으며 새로운 원장 쓰기 시험은 하지 않는다. verify:week는 기존 원장 차수 정정용이므로 이번 선택 UI에는 해당 없음. 입력·cross-year·저장중 추가입력·실패·frozen 회귀와 전체 필수 가드, 실브라우저로 검증한다.

메뉴 기준: 단일 shell/페이지 스크롤/키보드/선택맥락/원문보존/등록 전 확인 적용. 원장 부작용 변경·스키마 변경 해당 없음. 완료 결과는 세션 기록에 남긴다.
