# 2026-11-23 입고 수정 품목 검색 및 기존 포장값 보존

기존 입고를 선택한 뒤 품목만 바꿔도 불필요한 박스 수량 입력을 요구하던 문제를 수정한다. 검색창 바로 아래에서 품목명, 표시명, 품목 코드와 별칭으로 후보를 보여준다. 검색어 입력과 품목 선택은 독립적이다. 기존 입고 수정 메뉴의 내부 화면이므로 새 경로나 메뉴는 없다.

dnSpy CLI로 실제 Nenova.exe의 ClassWarehouseDetail.GetData를 확인했다. 박스 수량을 포함한 원장 수치 필드를 읽고 decimal.TryParse로 해석한다. 웹은 원장에 새 수치를 추정해 쓰지 않고 원본의 NULL을 보존한다. 운영 SELECT 전용 표본 8247 / 2026 / 47-02 / ProdKey 3170에서 BoxQuantity NULL, BunchQuantity·SteamQuantity·UPrice·TPrice 값 있음 및 출고/견적 단위 송이를 확인했다. 해당 원장을 쓰거나 변경하지 않았다.

| 동작 | 입고 | 주문·분배·출고일·견적·손익 | 재고 |
|---|---|---|---|
| 품목 검색·선택 | 브라우저 수정안만 변경 | 보존 | 보존 |
| 요청 미리보기·등록 | 같은 WarehouseKey·연도·차수의 원본행을 검증. 요청 등록은 기존 웹 요청/이력만 저장 | 보존 | 보존 |
| 영업지원 최종 승인 | 기존 원장 writer 사용. 출고·견적 단위에 필요한 원본 수량이 없는 새 품목은 차단. 원본과 같은 NULL만 허용 | 기존 검토·확정·검산 계약 | 기존 원자적 재계산 |

검증 기준은 박스가 없는 기존행과 명시적 0을 구분하고, 다른 연도나 숫자가 기입된 원본행에 빈 값을 덮지 않으며, 파킹리스트 교체 파일에서도 누락 검사를 유지하는 것이다. 회귀 fixture가 같은 차수의 2025년 원장을 차단하는지 확인한다.

2026-11-23 읽기 전용 같은 업무키 대조에서 2026/47-02/ProdKey3170은 ViewOrder 0, ViewShipment 0, ShipmentDate 0, ShipmentFarm 0, ViewOrder·ShipmentDate와 연결되고 DetailFix=1인 견적 노출행 0이었다. 2025 동일 차수의 같은 품목 출고도 0이어서 교차연도 차단은 별도 fixture에서 검사했다. 이 표본은 연결 확정행이 있는 품목의 최종 승인을 운영 검증한 결과가 아니다.
같은 조회에서 2026년 대차수 47의 활성 손익 확정 0건, 표본 품목의 해당 세부차수 확정 매출행 없음(SUM NULL)을 확인했다.
