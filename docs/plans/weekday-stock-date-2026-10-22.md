# 주광 출고일 저장·재고 판정 수정

## 확인 근거
- 설치 EXE FormShipmentDistribution을 dnSpy CLI로 재추출: 확정 SP 성공 뒤 native CALC.
- 운영 SELECT로 확보한 usp_ShipmentFix는 전차수 ProductStock + 해당 차수 ViewWarehouse - DetailFix=1 ViewShipment + CodeInfo StockType 조정을 검사한다. Product.Stock은 판정 원천이 아니라 확정/취소 증감 기록 대상이다.
- 기존 주광 API는 Product.Stock으로 먼저 차단하고 최종 현재고 음수도 별도 차단했다. 운영 SP와 다른 조건이다. 현재고와 차수별 재고는 서로 다른 시점/누적 이력을 가지며 임의 동기화하지 않는다.
- 2026/43-01 주광 플라야블랑카 50cm=10단(10/22), 60cm=70단(10/26 60,10/27 10). 사용자 설명 70단과 DB 80단 불일치로 운영 수량·날짜 임의 정정 금지.
- 실패 HTTP409 네 건은 요청 본문/품목이 기록되지 않아 플라야가 직접 부족 원인이었는지 단정 불가. 실패 진단에 품목·차수·재고 검산을 남긴다.

## 기준 및 부작용
| 동작 | 주문·입고 | 출고·날짜·금액 | 재고 | Estimate/손익 원장 |
|---|---|---|---|---|
| 확정 출고일만 이동 | 보존 | 기존 날짜 저장·금액 보존 | 보존, 불필요 CALC 생략 | 직접 쓰기 없음 |
| 미확정 출고일 이동 | 기존 계약 | 선택 상세 확정 후 날짜 이동 | native 차수 검산, 기존 확정 증감만 | 직접 쓰기 없음 |
| 수량 수정 | 기존 ADD/CANCEL 계약 | 기존 환산·단가·확정 순서 | 차수별 증가 검산 + native cascade/readback, 임의 조정 없음 | 직접 쓰기 없음 |
| 견적서관리 연결 | 보존 | 보존 | 보존 | 기존 관리 화면에서 사용자 입력 |

일반 API lifecycle에만 새 차수 검사를 적용한다. 선출고 내부 legacy 호출 정책은 보존한다. 전년도 같은 차수와 후속연도 경계를 분리하고, 배치의 이전 차수 소비 증감은 뒤 차수 가용량에 반영한다. 실패는 전체 rollback, 초안 유지. 음수 분량을 재고조정으로 자동 보충하지 않는다.

## 메뉴 기준
적용: 기존 shell, 페이지 세로 스크롤, 의미 있는 링크/Tab, 업체·연도·차수 유지, 입력 초안 보존, 저장 전 검토/후 조회. 해당 없음: 새 메뉴·파일 매칭 변경. 검증/배포 결과는 세션 기록에 추가한다.
