# 주광 견적서 접기와 합계·잔량·변경 3열

사용자 표시 범위에 맞춰 안내·작업 기준, 마감·이월 도구, 품목 검색·필터,
차수별 ERP 확정 상세를 기본 접힘으로 표시한다. 연도·중심 차수 이동,
새로고침·저장·업체 연결 버튼, 저장 대기·오류는 항상 접근 가능하다.
확정 상세를 접어도 원장 상태와 연결경고 요약은 보존한다.

합계·잔량·변경은 각각 실제 td/th/col로 분리한다. 논리 계산 열은 기존
remainingMajor를 유지하며 표시만 1→3열로 확장한다. 차수 헤더 13열,
3차수 전체 40열이다. 합계 내역/견적 대조, 잔량 수정·이력, 변경 비고는
기존 이벤트와 연도·차수·거래처·품목 식별을 보존한다. 미확인·0·음수와
초안·기준 미확정·이월 표시는 기존 계산을 따른다.

| 사용자 동작 | Order/Shipment/Date/Farm/Stock/Estimate/WebProfitReport | 웹 기록 |
|---|---|---|
| 펼치기/접기, 3열 표시, 가로·세로 스크롤 | 모두 보존 | 보존 |
| 내역 열기 | 모두 보존 | 보존 |
| 기존 명시 저장/잔량 수정/비고 수정 | 기존 계약·핸들러 그대로 | 기존 계약 그대로 |

공유 API/SQL/저장 정책/인쇄 eligibility 변경은 없다. 고정 헤더는 본문
버튼과 오류보다 위(z=5), 내역 팝오버(z=30)보다 아래다. 표 높이는
화면의 실제 상단 위치와 접기 상태를 반영한다.

근거: 설치 EXE를 dnSpy.Console --no-color -t FormEstimateView로 재추출하고
GetPrintDetail의 DetailFix=1 조건을 재확인했다. 기존 decompile와
docs/exe-golden/FormEstimateView.md의 조회·출력 범위를 보존한다.
운영 SELECT에서 주광 고객 533/675, 2026-40-01 및 40-02의 raw 상세 확정
상태를 확인했다. 533/40-01 상세 77개, 533/40-02 상세 22개이며 각각
부분 확정이다. DB probe는 UI 구현 후 재검증 단계에서 수행했다.
기존 probe의 bit MIN/MAX는 실행 불가여서 로컬 실행본에서만 int CAST로
보정했으며 API와 저장소 probe 파일을 수정하지 않았다. 운영 원장 쓰기 없음.

docs/CODEX_SUBTASK_ORCHESTRATION.md는 현재 master에도 없어 읽지 못했다.
메인 작업에서 입력·계약·검증을 준비하고 독립 읽기 검토에 표시 구조와
ERP 부작용 보존을 배정했다. 검토의 헤더 z-index 지적을 반영했다.

검증: 기존 cross-year 계약과 2025 같은 차수 sentinel을 추가한 실제 SSR,
수량/잔량/내역/실패/인쇄 보존 회귀. 50품목 browser fixture는
1920×1080 CSS px/100%, 1280×800에서 페이지 가로 넘침, 표 가로 스크롤,
확정 상세 토글, 환산 숫자·버튼 겹침, 내역/비고 창, 실패 안내를 검증했다.
전체 ERP 계약, dnSpy 근거, 변경 manifest, 쓰기 가드 및 build로 배포를 판정한다.
