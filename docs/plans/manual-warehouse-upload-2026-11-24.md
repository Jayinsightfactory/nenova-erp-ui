# 수기 입고 기준과 영향

사용자는 원장의 업로드 옆에서 수기 업로드를 열고 연도·세부차수·실제 입고일·활성 농장과 품목을 선택한다. 연도별 세부차수 선택 목록은 실제 `StockMaster`에서 읽고 목록에 없는 차수는 직접 입력할 수 있다. 연도 변경은 기존 차수와 미리보기를 지우며 미리보기에는 등록 대상 연도와 세부차수를 다시 표시한다. 인보이스와 AWB는 기존 파일 업로드와 동일하게 입력할 수 있으며, 기등록 자료를 수정하지 않는다. 여러 품목을 미리 확인한 뒤 한 원장으로 등록한다.

| 단계 | 기준 | 원장 영향 |
|---|---|---|
| 입력 및 미리보기 | 현재 활성 농장/품목과 출고·견적 단위를 서버에서 다시 대조. 박스·단·송이 중 실제 기준량과 포장당 송이수를 입력. 단위가 다른 경우 필요한 환산은 명시된 비율과 정확한 단위가 있을 때만 허용. | SELECT만. |
| 금액 | dnSpy 수기 등록은 `TPrice=SteamQuantity×UPrice`. UI에서 송이당 단가 또는 행 금액을 명시. 원본 통화의 소수·0을 그대로 취급. | 미리보기는 쓰지 않음. |
| 등록 | 같은 `OrderYear+OrderWeek+FarmName+InvoiceNo`의 중복 검사, 같은 UUID의 동일 요청 복구. 파일 업로드와 같은 재고 게이트, 확정 검사, 트랜잭션, 사후 대조. | `WarehouseMaster/Detail` 신규, 기존 입고용 재고·이력/재계산만. |
| 보존 | 기존 입고·인보이스 문서·개정, 주문 및 출고, `ShipmentDate/Farm`, `Estimate`, `ShipmentDetail.Amount/Vat/isFix`, `WebProfitReport`를 직접 수정하지 않음. | 기존 파일 업로드의 영향 범위와 동일. |

설치본을 dnSpy CLI로 재추출했다. `FormWarehouseAdd.CheckValue`가 품목과 양수 수량, `CommonLogic.CheckFixSave`를 검사한다. `CheckFixSave`는 현재 차수 확정, 직전 재고 차수 미확정, 다음 재고 차수 확정을 확인한다. `btnSave_Click`은 `UnitQuantity`로 출고·견적에 사용하는 단위를 각각 고르고 송이 기준 가격을 기록한다. 상세 저장, `StockHistory` 추가 및 `Product.Stock` 갱신에 이어 연도·차수·품목 재계산을 수행한다. 웹은 기존의 선수행 재고 게이트와 등록·재계산을 함께 묶은 보호된 트랜잭션을 재사용한다.

운영 #8247 2026/47-02 읽기 대조는 상세 140행(출고단위 단 70, 송이 70), 활성 농장 1, 등록 문서 3, 같은 연도·차수·품목의 주문/출고 130행, 출고의 `DetailFix=1` 130행, 해당 대차수 활성 확정 손익 0건이었다. 활성 농장명 우측 공백을 정리한 표시값에서 새 서버 검사도 중복 송장과 확정을 확인했다. 운영 시험 등록을 수행하지 않는다.
