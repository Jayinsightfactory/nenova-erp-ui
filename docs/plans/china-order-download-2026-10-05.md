# 중국 발주 현황 다운로드

## 요구사항 및 계약
- 메뉴 `/stats/china-order-download`: 중심 메인차수 이전3 + 현재 + 다음3, 총7개를 가로로 표시. 세부차수 주문을 합산하되 상세 다운로드에는 보존한다.
- 기본 중심차수는 한국 현재일에 해당하는 실제 `PeriodDay` 목요일(WeekDay=5) 업무차수. ISO 주차나 연간52차수 가정 금지. 연도 경계도 실제 전산 달력으로 이동.
- 수량은 native `ViewOrder.OutQuantity > 0`, 중국 `CounName=N'중국'`, 활성 Product 기준. 주문등록 수량이며 분배/출고/입고/재고를 섞지 않는다. 단위별 합계만 허용.
- 실제 설치 EXE를 2026-10-05 dnSpy.Console.exe --no-color -t FormQuantityPivot로 확인: GetData 주문영역은 ViewOrder.vo.OutQuantity를 읽는다. 원본 피벗은 StockList를 연결하지만 이 페이지는 주문등록 전체를 조회하므로 재고마스터가 없어도 주문을 보여준다. ERP 수정은 하지 않는다.
- 정확한 업무키: OrderYear + OrderWeek + CustKey + ProdKey. 조회 응답에서 품목번호/품목코드/원본 이름/단위/차수와 상세 내역 유지.
- API는 네 업무키별 주문수량을 SUM하여 중복 상세도 한 업무행으로 반환한다. HF 식별자 없는 정확명/코드 fallback 유일성은 전체 활성 중국 Product 사전으로 검증하며 사전 조회 실패시 부분 사전으로 대체하지 않는다. availableCycles는 선택 연도 앞뒤 연도를 포함한 실제 달력 목록이고, 선택7개는 offset -3..3 정렬이다. warnings는 문자열 배열, queriedAt는 UTC ISO 문자열이다.
- 첨부 `품목목록_2026-10-02 hf code.xlsx`, `Sheet` 416행을 기본 HF 사전으로 제공. 실제 HF code 열만 사용. HF match review의 Closest catalogue code는 절대로 빈 HF를 대체하지 않는다. Check/No match 상태는 참고 경고로 보존한다.
- 매칭 우선순위: 품목번호와 품목코드 동시 검증 → 유일한 품목코드(번호 누락시만) → 유일한 정확한 원본 이름(번호/코드 둘다 없을때만). 식별자가 서로 모순되면 미매칭/충돌. 이름 퍼지 추측 금지. HF 코드 하나가 여러 품목에 쓰이는 것은 허용(역키가 아님).
- 재업로드: xlsx 파일을 브라우저에서 읽고 이 화면의 사용자 브라우저 사전으로만 저장. 기본파일 복원 버튼. 서버/ERP 품목정보를 쓰지 않는다. 보관 범위 표시. 잘못된 파일은 기존 사전 유지.
- 업체 주문코드(CL2, CLS 등)는 활성 `Customer.OrderCode`를 `CustKey`로 연결한 현재 전산 정보다. `CustKey`, `CustCode`, `ViewOrder.OrderCode`/`OrderMaster.OrderCode`로 대체 추정하지 않는다. 없으면 빈값과 경고를 보존한다.
- 다운로드: 화면 필터/매칭상태와 같은 모델의 `발주현황` 시트(품목번호,품목코드,품목명,HF CODE,매칭상태,단위,7차수,합계), `업체별발주` 시트(업체키·업체 주문코드(CL)·업체명·품목/HF·단위·7차수·합계), `주문상세` 시트(연도,세부차수,업체키,업체명,업체 주문코드(CL),품목키,품목코드,품목명,HF CODE,단위,수량), `조회기준` 시트. 업체별 집계도 CustKey+ProdKey+단위로 구분하며 같은 CL의 다른 업체를 합치지 않는다. 원본 숫자 보존, 코드 문자열 보존, 회색/흰색 행 구분·테두리·헤더고정·필터 제공. 미매칭은 다운로드에서 제외하지 않는다.
- UI 기준1920×1080 /100%. 상단 연도/중심차수/앞뒤 이동/조회/HF업로드/다운로드, 상태 요약과 검색. 진한 14px 숫자 중앙. 행 hover. 전체 페이지 세로 스크롤, 좁은 화면 가로스크롤, 고정 품목명. 비어있음/실패/로딩 구분. 실패·로딩·stale 결과 다운로드 금지.
