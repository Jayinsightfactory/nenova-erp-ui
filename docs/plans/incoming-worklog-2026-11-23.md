# 입고 수정 요청 검색과 검토 피드백

수입부 업무도구의 입고 수정 탭에서 운영 브라우저 조회만 사용해 같은 품목 검색을 확인했다. 기존 브라우저 검색에서 `abosrbed red`는 0건, `absorb`는 1건이었다. 기존 품목 API의 검색 모드는 오타 검색에서 품목 1014를 첫 후보로 반환했다. 이 공용 조회를 직접 후보가 없을 때 사용하고 사용자가 다시 명시적으로 고르게 한다.

| 화면에서 하는 일 | 확인 근거 | 실제 쓰기 범위 |
|---|---|---|
| 품목 검색, 선택, 변경값 강조 | 현재 선택할 수 있는 품목 목록, 행별 원본키, 원장 값을 확인 | 검색은 품목 조회, 선택은 브라우저 수정안 |
| 제출 중, 처리 완료, 실패 | 초안 생성, 요청 상태 조회, 실제 요청 상태 응답 | 기존 웹 승인 요청과 감사 이력 |
| 영업지원 검토 | 원본 행의 변경 전후, 매칭 저장 응답, 기존 검증 결과 | 기존 요청 매칭 및 원장 영향 롤백 검증 |
| 영업지원 최종 확정 | 적용 상태의 실제 성공 응답과 기존 서버 이력 | 기존 서명·버전·업무키·원장 계약과 동일 |

정정 로직은 `WarehouseKey + OrderYear + OrderWeek`와 기존 원본행키를 그대로 사용한다. 새 저장 API나 ERP 쓰기, 확정 해제, 견적·손익 갱신을 넣지 않는다. 새 작업 로그의 실패를 완료로 기록하지 않는다. 지도된 권한·최종확정·중복 복구를 적용하는 기존 서버 감사 이력이 지속 기록이다. 브라우저에서 요청을 바꿔 열면 해당 이력을 다시 읽는다.

기존 `ClassWarehouseDetail` dnSpy 및 실제 HOLEX 8247의 연동 검증을 재사용한다. 새 화면에서 영업지원 미리보기와 최종 승인 검증은 합성 자료만 사용한다. 운영 스모크는 조회 동작만 수행한다. 같은 업무기능은 이미 데스크톱 입고관리 및 수입부 업무도구 메뉴 양쪽에 있으므로 별도 메뉴나 버전 변경이 필요하지 않다.
