# 확인된 도착원가 평균 대체 — 구현 전 기준안

## 최신 승인 ledger (이 절이 아래 이전 설계·대기 상태를 대체)

사용자가 국가 평균 대체와 유사품목 단·송이 환산을 명시 승인했다. 동일품목→동일국가·품종→동일국가 순서의 원도착원가 총액/송이분모 가중평균을 결손에 사용한다. 유사환산은 같은국가·품종·형태·규격의 확인된 값에서 선택하며 기본1은 만들지 않는다. 이전연도 읽기도 허용하되 OrderYear+전체세부차수로 평가시점 이하만 선택한다. 2025기초에2026미래단가를 넣지 않는다.

실제입력·수기·명시0는보존하고 source=missing의자동0과구별한다. 누락성분만보완하며 상품/운임G와통관H를분리해완전도착원가를G에넣고H를다시더하지않는다. 재고는도착원가×보유송이이며음수수량도원장그대로보존한다. fallback결과를donor에재등록하지않고판매단가를원가로쓰지않는다. 평균근거·cutoff·출처·환산근거는상세에보존하되반복'추정포함'문구를재도입하지않는다.

조회설계는연간rawsnapshot/context재사용+부족receipt/stock메타boundedSELECT·process-memory단일flightcache다. 모든차수live보고서/출고원장재계산을조회마다추가하지않는다. 구현중이며금융출력전체완성·배포완료는아직아니다. 먼저순수엔진과오프라인재생후독립검토,이어공통조회어댑터와전체gate를실행한다.

상태: 설계·정량 사전조사. 금융 런타임 변경 없음. 기준 `05a20477`, 전용 `codex/profit-average-fallback`.

사용자 최신 승인: ‘누락이나 못찾는건, 평균가로 대체해줘’. 과거 보완 불가 정책보다 최신 승인을 우선하되, 평균의 대상은 판매단가가 아니라 확인된 매입·도착원가다. DB·원장·저장본은 수정하지 않는다.

## 2. 제안 구조

1. 읽기 전용 연간 raw 저장본의 category_average 근거를 1회 수집한다. `totalCost/purchaseQty`를 원수치로 보관하고 current/prior cutoff별 누적합을 만든다.
2. 필요한 결손 품목에 한해 bounded WarehouseDetail 실제 송이·출고단위·품종/국가 및 exact FreightCostDetail 실비를 보충한다. 전체 출고원장이나 전수 live 재계산을 매조회 실행하지 않는다.
3. donor vector = `{goodsKRW, freightKRW, dutyKRW, otherCustomsKRW, stems, year, fullWeek, product, country, flower, form, sourceIds}`. 성분별 분모와 결손 여부를 유지한다. 중복 WdetailKey·AWB 비용을 재합산하지 않는다.
4. 동일품목 원단가가 있으면 우선하고, 없으면 동일국가·품종 평균을 적용한다. 이미 평균 대체된 결과는 donor로 등록하지 않는다.
5. 재고 E/F = 검증된 대상 송이수 × 도착원가평균. H는 당주입고의 누락된 관세/기타통관 성분만 보완한다. 원도착원가에 들어간 H를 재고액에 다시 더하지 않는다.
6. 계산본 clone만 수정하고 동일 canonical helper를 웹·월별·출력·검산에서 공유한다. 원본 저장/확정본·DB는 보존한다.

## 3. 사전 근거와 실제 가능 범위

- guard 스킬·AGENTS·관련 원가/평균/송이/이월 계약을 재확인했다. 공통 ERP/CLAUDE/dnSpy 지침은 이전 완료작업 기준 대비 git diff가 없어 이미 읽은 정본과 동일하다. Next API Routes 가이드 전체 재확인.
- 실제 dnSpy `FormWarehouseView` 재실행: OrderYear/OrderWeek 및 uspStockCalculation 연결 확인. 이번 작업은 해당 SP를 실행하지 않는다.
- 기존 SELECT-only 연간 감사 재사용: 입고21,888행에는 goodsForeign/freightForeign/actualDuty는 있지만 송이수·품목별 기타통관·완전landedAmount가 없어 품목별 원/송이 평균을 바로 만들 수 없다.
- 01~43 raw category_average end 메타255건. 송이 단위이면서 estimated=false·H source!=missing·총액/매입분모유한 양수인 **메타 후보**51건: 수국16/알스트로12/에콰도르2/베트남6/네덜란드15. 실제 donor 확정이 아니며 H구성·원환율·그룹 동일성을 추가 검사해야 한다.

- 현재 자료만으로 ‘전누락복원’이나 정확한 수익률 영향액을 단정할 수 없다. 우선 지원가능성 상한과 원천 보충 필요 목록을 분리한다.

## 5. 구현 전 결정할 경계

- 기존 완전 승인 계산식(공식 관세 조건부·통관주간 규칙)을 donor에 허용할 것인지, 실납부/원문실비만 허용할 것인지 명시한다. 평균대체 값 자체는 어느 경우에도 재사용하지 않는다.
- 국가 단독 보고서 행(NL/TH/CN/EC)의 기존 category-average는 국가 전체 가중평균이다. 이를 같은 집계행 보완에만 쓸지, 개별품종 대체까지 허용할지 분리한다(기본안: 개별품종에는 직접 확대하지 않음).
- R결손을 원화도착원가 평균으로 우회할 때 R은 미확인으로 유지하고 금액 직접근거를 표시할지, 같은통화 FX 평균을 별도 승인할지 확정한다(기본안: 가짜 R 생성 금지).
- 음수재고·단위불명·기초연도경계는 가격평균으로 해결되지 않는다. 수량은 원문 그대로 두고 평가 불가 사유 유지.

실제0/수기/확정원본 보존, donor 원총액/분모, 중복원행, 다른연도/미래차수, 다른통화·품종·형태, 추정값재학습, 무분모, 음수/미확인수량, 동일 E/F 평가정책, H중복, 원천총액불변, 원단가우선, 웹/월별/Excel/인쇄 동일성을 실행형 양성/반례로 검증한다. 구현 승인 후 계약 manifest·전체ERP·dnSpy·쓰기guard·build·운영read-only smoke를 통과하기 전 배포하지 않는다.

## 7. 조사 종료 시점 정량·대기 사항

최신71개 정책 연결 후01~43 재생본에서 E/F공란은167셀이다: 호주37, 중국57, 미국22, 태국31, 콜롬비아장미16, 네덜란드2, 에콰도르2. 이 중 수량 단위미확인도 포함되므로 가격평균만으로 모두 해결되는 수가 아니다.

255개 원평균 중 위51개는 `(purchaseForeign+forwardingForeign)*taxableRate+customsCost≈totalCost` 산식까지 통과했다. 그러나 같은품종이 명확한 콜롬비아 수국·알스트로에는 현재 E/F공란이 없다. **이 송이단위 메타만으로 곧바로 보완 가능한 동일품종 공란은0셀**이다. 다른 단위·국가집계·개별실비까지 확인하면 가능범위는 달라질 수 있으므로 전체평균대체가 불가능하다는 뜻은 아니다.

추가 재사용 가능 자료: `nw-profit-stem-cost/.verify/stem-dataset.json`의22,786입고행과 `stem-arrival-evidence-v3.json`. 후자는 currency_master·기본 통관비·부분원가가 섞여 있어 VERIFIED/estimated=false 라벨만으로 donor에 넣지 않는다. `stem-full-costs-v2.json`은 이월산출물이므로 원매입원가 donor로 직접 재사용하지 않는다.

사용자에게 ‘같은 품종이 없을 때 같은 국가 평균도 허용하는지’를 확인 중이다. 답변 전 국가 범위를 넓히거나 금융 코드를 구현하지 않는다. 현재 변경은 계획·계약 초안만이며 신규 SQL0/DB쓰기0/앱코드수정0/미배포다. 런타임이 미구현이므로 전체 gate를 완료했다고 표시하지 않는다.
# 후속 사용자 지시: 계산 보류 대신 평균 비용 보완 검토

2026-11-03 관세 직접원본 연결 이후 재생 결과에 대한 추가 설계이며, 아래 평균 보완은 **아직 구현하지 않았다**. 사용자는 수익률 계산 보류를 원치 않으며, 부모가 국가 평균 확대 여부를 별도로 확인 중이다. 진행 중 관세 gate는 완료하되 배포는 부모 지시에 따라 대기한다.

실제0·수기·확정원본·DB는 계속 보존한다. 매출단가를 원가로 사용하지 않고, 평균 대체값을 다음 평균의 학습원천으로 재사용하지 않으며, 미래차수 근거를 과거로 누출하지 않는다. 국가 평균 확대는 사용자 선택 전 적용하지 않는다.

### 저장 계산행 표시와 원가 보완의 구분

131행 중 원본 계산 K가 있는59행, 원본도 K가 없는72행으로 나뉜다. 그러나59행 중36행은 `source.H=missing, H=0`이다. 나머지는 gw_auto16, 역사값2, approved_estimate5다. **숫자가 저장됐다는 이유만으로 원가가 완전하다고 인증할 수 없다.** 기존59행 표시가 승인된다면 C/E/F/G/H/I/J/K 원본 계산 묶음 전체를 참고값으로 보여주고, 새로 보완한 일부H와 기존E/F를 섞지 않는다. 해당 참고값은 평균 donor로 사용하지 않는다. 특히missingH0의36행은 비용 평균 보완 대상이며 원래0으로 되돌리는 것을 해결이라고 기록하지 않는다. 원본K가 없는72행도 수량/통화 근거와 같은품목·품종의 과거 원가 구성이 먼저 필요하다.

# 최종 추가 승인: 참고기간·성분보존·숫자 K의 누락비용

- 기존 과거-only 제약은 같은 품목 과거→참고기간, 같은 품종 과거→참고기간, 같은 국가 과거→참고기간 순으로 대체한다. 실제 평가일 원가 인증이 아니며 기간을 표시한다.
- 환산도 과거 근거 우선, 없을 때 같은 품목 또는 같은 품종·형태·규격 확인 입고의 참고기간 환산을 허용한다. 국가 광역계수/기본 1은 금지한다.
- 실제 외화 상품액을 평균으로 덮지 않는다. 18차 누락 환율만 기존 국가별 통관주간 규칙과 공식 고시값으로 보완한다. 실제 신고일 인증은 하지 않는다.
- 숫자 수익률이 있어도 H=0·source missing/partial·실제 입고 양수·수기 없음이면 누락 비용 보완 대상이다. 무입고/명시 0/수기/국내/미분류를 강제로 평균 처리하지 않는다.
- 원재고 snapshot key를 우선하며 없으면 canonical ProductStock 행수→StockKey 순으로 선택한다. 원래 E/F와 보완 basis는 함께 보존한다.
- runtime은 기존 연간 context에 3개 bounded SELECT를 붙이고 single-flight 메모리 재사용한다. cold/warm 성능 및 응답 크기를 검증한다. 저장본·DB 쓰기는 없다.
