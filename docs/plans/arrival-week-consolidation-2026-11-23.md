# 같은 차수 도착원가 통합 기준

목적: 중국 분할편 A/B와 콜롬비아 수국·카네이션·장미를 업로드 파일 경계와 무관하게 한 원가 시트에서 계산한다. 연결 목표 g17/g19.

## 근거와 범위
- 실제 EXE ExcelLoadingPackingList를 dnSpy CLI로 재확인. 입고 원문 수량·단가·금액과 원가 작성은 분리한다.
- 운영2026/45-03 Cloudland8061/8062의 OrderWeek는 동일45-03, 송장051A/051B·파일A/B·AWB78469519262/78469519730은 구별된다. A/B suffix를 원장에서 임의 제거하지 않는다.
- 운영2026/46-02 수국8073~8081과 일반꽃8085~8097의 AWB는 하이픈 제거 후01441369974로 같다. 업로드 파일이 달라도 같은 비용분모를 사용한다.
- 국가·연도·정확 세부차수에서 사용자 선택 입고만 계산. 다른 국가는 후보에서 제외하고, 다른 연도/차수·중복 입고·중복 상세는 거부한다.

## 입력·배분·출력 기준
- 원장 행 PK와 원문 파일·농장·송장·AWB·원본 지문을 보존한다. 재업로드로 원장에 중복 생성된 동일 농장·송장은 사용자 선택에서 한 입고만 포함하게 한다.
- 비용은 종류+증빙식별자, 통화, 금액, 대상AWB, 배분기준으로 식별한다. 동일 증빙 반복은 한 번, 같은 증빙 충돌은 차단, 동액 별도 증빙은 각각 보존한다.
- 운임은 실제 대상 AWB에만 귀속. 공유 운임의 대상/중량비율과 통관비의 공동/개별 범위는 사용자가 확인한다. 빈값은0으로 대체하지 않는다.
- 콜롬비아는 기존 품종별 GW/CW계수와 혼합품종 FB환산박스를 유지. 중국 CLOUD는 기존 CBM·단수·관세 공식을 유지한다. 과거 고정비는 실비로 주장하지 않고 추정 표시한다.
- 조회 후 새 입고/가격/비용이 변경되면 기존 미리보기·다운로드를 거부한다. 순서와 무관하게 정렬한 입고 집합에서 다시 계산한다.
- 한 워크북의 한 원가 시트에 전 상품행과 원문 귀속, 계산식, 비용증빙 범위와 합계 검산을 표시한다.

## 부작용
조회·미리보기·다운로드 모두 WarehouseMaster/Detail SELECT만 수행. OrderDetail, ShipmentDetail.Amount/Vat/isFix, ShipmentDate, ShipmentFarm, StockHistory/ProductStock, Estimate, WebProfitReport 보존. 운영 입고 생성/보정·재고 SP·승인원가 저장 없음. 따라서 출고/견적 downstream 변경은 적용 범위 밖이다.

## 실제 재생·사용자 결정
- 중국: 원문A49행/B15행, 상품58행2190단/42675CNY, 운임10550+9920=20470CNY. 사용자210원/CNY 검증용 선택 및 A/B각각 청구 확인. 원가표 추정 통관비A1081000+B978800=2059800원, 당시확정환율·실제청구확정액이 아님. 합계18434216.141562원.
- 콜롬비아: 원문GW3942/CW4824, AWB운임13737.8USD. MasterInvoice FB: ROSE31/CARNATION22.5/ALSTROMERIA27.25/HYDRANGEA115, 총195.75. 송이8200/13500/9440/13800=44940. 송장부대비15+15USD는 해당입고 원본박스비율로 계산배분한다(청구원문이 배분비율을 지정했다는 주장이 아님). 선율 원문참고환율1345.2, 원가표추정 통관2025320원, 합계43916865.799999원. 실제 납부액 인증·승인원가가 아님.
- 업로드 parser와 입고writer는 변경하지 않는다. 인보이스 업로드후 기존입고 원가 진입 및 원가전용 작업의 동일 차수 취합에서 현재입고를 다시 조회한다. 별도 /import/pipeline 기능은 이번 변경대상이 아니다. 원장에 같은 농장/송장이 새PK로 중복되어도 취합에서 중복의심 차단하고 하나만 선택한다. SKU가 같아도 서로다른 송장의 원본행은 보존한다.
