# 업체 비교 입력 제한 해제와 고정 작업 영역

사용자 요구: 업체선택5개제한 제거, 품목명의 반복 품종 접두어(CARNATION/카네이션 등)는 화면에서만 축약, 품목명칸 압축, 출고일표시 기본ON/숨김전환, 다업체표 중간 이동칸 제거. 긴 왼쪽 품목/업체목록을 스크롤해도 오른쪽 선택품목·업체검색/추가·분배표가 보이도록 독립 스크롤로 고정한다.

## 기준과 허용 부작용

현재 EXE FormShipmentDistribution을 dnSpy CLI로 다시 추출해 GetCustomerList/GetProductList/btnSave_Click의 연도+세부차수+업체+품목 및 native OutUnit 저장을 확인한다. UI 비교 열수5개는 웹의 고정 슬롯 배열/추가창 분기뿐이며 Native ERP의 업무키가 아니다. Product.ProdName/DisplayName 및 CountryFlower 원본은 변경하지 않는다. CounName/FlowerName 문맥으로 기존 distributeProductName 표시함수만 재사용한다.

| 동작 | 허용 | 보존 |
|---|---|---|
| 업체 추가 선택/제거·검색·날짜 표시·스크롤·이름 축약 | UI 상태와 명시연도/차수 GET만 | OrderDetail/ShipmentDetail 모든 수량·단가·Amount/Vat/isFix, ShipmentDate/Farm, Estimate, 재고, WebProfitReport |
| 수량 입력/이동 | 화면 초안만. 이동은 별도 창으로 분리 | 모든 원장 |
| 명시 저장 | 기존 양수 주문등록→기존 단일 트랜잭션 분배·검증·수정품종 확정 사이클 | 다른 연도/업체/품목 및 기존 주문수량, 변경하지 않은 금액/날짜 |

업체선택 개수에는 고정 상한을 두지 않는다. 기존 서버의 변경행1~1000 트랜잭션 제한은 유지하며, 이 한도를 넘는 요청은 주문등록/확정해제보다 앞에서 차단한다. 0/빈 임시행은 주문을 만들지 않는다. 변경업체만 저장·집계한다. 500개 품목 조회 제한/확정 guard를 넓히거나 우회하지 않는다.

## 구현 전 확인한 문제와 정책

- 추가업체 조회가 전역 request 번호 하나를 공유하여 여러 업체를 연속 선택하면 먼저 보낸 응답이 버려진다. 업체키+선택연도/차수+세대 번호로 독립 소유권을 검증한다. 교체/제거/전년도 늦은 응답이 다른 열을 덮지 못한다. 조회 실패는 미주문으로 취급하지 않고 재조회 전 저장을 막는다.
- 슬롯 번호/색상은 배열5개를 넘어도 항상 정의한다. 같은 업체 중복 선택 금지, 추가 모드에서 연속 선택 가능. 가운데 업체를 제거해도 나머지 업체·초안은 보존한다.
- 오른쪽 표는 2곳 이상 모두 같은 비교 표를 사용하고 가운데 이동 칸을 없앤다. 기존 수량 이동은 상단 별도 창에서만 수행한다.
- 날짜 표시 숨김은 초안과 수량을 지우지 않는다. 저장하지 않은 날짜가 있으면 숨김을 막아 먼저 저장/취소하도록 한다. 기본은 항상 표시.
- 왼쪽 탐색과 오른쪽 표를 각각 제한된 높이의 스크롤로 분리하고 선택품목/업체 검색·추가와 표 머리글은 우측 내부에서도 고정한다. 작은 화면에서는 기존 세로 배치를 유지한다.

## 검증

8곳 이상 연속/역순 응답·교체·제거·같은 차수 이전연도 fixture. 날짜ON/OFF 수량/상태 보존, 반복 이름 화면축약/원본 불변, 이동창과 중간버튼 부재, 긴 왼쪽 목록 끝을 선택해도 우측 표 가시성/고정. 실제 운영 POST를 격리 LocalDB에 연결하여 8업체 일괄 저장→새로고침→실제 견적/ECOUNT XLSX 출력 및 재열기, 전년도/기존 수량·매출 보존. 필수 계약/dnSpy/manifest/쓰기guard/build와 가이드 갱신, CI/배포/실운영 읽기 확인.

### 로컬 검증 결과

- 실제 Chrome + 전용 LocalDB 임시 DB: 고객 534~541에 1~8박스, 실제 `/api/orders` 양수 주문등록 후 실제 `/api/shipment/distribute` 단일 배치 8건 COMMIT. 새 페이지의 SQL 재조회에서 8개 모두 유지. 날짜 ON/OFF 초안 보존, 역순 응답 및 8열 확인.
- 실제 `/api/estimate` 인쇄/엑셀 각 8행. ECOUNT 30~240단(합계1080단), 거래별 금액+부가세=박스×30×100원 검증. 두 XLSX를 파일로 출력하고 다시 읽어 8행 확인. `outputs/distribution-unlimited-save/estimate.xlsx`, `ecount.xlsx` (합성 업체만).
- 출력 자격 검증은 격리 DB의 isFix를 별도로 seed하여 저장·출력 경로를 분리했다. 확정/취소는 별도 실제 native SP fixture `--fix-cycle`로 검증하며 8업체 UI가 운영 확정을 누른 것으로 주장하지 않는다.
- 기존 downstream fixture의 전년도/기존 Detail 금액 보존, 주문 없음/삭제/담당자 불일치/미확정/날짜 불일치 차단 통과. 운영 원장 쓰기0.
- `shipmentDistributionBrowser` 통과: 별도 이동창 박스/단 환산, 전체/부분/되돌림, 미주문 등록→한번 저장, 변경행만 확정 사이클, 늦은 응답/취소/즐겨찾기/키보드/뷰포트.
- 1100×800 40행 양쪽 작업공간: 선택 context와 table head 고정, 좌우바 양방향, 저장 위치 유지. 왼쪽 70품목 마지막 선택 후 오른쪽 업체 context가 viewport 내 유지.
- 계약 전체(후속 스크립트 포함), dnSpy evidence, ERP manifest217개, API write guard 통과. 최종 가이드/정식 build/CI/운영은 아래 완료 기록에 남긴다.

- 최신 실제 UI 가이드 377.6초, 1920×1080/100%, 7단계. 업체8곳 선택→날짜숨김→각2~9박스 입력→한번 저장→변경거래처8개/44박스 완료 표시. 첫/중간/마지막 및 최종 줌아웃 프레임 육안 확인, 번호/카메라/자막/해시 검사 통과. 가이드의 저장은 합성 API이며 실제 SQL 저장 검증과 구분한다.
