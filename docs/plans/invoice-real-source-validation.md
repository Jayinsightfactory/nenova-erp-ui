# 실제 차수 인보이스 인식 보강

## 범위
실제 업무드라이브 원본과 기존 AI 응답을 재현 입력으로 사용하여 국가별 변환의 신뢰도를 높인다. 같은 국가 여러 차수의 양식 차이를 조사한다. 운영 원장에 시험 입고하지 않는다. 유료 재분석은 기존 승인 범위 내 대표파일에만 수행하고 우선 저장된 응답을 재사용한다.

## 보존 및 부작용
파싱/수량 검증/표시 보강은 로컬 함수만 변경한다. Order/Shipment/Estimate/Stock/Warehouse 및 SP/EXE 모두 보존. Product/매칭/업무드라이브 GET만 실행한다. 웹 초안·매칭 이력도 테스트에서는 저장하지 않는다. 기존 입고 writer, 확정검사, 연도·세부차수 입력, 명시 확인 단계는 보존한다.

## 판정 기준
- NL: CBS Units가 원본에 있으면 위치 차이를 지원하되 다른 Total/Weight 값을 대체하지 않는다. 독립 송이·금액 합계 검증 유지.
- AU: 원본 total_stems가 없을 때만 명시 total_bunch×bunch_st로 preview 수량 산출. 0은 보존, 누락/잘못된 값은 임의0으로 성공 처리하지 않는다. XLSX 원본 수식 변경 금지.
- AI metadata: 원본 누락과 명시0 구분. 잘못된 currency 객체 등은 근거 있는 코드만 정규화하거나 검토 오류로 노출. 인보이스 합계를 품목 합계로 조작하지 않는다.
- TH: loose blooms/garland는 동일 송이로 합계/확정하지 않는다. 수동 검토와 명시 단위/환산 근거가 필요하다.
- 연도+세부차수는 명시 업무키. 파일명의 짧은 차수에 현재연도를 자동으로 넣지 않는다. 같은 차수의 과거연도/여러 인보이스를 섞지 않는다.
- 정확한 ProdKey 연결과 의미상 품종/규격 일치를 분리한다. 미매칭을 추정 저장하거나 글로벌 별칭을 임의 추가하지 않는다.

## 근거
ExcelLoadingPackingList.MakeTempTable 원본 CLI 저장 decompile 194~259행 재확인. BOX/TOTAL BUNCH/TOTALSTEAM을 별도 수량으로 저장한다. 실제 운영 Product 및 매칭 GET, 원본 PDF/엑셀/AI 응답은 outputs의 감사 자료. 이전 감사 MD 두 개 참조.

## 완료 검증
실제 파일 재생 + 익명 회귀 fixture, 누락/0/잘못된값/다른 차수/연도 경계. 국가별 지원/미지원/수동 검토 필요를 별도 기록. 계약·빌드 성공 후 배포 검증. 파일 다운로드 성공이나 문자열 테스트만으로 입고·원가 성공이라 하지 않는다.
