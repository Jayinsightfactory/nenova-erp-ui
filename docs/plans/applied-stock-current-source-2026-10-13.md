# 적용재고 현재 매칭 일치

사용자 보고: 믹스박스23/37, 연핑크43/두바이51 중복과 알바리코게 누락. 사용자는 두 작업 모두 네노바 웹앱이라고 확인했다. 실제 작업 브라우저는 현재 연결되지 않아 실제 ProdKey 대조는 미완료다.

## 재현된 결함과 범위
- AppliedStockCopyPanel은 캐시된 draft.appliedCopySource를 계산하면서 별도 currentScope를 검증해 두 입력이 달라도 계산한다. 현재 매칭은 정상, draft 매칭은 중복인 fixture에서 보고된 경고 재현.
- 350ms 자동 매칭 callback은 이전 render의 매칭을 캡처한다. 그 사이 수동 선택하면 이전 선택으로 돌아갈 수 있다.
- 적용재고에는 현재 원문/품목/제외/차수를 직접 전달한다. 기존 draft fallback은 페이지에서 제거한다.
- 명시 행 매칭은 현재 scope.matchesKey와도 대조해 오래된 사본을 사용하지 않는다. 기존 결과 scope, 연도, 실패/rollback/undo, 단위, 중복/누락 경고는 유지한다.
- 자동 매칭은 실행 시점의 최신 매칭을 사용하고 수동 변경 뒤 오래된 예약이 덮지 않도록 한다. setState updater 안의 다른 setState/refresh 부작용을 제거한다.

## 보존과 확인
모든 ERP 테이블/SQL/저장 API/기존 처리 결과는 보존한다. 이전 결과의 scope를 새 매칭으로 조작하거나 기존 주문을 재실행하지 않는다. 현재 데이터에 진짜 중복·누락이 있으면 여전히 차단한다.
실제 dnSpy CLI FormShipmentDistribution 재확인. 새 운영 SQL probe는 하지 못했으며 이 변경은 웹 메모리 입력 경계만 수정한다.
필수 검사와 실제 페이지 fixture 후 배포. 실제 사용자 자료에서 해소됐는지는 별도로 확인해야 하며 코드 재현 통과를 사용자 자료 해결로 단정하지 않는다.
