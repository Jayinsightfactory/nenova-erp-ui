# 네노바 견적 변경 이력 구현 계약 (2026-11-19)

사용자가 기획안을 승인해 독립 메뉴 구현·검증·배포까지 진행한다. 탭: 변경 등록 / 변경 이력 / 변경요청서 출력. 기존 견적서관리에서는 해당 실제 행의 관련 이력 및 역방향 이동을 제공한다.

## 동작 및 부작용

|동작|ERP 주문/출고/ShipmentDate/Estimate/재고/손익|웹 전용 기록|
|---|---|---|
|업체/실제 행/현재값/이력 조회|SELECT만, 보존|읽기|
|이카운트 엑셀 생성 준비|동일 EXE GetExcelDetail+실제 행 SELECT, 식·합계 보존|다운로드 당시 파일행+원장행 snapshot 불변 저장|
|브라우저 다운로드 요청|보존|요청 이벤트 추가; 실제 파일 저장/이카운트 입력 완료라고 단정하지 않음|
|담당자 업로드일 확인|보존|capture에 연결된 담당자 확인일·확인시각·확인자 추가|
|반영 전 변경안/과거 내역 기록|SELECT 재대조만, 자동 전산 수정 없음|수량/단가 전후·전산수정일·작성시각·작성자·사유 추가, 기존 기록 덮어쓰기/삭제 없음|
|변경요청서 미리보기/엑셀|보존|선택한 저장 기록만 출력; 원본 개인정보 없는 표준 양식|

## 원천/범위 기준

- 연도4자리+대차수1~53 명시. 업체는 실제 CustKey. 일반 견적은 ShipmentDate.SdateKey(`sdate:`), 별도 견적/차감은 EstimateKey(`est:`). 연도/차수/업체/품목 범위도 함께 보존/검증한다. 같은 날짜·품목이라도 PK가 다르면 별도 행이다.
- 실제 EXE FormEstimateView/ClassShipmentDate dnSpy CLI 확인. GetDetail의 DetailKey=SdateKey, Estimate branch DetailKey=EstimateKey. GetExcelDetail은 품목/단가/비고 등으로 합산한다. 파일행과 합산 전 물리행 snapshot을 함께 보존하고 파일 수량을 특정 출고일 행에 임의 배분하지 않는다.
- 기존 sqlEstimateGetExcelDetail의 WHERE/JOIN/ROUND/SUM/GROUP BY 식은 변경하지 않는다. 원장행 식별 메타데이터만 확장하고 같은 SELECT 원천을 공유한다. 정상 출고의 저장 EstQuantity/Cost와 화면 ROUND 표시값을 구분한다.
- Product에는 별도 Color 컬럼이 없음을 운영 metadata로 확인. 색상은 미기록 또는 직원이 명시한 내용이며 품목명으로 추정하지 않는다.
- 새 변경안은 전산 반영 전 작성하며 실제 전산 수정일을 미리 채우지 않는다. 전산 수정일(직원 입력), 작성시각(서버), 다운로드 생성/요청시각(서버), 업로드 확인일(직원 입력)/확인시각(서버), 출고/견적 업무일자를 각각 분리한다. 과거 없는 다운로드 이력은 역산하지 않는다.
- 입력 수량/단가는 유한 숫자이고 명시적0 허용. 전후 값이 모두 같은 기록은 거절. 변경 종류는 실제 달라진 필드로 결정. 두 필드 변경은 출력에서 두 줄. 사유는 필수. 저장자는 로그인 사용자에서만 취득한다.
- 다운로드 이벤트는 해당 capture의 실제 고객/품목 범위에서만 달력에 표시. 업로드 확인은 직원 확인이며 이카운트 API/실전표 입력 증거가 아니다.

## 웹 저장/동시성

기존 shipmentStatementStore/userActivityStore의 불변 파일·fsync·hard-link 원자 생성 패턴 사용. 운영 경로는 /var/lib/nenova/estimate-change-history(환경변수), 개발은 gitignored data/runtime. 공개 public/ 또는 Git에는 실제 자료를 저장하지 않는다. 새 DB 테이블/DDL 및 SSMS 선행작업 없음. UUID 요청 멱등성·동일ID 다른 내용/사용자 충돌 거절, 완성 파일만 원자 공개, I/O 오류는 빈 결과나 저장 성공으로 처리하지 않는다. 다른 pm2 worker의 동시 저장을 덮어쓰지 않는다. 원본 snapshot과 모든 반복 변경 이력은 보존한다.

## 기준선/검증

페이지 세로 스크롤·키보드·원본/현재 대조·선택범위 보존·실패 안내·양식 미리보기·새 메뉴/기존 견적 가이드 갱신·desktop 카탈로그/버전/검색/즐겨찾기/업데이트 적용. 원장 직접 반영 및 Rust 핫패스는 해당 없음(일반 웹 CRUD/파일 I/O). 1920/1280/390 및 popup=1 shell, Tab/Shift+Tab/Enter/Space/Esc/방향키, 같은 품목 다른 SdateKey·일자,2025/2026 같은 차수, 명시0·빈값·오래된 선택·누락 snapshot·저장 실패·중복 재시도·동시 프로세스·불변/개인정보 없는 템플릿·실제 XLSX print area를 검증한다.

운영 SELECT 근거: 2026/45 EXE 업체67곳, 표본 상세173행(고유 SdateKey152/EstimateKey21), 같은 품목의 서로 다른 출고일 존재. 실제 고객/직원/금액은 조사 출력·커밋에 남기지 않았다.

## 업무 순서와 매출 기준 (최신 사용자 정정)

변경이력표 작성·엑셀 출력 → 차장 보고 → 이카운트 수정 → 네노바 전산(견적서관리) 수정. 변경안 작성 당시 미반영이 정상이다. 각 후속 단계는 직원이 실제 완료 단계·완료일·담당자를 확인한 경우만 별도 불변 PROGRESS_CONFIRMED 기록으로 추가한다. 출력/다운로드만으로 단계를 완료하지 않고 ERP/ECOUNT 쓰기를 호출하지 않는다. 원본 변경안 작성자·시각·입력값과 실제 완료일/확인자/확인시각은 분리한다.

매출은 기존 sqlEstimateGetData의 동일 ViewShipment/ViewOrder/ShipmentDate/PeriodDay 및 Estimate 원천·전체 요일·저장 Amount+Vat(부가세 포함) 기준이다. 기존 집계의 WHERE/JOIN/SUM은 보존하고 동일 CTE의 물리행 기여액을 별도로 읽는다. 2026/45 SELECT probe에서 기존 결과와 완전히 같고 1,610 양수출고·견적 물리행 합계가 고객별 총액과 일치했다(업무 값 출력/저장 없음, 원장 쓰기0). 0수량 일자 행은 기여액0의 조회 메타데이터로 추가하여 0→양수 변경도 계산하며 총1,653행과 기존 총액 일치를 재확인했다. 동일 물리키 중복 또는 행별/총액 불일치 시 예상액을 미확인으로 처리한다.

새 변경안은 조회 재확인한 변경 전 값과 작성 시점 전체/업체 합계·물리행 스냅샷을 보존한다. 선택 기록 전체에서 최초 기준 한 번만 사용하고 동일 실제 행의 이어지는 전후 변경을 하나의 최종 기여액으로 계산한다. 불연속/경쟁 변경안은 합산하지 않는다. 변경 후는 공통 exeDateAmountVat(부가세 포함 단가·정수화 견적수량)를 사용하고 변경 전은 저장 Amount+Vat를 그대로 쓴다. 정상출고0은 합계 제외, 음수 차감은 별도 Estimate 물리키로 유지한다.

이력표에서 선택차수 전체와 해당 업체 각각 변경 전/부호 있는 변경액/변경 후 예상액을 표시한다. 별도 현재 실측은 조회시각·예상차이와 남은 변경액을 표시하며 이미 적용된 물리행을 다시 더하지 않는다. 전산 반영 완료 확인 시 실측 원본도 불변 저장한다. 현재 견적 화면과의 차이는 시점 및 다른 업체/작업의 변화도 포함하여 이 변경의 효과로 단정하지 않는다. 과거 수기는 당시 부가세 포함 합계 전후와 증빙/직접입력 출처가 있는 경우만 표시하며 없으면 미확인이다. 여러 과거 기록의 전체 총액은 더하지 않는다.

## 기준선 확인

적용: 독립 메뉴·데스크톱 카탈로그/검색/즐겨찾기·1.3.52 업데이트, 단일 Layout, 페이지 주 세로스크롤, 고밀도 표/폼, 숫자 고정폭 정렬, 최소 상태색, 한국어 업무 버튼/날짜, Tab/방향키/Esc, 빈 상태/오류/동시성/명시0, 가이드 영상 및 실제 XLSX 미리보기/전체 인쇄범위. 해당 없음: Rust(일반 React와 DB/I/O 대기), 새 DB DDL/SSMS(기존 private file 저장), 공용 원장/재고/손익 수정(모두 SELECT). 예외 없음. 첨부의 실제 예시·개인정보를 템플릿/영상/커밋에 포함하지 않는다.

양식 재생성: Codex load_workspace_dependencies로 받은 bundled Node와 Node module root를 사용한다. ARTIFACT_NODE_MODULES에 해당 node_modules 절대경로를 설정하고 scripts/build-estimate-change-template.mjs <임시출력폴더> 실행 후 생성 파일/렌더를 검사한다. Artifact API로 빈 양식의 셀/서식/병합/숫자를 작성하고, 문서화된 print setup API가 없어 기존 런타임 OpenXML helper로 인쇄 영역·제목 반복·A4 설정만 마무리한다. 원본 업무 첨부는 읽거나 가져오지 않는다.
