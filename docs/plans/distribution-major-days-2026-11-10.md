# 출고일 세부차수 비교와 메인차수 합계

2026-11-10 실제 설치 Nenova.exe FormShipmentDistribution을 dnSpy.Console로 재추출.
GetCustomerList/GetShipmentMaster는 OrderYear+OrderWeek+CustKey를 분리하며
ShipmentDate의 실제 날짜별 수량을 사용한다. 메인차수 비교표는 웹 읽기 전용 확장이고
기존 날짜 저장의 단일 세부차수 업무키/변환/원자성은 변경하지 않는다.
운영 SELECT: 2025/45-01 상세1200,45-02 298;2026/45-01 893,45-02 404,45-03 73.
이 범위 날짜누락0. 개인정보 없는 건수만 기록했다.

| 기준 | 원천/소비자 |
|---|---|
| 조회 | 같은 명시연도, 같은 메인차수의 -01~-04, Master업체+품목 |
| 요청 검증 | GET은 정규화 전 원본 차수의 내장연도와 명시연도를 대조, 충돌/누락400 |
| 표시 | 실제 존재하는 상세의 세부차수와 현재 선택 행, 번호순; 없는 차수는 만들지 않음 |
| 날짜 | 같은메인 PeriodDay exact7일, 실제날짜순, 날짜머리글1회 |
| 수량 | 세부차수별 저장 ShipmentQuantity 및 OutQuantity, 원본출고총량 한번만 합산 |
| 단위 | 모든 비교행을 정확히 정수환산할 수 있는 공통 단/송이, 임의반올림0 |
| 합계 | 날짜별세부합+오른쪽메인총량, 불일치/중복/연도오염이면 미확인 안내 |
| 초안 | 현재선택차수만 날짜입력, 다른차수 읽기전용, 날짜초안은 일별표시합계에 반영 |
| 저장 | 현재선택 OrderYear+OrderWeek+CustKey+ProdKey 기존 canonical editor만 사용 |
| 누락/0 | 실제0은0, 미조회/누락은0으로대체하지 않음; 잘못된전체합계 표시금지 |
| 공간 | 기간문구/정상상태합계 중복줄 제거, 단위·저장 같은 줄,날짜 머리글 공유 |

| 동작 | Order* | ShipmentMaster/Detail | ShipmentDate/Farm | Stock* | Estimate | WebProfitReport |
|---|---|---|---|---|---|---|
| 메인차수 조회/표시 | 보존 | 보존 | 보존 | 보존 | 보존 | 보존 |
| 선택 차수 날짜저장 | 보존 | 보존 | 기존 date-only 계약만 | 보존 | 보존 | 보존 |

현재행만편집,기존미리보기/서명재검증.가이드 신규지침 단계번호·전체위치·줌인·실제입력/
결과·줌아웃으로 갱신, 실제프레임/플레이어 검증. 무관한메뉴변경0.

복수세부차수123조합. 2025년1376조합 중1355유효/복수95,기존불일치21은
합계확인필요로안내하며 보정0. 원본상태를실패/0값으로숨기지않는다.
