# 불량 단가 후보 및 이전 견적 상태 설명

## 원인 근거와 기준
- 실제 dnSpy ClassEstimate 2026-11-04 재확인: ShipmentKey와 ProdKey/Cost 독립 저장. native 계산 변경 없음.
- 운영 SELECT: 태림 983→3389(그로우 규격없음), 986→2473(스프레이 오션송)은 최근39~43차 해당 ProdKey 단가 없음. 실제 분배는3397(75~80cm),2085(일반장미)이며 태림 최근 단가6200(41차),6500(43차). 비슷한 품명만으로 자동 대체 금지, 후보 및 출처 표시 후 사용자가 매칭 결정.
- 라움926/1007는 이전 견적10499/10707 실체 없음. 출고없음과 다르다. 44차 태림565/689 및 라움680 출고분배 존재. 삭제 의도 확인 전 재등록하지 않는다.
- 가격 자동 선택: 같은 연도 직전5차수, 같은 ProdKey, 해당업체 우선/없으면타업체, 최신. 후보조회와 기존자동선택은 같은 SQL함수 사용. 현재차수/전년도 제외.
- 후보는 품목번호/규격/견적단위, 업체/차수/단가 표시. 다른품목은 매칭확인 후 기존 manage-edit(버전/처리이력가드)로 저장하고 재조회. 단가만 복사해 다른품목에 쓰지 않음.
- SQL 실패는 단가없음으로 삼키지 않는다. 조회실패로 구별하고 재조회 안내.

## 화면 기준
기존 화면틀·페이지스크롤 유지. 후보는 명시 버튼/키보드, 입력 오류는 현재 항목에 표시. 조회만으로 운영원장 변경하지 않음. 회귀: 동일품목 업체fallback/교차연도/다른품목참고만/조회실패/유령견적가드/선택후재검사. master배포후실페이지확인.

최신 사용자 결정: 라움 등 보류분은 별도 보류 목록. 이전 견적 재등록/삭제하지 않는다. 영업지원 기본은 단가·매칭을 해결할 등록대상, 원문/이전견적/현재차수분배 문제는 보류. 상태 해소 후 재조회 시 자동 재분류하며 목록 분리 자체는 DB쓰기0.
