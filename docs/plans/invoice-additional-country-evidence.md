# 추가 국가 도착원가 원본 근거

검토일: 2026-10-13. 범위: 준비된 로컬 원본 AU, EC, CO, TH, NZ의 계산 계약과 export 근거. 제품 코드, API, DB, 원본 workbook은 변경하지 않았다. 아래 세율·요율은 해당 원본의 관측값이며 현재 법정 세율이나 국가 전체의 기본값을 의미하지 않는다.

## 확인 방법과 판정

- `outputs/drive-pair-discovery/downloaded-costs.json`의 파일 목록과 `cost-cell-evidence.json`의 셀 수식·캐시를 대조했다. 원본 XLSX SHA-256을 로컬에서 다시 확인했다.
- JSON에 Python `ArrayFormula object` 문자열로 유실된 CO 배분 수식은 원본 ZIP의 `xl/worksheets/sheet1.xml`을 읽기 전용으로 직접 확인했다. Excel 재계산이나 실제 ERP 입고 수량 대조는 수행하지 않았다. 캐시는 재계산 검증이 아니다.
- 분모, 통화, 단위, 품목 그룹, 적용 세율, 실제 입고와 원본 수량 대응이 확인된 문서만 계산 대상으로 삼는다. 국가명만으로 공식 선택, 누락값을 0으로 처리, 잘못된 원본 수식을 정상식으로 조용히 교체하는 것은 금지한다.
- 공통 표기: `q_i`는 원본 가격 기준 단위 수량, `p_i`는 그 단위의 외화 단가, `x`는 원/외화 환율, `b_i`는 판매 단 하나에 포함된 가격 기준 단위 수량이다. ERP 수량 단위가 다르면 명시적 변환이 먼저 필요하다. `unitCost*b_i`는 판매 단 원가이며 전체 행 원가는 `unitCost*q_i`다. 두 값을 혼동하지 않는다.
- 관측 수식에는 원가 단계 `ROUND`가 없다. 화면 표시 반올림과 계산값을 분리하고 원단위 저장/합계 잔차 정책은 메인 계약에서 확정해야 한다. `/0.77` 판매 제안과 `/1.1` 판매 VAT 역산은 도착원가 공식에 포함하지 않는다.

## AU: CNF/단 기반 균등 통관비

`38-1!B12:M16`에서 E=수량, F=CNF(단), H=원화 CNF, I=관세, J=그외통관(단), K/M=도착원가다.

```text
D9 = SUM(E13:E16)                         // 1035단
N5 = D7*460; N6=33000; N7=D8*10000; N8=90000
N9 = SUM(N5:N8)                           // 285130원
G13 = E13*F13; H13 = F13*$D$6
I13 = H13*0; J13 = $N$9/$D$9
K13 = H13+I13+J13; M13 = K13*L13
unitCost_i = p_i*x*(1+t_i) + clearanceKRW/sum(q)
```

수동/확인 입력: CNF/단 단가·수량, 환율 D6, GW kg D7, 품목수 D8, 통관비 구성 또는 확정 총액, 행별 세율, 단당 변환 L. 항공료를 다시 더하지 않는다. CNF 포함 운임 범위와 통화는 인보이스 근거로 별도 확인한다.

세율은 국가 공통 0%가 아니다. `38-1!I13:I16`은 0%, `39-1!B18= Copper Glow`, `I18=H18*0.069`이며 같은 sheet의 다른 확인 행은 0%다. `H5:I5`에는 Flowers 0.069, `J5`에는 Until 2031 메모가 있으나 이를 현재 법규 검증으로 사용할 수 없다.

결함: `39-1!D5/F5=SUM(G13:G16)`은 실제 품목이 24행까지 있는데 16행에서 끝난다. 캐시 7635 대 `G13:G24` 합 15675로 8040 차이. 이 잘린 합계를 공식의 검증 총액으로 재사용하지 않는다. `38-1`은 16행까지여서 해당 범위가 맞는다. 판매가 미입력에 따른 R열 `#DIV/0!`는 원가 계산과 분리한다.

수치 대조: `38-1!K13 = 14.5*1090 + 285130/1035 = 16080.4879227053`원/단. 이는 원본 캐시와 일치한다.

## EC: 수량 균등 항공료와 통관비

`40-2!B13:O27`, 교차근거 `26-1!B13:O20`.

```text
C10 = SUM(E14:E27)
C11 = G11*E8+E11                         // CW*운임요율+고정비용
P6=C8*460; P7=C9*9000; P8=36000; P9=90000
P10 = SUM(P6:P9)+R6+R7
G14 = E14/$C$10
H14 = F14+($C$11*G14/E14)
J14 = H14*$C$7; K14 = J14*0.25
L14 = ($P$10*G14)/E14
M14 = J14+K14+L14; O14 = M14*N14
unitCost_i = (p_i+airForeign/sum(q))*x*(1+t_i)
             +clearanceKRW/sum(q)
```

수동/확인 입력: FOB/송이 F, 송이수 E, 환율 C7, GW kg C8, CW kg E8, 요율 G11(외화/kg), 고정비 E11(동일 외화), 품목수 C9, 통관비/검역차감 R6/소독비 R7, 행별 세율, 판매 단 송이수 N. 빈 추가비가 0이라는 명시 확인 없이 누락을 0으로 확정하지 않는다. 원본의 G열 제목은 금액포시죤이지만 실제 공식은 금액 비율이 아닌 **수량 비율**이다.

`40-2` 확인 14~27행은 25% 관세다. 두 원본은 같은 계산형이나 고정 항공비·환율 등은 다르다. 통화 코드는 이 sheet의 FOB 헤더만으로 확정되지 않는다. 해당 문서 인보이스 통화를 사용해야 한다.

대조: C10=4800, C11=1379.6, P10=312380, C7=1380. `M14=(0.6+1379.6/4800)*1380*1.25+312380/4800=1595.8729166667`원/송이. 캐시 일치. `26-1` 수식 캐시는 null이므로 0이나 계산 통과로 취급하지 않는다. 판매가 공란의 T열 오류는 원가와 별도다.

## CO: 운임과 통관비의 서로 다른 그룹 배분

세 원본 `12-2!J7:U10,AA8:AI11,B14:O...`에 동일 계산형이 있다. 그룹은 ROSE, CARNATION, ALSTROMERIA, RUSCUS 네 개다.

```text
AD8 = AB8*AC8/SUMPRODUCT($AB$8:$AB$11,$AC$8:$AC$11)
AI8 = AG8*AH8/SUMPRODUCT($AG$8:$AG$11,$AH$8:$AH$11)
C11 = E11+E8*E9
K7 = IF($C$8=$E$8,$C$11*AD8,$C$11*AI8)
L7 = AC8*100; L8=AC9*300; L9=AC10*160; L10=AC11*625
M7 = K7/L7
P6=C8*370; P7=33000; P8=C9*10000; P9=99000
P10 = SUM(P6:P9)+R6+R7
T7 = $P$10*AD8; U7 = T7/L7              // 통관비는 항상 중량 비율
H15=F15+G15; J15=H15*$C$7
M15=J15+K15+L15; O15=M15*N15
```

AD/AI 정확식은 `muki3lfy-23d4f8.xlsx` XML에서 복구 확인했다. 14-1A의 GW=4840, CW=5033은 부피 분기를 실제 사용하며 13-2와 14-2는 GW=CW로 중량 분기다. 주석 `GW << CW`와 달리 실행식은 **같지 않으면 전부 AI**다. GW>CW까지 정당한 업무라고 확대 해석하지 말고 차단/수동 확인 대상으로 둔다. 부동소수 허용오차로 동등 판정을 바꾸려면 별도 계약이 필요하다.

수동/확인 입력: 그룹별 박스수 AC/AH, 박스당 중량 AB, 부피 척도 AG, 그룹별 송이수/box, 실제 그룹 송이수, GW/CW, 외화 운임요율·서류비, 환율, 통관비, 판매 단 송이수 N, 명시적 품목 그룹. AG 값 10/9/7/9.6은 CBM이라는 제목만 있고 실제 m³인지 스케일값인지 증명되지 않았다. 비율 계산은 동일 척도이면 가능하지만 절대 m³로 저장·표시하면 안 된다.

그룹별 원가: `(FOB_i+airForeign*freightShare_g/groupStems_g)*x + clearanceKRW*weightShare_g/groupStems_g`. 원본 K열 관세는 제목 `관세(없음)`, 확인 데이터 행에는 빈 셀이다. 업무에서 0원 관세임을 명시 확인한 문서에 한해 0으로 정규화한다.

결함/조건: G/L열은 SEARCH 문자열로 그룹을 골라 미일치 시 빈 문자열을 반환한다. 이름 부분문자열을 ERP 매핑 근거로 삼지 말고 그룹을 명시 선택한다. 그룹 박스 환산 송이수와 매핑된 행 실제 송이 합이 다르면 운임/통관비 배분 총액이 보존되지 않으므로 차단한다. `13-2!C6`은 공란, H6은 실제 데이터가 아닌 `I269:I309`를 합산해 0이다. `14-1A!H6=SUM(#REF!)`. `14-2!H6=SUM(I27:I59)`도 확인 데이터 15~25행을 제외해 0이다. 해당 검증 셀을 신뢰하지 않는다.

대조: 14-2 ROSE 중량분자=8*19=152, 전체=312.7, 운임=1056.2. `M7=1056.2*(152/312.7)/1900=0.270214262871762`외화/송이. `U7=337800*(152/312.7)/1900=86.4214902462426`원/송이. 캐시 일치.

## TH: 포장 그룹 박스 비율 배분

`40!J7:K10,H15:N40`, `39!H15:N46`, `38!H15:P33`.

```text
C11 = E11+E8*E9
J10=SUM(J7:J9); K10=SUM(K7:K9)
H_i = (boxes_g/totalBoxes)*(q_i/groupUnits_g)
I_i = FOB_i+C11*H_i/q_i
K_i = I_i*C7; L_i = K_i*0.05
N6=C8*460; N7=33000; N8=C9*10000; N9=99000
N10 = SUM(N6:N9)+P6+P7
M_i = N10*H_i/q_i
N_i = K_i+L_i+M_i
P_i = N_i*O_i                             // 정상행의 판매 단 원가
```

그룹은 Anthurium / Others / Loose blooms(`I7:I9`). `40!J8=34,K8=3905,J9=3,K9=5100`, totalBoxes=37, 총 단위수=9005. `H15` Others, `H23` Loose blooms로 서로 다른 분모를 사용한다. Loose blooms는 송이·개·봉 등 실제 가격 기준 단위와 ERP 변환을 수동 확인해야 하며 전 품목 10송이/단으로 고정할 수 없다. O에는 5/10/100 등 행별 값이 있다.

수동/확인 입력: 각 행 FOB·수량·포장그룹·단 변환, 그룹별 박스수와 수량, 환율, GW/CW, 운임요율·서류비, 품목수, 통관비 구성, 검역 차감 품목/수량/단가 및 소독비. currency는 인보이스로 명시 확인한다. 그룹 내 행 수량 합=K그룹, 박스 합=J10, 배분비 합=1이어야 한다.

중요 결함: `40!P15`와 `39!P15`는 `N15*O15`가 아니라 `=($J$8/$J$10)*(N15/$K$8)`로 잘못 이동된 배분식이며 Q15:X15도 뒤따라 단위가 어긋난다. 반면 `38!P15=N15*O15`, 40의 P16 이후 정상행은 곱셈이다. 40/39 첫 행 **송이 원가 N15까지와 판매 단 원가 P15 이후의 신뢰 범위를 분리**한다. 원본 오류를 복제하거나 무통지 보정 export하지 않는다.

`40!G6=SUMPRODUCT(#REF!,#REF!)`. `P6` 검역차감은 차감 수량×별도 하드코딩 원가의 합인데 N10에는 **더한다**. 즉 사라진 상품의 손실원가를 남은 상품에 배분하려는지, 비용에서 빼려는지 이름만으로 확정할 수 없다. 38/39 P6 캐시가 같은 37755.0058189586인 점도 신규 실적과 연결됐다는 증명이 아니다. 손실 반영 정책, 실제 분모를 감량 전/후 어느 수량으로 할지 메인/업무 확인 전 자동 확정 불가.

대조: 40의 Others 행15 송이 원가 `(.35+640.75*(34/37)/3905)*1400*1.05+330178.886804237*(34/37)/3905=813.8443412904`. 정상 곱셈이라면 10송이 단 원가는 8138.443412904이지만 손상된 P15 캐시는 0.191512666393562다. 이 차이는 반올림 문제가 아니다.

## NZ: CNF/송이 기반 균등 통관비

`Sheet1!B12:M19`.

```text
C9 = SUM(E13:E19)
N5=C7*375; N6=33000; N7=C8*10000; N8=90000
N9=SUM(N5:N8)
G13=E13*F13; H13=F13*$C$6; I13=H13*0.082
J13=$N$9/$C$9; K13=H13+I13+J13; M13=K13*L13
unitCost_i = CNF_i*x*(1+t_i)+clearanceKRW/sum(q)
```

수동/확인 입력: CNF/송이 F, 송이수 E, 환율 C6, GW kg C7, 품목수 C8, 통관비 총액/구성, 관세 적용, 단당 송이수 L. 확인 행13~19는 8.2%, L은 수국1/작약5다. 국가명으로 NZD를 가정하거나 이미 CNF에 포함된 운임을 추가하면 안 된다.

결함: `C5=4403.1` 인보이스 총액과 `F5=SUM(G13:G219)=3701.1`의 차액이 702다. 별도 운임/누락품목/할인인지 원본만으로 판정할 수 없다. 702를 수량 배분해 보정하거나 무시하지 말고 인보이스 대응을 요청한다. C9는 19행까지인데 F5는 219행까지이므로 새 행 추가 시 두 범위가 달라진다. 20행 이후 0수량 템플릿에도 J 통관비와 K 원가가 계산되어 있으므로 상품행으로 가져오면 안 된다.

대조: `K13=7.06*800*1.082+177750/760=6345.01757894737`원/송이. 캐시 일치. 인보이스 차액의 원인까지 검증한 것은 아니다.

## 계산·export 통합에 전달할 수용 조건

1. 원본 hash, sheet, 차수, document revision/sourceHash, 실제 입고 대응, 단위/통화, 공식 버전을 승인 입력과 함께 보존한다. 원본의 숫자를 국가 기본값으로 자동 적용하지 않는다.
2. AU/NZ는 CNF 입력형, EC/CO/TH는 FOB+운임형으로 구별한다. 통화 혼합 시 각 비용의 환산 근거가 없으면 차단한다. 관세·요율은 명시 확인 입력이며 원본 숫자는 참조값이다.
3. 수량 0인 템플릿 제외, 양수 분모, 그룹 누락·중복 없음, 실제 수량 및 그룹 배분 총액 일치를 확인한다. CO는 운임과 통관비 배분비를 하나로 합치지 않는다. TH 검역손실 정책 미확정은 명시적인 blocked 사유다.
4. export는 APPROVED이며 현재 입고 MATCH인 서버 재조회 원가만 사용한다. 원본 캐시나 현재 편집 폼을 승인 원가로 다운로드하지 않는다. 양식 미지원/원본 결함은 원가 승인과 별도로 표시한다.
5. 국가별 양식은 위 sheet의 열 의미·단위와 승인값을 재현하되, 잘린 SUM 범위, #REF!, 0수량 원가, TH 이동 수식은 보존할 정답이 아니다. 수식 교정이 필요한 양식은 교정 사실과 버전을 명시한다. 판매가/이익 값은 원가 승인만으로 채우지 않는다.
6. 필수 fixture: AU 0%와6.9% 혼재 및 39-1 합계누락, EC 26-1 캐시없음/40-2 정상, CO GW=CW/GW<CW 및 미매핑·그룹수량불일치, TH Loose/Others와 손상 첫 행·검역차감, NZ 1/5송이 변환과 인보이스차액. 현재 문서는 수식 근거이며 해당 제품 테스트를 실행·구현한 보고서는 아니다.

## 작업 범위 기록

역할 IMPLEMENTER(근거 정리), P0_LOCAL, 상속된 기본 모델 사용. 모델/추론 설정 변경 없음. 메인이 준비한 로컬 자료만 계산 근거로 사용했다. 변경 파일은 본 문서 하나다. 메뉴/1920 UI 기준은 해당 없음(화면 변경 없음). ERP 가드에 따라 공유 원장·EXE 영향 판정이나 DB 실행을 하지 않았다. 원본 SHA 검증과 대표 수치 독립 계산을 수행했으며 Excel 엔진 재계산·실입고·법정 세율·인보이스 통화는 미확인이다. 위 모호함은 통합 전에 메인 업무 검토가 필요하지만, 본 근거 정리 자체에는 추가 권한 요청이 없다.
