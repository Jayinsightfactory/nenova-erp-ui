# 개발 여정 시각화

## 요청과 완료 기준

전체 개발 이력의 모든 페이지를 기업 연혁처럼 시간순으로 탐색하는 화면을 추가한다.
기존 목록은 유지하고 `/dev/history?view=journey`에서 월 → 한국 날짜 → 개별 기록을 볼 수 있게 한다.
안내 캐릭터는 코드 기반 SVG이며 실제 기록에 없는 성과·기능·작업 시간을 만들지 않는다.

## 데이터 계약

- 원천은 기존 안전한 `full-development-history.json`이다. 클라이언트 번들로 전체 snapshot을 가져오지 않는다.
- 기존 목록과 새 개요는 `selectSnapshot`을 공유한다. 전체/필터 결과의 집합이 동일해야 한다.
- KST 월·일마다 각 이벤트는 한 번만 속한다. 월·일 합계는 필터 결과 합계와 같다.
- 날짜 상세는 기존 인증 GET에 동일한 필터와 `from=to=선택일`, `order=oldest`, `limit=50`을 전달한다. 100건 이상인 날짜도 모든 페이지를 열 수 있다.
- 코드 변경·코드 통합·작업 메모를 구분한다. 집계는 요청 수·기능 수·배포 횟수가 아니다.
- 안전하게 수집된 원본 제목·허용 경로만 표시한다. 비공개 대화, diff, 작성자 개인정보는 추가하지 않는다.

## 부작용과 호환성

| 사용자 동작 | 웹 정적 metadata | ERP/SQL 원장 | 기존 화면 |
|---|---|---|---|
| 여정 개요·검색·필터 | 인증 GET, 메모리 집계 | 접근 없음 | 보존 |
| 월·날짜·상세 이동 | 인증 GET, 읽기 전용 | 접근 없음 | 보존 |
| 새로고침 | 클라이언트 캐시 해제 후 GET | 접근 없음 | 보존 |

nenova.exe에 대응하는 업무 저장 기능이 아니므로 dnSpy/운영 SQL probe는 해당 없음이다.
OrderDetail, ShipmentDetail, ShipmentDate, Warehouse, Stock, Estimate, WebProfitReport를 조회하거나 수정하지 않는다.
공통 Layout은 `_app.js`만 소유하며 신규 사이드바 메뉴는 만들지 않는다.

## 화면 및 검증

- 1920×1080 CSS px/100% 기준, 좁은 화면 반응형, 자연스러운 페이지 세로 스크롤.
- 월별 타임라인·색상 범례·기록수 그래픽, 캐릭터 안내, 읽을 수 있는 날짜/제목.
- 로딩/오류/빈 결과와 재시도, 요청 취소 및 오래된 응답 덮어쓰기 방지.
- native 버튼과 선택 컨트롤, Tab/Enter/Space/Escape/방향키 및 초점 복귀.
- 전체 합계·필터 교집합·KST 연말 경계·일별 100건 초과·중복 출처·미분류 보존 테스트.
- 기존 이력 테스트와 필수 ERP 가드/빌드 후 메인만 PR·병합·배포한다.

설계: `gpt-5.6-sol` xhigh, 구현: 재사용 구현 에이전트, 테스트: `gpt-5.6-luna` medium.
하위 작업은 P0_LOCAL만 수행한다. 최종 검토 및 실제 배포 상태는 세션 기록에 남긴다.
