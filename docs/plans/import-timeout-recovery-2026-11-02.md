## 고정 기준과 부작용
|동작|기준|주문/분배/날짜/농장|견적/금액/Vat/isFix/매출/재고|
|---|---|---|---|
|기존 적용|서명된 연도+세부차수+업체+품목, 기존 트랜잭션|기존 writer만 사용|기존 계약 보존|
|작업 접수/진척/완료|서버 private runtime 파일, owner hash, jobId hash, 수량 집계/감사키만|추가쓰기 없음|보존|
|결과 조회/재접속|같은 jobId, 소유자 확인, GET만|보존|보존|

|결과불명|원본 파일/고객정보는 저장하지 않고 작업번호 유지, 결과 확인 전 새 POST 차단|보존|보존|

- 저장 성공은 실제 terminal result만으로 표시. 커밋만 확인된 감사 이력은 최종 확인 중단으로 구분하며 현재 값으로 과거 성공을 추정하지 않는다.
- 작업 준비/적용/스냅샷/커밋전대조/사후대조/감사완료 단계 표시. heartbeat를 진척으로 위장하지 않는다. 진행 중 기록은 TTL로 삭제하지 않는다.
- 브라우저 재접속은 조회만 재개한다. 명백한 terminal 성공/실패에서만 자동으로 pending을 해제한다. 결과불명은 이력 확인 후 명시적 확인을 거쳐 해제한다.
- 원본/토큰/사용자명/고객명/파일명/행별값은 durable 파일에 저장하지 않는다. 소유자 해시와 집계/작업 메타만 저장한다.
