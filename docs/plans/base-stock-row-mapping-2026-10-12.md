# 기초재고 수동 매칭 보존

## 목적과 근거
사용자가 각 줄에서 수정한 품목을 저장/복원/적용재고/복사까지 그대로 사용한다.
현재 buildBaseStockMatchRows는 stockNorm(name) 단일 객체로 이전 매칭을 덮어쓴다.
적용재고는 다른 normalize로 resolvedMatches를 다시 조회하므로 로즈우드/루스커스를 놓친다.
동명이품을 마지막 이름 매칭으로 통합하지 않는다.

## 기준 계약
- 원본 행 idx와 원본 이름/품종 문맥을 보존한 행별 ProdKey가 확정 매칭의 권위다.
- 재구성은 같은 원본 행/문맥 선택을 우선 보존한다. 행 이동은 유일하게 대응되는 원본 서명일 때만 재사용한다. 모호한 중복은 재확인하며 다른 행 선택을 복제하지 않는다.
- 명시 수동 매칭이 현재 목록에 없으면 미확인으로 남기고 자동 후보로 덮지 않는다.
- 적용재고에 baseStockMatches를 직접 전달하고 현재 원본 행과 일치하는지 검증한다. 이름 별칭 맵은 확정 행을 덮지 않는다.
- 기존 legacy 호출 호환은 행 매칭이 아예 주어지지 않았을 때만 허용한다. 화면은 항상 행 매칭을 전달한다.
- 실제 같은 ProdKey 중복이면 원본 줄 번호/이름을 함께 알려 복사를 차단한다. 자동 합산하지 않는다.
- 41-2 잔량 제목 및 전각 숫자 입력을 공통으로 해석한다. 원본 이름/메모/문장은 보존한다.
- 전체 연도/차수/원문/매칭 scope, 검증된 실제 저장 결과, 단위/음수/중복실행 보호를 유지한다.

## 부작용

|---|---|---|---|
| 매칭 변경·저장·복원 | 기존 저장 경로의 행별 매칭 보존 | 보존 | 보존 |
| 적용재고 표시·복사 | 읽기 계산 | 보존 | 보존 |

새 SQL/API/SP/원장 보정 없음. dnSpy CLI FormShipmentDistribution을 실제 EXE에 재실행해 연도/차수 선택을 확인했다. 이번 오류는 웹 문자열/행 식별 경계에서 재현되며 운영 SQL 직접 probe는 아직 수행하지 않았다. 기존 golden 근거를 새 운영 검증으로 주장하지 않는다.
