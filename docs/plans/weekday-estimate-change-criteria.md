## 2026-10-01 실제 분배 저장 연결 (작업 중)

최종 요청은 브라우저 초안이 아니라 실제 분배·출고일 저장, 변경 추적과 저장 견적 인쇄다.
아래 과거의 읽기 전용/적용 비활성 문구는 당시 구현 경계이며 이번 완료 범위가 아니다.
현재 계약·부작용·운영 승인·검증 항목은
`docs/plans/weekday-erp-apply-2026-10-01.md`와
`docs/contracts/weekday-distribution-apply.json`을 따른다.
명시 저장 전에는 계속 초안이며, 저장 성공 뒤 SQL 재조회값으로 잔량·견적을 표시한다.
기존 확정 상태를 유지하고 실제 old-new 방향별 재고만 반영한다. 공용 확정 취소/재확정을
자동 호출하지 않으며 날짜를 임의 재생성하거나 입고 원천을 재배정하지 않는다.
전체 로컬·격리 SQL·배포 검증이 끝나기 전에는 적용 완료로 판정하지 않는다.

## 2026-10-01 잔량 즉시 반영·가독성·품목 행 강조 (최신)

수량 셀 편집을 Enter/blur로 기록하면 잔량의 주 숫자는 편집 수량을 반영한 예상값으로
즉시 바뀐다. 저장된 최초 기준은 불변이며 저장 전산 잔량은 tooltip에 별도로 보존한다.

최초 대비 변경량·하이라이트를 만드는 기준으로 사용하지 않는다. 기준 기록에 없는

## 2026-10-01 최초분배 빈칸 보완

확정 전에도 동일 연도+전체 세부차수+업체의 현재 ERP 분배 preview를 자동 조회하여
최초분배 칸에 **미확정** 수량을 표시한다. 이는 현재값의 읽기 전용 표시이며 과거 최초값을
복원하거나 자동 확정하지 않는다. 저장된 최초 기준이 있으면 항상 그 값을 우선한다.
미확정 수량은 최초 대비 변경량·날짜 하이라이트·확정 최초기준 잔량 계산에 사용하지 않는다.
위 최신 기준에 따라 명시적인 미확정 예상잔량만 별도로 계산한다.
조회 실패는 해당 차수에 표시하고 이전 범위의 응답/수량을 재사용하지 않는다.
확정 버튼은 기존의 새 preview/지문 재검증 및 불변 저장을 유지한다. ERP 쓰기는 없다.

## 2026-10-01 주광 페이지 최초분배 기준 (최신 사용자 답변)

운영 미리보기 보완: SQL의 출고일 JSON을 `CAST(ISNULL(...,N'[]') AS nvarchar(max))`로
명시한다. 실제 수량의 NULL/음수는 정상값으로 대체하지 않는다. 배열이 아니거나
분배 0행인데 날짜가 있는 모순은 계속 차단하고 품목 키·분배행 수·날짜 형식을 알린다.

추가 UI 기준: 중심차수 좌우 이동은 현재 PeriodDay로 확인된 전/후 cycle의 연도/차수를
사용한다(임의 +/-1 연말 계산 금지). 품목 칸의 품종 배지와 영문 접두어만 제거하고
ProdKey/원본 ProdName/인쇄명은 보존한다. 최초 날짜수량과 현재(또는 파란 초안)가 다르면

변경량은 잔량 옆에 표시한다. 클릭 시 floating 비고창으로 열고, 비고/선출고 확인은

## 2026-10-01 출고 없는 품목 숨김

사용자 요청: 표시 범위의 출고 수량이 없는 품목은 주광 가로 목록에서 숨긴다.
`hasHorizontalShipmentQuantity`를 화면 표시의 단일 판정으로 사용한다. 이미 year+major로
격리한 각 block의 실제 `shipmentOutQuantity` 또는 날짜별 `shipmentQuantity`에 유한한
0 초과 값이 하나라도 있으면 표시한다. 초안의 유한한 0 초과 `quantity`도 표시한다.
최초 확정 기준에 양수 수량이 있던 품목은 현재 취소/0이어도 유지하여 최초 대비 잔량을 보여준다.
null/undefined/빈 문자열/NaN/Infinity/0/음수만 있는 행은 숨기고, 전체 원문 배열은 보존한다.
전/후 차수, 범위 밖 날짜에 실제 양수 출고가 있거나 복수 단위/차수인 행도 개별 원문으로
판정해 숨기지 않는다. 입고·주문·견적수량은 출고 판정에 사용하지 않는다.
검색/품종 필터는 출고 있는 표시 대상 위에 추가 적용하고 숨긴 행 수를 표시한다.
추가 요청: `품목 추가`에서 숨긴 품목 또는 기존 ERP 품목을 검색·선택해 표에 추가한다.
선택 품목은 현재 업체·연도·차수의 기존 읽기 전용 대조로 메타데이터/실제 출고를 확인한다.
명시 추가 행은 현재 화면에서 0이어도 유지하며 업체·연도·차수 변경 시 화면 유지 목록을
초기화한다. 추가 자체는 주문·분배·재고·초안 수량을 만들지 않는다. 조회 실패 시
추가 성공으로 표시하지 않고 오류·후보를 유지한다. 늦은 응답은 기존 요청 순서로 폐기한다.

| 동작 | Order | ShipmentDetail/Date/Farm | Estimate/인쇄 | Stock/WebProfitReport |
|---|---|---|---|---|
| 출고 없는 행 화면 숨김 | 보존 | 원문 보존, 표시만 필터 | 기존 조회·인쇄 범위 보존 | 보존 |

SQL/API/단위환산/확정 로직은 수정하지 않는다. 2025 같은 차수, 빈값·0·양수 소수,
전후차수만 출고, 날짜만 출고, 복수 업무키, 초안 양수/0, 검색·빈결과를 회귀 검증한다.

## 2026-09-30 가로 통합 표·출력 보완

최신 요청에 따라 주광농원은 활성 거래처 검색의 유일한 정확명 결과를 기본 선택한다. 중복/미존재 시 임의 CustKey로 대신하지 않는다. 업체를 사용자가 변경하면 늦게 도착한 기본 검색/전산 조회는 적용하지 않는다.

37/38/39는 하나의 가로 표에서 3개 차수×목~수 7일과 차수합계를 연속 표시하고 ProdKey는 세로 한 행이다. 기준 viewport1920×1080/100%, 품목명은 한번만, 전산 조회 자동, 업로드/상세 설정은 접힌 보조 구역. 칸 편집은 브라우저 미적용 초안과 변경이력만 기록하며 복수 단위/복수 출고 업무키/복수 원본초안은 자동 합치지 않는다. 전산값·초안·차이는 tooltip/선택셀 정보에서 명확히 구분한다. 원천 불명 잔량은 계속 미확인.

요일 머리에 견적서 출력/요일 선택을 배치한다. 실제 저장된 ERP 확정 견적만 출력하고 미적용 초안은 제외한다. 단일/부분 요일 출력은 실제 선택 날짜에 ShipmentDate를 제한한다. 등록 Estimate는 선택 날짜에 배정된 행만 포함하여 각 일자에 같은 차감을 반복 출력하지 않는다. 대차수 전체 출력은 기존 GetPrintDetail의 모든 등록 Estimate 포함 정책을 유지한다. 모든 인쇄는 SELECT-only이며 주문·분배·재고·확정/Estimate 원장은 보존한다.

공통 견적 HTML은 설치 EXE ReportEstimate의 굴림 제목16pt, 상세8pt, 표머리9pt, 정보라벨9pt/값8pt, 합계9pt 기준을 사용한다. 기존 견적서 관리와 주광 출력이 동일 builder를 사용한다. 출력 크기 A4/100%/브라우저 머리말·꼬리말 없음 기준이며 사용자 인쇄 배율은 프로그램이 강제로 보증하지 않는다.

## 적용 범위

### 2026-09-30 최신 기준 (초기 제한 문구보다 우선)

최종 범위는 요일별 분배 적용·변경 추적·재고수정 전후값·확정 사이클·인쇄까지다. 최신 정정에 따라 입고 원천 변경/재배정은 제외하고 입고 차수는 읽기 전용 참고로 둔다. 현재 순서는 전산 달력 기반 37/38/39 연결 조회와 이동 초안 → 영속 변경이력과 재고증감 연결 → 정확한 ERP 적용 및 출력이다. 초기의 '후속 단계 요청 필요' 의미로 범위를 축소하지 않는다. 아래 현재 구현의 읽기 전용 제한은 완료 판정이지 최종 제품 범위가 아니다.

## 기준·정규화

- 업체: 로그인 세션 없이 임의 기본값 확정 금지. 사용자가 검색 결과의 실제 `CustKey`를 선택해야 한다. 주광 자동 선택은 결과가 정확히 하나일 때 제안하되 확인 전 업무키로 사용하지 않는다.
- 기간: `year`는 4자리 숫자, 대차수는 `01..53`, 세부차수는 입력된 원문 `NN-SS`를 유지한다. 모든 조회 요청에 `year + full OrderWeek + CustKey + ProdKey`를 전달한다. 차수 셀만으로 날짜 또는 세부차수를 추정하지 않는다.
- 워크북: ExcelJS로 값/수식/병합·셀 주소를 보존한다. 수식은 계산하지 않는다. 수식합계 행은 데이터행에 합산하지 않으며, 캐시값만으로 총량을 보증하지 않는다.
- 품목: 원본명과 행을 보존. 동일 후보가 명확하지 않으면 `미연결`; 직접 선택한 ProdKey만 비교 요청에 포함한다. 표시명 검색 결과가 ProdKey의 확정 근거가 되지 않는다.
- 수량: 순수 숫자 셀만 원문과 함께 후보 수량으로 제공. `2단`, `2+14단`, 빈칸, 날짜, 수식/메모는 자동 변환하지 않고 검토 상태로 둔다. 단위 변환은 하지 않는다.
- 요일/차수: 원본 날짜 헤더는 날짜 사실로 기록하되, 각 수량을 세부차수에 자동 귀속하지 않는다. 사용자가 세부차수 및 출고일을 선택해야 한다.
- ERP 대조: 선택한 year, full OrderWeek, CustKey, ProdKey 범위만 조회한다. 테이블 행 부재나 미확정 자료를 `0`/`적용됨`으로 오인하지 않고 `없음/미확정/대조불가`로 구분한다.
- 저장: 브라우저 작업안은 서버/DB 저장을 하지 않는다. 새 ERP 원장 쓰기는 별도 승인·계약·트랜잭션·사후대조 필요.

## UI 상태와 적용 판정

`파일 없음 → 파싱 완료(검토 포함) → 연결/차수 배정 중 → 대조 완료 또는 대조불가`를 표시한다. 수식/텍스트/단위불명/품목 미연결은 적용 차단 오류가 아니라 현재 단계의 “검토 필요”이지만, 전산 적용 자체가 아직 미지원이다. 이 단계에서는 어떠한 상태도 “적용됨” 또는 “출력 완료”로 표시하지 않는다.

## ERP 근거 및 downstream

- `docs/exe-golden/FormEstimateView.md`: 판매 견적은 `ViewShipment + ViewOrder + ShipmentDate + PeriodDay + DetailFix=1`; 실제 일자 행은 `SdateKey`, `ShipmentDate.EstQuantity`를 사용.
- `docs/ERP_COMPAT_INVARIANTS_2026-06-04.md`: 출고는 `ShipmentDetail` 1행 + `ShipmentDate` N행; 출고일별 수량행을 단순 집계 계획으로 덮어쓰거나 Detail을 날짜별 복제하지 않는다.
- 인쇄/대조가 읽기 전용이면 `OrderDetail`, `ShipmentDetail.Amount/Vat/isFix`, `Estimate`, `ShipmentDate`, 재고/매출을 보존한다. 향후 분배 저장 시 주문·출고·날짜원장과 견적 가시성/확정 매출을 별도 계약·실측 검증한다.
- 교차연도 fixture는 동일한 `OrderWeek=38-02`가 2025와 2026 양쪽에 있어도 2026 선택 요청에서 2025 행이 반환되지 않는 것을 검증한다.

## 남은 차단 조건

실 DB 조회 인증 및 실제 거래처·차수 데이터 확인, 일자별 계획의 OutUnit/EstUnit 변환 기준, 확정 건 저장 사이클, EXE 출력 레이아웃 골든 비교가 미확인이다. 따라서 ERP 저장·인쇄 구현으로 범위를 확대하지 않는다.
