# 패킹 업로드: 매칭 먼저, 위험 항목만 원문 확인

## 최신 사용자 합의
- 업로드 분석 직후 DB 매칭 현황을 먼저 표시한다. 미매칭/유사 매칭 기본 필터, 전체 보기 제공.
- 품목 선택과 팀 공용 매칭 저장은 날짜·미확인 단가와 독립적이다. 다음 업로드에 재사용한다.
- 원본 PDF 창은 자동으로 열지 않는다. 수량·단가·원문 불확실성이 있는 항목 또는 사용자의 명시 요청에서 연다.
- 검산된 중국 로컬 PDF101행 전부에 사람이 확인 체크하도록 강제한 이전 정책은 최신 요청으로 대체한다. 검산과 사람이 확인한 기록은 구분한다.
- 미확인 가격을0으로 대체하거나 미리보기를 입고 완료로 표시하지 않는다.

## 부작용 / 기준 ledger
| 동작 | Product | 팀 공용 매칭 | Order/Shipment/Warehouse/Stock/Estimate/WebProfitReport |
|---|---|---|---|
| 매칭 미리보기 | 기존 활성품목 GET | 읽기 | 모두 보존 |
| 후보 명시 선택·저장 | 기존 동일 국가 ProdKey 검사 | 기존 CAS·수정자 이력 저장 | 모두 보존 |
| 원본 확인/수정 | 보존 | 보존 | 모두 보존 |
| 최종 변환/입고 연결 | 기존 검증 유지 | 기존 조회 | 이번 작업에서 writer 변경 없음 |

미리보기는 원문 행/수량/단가 null을 보존하며 파일 버퍼와 입고 초안을 만들지 않는다. 전산 키/이름 판정은 기존 makeProductResolver + packingMatchReview + 팀 공용 GET/POST를 사용한다. 세부차수·연도는 기존 최종 저장 계약 유지. 실제 native ExcelLoadingPackingList.CheckData의 정확 ProdName/SIZE 조인 근거를 재확인했으며 SQL 변경은 없다.

## 검증
- 미확인 단가/날짜가 있어도101행 미리보기 표시, 자동 PDF 모달 없음, 다운로드/입고는 차단.
- 정확/수동/유사/미매칭 구분, 전체보기, 후보 키보드 선택, 저장 실패·CAS 충돌·재업로드 공유 매칭.
- 검산 근거 없는 행/누락 가격/박스 번호 경고/수동수정은 원문 확인 유지; 원문 해시와 스냅샷 변경 시 재검증.
- 1920×1080/100%,1280×800 실브라우저, 실제 PDF 무료 분석; 운영 저장시험·유료AI0.
- 전체 ERP 계약/manifest/write/dnSpy guard/build 통과 후 PR/배포/운영 smoke.

## 메뉴 기준선
페이지 스크롤·전체 이름·키보드·원본/매칭 비교·명시 저장 적용. 기존 원본 모달 내부스크롤은 필요한 예외. ERP 수량변경·재고보정은 해당 없음.
