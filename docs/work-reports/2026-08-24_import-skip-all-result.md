## 작업 흐름

1. **분석** — 행 단위 `skip` 체크만 있었고, 등록 성공은 배너 문구뿐이었다. 붙여넣기 화면의 DB 저장 내역을 참고.
2. **구현** — 전체 제외/해제(헤더 체크 포함). POST 성공 후 같은 연도·차수·업체로 ViewOrder를 다시 읽어 결과 표 표시. 주문 쓰기 API는 변경하지 않음.
3. **검증** — 헬퍼/화면 계약 테스트, manifest, write-scope(API 0건), dnSpy evidence, build.

## 사용자 확인 포인트

- 업로드 주문등록 → 품목 매칭 결과에서 **전체 제외** / **전체 제외 해제**, 제외 열 헤더 체크.
- 미매칭 행은 제외하면 등록 버튼이 풀린다. 전부 제외하면 등록할 품목이 없다고 막힌다.
- 주문등록 후 상단에 **주문등록 결과**(이전/증감/최종)와 **현재 DB 주문 내역**.
