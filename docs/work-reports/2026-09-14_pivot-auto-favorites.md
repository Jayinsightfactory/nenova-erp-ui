# 전산 피벗 자동 조회·사용자 즐겨찾기·즉시 재집계

## 구현 전 기준

- 요청: 페이지 진입 자동 조회, 사용자별 즐겨찾기 조합, 행·열·값·필터 이동 즉시 실제 표 변경.
- dnSpy 저장 소스 FormQuantityPivot_Load는 SetCombo 다음 GetData 호출. 기존 웹에는 refresh 버튼 외 호출이 없었다.
- 기존 모델은 zones 변경을 의존성으로 재집계하나 드래그 drop 연결이 없고, 접힌 그룹 상태가 배치 변경 후 남는다. 메뉴 이동과 drag/drop 모두 같은 moveField 경로로 연결하고 배치 변경 시 접힘을 해제한다. 수량 자체가 달라져야 한다는 의미가 아니라 묶음/축/집계가 바뀌어야 한다.
- 현재 차수 기본값은 기존 getCurrentWeek 유지. 연도+세부차수 검증은 normalizePivotExeRange 공유. 최초 진입 및 유효 범위 변경 후 자동 조회, 이전 요청 취소/응답 순서 보호, 실패 시 마지막 성공 표 보존.
- 즐겨찾기는 기존 인증된 /api/favorites 및 UserFavorite 사용, PageName=stats-pivot-exe. 이름 있는 조합 명시 저장/수정/삭제만 서버 저장. 선택 연도/차수나 원본 자료는 포함하지 않는다.
- 마지막 화면 설정은 확인된 /api/auth/me userId별 localStorage 키로 분리. 기존 사용자 구분 없는 pivotExeLayout은 다른 계정에 전파하지 않는다. 인증 확인 실패 시 자동 저장하지 않으며 기본 화면 사용.
- 저장 조합: 행/열/값/필터, 숨김, 집계 방식, 값필터/조건식, 정렬, 소수/0표시/합계, 폭/높이. 0, false, 빈 필터 선택은 유효하게 보존. 잘못된 조건식은 오류 처리하고 임의 해제하지 않는다.
- 최종 검토 보강: 인증된 사용자 설정이 복원될 때까지 편집 UI를 열지 않으며, 인증 확인은 8초 뒤 실패 안내/비저장 기본 화면으로 전환한다. 차수 자료 조회는 동시에 진행한다. 기본값이 기존 사용자 설정을 덮지 않는다.
- 개별 데이터 열 너비는 SHA-256 열 식별자로 저장한다. AWB/거래처/연도 등의 원본 열 값이 너비 키에 포함되지 않는다. 사용자가 명시 선택한 필터 값은 조합의 조건으로 저장하며 원본 행·수량·금액 저장과 구분한다. 이미 잠긴 @noble/hashes 1.8.0을 직접 의존성으로 명시했으며 버전 변경/추가 패키지 설치는 없다.

## 완료 기준

- 새로고침 클릭 없이 자료 표시, 범위 변경 응답 경합/503 보존.
- 실제 축 전환과 합계/개수 셀 대조. 단순 버튼 존재 검사로 통과 처리하지 않는다.
- 서버 즐겨찾기 저장·복원·수정·삭제, malformed/zero/false/교차연도/사용자 분리 fixture.
- 1920×1080 / 100% 및 작은 화면 잘림·필터 위치·표 스크롤 회귀.
- ERP 계약/manifest/dnSpy/write guard/build → PR/배포 → 운영 read-only smoke. 실제 고객 원장 쓰기 없음.

## 검증 결과

- test:pivot-exe 7개 검사, ERP 전체 계약, 59개 manifest, dnSpy 근거, 변경 API 쓰기 보호 통과. ERP API 변경 0건.
- 1920×1080 / 100% 및 1366×768 로컬 브라우저 smoke 통과. 실제 축 이동·집계값, 60개 메뉴 이동, 자동 조회, 503 시 기존 표 보존, 즐겨찾기 CRUD와 사용자 격리 검증.
- 인증을 500ms 지연시킨 재진입에서 편집 UI는 복원까지 숨겨지고, 원본 조회는 병렬 실행되며, 기존 개인 행 높이 33이 유지됨.
- 저장 열 너비 키는 SHA-256 식별자이며 원본 AWB 등 값이 포함되지 않음. 엑셀 내보내기 너비/원본 숫자 회귀 통과.
- 구현 Terra, UI/fixture Luna, 독립 최종 검토 Sol. 최종 검토 P1/P2 없음. 운영 CRUD·ERP 원장 쓰기 없이 fixture로 검증.
