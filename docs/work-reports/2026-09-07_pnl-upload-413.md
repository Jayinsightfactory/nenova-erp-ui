# 손익계산서 엑셀 업로드 HTML 오류

## 확인된 원인
- 신라 원본은 3,538,959 bytes. 앱 업로드 제한은 30MiB.
- 운영 `/api/raum/pnl-import`에 같은 Content-Length와 Expect:100-continue를 보내자 본문 전송 전 nginx/1.24.0이 413 text/html을 반환했다.
- 읽기 전용 서버 설정 확인(34072985742): `/etc/nginx/sites-enabled/nenova-erp`의 nenovaweb.com 서버에는 client_max_body_size가 없고 루트 프록시는 127.0.0.1:3000이다. 별도 n8n 설정의 50m는 이 사이트에 적용되지 않는다.
- 화면은 HTML 오류에 response.json()을 호출하여 Unexpected token '<'를 표시했다.

## 수정 계약과 부작용
- 파일30MiB 제한 유지. 업로드 정확 경로에만 multipart 여유 포함32MiB, 기존 루트 프록시 설정 복제 보존. 다른 경로·인증·n8n 변경 금지.
- 설정 백업, 문법 검증, reload, 실패 시 이전 파일 복원. 예상하지 않은 설정 구조는 추측하지 않고 중단.
- 미리보기/저장 응답을 한 번 읽어 해석하고 HTML 원문은 노출하지 않는다. 로그인·용량·연결 오류를 한글로 구분한다.
- 저장 실패/시간초과는 자동 재시도하지 않는다. 저장 여부를 목록에서 먼저 확인한다.
- 기존 파일·결산 계산·업로드 저장 계약·ERP 수량/단가/재고/원장은 보존한다. 이번 수정을 위해 운영 DB 쓰기는 하지 않는다.

## 검증
- 실행 가능한 응답 객체로 HTML413/401/403/502/503/504/200 및 정상JSON, 중복 본문 읽기, 네트워크 실패를 검사.
- nginx 설정 변환의 경로 격리/프록시 보존/멱등성/예상하지 않은 구성 차단/실패 복구 검사.
- 운영 적용 뒤 원본 크기 헤더의413 해소와 과대 업로드 차단, 기본 화면 접근을 다시 확인한다. 실제 원본 미리보기와 저장 검증은 각각 별도로 기록한다.
