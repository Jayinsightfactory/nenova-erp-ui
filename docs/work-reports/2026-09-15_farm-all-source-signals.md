# 전체 불량 원본 자동감지 확장

## 사용자 의도와 완료 기준

원본 조회 범위만 넓어지고 자동감지가 기존 적격 원본에 머문 문제를 수정한다.
자동감지 후보는 같은 연도·선택 차수의 활성 양수 불량 원본으로 확장한다.
농장 미지정은 농장 귀책으로 추정하지 않고 품목·업체 반복 확인 대상으로 표시한다.
미확인 원본 포함 후보는 확인 필요로 구별하며 확정 불량률과 원본 저장 기준은 유지한다.

## 기준 원천과 검증

- 원천: WebSalesDefectDeduction, DeductionKey 중복 제거, OrderYear 선필터.
- 기간: 기존 qualityWeek 부모차수 규칙. 잘못된 차수·품목·수량은 원본 확인에 남긴다.
- 농장 지정: 기존 4가지 반복 규칙, 미확인 원본 포함 여부를 별도 표시.
- 농장 미지정: 동일 품목·단위·부모차수의 2개 이상 업체, 또는 동일 업체(CustKey)·품목·단위의 연속차수/4차수 내 3회 반복. 농장간 집중으로 해석하지 않는다. 업체키는 응답 키에도 노출하지 않는다.
- 미확인/농장 미지정 후보는 피드백 생성하지 않고 원본 확인 안내만 제공한다.
- 자동감지 단위 선택은 확정 불량률 선택과 분리하고 기본값은 전체 단위다.
- 원본 건수는 DeductionKey 건수이며 이슈 간 겹침을 합산해 원본 수로 표시하지 않는다.
- dnSpy FormSalesDefectView.GetData 및 FormFarmQuality 근거: 웹 전용 읽기 분석이며 EXE 금액 계산은 변경하지 않는다.
- 직전 운영 읽기 probe: 2026 원본 436, 삭제 24, 활성 412, 농장 미지정 80, 미확인 55(중복 포함).

## 부작용 표

| 동작 | 불량 원본 | 피드백 Case/Event | Warehouse/Order/Shipment/Stock/Estimate/손익 |
|---|---|---|---|
| 자동감지/필터/근거 조회 | SELECT | SELECT | 기존 입고 분모 SELECT만, 모든 원장 보존 |
| 확인 필요 후보 보기 | 보존 | 생성 금지 | 보존 |
| 기존 적격 후보 이슈 처리 | 기존 저장 재검증 유지 | 기존 명시 저장만 | 보존 |

## 검증 결과

- 전체 `npm run test:erp-contract` 성공(기존 회귀 + 새 자동감지/화면/저장 차단 검사).
- dnSpy 근거·ERP 쓰기 scope 검사 통과. production webpack build 성공.
- 격리 fixture: 활성 69, 감지 대상 68 = 기존 적격 62 + 추가 6, 감지 고유 원본 10 + 패턴 없음 58, 차수 미상 제외 1. 3개 후보 모두 확인 필요이며 2개는 농장 미지정 신규 패턴.
- 실제 Chrome 1920×1080 / 760×900, 100%: 문서 가로 너비가 viewport와 일치. 새 단위 전용 후보도 기본 전체 단위에 표시, 기존 분석 단위를 바꿔도 감지 결과 유지, 업체명 근거 줄바꿈, 확인 필요 후보 생성 버튼 없음, 원본 확인 링크 정상.
- 기존 적격 품목 ‘피드백 건 만들기’는 새 피드백 입력 화면에 정상 진입. 저장하지 않음. Console error 없음. 모든 fixture API는 GET만 허용하고 운영 API에는 연결하지 않음.
- 화면 검토 후 집계에 ‘조회 기간 전체 · 모든 단위 기준’ 안내, ‘감지 대상 원본’·‘묶음 기준’ 명칭을 보완했다.
- Sol/high 설계·최종 검토, Terra/high 코어 및 UI 구현, 메인 통합·외부작업. 로컬 사전 준비 후 P0_LOCAL만 위임. 최종 추가 P0/P1 없음.
- 운영 반영과 배포 후 실제 자동감지 수치는 아래 후속 기록에 남긴다. 테스트를 위해 운영 ERP 원장이나 피드백을 저장하지 않는다.
