# 호텔+미우 차수 입력 확장 설계

## 사용자 기준

- 고정 종료값 `36-02`를 제거한다.
- 영업 기준 대차수부터 `+9` 대차수까지 빠르게 선택한다.
- 대차수와 세부차수를 직접 입력할 수 있다.
- 세부차수는 1·2·3·4를 사용한다.
- `1A`, `1B`, `2A`, `2B`도 입력은 받되 A/B는 항공편 표시로만 보고 ERP 주문 차수는 각각 01, 01, 02, 02로 저장한다.

## dnSpy 근거

- 대상: `FormOrderAdd`, `FormOrderAdd.Designer`
- 입력 컨트롤: `txtOrderWeek` (`TextEdit`)
- 마스크: `[0-9][0-9]-0[1-9]`
- 저장: `ClassOrderMaster.OrderWeek = txtOrderWeek.Text`
- 조회·중복 판정: `OrderYear + OrderWeek + CustKey`
- A/B를 포함한 주문 차수는 전산 입력 마스크에 맞지 않는다. 따라서 웹은 A/B를 숫자 세부차수의 입력 별칭으로만 처리한다.

## 기준표

| 구분 | 화면 입력 | 정규화 결과 | 기준 원천 | 사용처 |
|---|---|---|---|---|
| 기본 대차수 | 달력 대차수 +1 | 연도+대차수 | 영업 붙여넣기 주문 계약 | 초기 선택·빠른 선택 |
| 빠른 범위 | 기본~기본+9 | 연도 포함 10개 대차수 | 사용자 지시 | 화면 선택 |
| 세부차수 | 1·2·3·4 | 01·02·03·04 | dnSpy 숫자 마스크·기존 웹 계약 | 조회·합산·주문등록 |
| 항공편 접미 | A·B | 제거 | 도착원가/영업 붙여넣기 기존 계약 | 직접입력 정규화만 |
| 업무키 | 연도+차수+업체+품목 | `OrderYear+OrderWeek+CustKey+ProdKey` | dnSpy·ERP 가드 | 모든 조회·저장 |

## 수용 조건

- 2026-09-01 기준 36부터 45까지 대차수 빠른 선택이 보인다.
- 각 대차수에서 01~04를 선택할 수 있다.
- `39`와 `2` 직접입력은 `2026 / 39-02`가 된다.
- `36-1A`, `36-1B`는 모두 `36-01`, `36-2A`, `36-2B`는 모두 `36-02`가 된다.
- `00`, `53`, 세부차수 0·5, 알 수 없는 접미는 저장 전에 거부한다.
- 2025와 2026의 같은 `39-02`가 섞이지 않는다.
- 차수 선택·입력만으로 주문·분배·재고·견적·손익 원장은 바뀌지 않는다.
