# 호텔 결산 특이사항 설계·검증

## 사용자 결과

- 손익계산서 상단의 `차수별 매입단가 관리` 바로 옆에 `특이사항` 버튼을 둔다.
- 선택한 호텔과 연도별로 최대 5,000자의 자유 메모를 입력·저장·다시 조회한다.
- 마지막 저장 시각과 담당자를 표시한다.
- 다른 사용자가 같은 메모를 먼저 저장했다면 조용히 덮어쓰지 않고 최신 내용 재조회를 요청한다.

## 기준값 원장

| 항목 | 기준 | 소비자 |
|---|---|---|
| 거래처 | 서버에서 다시 확인한 활성 `PartnerCode` | GET/PUT API, 저장 SQL |
| 연도 | 명시적인 4자리 `OrderYear` | 화면 연도 선택, GET/PUT API, 저장 SQL |
| 메모 길이 | 0~5,000자 | textarea, 서버 정규화 |
| 동시 수정 | 조회에서 받은 `Revision`의 정확 일치 | PUT 잠금 재검증 |
| 빈 메모 | 신규면 쓰기 없음, 기존이면 빈 문자열로 명시 저장 | 저장 코어 |

## 부작용 표

| 동작 | WebRaumPnlSpecialNote | WebRaumPnl/Item | Order/Shipment | Stock/Estimate/WebProfitReport |
|---|---|---|---|---|
| 특이사항 열기·연도 변경 | SELECT | 보존 | 보존 | 보존 |
| 특이사항 저장 | 동일 거래처+연도 INSERT/UPDATE | 보존 | 보존 | 보존 |
| 내용 동일 저장 | 쓰기 없음 | 보존 | 보존 | 보존 |
| 오래된 화면에서 저장 | 409, 쓰기 없음 | 보존 | 보존 | 보존 |

## 경계 fixture

- 정상: 신라호텔 2026 메모 신규 저장 후 수정.
- 근접 실패: 같은 거래처 2025, 같은 연도 라움 메모가 2026 신라 메모와 섞이지 않음.
- 근접 실패: 이전 `Revision` 또는 빈 `Revision`으로 기존 행을 저장하면 409.
- 명시적 빈 값은 유효하며 truthiness 기본값으로 대체하지 않음.

`nenova.exe`에는 웹 특이사항 테이블을 읽는 화면이나 저장 경로가 없으므로 EXE 원장 SQL은 변경하지 않는다. 기존 `docs/exe-golden/FormRaumPnl.md`의 주문·출고 보존 근거를 유지한다.
