# 견적서 본인 작업의 외부 변경 반복 차단 보완

## 현상

견적서관리에서 수량 또는 단가를 저장하려 할 때 `nenova.exe 또는 다른 화면에서 값이 변경되었습니다`가 반복되고, 브라우저를 새로고침해도 계속 저장할 수 없는 경우가 있었다.

## 원인

`WebErpEditLease`가 같은 로그인 사용자와 같은 브라우저 탭의 작업권을 보유한 상태에서 ERP 내용 지문이 달라지면 서버는 안전하게 저장을 막았다. 그러나 화면을 다시 연 초기 작업권 취득 단계의 오류 응답에는 본인 작업권 토큰이 없었다. 화면은 변경 사실은 알지만 명시적 `확정 현황 다시 불러오기`를 실행할 권한을 복구하지 못해 90초 만료 전까지 반복 차단됐다. 이전 화면이 heartbeat를 계속 보내는 경우에는 차단이 더 오래 유지될 수 있었다.

## 변경 계약

- 같은 `UserID + clientId`가 소유한 작업권에서만 오래된 기준 오류 응답에 기존 토큰을 돌려준다.
- 화면은 토큰을 복구하되 `stale=true`를 유지하여 저장을 계속 막는다.
- 사용자가 `확정 현황 다시 불러오기`를 눌러 실제 확정현황과 견적 상세를 다시 읽은 경우에만 현재 ERP 지문을 새 기준으로 받아들인다.
- 다른 사용자 또는 같은 계정의 다른 브라우저에는 토큰을 노출하지 않는다. 다른 창은 기존처럼 `이 창에서 계속 작업`을 명시적으로 눌러야 한다.
- 자동 8초 확인은 변경을 감지만 하며 현재 ERP 값을 자동 수용하지 않는다.

## ERP 영향표

| 대상 | 영향 |
|---|---|
| OrderMaster / OrderDetail | 없음 |
| ShipmentMaster / ShipmentDetail | 없음 |
| ShipmentDate / ShipmentFarm | 없음 |
| Estimate | 없음 |
| Product / ProductStock / StockHistory | 없음 |
| WebProfitReport | 없음 |
| WebErpEditLease | 사용자의 명시적 최신화 때 BaselineDigest와 만료시간만 갱신 |

수량·단가의 계산식, 확정 상태, 재고 계산, 거래처 지정단가는 이번 변경에서 수정하지 않는다.
