# 붙여넣기 전체 되돌리기·주문조회 연도 회귀 보강

## 확인된 원인

- 붙여넣기 전체 작업이 완료되자마자 화면의 `저장 중` 표시가 먼저 풀려, 주기 조회가 자기 변경을 외부 변경으로 오인할 수 있었다.
- 전체 되돌리기는 원래 처리와 달리 업체 작업권을 얻지 않았고 서버로 작업권 정보를 보내지 않았다. 활성 작업권이 있으면 서버가 대기·차단될 수 있었다.
- 주문조회 화면은 `35-01`처럼 연도를 생략한 차수를 API로 보낼 때 연도를 함께 보내지 않았다. API의 과거 호환 규칙이 이를 2025년으로 해석했다.

## 적용 기준

- 전체 저장·되돌리기 모두 모든 대상 업체의 작업권을 먼저 얻는다.
- 서버는 한 트랜잭션 안에서 모든 행을 되돌리고, 각 행의 주문·분배·출고일 수량 대조가 끝나야 완료를 반환한다.
- 한 행이라도 실패하거나 대조되지 않으면 전체를 취소한다.
- 작업권 기준값 갱신과 반납이 끝난 뒤에만 화면 버튼을 다시 누를 수 있다.
- 응답 시간초과는 완료나 전체취소로 추정하지 않고 재조회가 필요하다고 안내한다.
- 주문조회는 `OrderYear + OrderWeek`를 항상 같이 사용한다. 짧은 차수는 화면 조회기간의 연도 또는 현재 운영연도로 보정하며, 전체 차수의 연도와 명시 연도가 다르면 차단한다.

## 부작용 표

| 사용자 동작 | 주문 | 분배 | 출고일/농장 | 견적·매출·재고·손익 |
|---|---|---|---|---|
| 주문조회 | 보존 | 보존 | 보존 | 전부 보존 |
| 원래 추가행 되돌리기 | 기존 `PASTE_UNDO_BOTH` 정책에 따라 추가분 감소 | 추가분 감소 | 분배와 동기화 | 직접 변경 없음 |
| 원래 취소행 되돌리기 | 주문 보존 | 취소분 복원 | 분배와 동기화 | 직접 변경 없음 |
| 중간 실패·수량 불일치 | 전체 취소 | 전체 취소 | 전체 취소 | 직접 변경 없음 |

## 운영 자료 보호

- 기존 진단 오류행과 운영 수량은 이 수정 과정에서 보정하지 않는다.
- 2025·2026 동일 차수 fixture로 선택 연도만 조회되는지 검사한다.
- 운영 반영 후 실제 수량을 바꾸지 않는 화면 조회와 상태 검사만 수행한다.
