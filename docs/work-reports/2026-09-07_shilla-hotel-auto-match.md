# 신라 동일 호텔·품목 자동 연결 설계

## 사용자 요구

같은 호텔에서 품목명이 같으면 매칭을 차수마다 반복하지 않고 자동 재사용한다.

## 범위와 기준

- 이번 신라 연결 화면에서 선택한 연도의 활성 신라 결산만 대상으로 한다. 다른 호텔·전년도는 자동 변경하지 않는다.
- 동일성은 원본 품목명과 단위의 앞뒤/연속 공백 정리 후 정확 일치다. 색상·길이·품종·괄호를 임의 제거하지 않는다. 수동 행은 제외한다.
- 한 번 명시 선택한 Product 연결로 같은 그룹의 미연결 행을 채운다. 다른 Product로 이미 연결된 행은 덮어쓰지 않으며 충돌을 표시한다.
- 원본 수량·매입단가·판매단가·매입액·매출액·분배비율은 보존한다.
- 새 화면은 적용 범위를 표시한다. 기존 클라이언트 요청은 기존 단일 행 계약을 유지한다.
- 이후 엑셀 미리보기와 저장은 같은 호텔·연도 그룹의 유일한 활성 Product 연결을 재사용한다. 후보가 둘 이상이거나 비활성 품목이면 자동 선택하지 않는다.
- GET은 읽기 전용이다. 화면을 연 것만으로 기존 DB 행을 자동 수정하지 않는다.

## 부작용 표

| 동작 | WebRaumPnlItem | WebRaumPnl | Product/주문/분배/재고/견적 |
|---|---|---|---|
| 그룹 연결 | 해당 연도·호텔·정확 이름/단위의 대상 ProdKey만 | 변경 부모 UpdatedAt/By | 보존 |
| 연결 해제 | 명시된 그룹 해제 범위만 | 변경 부모 UpdatedAt/By | 보존 |
| 엑셀 미리보기 | 읽기/반환 초안만 | 읽기 | 보존 |
| 엑셀 저장 | 기존 원본 저장 계약 + 동일 자동연결 규칙 | 기존 저장 계약 | 보존 |

## 사전 근거

- 실제 신라 35차·30차에 '장미 · 쉬머' 단 행이 반복되고 단가는 차수별 독립이다. 기존 화면 읽기에서 35차16개·10,800원과30차40개·10,800원을 확인했다.
- 현재 저장 API는 한 ItemKey만 업데이트하며 반복행에 대한 전역 학습은 하지 않는다. 신규 범위는 호텔·연도 안으로만 확대한다.
- 기존 dnSpy FormOrderAdd.GetDataProduct의 Product.ProdKey/원본명/단위 구분은 유지한다. ERP 저장 경로/SP 변경은 없다.
- 고성능 설계 GO: 선택연도 신라 group/import 공통 잠금 → master → items → active Product 순서를 통일한다. 그룹 전체 해제로 추후 자동연결 근거가 남지 않게 한다. preview/save 동일 inference와 재계산 fingerprint를 검증한다. 실제 운영 자료에 자동연결 보정은 하지 않고 사용자의 명시 연결 또는 엑셀 저장 시에만 적용한다.

## 구현·검증

- 기본 선택된 ‘같은 호텔 동일 품목 함께 연결’ 옵션, 적용 건수·차수 표시, 그룹 해제 확인을 구현했다. 옵션을 끄면 기존 한 행 연결이다.
- 그룹 연결과 엑셀 저장의 연도 잠금을 공유하며 잠금 획득 실패는 중단한다. 다른 호텔·연도·단위·수기 행은 제외한다.
- 그룹 연결/해제, 이미 연결된 기준행에서 미연결 동료 채우기, 상충 연결 중단, 중간 부모 저장 실패 롤백, 새 업로드 자동 연결과 미리보기 이후 연결 변경 차단 실행 검사를 통과했다.
- `npm run test:shilla-pnl`, `npm run test:raum-pnl`, `npm run verify:erp-change` 통과. 원본 35차수 대조, dnSpy 근거, 변경범위·쓰기 보호 및 103페이지 운영 빌드 포함.
- 운영 자료의 연결·해제 및 엑셀 저장은 시험 목적으로 실행하지 않는다. 운영 반영과 화면 확인 결과는 후속 기록한다.

## 운영 결과

- 최종 검토에서 해제를 연결로 표시하던 안내와 이전 단일행 툴팁을 수정했다. 변경 #527 자동검사 성공 후 운영 기준 5af40aa8 반영.
- Cafe24 34084673123 성공(2분41초), ERP 보호 검사·SSH 설치·실브라우저 검사 모두 성공.
- 로그인된 새 Chrome 탭에서 5af40aa8 확인. 신라 35차 수량/매입/매출/이익 기존값 유지, 동일 호텔 옵션 기본 ON 및 OFF 전환 확인. 한글 ‘쉬머’로 실제 Shimmer 후보 검색 성공, console error/warn 0건.
- CSS viewport 1920×1080에서 페이지 가로 넘침 없음. 기존 브라우저 확대율 80%를 유지하여 100% 확대 검증과 동일하다고 주장하지 않음. 임시 viewport 원복.
- 운영 연결·해제·엑셀 저장은 미실행. 실제 사용자 연결이 저장되는 순간 동일 연도·호텔의 미연결 그룹을 채우며, 운영 자료가 이미 자동 수정됐다는 의미가 아니다.
