# 차수별 출력·가로 비고 독립 QA

## 상태

로컬 합성 PDF 통과. 앱 통합·전체 gate·운영 배포 검증은 진행 중이다. 앱·SQL 코드는 독립 담당이 수정하지 않는다.

## 기준 및 읽기 검토

- 차수별 출력은 조회 완료된 동일 연도·시작/끝 범위만 허용한다. 모든 차수 성공 후에만 완료 scope를 설정한다.
- 입력 범위 변경·요청 전환·탭 전환 시 abort/sequence 및 입력 ref 비교로 늦은 응답을 완료로 승격하지 않는다.
- 미저장 카테고리 초안/비고가 있으면 출력 차단, 자동 저장 요청 없음.
- 출력 도중 scope/dirty/saving 변경도 requestScopeKey로 취소한다. 부분 실패를 성공한 차수만의 다운로드로 바꾸지 않는다.
- 인쇄 비고만 CRLF/LF/CR 줄을 trim 후 ` · `로 연결하고 페이지 폭에 맞게 wrap한다. 원본 비고·metadata·Excel 셀은 변경하지 않는다.
- 기존 금융 계산·확정값·연도 포함 업무키·원장 보존. 신규 DB/API 쓰기 없음.

현재 diff의 scope/abort/seq/dirty/부분실패 경계에 독립 검토 P1 없음. 실행형 앱 검증으로 반례 확인 필요.

## 실제 Chromium PDF

`.verify/weeks-output-pdf.mjs` 실행 EXIT0. 현재 실제22개 COLUMN_DEFS 헤더·18행·비고 문라이트1~50의 합성 fixture 사용.

| 검사 | 결과 |
|---|---|
| 18차 한 차수 | A4 가로1장 |
| 18·38·39차 | A4 가로3장 |
| 비고 줄 연결 | `문라이트1 · 문라이트2` 및 마지막 문라이트50 PDF 텍스트 존재 |
| 원본 보존 | HTML 생성 전후 전체 workbook JSON 동일, 원래 CRLF 비고 동일 |
| 시각 확인 | pdftoppm 실제PDF PNG에서 가로흐름·폭 자동줄바꿈·마지막항목 확인 |

산출물 `.verify/weeks-output-pdf/`는 합성 자료이며 커밋 제외. 물리 프린터는 미검증이다. 이전 작업 운영41607954025 통과는 이전 인쇄 기능의 근거이며 이번 차수별 UI 연결까지 검증한 것으로 간주하지 않는다.
