# 차수별 출력·가로 비고 독립 QA

## 상태

로컬 합성 PDF와 제목 보완을 포함한 production-build 실제 Chromium 모의 UI 재검증 통과. PR1453 head4be68df3e CI41610146868 및 전체 verify28427 진행 중이며 배포·운영 결과는 대기한다. 앱·SQL 코드는 독립 담당이 수정하지 않는다.

## 기준 및 읽기 검토

- 차수별 출력은 조회 완료된 동일 연도·시작/끝 범위만 허용한다. 모든 차수 성공 후에만 완료 scope를 설정한다.
- 입력 범위 변경·요청 전환·탭 전환 시 abort/sequence 및 입력 ref 비교로 늦은 응답을 완료로 승격하지 않는다.
- 미저장 카테고리 초안/비고가 있으면 출력 차단, 자동 저장 요청 없음.
- 출력 도중 scope/dirty/saving 변경도 requestScopeKey로 취소한다. 부분 실패를 성공한 차수만의 다운로드로 바꾸지 않는다.
- 인쇄 비고만 CRLF/LF/CR 줄을 trim 후 ` · `로 연결하고 페이지 폭에 맞게 wrap한다. 원본 비고·metadata·Excel 셀은 변경하지 않는다.
- 기존 금융 계산·확정값·연도 포함 업무키·원장 보존. 신규 DB/API 쓰기 없음.

현재 diff의 scope/abort/seq/dirty/부분실패 경계에 독립 검토 P1 없음. 실행형 앱 검증으로 반례 확인 필요.

## 실제 앱 통합 결과

별도 production build EXIT0 후 `scripts/profit-weeks-output-smoke.cjs` 실제 Chrome 실행 PASS. 합성 API만 사용했으며 API writes0/pageerrors0이다.

- 조회27~29 최초3주 선택에서27·29만2주 출력.
- 2025 연도 격리,28차 부분실패 시 범위 출력 차단.
- 지연 응답 도중 범위 변경 시 늦은 응답의 출력 승격 차단.
- 카테고리 미저장 비고가 있는 상태의 차수별 출력 차단.
- 시나리오별 직접 print 총3회, 비고 가로 흐름,390px 버튼 경계.

첫 실행의 입력 실패는 검사기의 triple-click 선택 문제였으며 Ctrl+A로 테스트 입력만 정정했다. 앱 로직 우회나 assertion 완화로 통과시키지 않았다. 합성 화면 산출물은 `.verify/profit-weeks-output-mobile.png`.

부모가 설치 EXE FormStockView.GetData dnSpy를 다시 실행하여 EXIT0 및 ViewWarehouse/ViewShipment 연도 포함 조회를 확인했다. 신규 SQL 쓰기 없음. 현재 앱 코드 동결, PR1453 CI 및 전체 verify28427 진행 중, 운영 완료는 후속 기록한다.

## 후속 제목 범위 보완

모바일 추가 검토에서 차수별2025/27~30 조회 중 제목에 이전 카테고리29차(2026)가 남는 표시 결함을 확인했다. 기존 모의 UI 통과는 이 제목 일치까지 검증한 결과가 아니었다. 구현 담당이 완료된 weeksScope의 연도·범위로 제목을 구성하고 입력범위 불일치/미조회에는 `조회 범위 확인 필요`를 표시하도록 보완 중이다. 운영 weeks_view 검사에도 완료 제목 전체 정확일치와 입력 비움 시 이전 제목 제거를 추가했다. 새 빌드/앱 재검사 완료 전 제목 문제 해결로 확정하지 않는다.
