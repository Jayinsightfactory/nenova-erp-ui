# 견적서 본인 저장 외부변경 오인 수정

## 증상

견적서관리에서 사용자가 직접 수량·단가·품목·차감 등록 또는 삭제를 정상 저장한 뒤에도
`nenova.exe 또는 다른 화면에서 값이 변경되었습니다` 경고가 나타났다.

## 원인

저장 API는 ERP 원장 변경과 같은 트랜잭션에서 `WebErpEditLease.BaselineDigest`를 새 지문으로
정상 갱신한다. 그러나 화면은 저장 종료 직후 저장중 표시를 먼저 해제한 다음, 저장 전 화면
지문과 저장 후 지문을 비교했다. 본인 저장으로 지문이 바뀐 정상 상황을 외부 변경으로 오인했다.

기존 종료 처리는 `refresh`를 호출해 현재 원장을 무조건 새 기준으로 수용했다. 이 방식은 본인
저장 직후 `nenova.exe` 또는 다른 화면이 다시 수정한 값까지 본인 저장으로 받아들일 수 있다.

## 수정 계약

- 저장 성공 시 저장중 표시를 유지한 채 `heartbeat`로 서버 기준과 현재 ERP 원장을 비교한다.
- 서버 기준은 각 쓰기 API가 성공 트랜잭션 안에서 이미 갱신한 값만 사용한다.
- 두 값이 같으면 본인 저장으로 처리하고 경고를 표시하지 않는다.
- 저장 직후 외부 변경이 들어오면 `stale=true`가 되어 기존 경고와 저장 차단을 유지한다.
- 실패·부분 성공·업체 전환 중에는 새 기준을 자동 수용하지 않는다.
- 이 변경은 Order/Shipment/Estimate/Stock 원장을 추가로 쓰지 않고 작업상태 heartbeat만 갱신한다.

## 회귀 기준

1. 본인 저장 A→B 후 heartbeat: 경고 없음, 화면 지문 B.
2. 이후 외부 변경 B→C 후 heartbeat: 외부 변경 경고 유지.
3. 저장 확인이 끝날 때까지 8초 polling 중지.
4. 2025/2026 동일 차수와 다른 업체 범위는 기존 복합키로 분리.
