## 후속 요구사항: 기초·기말 재고별 이익률 원인 진단

사용자의 최종 목적은 이익률 이상을 발견했을 때 **기초재고에서 시작된 문제인지, 기말재고 문제인지 확인할 수 있는 보고서**다. 단순 전차수 대비 이익률 변동이나 재고 잔차를 원인으로 단정하지 않는다.

| 검사 | 필요한 대조 | 표시 제한 |
|---|---|---|
| 기초 이월 | 전차수 F와 이번 E의 금액·품목별 수량·StockKey·평가기준 | 서로 같아도 전차수 기말 원천이 검증되지 않았으면 정상 판정 금지 |
| 기초 원천 | 전차수 기초+입고−출고+실제 조정 ↔ 전차수 기말 | 전차수 이력·범위가 없으면 기초 원천 확인 필요 |
| 기말 원천 | 이번 기초+입고−출고+실제 조정 ↔ 이번 기말 | 차이를 폐기·선판매·오류 중 하나로 자동 단정하지 않음 |
| 평가금액 | 검증된 수량·환산계수·평가단가·통화 ↔ 보고서 E/F | 수량 문제와 단가 문제를 분리, 미검증 영향금액 산출 보류 |

판정은 기초 확인 필요 / 기말 확인 필요 / 양쪽 확인 필요 / 검증 범위 내 재고 차이 없음 / 자료 부족을 구분한다. '재고 차이 없음'도 환율·비용·매출 등 보고서 전체가 정상이라는 뜻은 아니다. 각 판정에 대상 연도·차수·품목·비교 값·근거 시점·미확인 조건을 붙인다.

### 구현 전 확인한 근거와 차단 조건

- 로컬 실제 Nenova.exe를 dnSpy.Console.exe의 FormStockView 타입으로 읽었다. 실제 조정은 StockHistory를 CodeInfo.Category='StockType' 및 ChangeType=Descr로 연결하여 AfterValue−BeforeValue를 합산하며, 선택 OrderYear+OrderWeek 범위를 사용한다.
- 기존 분석은 StockHistory 없이 잔차를 계산한다. 이 응답만으로 기초/기말 오류 확정 기능을 만들지 않는다.
- 확정 보고서의 저장 금액과 현재 실시간 원장을 섞어 확정 당시 수량이라고 표현하지 않는다. 확정 revision/시각과 조회 시각을 따로 표시한다.
- 품목 스냅샷 행 누락과 명시적 0은 구분한다. OutUnit/EstUnit 혼합 합산을 금지하고, 검증된 환산계수만 쓴다.
- 영향금액은 검증된 비교값이 있을 때만 제공한다. 일반식에서 기초 과대액은 이익을 그만큼 낮추고 기말 과대액은 이익을 그만큼 높이지만, 원가 평가 방식과 CNF 이익률 분모까지 확인해야 % 영향을 표시할 수 있다.
- 추가 진단 동작은 SELECT만 허용한다. StockHistory, StockMaster, ProductStock, 주문·출고·견적 및 WebProfitReport 저장값을 보존한다. 기존 본표 조회의 자동 draft snapshot 갱신과 새 진단 동작을 구분한다.
- 회귀 사례: 32차 세 품목 잔차, 실제 조정으로 설명되는 차이, 미존재 행 대 0, 전년도 동일 차수, 단위 불일치, 전차수 기말 오류의 이월, 양쪽 오류, 확정본/실시간 혼합, 검증 금액 영향 및 CNF 분모, 조회 실패 후 오래된 결과 표시 방지.

당시 운영 32차와 전차수의 실제 StockHistory·선택 StockKey·품목행 존재를 조회할 준비된 읽기 전용 DB 연결을 찾지 못해 필수 DB probe가 미완이었다. **이 접근 차단 판단은 아래 후속 SQL 조회로 해소되었다.** 기존 인증 브라우저의 직접 API 탐색 차단은 우회하지 않았다. 이 절은 수용 기준/조사 결과이며 웹에 반영된 기능 설명이 아니다.

## 최종 후속: MD의 연결 정보로 실제 SQL 조회 (2026-10-07)

사용자가 `sql에서 데이터 확인해봐 md에 있어`라고 지정했다. 주 저장소 `docs/work_history.md`의 DB 연결 현황을 찾아 기존 MSSQL 연결로 SELECT를 실행했다. 앞선 환경변수만으로 연결 부재를 판단한 결론은 불충분했고 이번 조회로 정정한다. 인증값은 결과 문서에 복사하지 않는다. 운영 쓰기, 프로시저 실행, 재계산, 보고서 최신화·저장·확정은 하지 않았다.

### 기초·기말 금액 및 이익 영향

저장된 계산 결과를 SELECT로만 읽었다. 31차 SnapKey69/version7, 32차 SnapKey73/version5 기준:

- 31차 F와32차 E는 모두142,049.31425525935원, 수량270송이(27단), StockKey261로 일치한다.
- 32차 F는80,565.88003499228원, 수량170송이(17단), StockKey263이다.
- 평가 경로는 저장 payload의 `VERIFIED_CATEGORY_AVERAGE`, `(G+H)/purchaseQty*ProductStock`이다. 이 상태명이 실사 재고나 조정사유까지 검증했다는 의미는 아니다.
- 32차 해당 평가단가를 고정하면80,565.88003499228÷170=473.9169413823075원/송이. 실제 순조정−48단(−480송이)이 없었다는 **단일 변수 가정** 대비 기말/이익은227,480.13186350762원 낮다. 매출4,633,298원 기준 이익률 영향은−4.909680574474329%p다.
- 이 가정 계산은 조정이 잘못됐다는 증거나 확정 보정액이 아니다. 기초·매입·매출·환율·평가단가를 고정했고, 조정의 타당성과 평가 원가 전체는 별도 검증이다. 실제 보고서나 원장은 변경하지 않는다.

**현재 판정:** 32차 기초 이월 일치, 31/32차 원장 수량식 일치(실제 조정 포함), 조정사유 미확인. '기초 또는 기말 계산 오류'로 단정할 증거는 없으며, 보고서에 실제 조정 내역과 조건부 손익 영향을 드러내는 것이 필요한 개선이다. 30차 이전의 기초 원천 및 전체 과거 차수 이익률 정상 판정은 이번 결과에 포함하지 않는다.
