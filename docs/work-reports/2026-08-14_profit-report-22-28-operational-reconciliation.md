# 주차별 매출이익보고서 22~28차 운영 원장 대조

## 결론

- 차수 없는 `매출원가 양식.xlsx`의 7행 설명을 계산 규칙의 최상위 원본으로 고정했다.
- 22~28차 원본 7개는 전체 시트·셀·수식 fingerprint 재생성에서 금액 1원, 비율 0.01%p 허용범위 안으로 모두 일치했다.
- 현재 운영 DB와 과거 Excel의 차이는 계산식 하나로 설명되지 않는다. 과거 보고서 작성 뒤 출고·입고 원장이 수정된 `현재 원장 변동`과, 기존 웹이 원본의 품목군 평균원가 공식을 사용하지 않고 모든 품목에 개별 단가 증거를 요구한 `재고평가 공식 불일치`가 함께 있었다.
- 26차 F→27차 E만 원본 workbook 내부에서 3,658,862.88875원 불연속이며 전액 베트남이다. 사용자 확정 규칙에 따라 웹은 26차 마지막 ProductStock 재고를 27차 기초재고로 이월하고, 이 예외 Excel 값으로 덮어쓰지 않는다.

## 적용한 재고 평가 규칙

1. 수량은 해당 대차수에서 ProductStock 행이 실제로 있는 마지막 숫자 세부차수를 사용한다. `FormStockView.GetData`와 동일하게 `StockMaster.isFix`를 재고 마감 조건으로 쓰지 않는다.
2. 27차 기초재고는 같은 연도 26차 마지막 ProductStock 재고이며, 01차만 전년도 52차로 넘어간다.
3. 원본 workbook에서 공식이 확인된 콜롬비아 수국·카네이션·장미·루스커스·알스트로와 베트남은 `(Q×R+S×R+H) ÷ 당주 매입수량 × 마지막 ProductStock 재고수량`으로 평가한다. 22~28차 replay에서 수식이 있는 셀은 1원 이내로 재현됐다.
4. 위 공식 대상이 아닌 국가는 같은 연도·세부차수·품목의 직접 확정 단가를 우선하고, 없을 때 같은 품목·매입단위의 사용자 확정 도착원가를 수량가중 평균한다.
5. 2026년 22~28차는 위 자동식·품목단가가 없을 때만 파일 SHA와 시트·F셀 위치가 고정된 원본 workbook 값을 역사 증거로 사용한다. 다른 연도와 29차 이후에는 적용하지 않는다.
6. 단순 업로드/자동매칭, 단위 불일치, 다른 차수, 다른 연도, 최근매입단가, Product.Cost, 공식 대상 이외 카테고리 평균은 사용하지 않는다. 근거가 없으면 입력 필요로 표시하며 최종 E/F 직접입력은 허용하지 않는다.

## 2026-08-14 운영 재확인 정정

- 운영 재고관리 화면에서 `2026-27-02`는 재고가 있는 75개 품목군을 정상 조회했다.
- 같은 시점 주차보고서가 E/F를 0으로 표시한 직접 원인은 보고서 SQL만 `StockMaster.isFix=1`을 요구한 것이었다.
- dnSpy 근거상 FormStockView는 이 필드를 조회·필터하지 않으므로 조건을 제거하고 `OrderYear + 대차수 + ProductStock 존재 + 숫자 세부차수 최신순`으로 통일했다.

## 아직 직접 확인이 필요한 값

미래 차수에서 사람이 확인할 값은 계산식이나 DB 자동값이 아니라 외부 청구서로 확정되는 백상 창고료, 관세, 선율, 한국 방역, 콜롬비아 소독, 콜롬비아 방역 공제다. 원본 공식 대상 이외 국가의 재고단가는 E/F 최종금액이 아니라 품목별 확정 단가 근거를 저장한다. 과거 22~28차 원본 F는 확정자·확정시각 sidecar가 없는 역사 증거이므로 파일 SHA·시트·셀을 고정하고 미래 운영 저장 근거와 구분한다.
