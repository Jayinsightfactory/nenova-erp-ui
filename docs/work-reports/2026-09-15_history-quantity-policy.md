# 수량 대조 처리 표시

사용자 명시 기준: 변화 내역과 수량이 같으면 우선 처리된 것으로 본다.
동일 요청 반복 가능성이 낮다는 업무 판단을 UI 분류에 반영한다.

기존 정확 매칭(MATCHED)은 보존하고 QUANTITY_MATCHED를 별도로 표시한다.
서버가 같은 연도·차수·업체·원문 이후·유일 로그로 반환한 PRODUCT_HISTORY_CANDIDATE 중
같은 단위의 signed delta가 일치하는 요청을 대상으로 한다. 다른 단위의 숫자만 같은 경우,
서로 다른 원문이 하나의 로그를 경쟁하는 경우, 이력 잘림과 주문 이력만 존재하는 경우는
분배 처리됨으로 승격하지 않는다. 품목 매칭을 저장하거나 변경하지 않는다.

| 동작 | Order/Shipment | History | 재고/ShipmentDate/Farm | Estimate/손익 |
|---|---|---|---|---|
| 수량 대조 표시 | 보존 | 기존 읽기 결과 사용 | 보존 | 보존 |

SQL/API/ERP 저장 변경 없음. 기존 FormOrderAdd 주문수량 vs 미발주수량 구분과
원문 전체 차수별 대조 경로를 유지한다. 완료 표시는 업무 누락 점검을 위한 사용자 지정
휴리스틱이며 같은 원문을 처리한 직접 로그 증명과 구분한다.

검증: 동일 수량/방향/단위 양성, 반대 방향·다른 단위·다른 수량·중복 id 음성,
혼합 메시지에서 일부만 초록 표시, 정확/수량 혼합 전체 처리 표시, 기존 교차연도 가드.
