# 호텔 추가·신라 업로드/저장·기존행 보존 충돌

## 사용자 기준

- 호텔 이름을 직접 입력해 결산 탭을 추가한다. 전산 Customer 생성은 요청하지 않았다.
- 신라 버튼은 ‘신라 업로드’, 업로드 뒤 명시 ‘저장’ 작업이 보여야 한다. 검증 없는 자동 저장은 금지한다.
- `시네신스 · 화이트`의 동일 품목·단가 기존행 2개 오류 원인을 확인한다. 임의 중복 삭제/합산/원가 평균 금지.
- 기존 호텔 데이터와 ERP 주문·출고·재고·견적을 보존한다.

## 원인 근거

`mergePnlImportedItems`는 이름+판매단가(+신라 단위)로 후보를 만들며 2개 이상이면 즉시 예외를 던진다. 신라 parser는 행을 합산하지 않고 `remark=시트명 N행` 원본 위치를 보존한다. 기존 저장 Remark가 있어도 재업로드 연결에 사용하지 않아 정상적으로 반복된 원본 품목도 충돌할 수 있다. 사용자 오류의 정확한 연도/차수/기존행 내용은 아직 직접 조회하지 않았다.

| 호텔 추가 | 명시 이름·안정 식별키 저장 | 보존 | 보존 | 보존 |

| 행 구분 불가능 | 보존 | 전체 저장 차단 | 보존 | 보존 |

## 보존 매칭 기준

- 기존 정확 identity는 유지한다. 신라에서 여러 후보가 있으면 같은 원본 위치+동일 품목/단위 후보를 우선하되, 행 삽입·이동에서 잘못 이전하지 않도록 원본 내용 근거도 대조한다.
- 한 기존행은 한 업로드행에만 사용한다. exact/fallback 양쪽에서 재사용하지 않는다.
- 유일한 내용(수량·금액) 후보 또는 동일한 보존 메타데이터만 결정적으로 연결할 수 있다. 서로 다른 수기 원가/품목키를 임의 선택하지 않는다.
- 원본 행 수·수량·판매가·금액은 그대로 두고 수기 원가/명시 품목 연결만 보존한다.
- 실패 시 호텔·차수·품목과 확인할 기존행을 쉬운 말로 안내하고 같은 오류를 반복 나열하지 않는다.
- preview와 transaction은 같은 helper, 원본 재파싱/token/snapshot 보호를 유지한다.

## 원천과 미확인

main이 FormOrderAdd.GetDataProduct 저장 decompile, FormRaumPnl golden, WebRaumPnl/Item 문서·실제 SQL, 기존 계약을 읽었다. EXE에 호텔 웹 결산 등록부는 없으며 Customer·공유 ERP 생성은 범위 밖이다. 운영 원본 업로드/저장 시험은 하지 않는다. 기본 UI 검사는 1920×1080, 확대100%, 작은 화면도 접근 가능해야 한다.

## 구현·중간 검증

- 이름 직접 입력 등록부 `WebPnlHotel`과 인증 API. 기존 3개 호텔 코드 유지, 새 호텔은 `hotel_`+12자리 식별자, 선택 연도+차수+호텔로 저장한다.
- 신라 버튼을 ‘신라 업로드’로 변경하고 업로드 전에도 저장 위치·작업 순서를 표시한다. 미업로드 저장은 비활성이다.
- 새 호텔은 전산/전역 매입단가 기능을 상속하지 않는다. 표준 견적서 업로드 후 수동 저장, 매입단가 입력은 해당 호텔 결산에만 반영한다.
- 프로덕션 빌드 2회 통과. 손익계산서 전체 테스트, ERP 계약/manifest/쓰기 보호, 저장 dnSpy 근거 검사 통과. 검토에서 발견된 원본 행 삽입·삭제와 단순 수량 수정, 내용 중복의 선점 문제를 보완했다. 행 수 변화에 기존 수기원가/품목키가 있으면 보수적으로 확인을 요구하고, 기존행이 없는 첫 업로드는 허용한다.
- 호텔 master 상세/월지정/삭제는 기본 호텔까지 정확한 PartnerCode 일치를 검사한다. 새 호텔명은 인쇄 HTML에서도 escape한다.
- 실제 Chrome 1920×1080 로컬 API fixture에서 직접 이름 등록, 실패 안내와 입력값 유지, 추가 후 선택 이동, 새로고침 후 호텔 선택 유지, 신라 업로드/저장 배치 확인. 모든 `/api`는 loopback mock이며 운영 DB/원장 쓰기 없음.
- 운영 읽기 API 직접 탐색은 브라우저에서 `ERR_BLOCKED_BY_CLIENT`로 중단됐다. 이후 기존 탭이 다른 업무 페이지임을 확인해 더 조작하지 않았다. 해당 탭은 종료 대상에서 제외한다. 사용자 오류의 정확한 차수·기존행은 아직 확인하지 못했다.
- 작은 화면 1366×768에서도 호텔 추가 모달과 실패 후 재입력, Escape 닫기 확인. 기본 검증은 1920×1080이다.
- 배포는 이 기록 작성 시 대기. PR/운영 결과는 작업 세션 기록과 GitHub workflow 결과를 참조한다. 운영에 시험 호텔/결산을 추가하지 않는다.
