# 신라 품목 연결 사전 확인

- 요청: 신라 결산 품목을 전산 품목에 연결하고 차수별 매입단가 관리에서 함께 비교한다.
- 기준: `f3aff785`, 전용 `codex/shilla-product-matching` 작업공간. 기존 업로드 용량 보호와 거래처 응답 경계 유지.
- 허용: 사용자가 선택한 신라 결산 행의 품목 연결, 결산용 매입단가 조회·수정 기능.
- 보존: 원본 품목명·단위·수량·매출·이익배분율, 주문·분배·재고·견적 원장 및 전산 Product. 라움/초이문 공통 단가와 신라 단가는 독립한다.

## 전산 근거

기존 디컴파일 `FormOrderAdd.cs`의 `GetDataProduct`(326행부터)를 직접 읽었다. 품목 연결은 `Product.ProdKey`이며 `OutUnit`, `BunchOf1Box`, `SteamOf1Bunch`, `SteamOf1Box`가 별도 값이다. 해당 EXE 주문 저장 경로는 주문·출고 원장을 변경하므로 이번 웹 결산용 품목 연결에서는 호출하지 않는다. 새 dnSpy 실행을 했다는 의미는 아니다.

현재 웹 `item-mapping` 검색은 활성 Product를 읽지만 POST는 전역 이름 매칭을 저장한다. 신라에는 이를 그대로 쓰지 않고 결산 연도·차수·부모·행을 제한한 저장이 필요하다. 기존 `mergePnlImportedItems`는 원본명·단위·단가가 같은 기존 행 또는 유일한 대체 행의 ProdKey를 보존하고 충돌 시 중단한다. 재업로드 보존은 회귀검사로 다시 확인한다.

## 검증 경계

전용 작업공간에 운영 연결 환경파일은 없다. 비밀값을 다른 작업공간에서 복사하지 않는다. 서버 저장은 실행형 가상 거래 검사로, 운영 확인은 로그인 화면의 읽기 및 검색으로 수행한다. 실제 사용자 자료의 임의 연결·단가 수정은 시험 목적으로 실행하지 않는다.
