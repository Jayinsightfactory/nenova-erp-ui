# 신라 미매칭 일괄 연결 — 사전 준비 및 검증 기록

## 사전 준비

- 작업 기준: `4e5ac662`, 전용 `codex/shilla-bulk-unmatched` 작업 브랜치. 다른 작업의 도착원가 변경은 보존한다.
- 기존 작업 완료 보고서 2개 수정은 앞 작업의 운영 결과이며 보존한다.
- 의존성 설치 확인, GitHub 로그인 확인. 운영 SQL 연결/비밀값은 사용하지 않는다.
- 전용 worktree에 없는 `docs/CODEX_SUBTASK_ORCHESTRATION.md`는 승인된 메인 작업 `work/nenova-erp-ui/docs` 원본을 읽고 적용했다. 하위 작업은 승인창 없이 로컬 파일·검사만 수행하고 외부 쓰기·배포는 메인이 수행한다.
- 설계/최종 검토: gpt-5.6-sol high. 서버/API·화면 구현: 각각 gpt-5.6-terra high. 설계 GO 후 분리된 파일 범위로 구현을 시작했다.
- 현재 운영 35차 6개 미연결 항목과 쉬머 한글 검색 후보를 화면에서 읽었다. 이 자료를 임의로 연결하지 않는다.
- `FormOrderAdd.cs` GetDataProduct의 ProdKey/ProdName/OutUnit/환산필드 원문을 다시 확인했다. 이번에는 기존 웹 결산 연결키만 쓰며 EXE 저장/SP를 추가 호출하지 않는다.

## 수용 기준

- 선택 연도·신라의 미매칭 원본명+단위 그룹을 모두 모으고 연결된 형제행까지 동시성 대조에 포함한다.
- 기존 유일한 활성 연결만 추천값으로 제공한다. 새 후보는 한글 검색 후 사용자가 선택한다. 추천이나 검색만으로 저장하지 않는다.
- 선택한 그룹/행/차수 확인 후 단일 요청·단일 트랜잭션으로 빈 ProdKey만 채운다. 저장 전 그룹 구성과 원본값을 재조회하고 충돌 시 전체 중단한다.
- 수량·매입가·판매가·금액·배분율·다른 호텔/연도와 모든 ERP 원장은 보존한다.
- 저장 중 중복 제출 금지, 연결 실패 시 입력 선택 보존, 불확실한 응답에 자동 재시도 금지. 완료 후 남은 미매칭만 표시한다.
- 기준 UI 1920×1080 CSS. 이름 열 무제한 확대 없이 조밀한 표/검색 영역, 좁은 화면에서 명확한 스크롤. 중첩 화면틀을 만들지 않는다.

## 검증 결과

- `npm run test:shilla-pnl` 통과: 원본 35차수 파서·개별/그룹 연결·일괄 API·화면·공통 매입단가 기존 검사 포함.
- `npm run verify:erp-change` 전체 통과, 운영 빌드 103페이지 성공. 최초에는 기존 화면 잠금 검사 정규식이 새 모달 조건을 허용하지 않아 중단됐으며, 새 조건까지 필수로 요구하도록 보강한 뒤 재실행했다.
- 새 파일을 스테이징한 뒤 `test:erp-manifest -- --changed-from origin/master` 43개 계약 및 `guard:erp-writes -- --changed-from origin/master` 변경 API 1개 통과.
- 실제 공용 이름/단위·동시성 함수를 사용하는 모의 DB 검사에서 그룹 구성 변화, 유효하지 않은 품목, 잠금 실패, 영향 행수 불일치, 중간 실패 전체 롤백과 0원 원본 보존을 확인했다.
- 화면 검사: 한글 조합 중 Enter 방지, 검색 세대 무효화 후 로딩 해제, 충돌 그룹 제외, 단일 저장 요청 구성, 선택 범위 집계, 실제 React 서버 렌더 통과.
- 최종 검토 및 운영 읽기 전용 확인은 이어서 수행한다. 실제 운영 연결 저장 시험은 별도 실행하지 않는다.
- 최종 검토에서 운영 프록시 1MiB 제한 대비 앱 8MB 허용 불일치를 발견했다. 운영 설정 확대 대신 UI의 UTF-8 JSON 사전 검사를 900KiB로 제한하고 API도 900kb로 맞췄다. 한글 다중바이트 상·하한, 초과 요청 전송 0회·선택 보존 검사와 신라 전체 검사를 다시 통과했다.
