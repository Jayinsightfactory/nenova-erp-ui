# Nenova Desktop 1.0.0 검증 기록

## 범위

Windows x64, Electron 44.6.0, electron-builder 26.15.3. 별도 `desktop/` 패키지이며 기존 Next.js 화면·서버 API·SQL은 변경하지 않았다. 공유 ERP 원장 쓰기 기능을 새로 구현하거나 서버 검증을 우회하지 않는다.

## 검증 결과

| 항목 | 결과 |
|---|---|
| URL 원점·프로토콜·자격증명 거부, 저장 query 허용 목록 | Node 정책 테스트 통과 |
| 정본 메뉴의 비공개 항목 제외·재생성 결정성 | 통과, 일반 메뉴 80개 |
| 같은 경로의 독립 탭, 입력 후 전환 | 실제 Electron fixture 통과 |
| 창 분리·다시 합치기 | 동일 WebContents ID와 편집값 유지 |
| 탭별 확대 | 실제 getZoomFactor로 120%/100% 격리 확인 |
| 빈 인쇄창 document.write와 같은 origin 팝업 | 반환 핸들 및 opener 메시지 왕복 통과 |
| 원격 Node·process·desktop IPC | undefined 확인 |
| 개별 닫기 취소·beforeunload 취소 | 탭·편집값 보존 |
| 탭·보조 창 종료 객체 정리 | destroyed 후 WebContents getter가 없어지는 경우 수정 후 통과 |
| A→B 계정 변경 | 인증 대기 중 쓰기 차단, 기존 view 폐기 및 A localStorage 정리 확인 |
| 재실행 복원 | 두 개 별도 프로세스에서 2개 창·3개 탭·즐겨찾기·배율 복원 |
| 교차연도 | 2025/2026 동일 week=1 URL을 각각 보존 |
| 저장 형식 | 암호문에 URL·제목·입력 sentinel 없음, 복호화 스키마에 폼 입력 없음 |
| 화면 | shell 1920×1080 및 800×1080 CSS px, 100%; 가로 overflow 없음 |
| 고정 상태바 | 메뉴 표시/숨김 모두 마지막 28px 유지 |
| 설치기 | NSIS 설치·실행·제거 exit 0, 실제 설치된 앱 로그인·메뉴·새 창 확인 |
| 패키지 | asar 13 entries, .env·DB 드라이버·테스트·개발 스크립트 미포함; 소스와 패키지 비교 |
| 보안 fuse | RunAsNode/NodeOptions/Node inspect 비활성, cookie encryption/asar-only/integrity 활성 |

실제 운영 서버의 `/orders/paste`, `/sales/defect-deductions`, `/raum/pnl`, `/estimate`를 격리 프로필로 로그인하여 조회했다. shell 기준 1920×1080에서 업무 view는 상단/상태바를 제외한 **1920×924**다. 해당 읽기 전용 확인에서는 모든 non-GET/HEAD/OPTIONS 요청을 차단했고 ERP 업무 쓰기는 실행하지 않았다. 폼 등록·확정·실제 프린터 출력의 전체 회귀를 실행했다는 의미는 아니다.

## 저장소 검증

`npm run test:erp-contract`, `npm run test:nenova-dnspy-evidence`, `npm run test:erp-manifest -- --changed-from HEAD`, `npm run guard:erp-writes -- --changed-from HEAD`, `npm run build` 통과. 별도 desktop 단위·실행·재시작 테스트 통과. 고성능 에이전트의 보안/수명주기 최종 검토에서 차단 이슈 없음.

## 한계

복원은 탭 주소·창 배치·즐겨찾기·배율이다. 모든 미저장 업무 폼 복원, 오프라인 ERP, 자동 재전송, 자동 설치 업데이트, 다중 계정 동시 작업은 제공하지 않는다. 창 전체/앱 종료는 사용자가 명시적으로 미저장 입력 일괄 폐기를 확인하는 동작이다. 업무 안전성은 기존 서버 인증·트랜잭션과 각 화면의 계약을 따른다.
