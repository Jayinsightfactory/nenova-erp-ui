# Nenova Desktop 제품·구조 계획

작성: 2026-10-07. 이 문서는 제품 목표와 인수 기준이다. 구현·검증 완료 여부는 별도 빌드/검증 기록으로 판단한다.

## 목적과 범위

기존 `https://nenovaweb.com` 업무 화면을 Windows 앱 안에서 열고, 여러 업무를 Chrome 탭이나 Excel 시트처럼 전환한다. 초기 구현은 상단 탭 방식이다. 탭을 별도 창으로 분리해 모니터 사이에서 이동하고, 다시 원래 창으로 합친다. 즐겨찾기와 마지막 창 구성을 복원해 매번 같은 화면을 다시 찾는 시간을 줄인다.

Windows 설치 파일까지 제공하는 것이 1차 목표다. 오프라인 ERP 저장, MSSQL 직접 연결, `nenova.exe` 코드 복제, 다른 계정의 동시 사용은 포함하지 않는다. 인터넷과 기존 웹 서버가 필요하며, 웹 화면 변경은 기존 웹 배포를 통해 반영된다. 데스크톱 창 관리 코드 변경은 새 앱 설치 파일이 필요하다.

## 구조 결정

Electron 44.6.0을 고정한 별도 데스크톱 패키지를 사용한다. 배포 전에 실제 lockfile과 Electron 지원 상태를 다시 확인한다. 기존 Next.js 서버를 EXE에 내장하거나 PC에서 별도 DB 서버를 실행하지 않는다.

| 구성 | 책임 | 허용하지 않는 책임 |
|---|---|---|
| Electron main | 창·탭 수명, 화면 배치, 승인된 URL 정책, 로컬 설정, 다운로드·인쇄 진입 | SQL, ERP 재계산, 주문 자동 재시도 |
| 패키지에 포함한 로컬 shell | 탭, 시트 표시 방식, 즐겨찾기, 새 창·합치기 메뉴 | 원격 HTML·스크립트 실행, 임의 파일 탐색 |
| 탭별 WebContentsView | 기존 Nenovaweb 화면과 브라우저 상태 | Node.js, preload, 데스크톱 IPC 접근 |
| 기존 HTTPS 서버 | 로그인·권한·ERP API·기존 저장 계약 | 데스크톱 창 위치 관리 |
| PC 로컬 설정 | 탭 URL·순서·창 위치·즐겨찾기 | JWT·비밀번호·수량 입력·ERP 응답 복사 |

원격 웹과 로컬 shell의 보안 경계를 분리한다. 로컬 shell에만 최소 preload를 두며, 탭의 원격 페이지에는 preload를 주입하지 않는다. `WebContentsView`는 독립 webContents를 표시하고 한 webContents를 두 view에 동시에 표시할 수 없다. [Electron WebContentsView API](https://www.electronjs.org/docs/latest/api/web-contents-view)

탭을 이동할 때 기존 view를 원래 부모에서 제거하고 대상 창에 연결한다. URL을 다시 열어 옮기면 미저장 입력이 사라지므로 이동 구현으로 인정하지 않는다. 창을 닫는 과정에서는 소유한 webContents도 명시적으로 정리한다. 이 수명 관리 정책은 프로젝트의 설계 결정이며, 실제 detach/attach smoke에서 DOM·스크롤 유지 여부를 확인한다. [Electron View API](https://www.electronjs.org/docs/latest/api/view)

## 사용자 흐름

1. 설치 후 실행하면 Nenovaweb 로그인이 열린다. 로그인은 기존 웹 양식에서 한다.
2. 사용자는 업무 URL 또는 시작 메뉴에서 새 탭을 연다. 같은 화면을 두 탭에 열어 서로 다른 연도·차수·업체를 비교할 수 있다.
3. 탭을 선택하면 해당 페이지의 현재 입력·스크롤이 유지된다. 탭 순서를 드래그 또는 키보드로 바꿀 수 있다.
4. `새 창으로 분리`를 실행하면 해당 탭이 새 Windows 창에 그대로 이동한다. 대상 창 선택 메뉴로 다시 합칠 수 있다. 드래그 분리와 합치기는 동일한 main 명령을 사용한다.
5. 별표로 현재 페이지를 로컬 즐겨찾기에 추가하거나 해제한다. 탭 이름을 바꾼 뒤 즐겨찾기에 등록할 수 있다. 별도의 즐겨찾기 이름 편집창은 후속 범위다.
6. 정상 종료 후 다시 실행하면 저장한 창·탭 구성을 복원한다. 인증 만료 시 로그인 뒤 복원하며 미저장 입력 복구를 약속하지 않는다.

## 미저장 상태와 복원 계약

`탭 구성 저장`과 `ERP 저장`은 별개의 상태다. 로컬 설정 저장 성공으로 주문/출고 저장 완료를 표시하지 않는다. 닫은 탭 다시 열기는 URL을 새로 여는 것이며 미저장 양식을 복원하지 않는다. 복원 파일에는 POST body, DOM, 입력값, 수량, 가격, 고객 정보, 토큰을 넣지 않는다.

현재 일부 페이지만 `beforeunload`를 구현한다. 따라서 초기 버전은 페이지의 정확한 dirty 상태를 안다고 표시하지 않고, 손실 가능한 닫기·재로드·전체 종료에 명시적 취소 가능한 경고를 제공한다. 개별 탭 닫기는 `webContents.close({ waitForBeforeUnload: true })`를 사용하며, 페이지가 등록한 `beforeunload` 차단도 확인한다. 새로고침·탐색의 unload 차단도 `will-prevent-unload` 확인으로 처리한다. 취소가 기본이며 사용자가 폐기를 선택했을 때만 진행한다. [Electron webContents API](https://www.electronjs.org/docs/latest/api/web-contents)

창 전체 닫기는 **이 창의 모든 탭**, 앱 종료는 **모든 창의 모든 탭**의 미저장 입력을 버린다는 문구로 한 번 확인한다. 사용자가 진행을 선택하면 해당 범위를 일괄 폐기하며 페이지별 `beforeunload` 대화상자를 다시 반복하지 않는다. 이 전역 확인은 자동 저장이나 미저장 상태 탐지를 의미하지 않는다. 계속 작업을 선택하면 전체 종료를 취소한다.

PC 강제 종료, 프로세스 crash, 전원 차단 이후 미저장 폼은 복구되지 않는다. 복원 안내에 이 한계를 표시한다. 자동 저장 기능을 추가하려면 웹 페이지별 업무키·초안 격리·권한·동시 수정 계약을 별도 설계한다.

## 계정·설정 범위

기존 인증 근거는 `pages/api/auth/login.js`, `pages/api/auth/me.js`, `pages/api/auth/logout.js`, `lib/auth.js`다. `nenovaToken`은 HttpOnly 쿠키이며 토큰 유효기간은 8시간이다. `localStorage.nenovaUser`는 화면 표시용이므로 권한 판단에 사용하지 않는다.

1차 앱은 Windows 사용자 한 명당 한 ERP 로그인 세션을 공유한다. 계정 A의 열린 화면이 계정 B의 새 쿠키로 저장하는 사고를 막기 위해 인증 교체는 전체 창의 전환으로 처리한다. 로그아웃 또는 토큰 교체 감지 시 기존 remote view를 중지하고, 검증된 현재 계정이 확정되기 전 다른 업무 페이지를 다시 활성화하지 않는다. 자세한 조건은 [SECURITY.md](SECURITY.md)를 따른다.

현재 로컬 설정은 서버로 검증한 계정 ID와 함께 safeStorage로 암호화한 단일 snapshot이다. 같은 계정으로 확인된 경우만 복원하며, 계정을 바꾸면 이전 구성·즐겨찾기를 새 계정에 적용하지 않는다. `policy.cjs`가 지정한 연도·차수·고객/품목키 등 query만 남기고 token·검색어·fragment를 제거한다. 탭 이름도 저장하므로 민감한 메모를 제목에 쓰지 않도록 한다. 계정별 여러 작업 공간을 보관하는 기능은 후속 범위다.

## 화면·키보드 기준

기준은 CSS viewport 1920 × 1080, 브라우저 확대 100%다. 데스크톱 shell이 차지하는 높이와 실제 원격 페이지 viewport를 각각 기록한다. 물리 모니터가 1920 × 1080이라는 이유로 원격 콘텐츠도 동일 크기라고 주장하지 않는다. 웹 페이지는 독립 브라우저의 1920 × 1080에서도 기존 기준 검증을 유지한다.

앱 창과 원격 페이지 모두 반응형으로 배치하고 작은 창에서도 핵심 버튼을 접근 가능하게 한다. 탭이 많으면 가로 스크롤/전체 탭 목록을 제공하고, 고정 폭 1920px 페이지를 만들지 않는다. 웹 메뉴·상단바는 기존 `_app.js` 소유를 유지하고 데스크톱 shell은 창·탭 조작만 담당한다. `?popup=1`은 기존 팝업 화면 계약에 맞는 경로에만 적용한다.

| 조작 | 기본 동작 |
|---|---|
| Ctrl+T / Ctrl+W | 새 탭 / 현재 탭 닫기 확인 |
| Ctrl+Tab / Ctrl+Shift+Tab | 다음 / 이전 탭 |
| Ctrl+N | 새 창 |
| Ctrl+D | 즐겨찾기 |
| Ctrl+K / Ctrl+L | 업무 메뉴로 이동 |
| Ctrl+R / F5 / Ctrl+P | 새로고침 확인 / 인쇄 |
| Alt+← / Alt+→ | 뒤로 / 앞으로 이동 확인 |
| 방향키, Enter, Space | 탭 목록·메뉴 선택 및 실행 |
| Escape | 메뉴·이동 선택 취소, 호출 위치 초점 복귀 |

웹 업무 입력과 충돌하면 해당 단축키를 조정하고 화면 도움말에 표시한다. 방향키로 셀/입력값을 편집하는 기본 동작은 보존한다. 모든 shell 동작은 키보드 메뉴로도 가능해야 한다. 현재 탭 이름 변경은 더블클릭 진입 방식이며, 키보드 진입·순서 변경 등 전체 인수 항목은 실검증 결과와 구분한다.

데스크톱 main은 저장을 대신 실행하거나 재시도하지 않는다. 기존 웹 기능 변경이 필요해지면 실제 dnSpy SQL·read-only probe·대상 계약 JSON·교차연도 fixture를 먼저 준비한다. 앱 포장 작업을 이유로 주문/재고 가드의 예외를 만들지 않는다.

## 검증과 배포 단계

1. URL·IPC·저장 파일 정책의 실행형 테스트와 shell fixture를 검증한다.
2. 로컬 fixture에서 1920 × 1080/100%를 기록하고 탭 전환·분리·합치기·복원·키보드·종료 취소를 검증한다. fixture 통과는 운영 로그인·ERP 검증을 대신하지 않는다.
3. Windows 설치 파일과 SHA-256을 만들고 설치/실행/제거를 검증한다. 앱 버전과 Electron 버전을 기록한다.
4. 로그인한 실제 Nenovaweb에서 읽기 전용 화면과 기존 다운로드·인쇄를 확인한다. 운영 ERP 테스트 쓰기를 임의로 만들지 않는다.
5. 외부 배포는 서명 상태·검증 결과·잔여 제한을 구분해 제공한다. 서명되지 않은 내부 확인용 설치 파일을 정식 배포판이라고 표시하지 않는다.

목표 성능은 10개 탭 전환에 페이지 재로드가 없고, 반복 50회 창 분리·합치기 후 webContents 누수가 없는 것이다. 초기 측정 전 고정 메모리/초 단위 성능을 보장하지 않는다. 비활성 탭의 타이머·폴링은 기존 웹 동작이므로 다중 탭 부하를 실제로 측정한다.

## 인수 시나리오

- 주문과 출고 페이지를 다른 탭에 열고 서로 다른 연도·차수 선택을 유지하며 전환한다.
- 입력 중인 fixture 탭을 분리·재결합해 입력값과 스크롤을 비교한다.
- 2개 창에서 로그아웃한 뒤 다른 계정으로 로그인하여 이전 화면의 표시·쓰기가 차단되는지 확인한다.
- 닫기/종료 경고를 취소했을 때 해당 작업 페이지와 초점이 남는다.
- 비정상 종료 후 복원하되 미저장 데이터가 복원됐다고 안내하지 않는다.
- 두 번째 모니터를 제거한 뒤 다시 실행해 모든 창에 접근한다.
- 조작 버튼 겹침, 가로 잘림, sticky 가림, 모달 화면 이탈, 실패 알림, 표 스크롤을 검증한다.
- 로그/로컬 설정/설치 파일에 비밀번호, JWT, DB 연결 문자열이 없는지 확인한다.

## 구현과 인수 판정의 구분

2026-10-07 코드 검토 시점의 구현은 `desktop/main.cjs`, `policy.cjs`, `preload.cjs`, `shell/*`다. 로컬 shell만 preload를 갖고, 원격 탭은 WebContentsView로 표시한다. `window.open`은 `createWindow` 콜백에서 Electron이 제공한 webContents를 받아 관리 탭에 연결해 opener·빈 창 document.write 관계를 보존하는 구조다. 이 방식은 단순 `deny` 후 URL을 새로 여는 방식과 동작이 다르므로 fixture와 실제 업무 흐름 양쪽을 검사한다.

탭 상한은 50개이며 snapshot은 창 최대 12개·즐겨찾기 최대 100개로 제한한다. 소스에 동작이 존재한다는 사실은 운영 인증·설치·키보드·성능 인수 통과를 의미하지 않는다. 최종 빌드의 검증 기록에 완료·미검증·제한을 따로 남긴다.
