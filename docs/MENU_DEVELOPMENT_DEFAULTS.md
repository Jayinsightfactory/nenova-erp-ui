# 메뉴 개발 기본값

이 문서는 새 메뉴와 이번 작업에서 실제로 수정하는 메뉴에 적용할 기본 점검표다. 사용자가 여러 작업에서 반복해 요청한 방향을 다음 작업에서도 놓치지 않기 위한 기준선이며, 관련 없는 기존 페이지를 전부 다시 만드는 지시가 아니다.

최신 사용자 지시와 확인된 업무·ERP 계약이 이 문서보다 우선한다. 화면이나 업무 특성상 예외가 필요하면 이유와 검증 근거를 PR에 남긴다. 기능을 실제로 구현하지 않았는데 미래에 자동으로 처리될 것처럼 약속하거나 완료 상태를 만들지 않는다.

UI에서 같은 내용을 보여줄 때는 [`config/menu-development-defaults.json`](../config/menu-development-defaults.json)을 읽는다. JSON의 `section.id`, 제목, 항목 순서는 이 문서와 함께 유지한다. 이 기준 파일과 전용 테스트는 설명 자료이며 런타임 데이터나 ERP 원장을 읽거나 변경하지 않는다.

<!-- section:scope-and-iteration -->
## 항상 적용 · 범위와 개선 방식

- 새 페이지와 이번 작업에서 실제로 손대는 기존 페이지에 적용하고, 관련 없는 기존 페이지를 한꺼번에 다시 만들지 않는다.
- 이 목록은 반복해서 확인할 목표와 점검 기준이지 모든 화면을 똑같이 만드는 절대 규칙이 아니다.
- 최신 사용자 지시와 확인된 기능 계약이 다르면 최신 지시와 계약을 따르고 예외 이유를 기록한다.
- 기능을 실제로 만들지 않았다면 앞으로 자동으로 처리된다고 약속하거나 완료로 표시하지 않는다.

<!-- section:layout-and-accessibility -->
## 항상 적용 · 화면과 키보드

- 기준 화면은 `1920 × 1080` CSS pixel, 브라우저 확대 `100%`다. 정보 밀도와 첫 화면 접근성을 이 환경에서 우선 확인한다.
- 폭과 높이를 고정하지 않고 반응형으로 만들며, 작은 화면에서도 주요 버튼과 오류 메시지가 잘리거나 겹치지 않게 한다.
- 목록과 이력은 페이지 세로 스크롤을 기본으로 한다. 작은 고정 높이 상자 안에 세로 스크롤을 겹치지 않는다. 대용량 가상 표, 가로 표, textarea, 모달은 필요한 예외가 될 수 있다.
- 상단에서 주요 작업을 쉽게 찾게 하고, Tab·Shift+Tab·Enter·Space·Escape와 필요한 방향키로 핵심 업무를 마칠 수 있게 한다.
- 엑셀처럼 촘촘한 표도 이름과 핵심 수치를 읽을 수 있어야 한다. 업무상 전체 이름 확인이 필요하면 행 높이와 줄바꿈을 허용한다.
- 공통 shell과 메뉴 등록, 팝업 동작은 [`UI_LAYOUT_AND_MENU_CONTRACT.md`](UI_LAYOUT_AND_MENU_CONTRACT.md)를 따른다.

<!-- section:navigation-and-context -->
## 항상 적용 · 이동과 선택 맥락

- 뒤로가기는 창 닫기가 아니라 같은 메뉴의 처음 목록·선택 상태로 돌아가는 동작을 먼저 제공한다.
- 저장하지 않은 입력이 있으면 사라질 내용을 알기 쉬운 말로 경고하고 사용자가 계속할지 선택하게 한다.
- 연결된 검색·필터는 서로의 범위를 설명 가능하게 좁히며, 재조회와 상세 전환 뒤에도 유효한 선택을 보존한다.
- 선택이 더 이상 유효하지 않으면 조용히 다른 값으로 바꾸지 말고 이유와 다시 선택할 방법을 보여준다.

<!-- section:matching-and-apply -->
## 해당할 때 적용 · 입력, 매칭, 실제 반영

이 항목은 붙여넣기, 파일 업로드, 매칭, 대량 적용 기능이 있는 메뉴에만 적용한다. 모든 메뉴에 클립보드나 업로드 기능을 추가하라는 뜻이 아니다.

- 원본 값과 매칭된 수량·단위·단가를 나란히 보여 사용자가 비교할 수 있게 한다.
- 실제 ERP 반영 직전에 대상, 변경량, 제외·경고 건을 다시 보여주고 명시적인 확인을 받는다.
- 최종값 적용인지 증감 적용인지 화면과 요청 계약에 분명히 표시하고 두 방식을 추측으로 섞지 않는다.
- 매칭 저장 범위는 확인한 거래처·품목 조합으로 제한하며, 근거 없이 전체 공용 매칭을 덮어쓰지 않는다.

<!-- section:drafts-history-and-progress -->
## 해당할 때 적용 · 초안, 이력, 진행 상태

- 여러 단계 작업은 작업 초안과 이력을 다시 열어 이어갈 수 있게 한다. 사용자·시각·원천·적용 결과를 확인 가능한 근거와 함께 남긴다.
- 과거 근거가 없는 값을 현재 상태로 역산하거나 추측해 이력처럼 표시하지 않는다.
- 진행률은 측정 가능한 전체량이 있을 때만 실제 단계와 퍼센트를 표시한다. 알 수 없는 작업에는 가짜 퍼센트를 만들지 않는다.
- 실패하면 어느 단계에서 무엇이 실패했는지, 다시 시도하거나 고칠 수 있는 방법과 확인 가능한 로그를 보여준다.

<!-- section:erp-safety -->
## 해당할 때 적용 · 전산 자료 안전

ERP 데이터를 읽거나 쓰는 메뉴에만 적용한다. 자세한 사전 확인과 부작용 계약은 루트 `AGENTS.md`, [`ERP_CHANGE_GUARD.md`](ERP_CHANGE_GUARD.md), 기능별 `docs/contracts/*.json`을 따른다.

- ERP 조회·쓰기는 `nenova.exe`와 기능 계약의 실제 근거를 먼저 확인하고, 웹 화면만 보고 저장 범위나 부작용을 추측하지 않는다.
- 차수 업무키는 `OrderYear + OrderWeek + CustKey + ProdKey`를 기준으로 한다. 해마다 반복되는 `OrderWeek`만으로 조회·수정·삭제·집계하지 않는다.
- 확정 상태, 주문·출고·견적·매출 원장과 재고를 기능 계약 밖에서 바꾸지 않는다.
- 취소, 확정 해제, 재고 조정은 자동으로 실행하지 않는다. 계약에 있는 경로와 사용자의 명시 확인이 모두 있을 때만 수행한다.
- 화면 미리보기와 최종 저장은 같은 대상 범위와 정책을 사용하고, 저장 전 재검증과 저장 후 읽기 검증을 남긴다.

<!-- section:verification-and-release -->
## 항상 적용 · 검증과 완료 보고

- 관련 단위·계약·UI 테스트와 빌드를 통과한 뒤에만 다음 배포 단계로 진행한다.
- `1920 × 1080`, `100%` 실브라우저에서 가로 잘림, 겹침, sticky 가림, 모달 이탈, 표 스크롤, 버튼 상태와 실패 알림을 확인한다.
- 배포 대상 작업은 배포 뒤 실제 화면에서 핵심 흐름을 다시 확인한다. 확인하지 못한 단계는 완료라고 쓰지 않는다.
- PR 완료 전 아래처럼 각 기준을 기록하고 테스트·스크린샷·계약 같은 근거를 연결한다.

| 기준 | 판정 | 근거 |
|---|---|---|
| 예: 페이지 세로 스크롤 | 적용 / 해당 없음 / 예외 | 테스트, 스크린샷 또는 예외 이유 |
| 예: ERP 반영 전 확인 | 적용 / 해당 없음 / 예외 | 계약과 검증 결과 |

`해당 없음`은 기능이 없는 경우다. `예외`는 기능은 관련 있지만 다른 방법이 더 맞는 경우이며, 사용자 영향과 대체 검증을 함께 적는다.
