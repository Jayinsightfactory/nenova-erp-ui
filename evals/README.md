# evals — 정답 대조 회귀 방어 (파일럿)

## 목적
계산 로직(단위 환산, 선입선출 재고 평가, 박스당 무게)을 고치다가 **과거에 맞던 숫자가 조용히 틀어지는 것**을 막는다.
`gold_outputs/*.json` 에 "입력 + 기대 출력 + 근거 출처"를 두고, 실제 함수 출력과 **숫자 하나까지** 비교한다.
DB·네트워크·ECOUNT 접속 없이 돌아간다.

## 실행
```
npm run eval
```
- 전부 일치: 종료코드 0
- 하나라도 다르면: 종료코드 1, 마지막에 `케이스 | 항목 | 기대값 | 실제값` 차이 표 출력
- 케이스 파일 형식 오류(근거 출처 누락 포함): 종료코드 2
- 숫자는 기본 완전 일치. 부동소수점 나눗셈 등은 케이스에 `"tolerance": 1e-9` 처럼 명시한 경우만 허용.

## 케이스 파일 형식 (`gold_outputs/<id>.json`)
| 항목 | 뜻 |
|---|---|
| `id` · `title` | 이름과 한 줄 설명 |
| `module` · `export` | 호출할 함수 (저장소 루트 기준 경로) |
| `source` | **정답의 근거 출처** (문서·테스트·엑셀 등). 비어 있으면 러너가 거부한다 |
| `cases[].input` | 함수에 넘길 인자 배열 |
| `cases[].expected` | 기대 출력. 적은 항목만 비교한다(나머지 출력 항목은 무시) |

## 케이스 추가 규칙
1. **정답은 근거가 있는 값만** 쓴다. 엑셀·문서·기존 테스트·사장님 확인값이 출처다. 코드를 돌려 나온 값을 그대로 베끼지 않는다.
2. **사고가 재발하면 케이스로 승격**한다: 사고 때의 입력과 바른 값을 새 케이스로 추가하고 `source` 에 사고 날짜·문서를 적는다.
3. 기대값을 바꾸는 PR 은 "왜 정답이 바뀌었는지" 근거를 PR 본문에 적는다.
4. 새 함수를 대상으로 하려면 DB 없이 호출되는 순수 함수여야 한다(모듈 로드 시 `mssql` 패키지만 필요).

## 현재 케이스
- `adjust-units-rose-bunch` — 출고분배 단/박스/송이 환산 (장미 10단=1박스)
- `fifo-stock-price` — 기말재고 선입선출 단가 (2026-09-30 규칙)
- `fifo-layer-price-guard-aud` — 호주 30~32차 환율 누락 사고 가드
- `fifo-box-qty-salal` — 박스 입고 → 단 환산 (SALAL 70박스=1750단)
- `colombia-box-metrics` — 콜롬비아 박스당 무게·CBM 표

## 아직 없는 것
- 차수(OrderYearWeek) 계산, 매출원가 총액 등 **엑셀 정답 기준 케이스**는 근거 파일이 저장소에 없어 넣지 않았다. 엑셀 정답을 받으면 여기에 추가한다.
